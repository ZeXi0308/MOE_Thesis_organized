# Native full-save ordinary backfill：单格 CPU 计时诊断

[权威分析](A_NATIVE_BACKFILL_CPU_DIAG_RESULT_R01_20261001.json)对应一格加装计时器的 native full-save + ordinary backfill 诊断。正式测量 **83.160 s**，128/128 请求完成（123 个 `length`、5 个 `stop`）。记录了 20 次普通 backfill 选择，20 次均获原生异步加载准入、后续新输出并最终完成；动作步没有实际新增抢占。适配器主动 forced rotation 为 0，服务中仍有 66 次原生抢占。诊断格输出率为 1,524.748 token/s、mean flow 为 35.497 s、全体最大请求 gap 为 12.161 s；这些服务值只表明本格完整运行，不能与之前不同物理 GPU、不同自然输出轨迹的性能 pair 做差归因。

正式测量结束时的计时快照将四段互斥的适配器主机工作单独累加；`begin` 和 `hold` 在原生调度调用内，`schedule_pre` 在调用前，`schedule_post` 在返回后。下表的占比均以本格 **83.160 s** 正式测量时长为分母。

| 适配器段 | 调用数 | Host wall (s) | Thread CPU (s) | Wall 占正式测量 |
|---|---:|---:|---:|---:|
| `begin` | 5,479 | 2.534779 | 2.530850 | 3.048% |
| `hold` | 126,737 | 0.130115 | 0.085890 | 0.156% |
| `schedule_pre` | 5,479 | 0.022328 | 0.009224 | 0.027% |
| `schedule_post` | 5,479 | 0.033352 | 0.029095 | 0.040% |
| **四段合计** | **143,174** | **2.720574** | **2.655059** | **3.271%** |

合计调用数是四段回调次数之和，不是调度步数。`begin` 占已计入适配器 wall 时间的约 93.2%，单次平均 wall 为 0.463 ms；本格 5,479 次 `begin` 中最长一次为 41.293 ms。这里量到的是带计时器的适配器代码段，并非为服务额外增加的净时延或系统总 CPU 占用。原生调度主体、GPU 执行、异步传输不在这些段内；计时及汇总本身也有开销。

测量结束快照与卸载适配器时的最终计数相减，四段调用数、wall 和 CPU 增量均为 0；请求后 drain 调用数亦为 0。最大单次耗时不可通过快照差值计算。这个诊断定位了本格适配器计时段的成本，但没有重判此前 native full-save 对照的固定性能条件：那组已记录的 ordinary 臂输出率为原生参照的 94.108%，mean flow 为 105.225%，两项均未达 97%/105% 预算。[诊断原始会话](moe-a-native-backfill-cpu-session-r01-20261001/)和[此前性能 pair](A_NATIVE_BACKFILL_ONLY_PAIR_RESULT_R01_20261001.md)分别留存。

缓存文件最终 mtime 分类记录：源 seed 395 个文件、98,680,827 B；初始化新增或修改 32 个文件、15,624,697 B；预热及正式区间均为 0 个。这个端点记录不等于零编译或完整的即时缓存开销轨迹。
