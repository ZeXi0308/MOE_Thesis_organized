# G 首轮立项协议

冻结于 2026 年 10 月 8 日，任何 G 性能实验之前。首轮为 1–2 个工作日规模，最多两个候选版本；门槛未过不实现选择框架。本次现场 GPU 锁不可用，交付代码审计、历史可行性证据和测量探针，不排队等待、不启动模拟扫描。

## 决策门槛

A：同一 BF16 输入、权重、top 8 专家及其权重上，两个合法有效路径均通过正确性，且少量代表性真实路由下各自有竞争力。`moe_probe.py` 的 synthetic 模式仅检验算子和工具，不能通过现实竞争力门槛。

B：完整集合的稳态实际驻留差异与执行收益构成非支配权衡。若更快方案不增加实际内存，选它并停止组合论文探索。Triton tile 改变寄存器、共享内存或排序填充，不等于增加跨调用 GPU 驻留。

C：同一显存预算下，实际可分配 KV blocks 的差异，在预先冻结的自然轨迹上改变 batch、等待或抢占/恢复行为。估计扣了更多 KV、删除 graph、`reserved` 减少或图数量变化均不是充分证据。不能靠减少 KV 配额、填充显存或增加请求数通过此门槛。

仅在 A/B/C 全部通过后投入候选选择方法。核心 high 负载的请求 SLO goodput 相对最强简单基线至少提高 10%；至少三个配对反序重复均为正，改善应明显超过基线自身重复极差。完整报告 low 的全部退化、吞吐、尾延迟、规划和 capture 成本。若基线 goodput 为零，则只报告绝对值且不以无穷相对增益立项；不事后改 SLO。此规则仅决定资源投入，不证明论文贡献。

## 固定输入与完成条件

只用 `inputs/workload_low.json`（12 请求）和 `inputs/workload_high.json`（160 请求），字节与 D 既有输入一致。SHA、原始来源、历史环境见 `evidence/historical_feasibility.json`。不缩放到达时间，不改变 prompt、输出长度、路由规则或 BF16 精度。high 是既有高到达压力负载，目前没有证据表明其是 graph 成本导致的容量压力；若仍不敏感，应停止，不临时换 E320 或更大模型。

继承既有实验 SLO：请求 TTFT ≤ 4 s，输出 token 最大相邻间隔 ≤ 100 ms，从原定到达至完成 ≤ 20 s。三项同时满足才计入 goodput，分母为原定第一到达到全部请求完成的时间。统计使用引擎交付时间，不能标成含网络的 HTTP SLO。固定输出长度、`ignore_eos=True`、`detokenize=False` 与已有轨迹一致；保留所有失败/超时记录，不把未完成请求丢掉。

未来 G 服务主对照统一 BF16 OLMoE、TP1、GPU utilization 0.9、max model len 4096、max batch tokens 2048、max seqs 256、原生 FCFS、相同 prefix caching/chunked prefill/async 设置及默认恢复路径。不得带入 D 自适应 prefill 或 E 恢复选择 hook。启动探针只是对这一固定配置测成本，不把不同于历史 D 的配置差异当作 G 收益。

## 强基线与候选

1. 紧凑基线：少量合法 tile 筛选后，固定最大桶的稀疏 graph 集合；还必须核验原生 FlashInfer CUTLASS，避免故意弱化基线。
2. 局部速度基线：相同张量测得逐 token 桶最快的合法配置，保留其需要的计划；不考虑 KV 机会成本。用原生 tuned-config/M 分派，禁止逐层 GPU 到 CPU 路由同步。
3. 简单预算固定组合：按固定步长/几何桶或实测边际收益规则，在同一真实预算内选择；必须报告最强者，不能只比未调默认值。
4. 候选一（门槛通过后才实现）：整集合成本查表，按每个候选自身 KV 容量做一次短轨迹校正，以容量条件化 batch 分布估计 SLO goodput，输出一个启动期静态集合。无需模拟器或在线驱逐。第二版只能修正观察到的一个主要不足。

方法并不声称静态组合不能解决问题，最终输出本身就是静态组合。可检验的贡献是更可靠的选择过程；须用去掉集合成本、去掉容量条件化两项消融证明实际选错，否则停止。

## 成本测量与完整服务次序

每个集合独立新进程，固定 capture 顺序和编译缓存冷热策略。先记录 weights/context 基线，记录 native profile 的估计与瞬时峰值，再记录实际 KV allocation、真实 capture 和清缓存后的稳态。分别报告 PyTorch active/reserved/峰值、共享池分组、设备可用内存、持有的 KV storage，以及整集合 free-memory 差；池外残差只能称估计，不能武断全归 graph metadata。不要相加单图峰值。

当前 vLLM 的启动顺序是临时采样估计 → 分 KV → 捕获正式全集合。`startup_probe.py` 保留并观测它，不把它冒充“已精确测完全集合再分 KV”的新算法。若未来发现估计误差影响选择，需要用独立校准启动和新进程复核真实预算，不能在线扩 KV 或仅因 profiler 的每图 1 MiB 下限扣减而宣称收益。

只让筛选出的最强简单基线和一个候选进入完整 low/high 服务比较。主对照使 KV 随实际计划成本自然变化，并验证最终总占用相同预算；另将双方 KV 固定为主对照中较小的有效容量做辅助归因，明确标为固定 KV。主指标及 blocks、batch 分布、执行时间、真实集合内存、尾延迟、启动和 capture 成本须同时保留。固定 KV 不能替代主实验。

第一天：源码/兼容性/文献边界；锁允许时少量同输入算子正确性与三个集合启动测量。第二天仅在三门槛通过后做候选一与强基线的两负载配对；必要时一次针对性修改。任何资源锁忙直接退出 75，不启动等待器；本轮不补齐无意义的大矩阵。
