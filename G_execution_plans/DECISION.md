# G 研究卡与当前判决

2026年10月9日收束。**关闭当前候选投入，作为容量适用边界材料归档。** 已测compact在冻结low/high上的KV约束不生效；dense未测，联合优化主张未获支持，整体执行计划问题尚未确定。本轮按用户要求完成本地归档，不再补dense、扩展桶/tile或进行GPU实验。

| 研究卡 | 明确范围 |
|---|---|
| 服务对象与目标 | 单机MoE服务运营者；原目标为相同资源下完整请求吞吐与尾延迟取舍。缺应用SLO，历史4s/100ms/20s只作探索辅助，不作成功阈值。G完整服务未运行。 |
| 已测部署 | RTX PRO 6000 SM120、BF16 OLMoE、TP1、vLLM 0.26，原生显存策略0.9；长度4096、max seqs256、max batched tokens2048，FCFS，同步，无prefix/spec/connector。仅既有low12/high160有限请求，均为开发证据。 |
| 剩余损失与证据 | 历史D的尾延迟不能归因于G可控制的容量损失，也不是G强基线。compact的容量不足解释被排除；没有跨计划速度、内存和服务比较。 |
| 原合法动作及本轮决定 | 启动选择合法backend/tile/graph集合，固定路由、精度、准入与恢复。当前投入关闭，未测native、dense、其他tile/backend保持未测，不以两个请求桶集合的包含关系推断内存单调性。 |
| 近邻及贡献状态 | TensorRT-LLM已有graph桶/KV取舍，RaMP/DA-MoE已有选择机制；真实集合成本及容量反馈是否提供增量决策信息仍未知。本次仅形成条件边界材料，不包装为独立方法或负结果论文。 |

**可复算事实。** compact一次启动获得36828总/36827可用blocks，每块2 MiB。low/high逐请求最大长度包络为2107/34430 blocks，对应余量34720/2397 blocks（67.8125/4.681640625 GiB）。该条件界不依赖批次与执行速度，不是服务实测峰值。至少损失2398个可用blocks才会低于high充分界；这只是证书失效阈值，既非新增graph字节阈值，也不证明瓶颈激活。

**成本口径。** compact实际19个graph；132 MiB是启动估计，76 MiB是正式capture阶段差额，28 MiB为PyTorch graph池reserved，128 MiB为共享workspace。它们不可相加、不可替代graph独立驻留或两计划成本差。清cache释放106 MiB，KV仍为36828总blocks；最终整设备占用减KV storage为14.03729248046875 GiB，包含模型及context等。dense四次尝试均锁忙未初始化CUDA，容量和graph成本都是NA；既有D来自不同设备和调度代码，不构成受控对照。

**适用边界。** 该compact处理冻结有限负载时，继续节省少量graph内存不会增加可容纳请求集合；执行速度、排队与启动成本仍可能重要。当前负载加单端点证据不足以检验所设想的跨计划graph/KV取舍，不能写成dense或所有方案也容量充足。未来仅当有依据的并发/上下文契约、持续到达负载或实际设备/资源预算变化，使合法计划的实际KV差异跨越服务决策所需容量时，联合问题才可能重新重要；更小显存（如5090）本身不构成证据。本轮不实施这些变化。

**归档入口。** [容量账表、论文段落与最小复现](capacity_boundary.md)；[完整服务表及未运行项](service_comparison.md)；[三层假设与语义依据](hypotheses.md)。唯一归档命令为 `python3 -B G_execution_plans/archive_capacity.py`，只用G内现有材料。原始失败/未运行记录、配置与代码全部保留；当前没有待执行实验或资源等待。
