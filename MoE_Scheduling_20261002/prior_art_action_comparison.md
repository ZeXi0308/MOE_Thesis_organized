## 对当前候选的裁决

1. **验证前自适应长度可作必要参照，难作主创新。** 长度、接受率与成本的权衡已经有直接动作先例。若原型只有历史接受率或 prompt-lookup 匹配长度 → N1/N2/N4，则应标成轻量适配基线。即使增加预计冷专家数，也不能仅靠“cache aware”命名形成差别。
2. **层内合法后缀撤销仍有一个窄差异。** 当前 MoE 层已经获得真实路由，在冷专家实际加载前改变继续执行的 token 集合；幸存 token 保留全部原始 top-k 及权重。它和上述三个主要相邻动作的区别是“看到了什么后撤销什么”，而不是“减少专家数”。这只是所核文献未见直接覆盖，尚待收益证据。
3. **阶段加载摊销需要更具体的新动作。** 加大 batch、增加验证 token、CPU attention、流水线重叠已不能作为贡献。若转向阶段机制，必须给出同样 token budget 下不同的合法执行组织、明确何时可以保留已加载权重继续服务，以及延迟/重载代价；当前这四篇没有替代此前 `prior_notes.md` 对 ExpertFlow、HybriMoE、QLLM、AMoE 的相关判断。

## 层内候选的最小可执行差异（本研究推断）

先做单条链、greedy、固定一个观察层的原型。当前层真实 top-k 产生后、expert dispatch/load 前，对每请求枚举有限个合法保留前缀。必须保留该轮推进所需的根行/采样行；请求间不能混淆位置。选择仅减少仍未发生的工作：加载已发出时，相关字节不能计入可避免成本；已经执行的浅层 attention/MoE 成本也不能追回。

令 `M` 为必须保留行，`P(p)` 为各请求保留前缀的行集合，`R_l` 为当前驻留专家集合，`E_l(i)` 为本层当前真实 top-k。固定缓存且每冷专家仅加载一次时：

```text
C_l(p) = union_{i in M ∪ P(p)} E_l(i) \ R_l
B_l(p) = sum_{e in C_l(p)} expert_bytes(e)
```

这个量用于判断动作是否真的改变专家加载集合，不能直接代替完整延迟。当删除后缀的所有专家也被幸存行使用时，`B_l` 完全不变；当增加行不增加冷专家时，更大验证块可能提高摊销。在容量小于联合工作集、存在多 wave、替换或重复加载时，要由真实 load 计划统计字节。重排本身也可能改变缓存未来状态。

一个可执行的初版规则应只在“预计可省的暴露加载/执行时间”超过“减少预期提交量带来的后续推进代价 + 本次选择/packing/KV 开销”时截断。预期提交量只可用已完成轮次估计或在线已知 draft 信号，不能用本轮最终接受结果；后续层路由必须由截断后的实际执行产生。初版可以采用保守阈值而不拟合复杂模型，但应保留 always-keep 与相同截断位置的固定短前缀作为对照。

实现接口至少需要把新的行长贯穿 hidden/position metadata、下游 attention、logits 采样、bonus token、KV 逻辑长度与下一轮重进。只将 expert mask 置零而仍分配/执行原来的块，不能算完成该动作。幸存行自然路由不变也不自动获得任意随机采样的分布保持结论；先使用 greedy 并对比完整输出、EOS 和 KV 连续推进。此处不是给 EVICT 的 tree sampling 证明作一般性否定，而是拒绝把其结论不加条件移植到另一个内容相关撤销接口。

## 尽快区分“有差异”与“有价值”

最小实验先完成已有 AR、N1、N2、N4 强基线，再把同一 execution backend 的常量保留策略、verification 前平均成本自适应参照、层内真 route 撤销放在相同资源下比较。自适应参照若使用 n-gram 而非 EAGLE，必须称为 EVICT-style 策略移植，不称其完整复现。

需要回答的单一问题：**真实路由额外揭示的“昂贵但可撤销后缀”，是否足以支付已浪费浅层计算和未来补算，并胜过静态短草稿？** 主要裁决是完整请求完成时间与实际有效输出率；层内冷并集、H2D 字节、有效提交量、截断率和控制开销负责解释。先跑一个小原型即可，不需要先搜尽相关工作。

若合法截断通常不改变冷并集，或改变后仍输给 N1/N2，立即转向不同机制；不要扩大任意删行 oracle 保留该候选。若有正信号，再补自然 EOS 的独立输入、运行级重复和真实容量受限配置。现有人工限制 OLMoE cache 的结果只支持该运行域，不能借这份查新文件扩大部署主张。
