# 从已有实测收敛的机制候选

2026-10-02。以下是可执行研究假说，不是性能或新颖性结论。只使用 NATURAL/HEADROOM/KV_RECOVERY/KV_RESTORE_DIAG/KV_RESERVE/NGRAM 的结果与 NGRAM_EXPERIMENT，以及 `results_ngram_r01/ngram_cost_model.json`；未扩展任意删行 oracle，未改旧结果。

## 最有信息量的反常现象

固定 N4 的 pure-decode 步数从 168 降到 127，但 copy 从 515.962 增至 641.452 GB，wall 从 15.523 增至 17.643 s。由实测派生的每步 copy 是 **3.071→5.051 GB（+64.46%）**，每步 wall 是 **92.40→138.92 ms**。group 总数仅 4699→4731；因此“少轮次”完全可能被每轮更宽的冷专家需求抵消。这里没有逐行身份，尚不能把增量归给某个草稿位置，也没有将 copy 时间等同关键路径时间。

完整 N4 实际输出率 −2.76%，输出量 +7.63%，自然 EOS、同为 8/16 正确，但仅 6/16 输出完全一致。少输出、较少轮次、较少抢占、相同小样本准确率都不能单独作为成功指标。N1/N2 是立即应运行的强简单对照；它不阻止同步实现小模型。

另外两条边界直接影响选线：

- Q2048 比 Q512 的 wall −12.07%、flow −14.77%、实际输出率 +10.07%，而 Q4096 相对 Q2048 没有进一步改善。新机制必须面对 Q2048，不能以增大静态预算为贡献。
- 原生 KV 恢复实际输出率 +3.50%，最坏 gap +43.35%。0044 数据就绪后至少等待 614 ms；单块预留虽然使它 57→52 恢复，却使 0047 的 gap 约 1.30→1.67 s，完整 wall +8.90%、输出率 −2.74%，且 0036 由对变错。**维持停止单块预留；不继续调整该规则。**

## 统一的可决策成本骨架

在已到达的层 ℓ，状态包含真实 request/position 映射、每行 top-k 集合 R、入口驻留集合 C、专家尺寸、当前加载顺序与可用 slot、KV 已提交长度、在线可见的阶段/等待年龄，以及过去完成轮次的接受与耗时统计。不得使用这轮尚未产生的接受结果、未来输出长度或未来层真实路由。

动作 k 保留每请求的合法验证输入前缀 0…k_r；必须执行的普通 decode/prefill 行集合为 M。一次 entry-miss 只加载一次时：

`U_l(k) = union(routes(M), routes(retained speculative input rows))`

`B_l(k) = sum(bytes_e for e in U_l(k) minus C_l)`。

若执行器因 slot 周转会重复加载，应使用实际加载序列 `B_load = sum(bytes of every load event)`，不能继续套单次并集公式。某草稿行的专家都被其他保留行使用时，删掉它的 ΔB 为零；两个尾部一起删除才可能省下一名共享冷专家，故独立 token 分数不能代替集合更新。

可执行的局部目标为：

`J(k) = estimated remaining critical-path time(k) + action overhead(k) + lambda * expected deferred output(k)`。

其中 λ 是近期已完成 AR/短草稿轮次的完整时间/真实提交量估计；它为少提交量的后续轮次、补算、加载提供保守价格，不再另加同一批未来工作，以免重复计费。完整比对仍以真实 episode 为准。剩余时间只包括当前尚未执行的专家工作及后续层的在线统计估计；已完成 attention/router/前层计算都是沉没成本。当前层专家集合可以精确，未来层只能由以往观测预测并在本策略实际执行中更新。

关键路径项需按现有执行方式标定：有重叠时用 `max(compute, transfer)` 或拟合的暴露传输项；不能把已经包含 DMA 的 engine wall 再加一遍 DMA。一个具体剪短动作只有在 **预测可省剩余时间 > 额外决策/重排/KV代价 + λ×预计少提交量** 时才执行。预期提交量须来自合法 sampler 接受计数；现有 `403/1580` 不具备该含义。

## 候选 A：真实路由可见后的验证后缀撤销（主攻）

**问题。** 验证前不知道额外草稿会引入哪些冷专家；固定 N1/N2/N4 无法区别“共享已有加载的便宜草稿”和“独占冷专家的昂贵草稿”。

**状态与动作。** 在某一个 MoE 层 router 已执行、专家权重尚未加载时，读取真实路由与驻留；在每请求 `{不缩短, 去掉最后一个, 截到预定较短前缀}` 这类小动作集里选择。各层前缀只能缩短。删除以请求为单位的连续尾部，保留幸存行原 top-k 权重与贡献，实际从专家分组及后续层移除死行，并向 sampler 传最终有效前缀。

**收益。** 避免尾部独占冷专家及其后续执行；保持多数共享现有专家的草稿，从而保留接受收益。核心不是“缓存感知”本身，而是由当前真实路由触发、改变原生验证提交接口的合法整行停止。

**代价与风险。** router 已付费；GPU→CPU 同步、集合决策、形状变化、重排、KV 回退和少提交带来的后续轮次都可能吞没收益。高并发的必留行可能已覆盖几乎所有冷专家，使合法后缀根本省不下搬运。初期 greedy；BF16 形状变化仍需报告输出分歧。不要先开发逐层复杂预测器。

**最近邻差异（待一手文献核对）。** 固定短草稿/验证前自适应长度没有本层真实路线；SpecMoEOff/EVICT 已覆盖大量卸载与验证自适应，AcceptMoE 已涉及逐层路由/驻留驱动的专家删减。候选的窄差异是**撤销完整 token 后缀并保留幸存 token 的原专家计算**，而不是删专家或重路由。只有实现及完整收益才使这个差异有意义。

**最小实验。** 先在单个选定层实现 request-position 身份、真实专家组排除、sampler/KV 正确截短；用 N2 或 N4 为提案上限，和同一执行底座的“观察但从不截短”比较，并与 AR/N1/N2/N4 对照。先用几条 greedy 自然结束请求使中途状态继续执行，再跑完整 16 请求。只枚举当前合法动作，不固定未来轨迹。记录真正删掉的加载、动作耗时、提交量、完整 drained/flow、输出与质量。若两次实跑显示可省加载稀少，或少提交与实现开销持续覆盖节省，切换 B；不要扩大离线 arbitrary-row 上界。

### A 的立即可执行策略：把可省冷专家与补算价格直接比较

建议首版只在一个早期 MoE 层决策一次，最大草稿 N2 或 N4；attention 维持原合法因果形状，MoE 仅对活行 gather/compute/scatter。后一实现意味着死行的 attention 工作没有省掉，模型必须把它视为仍需支付的成本。sampler 接收实际短 metadata，随后走原生拒绝后缀/KV 回退。先把一次动作做完整，比铺满 16 层更容易看清开销。

**1. 过去接受记录决定损失，不人为指定 lambda。** 对草稿位置 j，仅在此前草稿都匹配且 j 确实得到 target 验证的过去请求轮次里，累计机会数 n_j 与匹配数 s_j。可用 `q_j=(s_j+1)/(n_j+2)` 的统一弱平滑，`p_j=product(q_1…q_j)`。保留输入行 0…k 后，相对保留到 m 的预计少提交量为 `D_r(k)=sum(p_j, j=k+1…m)`；总 D 是请求间求和。EOS 及无 bonus 的边界单独计实际输出，后续可用已经记录的直接提交量修正。**被策略提前截短的位置是未观测/删失，不记作拒绝**。当前历史中的 chunk-size 不是精确接受数，首次运行须从 native sampler 取实际匹配前缀和提交量；不能使用 403/1580。

用最近 W 个已经完成的 pure-decode 轮次，取 `gamma = sum(step_wall) / sum(actual_committed_output_tokens)`，估计每个被推迟输出的后续服务成本。初值来自同资源 AR/N1/N2 的已完成 warmup/校准轮次；只能用在当前决策前已知的计数。它把后续轮次、重复加载和计算按真实已有服务率计价，**不是手设 lambda，也不另加同一未来补算账**。先只有 W=16 一个平滑参数；如并发变化很大，再按 1–4/5–16 个活跃请求两桶计算，避免用满并发价格外推单请求尾部。该估计是局部代理，完整请求时间才判定策略是否成立。

路由依赖的截短会使剩余可观测接受样本具有选择偏差。首版应将 p_j 固定为同提案长度的已完成 no-cut warmup/短基线统计；不要简单把选择性存活样本当无偏全量接受率。将来需要在线更新时，再用预定的 no-cut 校准轮次更新，仍不把被截短位置算作失败。

**2. 当前层节省先只认已经可见的工作。** 计算各合法动作的 `Δcold = |U(full)−C|−|U(k)−C|`、活跃 MoE expert-token assignments 减少量 ΔA。以同底座已完成的层调用，标定一个很小的非负模型 `t_layer ≈ a + b_c*ncold + b_a*nassignments`；这些是数据系数，不是为赢结果手调的权重。若已有精确“传输等待暴露在计算关键路径”的测量，可直接用其斜率替代 b_c；**只有 DMA 总时长而不知道重叠时，不能直接当 b_c**。拟合只辅助决策，不宣称两个系数具有因果解释。样本不足/无法拟合时先执行 no-cut 收集校准，不用任意带宽常数强行制造动作。

首版预测 `S(k)=b_c*Δcold+b_a*ΔA`，不预支未知后续层路线节省；保留 attention 形状时没有 attention 节省项。读取 routes、生成候选、mask/gather/scatter 的共同可测额外开销合为 h（同底座 no-cut 与实际控制路径实测）。选择最大正分数 `score(k)=S(k)−gamma*D(k)−h`，否则不裁。每个草稿长度的收益不同由 p_j 自然产生，冷专家共享则由联合 U 决定。后层确有收益时首版会保守漏选，这是比借用未来轨迹更明确的起点。若需要抗噪声，仅加一个乘法余量 `S > (1+epsilon)*(gamma*D+h)`；先 epsilon=0，不能事后挑选多个阈值的最佳点汇报。

**3. 不做指数枚举，也不丢掉共享专家的联合动作。** N4、16 请求的所有组合为 5^16，不能逐一搜。候选集保留：不裁；每个请求单独 k=0…m−1 的至多 64 个合法 cut；以及每名冷专家的一次“删除其全部可删引用”的联合 cut。最后一种构造：若冷专家 e 被任何必留行引用，跳过；否则对每个引用它的请求，把 k_r 设为该请求首次引用 e 的 speculative 行位置减一，其余请求不裁。这样至多再有 64 个候选，且每个候选都是合法前缀，不是 arbitrary-row oracle。它会捕获“两个请求各剪一个尾部，合起来才能省一个冷专家”的互补情形。对每个候选重算完整冷并集和 D，只应用最佳一次，不堆多轮局部搜索。

候选计算可用每请求各前缀的 64-bit 专家集合或小布尔张量批量完成；不要为了少量 bit 操作引入逐专家 CUDA 同步。若现有 pager 已把路由传回 host，复用那次数据；若没有，新增同步必须进入 h。用于说明策略的最小例子：A、B 的最后一行共同独占冷专家 e；单独剪 A 或 B 的 Δcold 都为 0，联合剪才为 1。只有一名专家的实测剩余成本，大于两条尾部预期提交损失的 `gamma*(p_A+p_B)` 加执行开销，才触发联合动作。

**4. 必须保留的最小在线账本。** 每步实际 m/k、合法保留范围、裁前/裁后冷并集、实际加载事件/字节、预测 S/D/h、原生实际匹配/提交量、完整 step wall。统计参数只在这一步提交完成后更新。可用它区分无独占冷专家、估计失准、动作开销过高以及真实收益四种结果；无需新增庞大 manifest 或固定未来路线回放。与 no-cut 同底座的额外开销消融应保留，避免将 gather/scatter 底座变更误记为 policy 收益。

**已实现的小模型。** `suffix_src/suffix_policy.py` 提供纯 Python `plan_suffix`；接受显式行身份、当前保留量、真实路由/驻留、过去接受 survival、暴露传输带宽和未来 token 价格，返回合法 `keep_drafts` 与成本 receipt。支持 off/full、固定合法 cut、只计当前层冷加载的 conservative、以及明确标为预测的 horizon 乘法模型。初版只用 `ΔB/bandwidth`，尚未加入上面的行计算拟合；缺校准即 no-cut。horizon 不把放大的预测登记为实际节省。必留行已覆盖全部冷专家时直接不裁，不做多余枚举。已通过 250 个随机小状态、916 个穷举合法动作及定向共享专家/沉没死行/高补算价格/固定裁剪检查；证明的是实现合法性与成本账一致，没有证明最优性或真实 GPU 收益。

## 候选 B：按层聚合已经就绪的阶段工作（条件备线）

**问题。** 一个请求组单独执行的冷专家加载，有时可被另一组已经就绪的 prefill/decode 工作复用；统一 scheduler token budget 既不知道真实专家交集，也不能表达按层合批。

**状态与动作。** 为已经获得当前层真实路由、因果依赖已满足的微批保留短队列；将两个就绪微批合成一次 expert-major dispatch，或立即分别执行。仅合并同一层、同一权重版本的实际就绪行；最老 decode 的等待预算约束合并。初始原型只做一个层、至多两个微批和零主动等待，避免先实现整套异步流水引擎。

**收益。** 合并前后的加载差由两个连续真实 dispatch 的缓存变化和联合 dispatch 的加载顺序计算；共享冷专家只搬一次，并可摊薄 group/kernel 固定开销。这里所有 token 最终保留，收益不来自减少接受量。

**代价。** 每层 hidden-state 暂存、队列/重排、额外等待，以及容量不足导致的重复装载；跨层推进需要新的执行接口。当前运行器若只允许整个模型一个同步 batch，零等待原型可能根本没有两个就绪微批，因此先确认这个接口，不用伪造就绪机会。只有同一层真正有两组可用工作时才成立。

**模型产生动作。** 用实际顺序估计 `T(separate A then B)` 与 `T(merged A∪B)`；当合并节省大于缓冲/合并代价且不越过 decode 等待约束时合并。不能仅用 `B(A)+B(B)-B(A∪B)`：第二批可能本来命中第一批留下的缓存，必须更新中间 C。

**最近邻差异（待核对）。** Sarathi-Serve 的 chunk/budget、HybriMoE/ExpertFlow/AMoE 的加载顺序与流水都很接近；潜在差异限于“真实路由可见、阶段混合、以就绪集合决定一次专家执行的边界”。若已有系统已支持相同行为，不把它另起名字当创新。

**最小实验。** 若 A 因必留专家并集饱和失败，在真实 runner 中截取一层的两个就绪微批，比较实际顺序执行和联合执行，计入路由/缓冲/队列开销，并保持原 top-k 完整。只有局部正信号且不需要长期等待，再接入完整请求。保持 Q2048、总并发、内存预算相同；比较“同接口但禁止合并”以隔离中心机制。

## 候选 C：专家 slot 与 KV 页的阶段容量交换（暂不优先）

**问题。** 一个 KV 恢复请求可能被少量页阻塞，而闲置或低价值专家驻留占有更大空间。静态 expert24+KV1GiB 将这一取舍固化；单块预留是在同一 KV 池里改分配次序，没有从专家空间获取容量。

**状态与动作。** 在无在途 reader 的同步边界，从专家缓存归还一个可释放容量单元，变成 KV 页；压力解除后反向归还。每层专家为 12MiB、KV 页为 2MiB；若必须各层一致减少一个 slot，则 16 层合计约 192MiB，不是凭空多出 1 块。确切可借粒度必须由源码决定，不能从数字推断已有动态接口。

**收益与代价。** 对比可避免的阻塞/重算与未来额外专家 miss 暴露时间，加上转换、同步和缓存再热成本。动作必须维护同一总 GPU 字节上限，不改变模型计算；恢复可能只把等待转移给其它请求，必须衡量完整队列。使用过去访问统计与当前已知页需求，不能用未来输出长度。

**最近邻差异（待核对）。** 相对 Full-ISL admission、尾部预留和固定 headroom 的区别是实际改变专家/KV 容量边界；相对现有统一内存/弹性 KV 系统是否有新动作仍需查新。

**最小实验与取舍。** 先只检查是否已有可释放 slot、可增加 KV block 的小接口。若没有，先做等总 GPU 预算的两个静态划分，验证边际取舍是否足够大；静态划分本身只提供工程证据。当前固定池下不先开发新内存管理器，因此不选作立即主线，也不以它延续失败的单块预留。

## 执行顺序与判读

主攻 A；N1/N2 与 A 的小模型/正确原型并行推进。B 是 A 缺少可改变冷专家加载时的条件备线，且要先有真实双微批就绪接口；C 仅保留有现成容量交换接口时的机会。

本阶段最有用的新证据不是更多静态上界，而是：**一次合法动作是否改变实际加载、节省是否超过动作与少提交的完整代价、是否胜过同资源的固定短草稿。** 报告所有运行、输出长度及内容变化、真正接受/提交量；多 token receipt 使用 host chunk gap，不冒充 token ITL。当前 cap24 是人工压力、OLMoE 可全驻留，任何正信号都先限于探索域。
