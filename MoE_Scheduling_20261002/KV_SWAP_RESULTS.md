# 原生 CPU-KV R01：系统比较完成，纯恢复解释存在混杂

六臂完整完成，资源检查均通过。主分析将本轮范围标为 **CPU_PREFIX_REUSE_PLUS_RECOVERY**，纯恢复因果检验标为 **INVALID_CONFOUNDED_CPU_CROSS_REQUEST_PREFIX_REUSE**。S16 同时启用了跨请求 CPU 前缀复用和抢占恢复，不能将结果归因于“用 KV 换入替代专家重扫”。本报告直接使用[完整主分析](results_kv_swap_r01/metrics.json)，不重新计算 raw，不作论文 GO。

固定测量 Q=2048、expert cap24、GPU KV 1 GiB、engine4096、共同 warmup512/固定32输出。R16 为 recompute/cap16，H10 为 recompute/cap10，S16 为 native OffloadingConnector/cap16＋1 GiB CPU KV；同场按 R/H/S/S/H/R 顺序，各自真实生成自然 EOS 输出。完整成本以 **drained** 截止计时，覆盖 capture 清理及原生 push 排空；served 仅截止最后一次输出回执，初始化/预热不计入。所有 engine 调用，包括 connector-only 调用，均计入完整成本。

S16 相对 R16 的两次均值：drained **+0.18%**、mean flow **−2.20%**、实际 drained token/s **−0.05%**。两次 drained 配对分别为 **−0.64% / +1.02%**，不能声称稳定完整加速。相对 H10，S16 drained **−2.06%**、mean flow **−6.85%**，但实际 token/s **−2.29%**、最坏 gap 为其 **2.83 倍**；H10 的停顿优势仍保留。表中的最坏 gap 是每次全体最大值，不是请求间 P95；后者的两次均值 R/H/S 为 **0.5336/0.2686/0.4784 s**。

混杂有实际证据：S16 的 CPU lookup 中，**12 个尚未计算的新请求出现 624-token 前缀命中**，来源是共同提示前缀，而非这些请求经历过抢占。重复 lookup offer 不能相加为已提交恢复 token 数。S16 实际 scheduled prefill 仅 **3,633**，低于原始 prompt 总数 **11,115**；其 −7,482 的差值不能解释为“负重算”或纯恢复节省。R16/H10/S16 的实际重复调度位置分别为 **1,389/0/11**，原生抢占分别为 **2/0/1**。这些说明工作轨迹改变，不能把差额全部归到恢复动作。

资源和持续维护代价必须完整保留。三臂实际 GPU KV 均为 **1,073,741,824 B / 512 blocks**；S16 另分配 **1 GiB pinned CPU KV / 512 blocks**，R/H 为 0。测量 GPU peak allocated 都为 **7,044,517,376 B**，但 S16 peak reserved 为 **7,501,512,704 B**，比 R/H 的 **7,300,186,112 B 多 192 MiB**，并非所有 GPU 足迹完全相同。S16 每次已完成 KV load **1,075,838,976 B**、store **404,750,336 B**，包含持续保存和前缀复用，不能只计算受益恢复的加载；末态 pending transfer/store/push 均为零。传输跨度与 engine wall 不重复相加。这是增加 CPU 资源的系统选择，不是相同 CPU 资源的算法比较。

专家搬运的两次计数各自一致：R/H/S 分别为 **614.675/659.533/616.324 GB**（十进制），S 相对 R 反而 **+0.27%**；因此当前数据也不支持直接宣称总专家搬运减少。保存、调度、CPU 维护及其竞争的时间影响已进入完整请求/排空计时，但尚未被逐项隔离为因果开销。

主分析的互斥 stage 分账显示，R16→S16 的含 prefill engine 时间两次均值由 **2.405691 降至 1.798089 s**，pure decode 则由 **16.418643 升至 17.061129 s**，两项变化基本抵消。这是各臂真实执行的互斥分账，说明较少 scheduled prefill 没有转化为完整 engine 收益；它不是固定路由的因果投影，也不能消除上述 prefix reuse 混杂。

六臂均 **16/16 EOS、0 length cap、8/16 正确**，各自两次输出完全一致。R/H/S 实际输出分别为 **1,443/1,510/1,445 tokens**；S/R 完整输出仅 **6/16** 相同，S/H 为 **5/16**。S 相对 R/H 各有 **1 题由对变错、1 题由错变对**，并非同八题正确。自然输出差异不允许称等工作量加速；16 题总分相同亦不能证明质量等价。全部输出和差异均留存。
