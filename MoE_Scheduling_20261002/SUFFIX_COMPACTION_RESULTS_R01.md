# 跨层后缀压缩：八格完整请求结果

2026-10-02。**跨层压缩已减少真实执行行，但本组没有获得优于 AR 或 N1 的完整服务收益。** HC 两重复平均实际输出率为82.614 token/s，相对同场 AR **−2.84%**、N1 **−2.59%**；两个对应配对方向均为负。HC 相对关闭跨层压缩的 H，完整时间降低7.40%，但输出量同时降低10.06%，实际输出率反而降低2.86%。不能把这项 wall 降幅当作等工作量加速。

八格全部 COMPLETE、每格16/16自然stop、无长度截断、均答对同8题。局部加载、合法前缀和实际缩小后的层输入记录均可核对；这与“已证明语义等价或性能收益”是不同结论。全部原始运行保留，不删慢点，也不扩大离线反事实。

证据：[完整 metrics](execution_suffix_compact_41307_r01/results_suffix_compact_r01/suffix_metrics.json)、[均值/配对/逐请求差异与开销分布](execution_suffix_compact_41307_r01/results_suffix_compact_r01/compaction_r01_summary.json)、[自动逐格表](execution_suffix_compact_41307_r01/results_suffix_compact_r01/suffix_summary.md)。归档 SHA256：`190943ebd11e1bb929f70d691a2c67c13383ebab2079614f829046db2ae6b39f`。

## 实验与比较口径

四臂定义如下。H/HC 的接受先验来自未裁剪warmup，运行期的传输与未来提交价格使用已经完成的实际服务观测；没有使用未来路线。

| 臂 | 实际动作 | 对应运行 |
|---|---|---|
| AR | 原生自回归，无提案、无suffix hooks | 00 / 07 |
| N1 | 固定1-token ngram，suffix底座观察但不裁剪 | 01 / 06 |
| H | N4提案，第0层horizon合法后缀撤销；后层attention仍为原形状，MoE执行活行 | 02 / 05 |
| HC | 与H相同控制公式，加第0层之后的query/位置/slot及LM-head实际压缩 | 03 / 04 |

顺序为 AR/N1/H/HC/HC/H/N1/AR，八个独立engine。相同 source32–47开发输入、16请求同时到达、greedy自然EOS/max512、expert24、cap16、Q2048、engine4096；GPU KV与pinned CPU KV各1GiB，expert scratch为4,831,838,208 B，各臂按本算法进行Q512/固定32输出warmup。实际KV池均512块，未扩大候选资源池。AR测量峰值allocated为7,044,517,376B，其余为7,044,519,424B；reserved均7,501,512,704B。

模型/硬件仍是可全驻留的OLMoE与RTX 5090 32GB，expert24人为制造分页压力。本轮不是独立输入或真实自然超显存部署验证。N1保留观察底座的实际开销，未扣除约35.8ms决策记录成本；即使如此，HC仍未超过它。

Drained从请求测量起点覆盖实际服务、capture cleanup和末尾native drain；初始化、warmup与导出按既有边界排除。实际rate先逐格用返回token/drained计算，再平均两个运行的rate；时间、分位数等也先逐格统计再平均，不把token或专家调用当作运行重复。

## 组件开关消融与可重复性

H/HC保持相同模型、资源、提案上限与horizon成本公式，改变的是后层query与LM-head执行接口，是一次端到端组件开关消融。**它不是固定接受、固定路由或固定决策的纯kernel消融。** 控制器的未来token价格与传输代理由真实耗时更新；压缩既可能改变数值形状，也会改变后续价格、合法后缀选择、提交、KV和路由。不能把HC/H的全部时间差因果归给某个kernel或本次被删行。

HC两次首次记录的keep差异出现在测量step33（suffix state93）：请求、computed位置与提案长度相同，03保留全部，04对source0037保留1个草稿、source0042保留2个；固定survival先验相同，已观测token时间价格及历史决策开销价格不同。该事实说明记录的实际决策轨迹已不同；它没有证明所有分歧唯一来自计时，也没有将未记录的裁前全GPU状态视为等价。

## 后续独立 attention 数值检查

`compaction_attention_gpu_r03.json` 已在真实 vLLM 0.26 / FlashAttention2 / HND / BF16 上通过2 seeds×3动作共6个case，覆盖5请求混合prefill/decode、非连续物理blocks/slots。测试使用与本报告相同hash的compaction/runtime源：完整执行与压缩后的保留prefix在这些case中最大绝对差为0；压缩对FP32 dense reference最大绝对误差0.00726843，逐元素满足atol=rtol=0.01。整个KV cache（包括未写区域）均逐位符合预期，错误旧seq_lens与错误独立slot写入的负对照均被检出。它排查这些有界状态的attention/slot接口错误，不证明完整OLMoE的greedy位等价，也不改变本组性能负结论。r02在数值case之前因独立harness未显式设置KV layout而失败，原日志保留；r03只修测试配置，服务代码未改。
