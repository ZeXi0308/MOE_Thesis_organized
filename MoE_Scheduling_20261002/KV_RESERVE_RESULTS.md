# 单块恢复预留：完整六格结果（冻结）

2026-10-02。**停止当前单块预留方案，不启动 holdout。** P16 相对 S16 两重复均值：drained 时间 +8.90%、实际 token/s −2.74%、mean flow +4.78%、最坏 token gap +28.74%；正确答案由 8/16 降至 7/16。0044 的局部恢复提前成立，完整请求收益不成立。裁决仅适用于本实现和本运行域，不是整个 MoE 调度方向 NO-GO。

合同：同一 22937 GPU 上六个独立 engine，顺序 S16/H10/P16/P16/H10/S16；Q2048，共同 engine 编译容量 4096、warmup Q512、expert24、GPU KV 1 GiB。自然输入 source32–47、16 同时到达、自然结束上限 512，沿用探索输入；只在本组内比较。S16=cap16+CPU KV 1 GiB，P16=同 S16 加单块物理预留，H10=cap10、无 CPU KV。

六格均 COMPLETE、16/16 stop、无长度截断；资源检查、独立 request cache salt/前缀隔离检查及动作检查均 PASS。测前 CPU cache 空，正命中只属于实际被抢占请求，末尾无未完成传输。

0044 局部成功：两次均 57→52 恢复，首个新 token 前仍只计算 3 个位置，gap 内其它请求输出由 88 降至 38。0045 的抢占消失。但 0047 抢占由 72 推迟到 75、恢复由 81 推迟到 87，恢复计算由 9 增至 12 位置，gap 内其它请求输出由 98 增至 126；它成为更坏尾部，不能只汇报目标 0044。所有 receipt 的 scheduler_step_seq 都为 0，与 capture 无共享可验证计步，动作只按 source/抢占序号关联；本性能组没有 ready probe，**不声称 ready 后等待已消失，不把全部 gap 归因于单个分配或 DMA**。

新颖性边界沿用[实验文档](KV_RESERVE_EXPERIMENT.md)：vLLM [异步加载尾部预留 PR #44560](https://github.com/vllm-project/vllm/pull/44560/files)与 [Full-ISL admission PR #37307](https://github.com/vllm-project/vllm/pull/37307)已提供相近原生机制。此单块动作是简单容量修补，不是独立创新；本组未测最新 upstream，不能宣称其现版本仍有相同故障。

**冻结裁决：当前单块方案在本探索合同下停止，不启动 holdout，也不追加预测器或同方案调参。** 保留“可恢复 KV 已驻留仍可能缺继续执行容量”诊断，以及“目标恢复提前不保证完整请求收益”的负结果；更广 MoE 调度 family、不同容量/工作负载及其它动作均未被本组判死。
