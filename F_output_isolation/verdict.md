# 最终判决：停止C1，收束当前投入，保留问题与取舍证据

**2026-10-08：本轮审查与有限推进完成；停止C1，不追加复杂候选或GPU实验。** 公平隔离与真实部署价值尚未确定，不把此决定解释为一般问题不存在、简单方法覆盖全部机会，或P已经解决公平隔离。历史最初判决保存在[历史记录](review_20261008/historical_verdict.md)，全部不利数据保持不变。

**问题证据。** 原生vLLM 0.26.0、固定高压轨迹、同三核预算下，完成A/P/D/DP/DP/D/P/A八次探索运行。A为单条配额FIFO，P为稳定轻流优先，D为4096项在线解码缓存。P将轻交付P99从32.44/30.93ms降至18.22/17.80ms，主要减少取批后等待；120个轻请求两对均受益。但gap P99仅下降7.44%/6.18%，不能直接宣称相同幅度的交互体验收益。

**集中代价。** 总体重P99只增加1.63/0.92ms；逐请求审查却发现8个重background请求两对全部退化，其请求P99中位数8.83→25.58、9.38→24.15ms，配对增量中位数16.72/14.77ms。它们的gap与完成时间也增加。原回放固定把background排在前面，P将大量light移到其前方；输出长度、到达组与位置混杂。应报告请求级取舍，不能把总体小增幅称为每个重请求代价有限。

**方法证据与反例。** 旧C1相对fixed1一负一正，没有稳定优势，且未实现完整路径成本债务或严格积压界限。D虽使OutputProcessor CPU减约27%/38%，交付无稳定改善；DP轻P99为35.75/37.59ms、重为61.32/62.39ms，主要附加尾等待出现在服务器取批前，归因未定，未删去或补跑。P的server CPU变化+8.72%/−2.55%；8次均完成160请求、77,824 token、54,287,667字节，摘要一致；吞吐近似相同只证明固定输入下全部排空。

**为何收束。** H_problem在CPU回放的可控部分获支持；H_model解释批内方向，不能预测完整尾；H_method未获独立增量支持。局部模型中，固定轻内部顺序与成本时，P已去掉轻前方的重工作，单加CPU计量不能再减少这一项。WRR/aging单点可选另一种取舍，却不能辨认新成本状态的必要性。因此不为补矩阵继续实验；停止理由不是缺少SLO本身。该推论不是完整异步服务上界，同类重排、跨批积压或成本变化可打破，详见[假设与决策论证](hypotheses.md)。

**近邻与贡献定位。** [RFC #57479](https://github.com/vllm-project/vllm/issues/57479)已有分块、去对象、有界通道及缓存；安装版已有chunk/yield和GC freeze。P是已知类别优先适配，D是近邻组件适配，未完整复现RFC。原生回放器、请求级取舍和局部加速反例可复用，但不足以形成独立完整论文，不提供正向摘要或三项创新贡献。

**范围与未定事项。** 共享主机、每臂两次；原GPU未开logprobs、候选集合成、原批内顺序缺失、预开连接并省略模型与IPC。真实混合GPU收益未运行，DP原因未确定，未来无饥饿及简单公平方法的完整性能前沿均未证明。新证据若揭示明确请求级权益或类别无法区分的可控损失，可重新立题；当前不借未定事项继续堆实验。
