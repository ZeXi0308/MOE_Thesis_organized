# F 最终研究判决：停止本轮论文探索

2026-10-08；依据[工作区科研基准](../../AGENTS.md)，按用户最新反馈修正研究解释；历史协议、代码和实验数值不变。**结束当前实现分支及F独立论文投入，保留回放器与全部成果供复用。** 不追加动态timer、优先级或GPU验证。停止依据是尚未证明独立方法价值并伴随集中退化；总CPU不下降不是隔离方法失败的充分条件。

**已测问题与主张。** 在vLLM 0.26.0的单核输出前端，普通文本流与top-20 logprobs流共享同步处理。本阶段检验合并输出物化能否减少实际工作并改善轻流交付。固定两条轨迹、三核预算与原生输出路径，六个静态对照和一个候选各正反序两次，共28次。轻流P99是当时的探索指标，不代表普通文本具有更高服务优先级。

**必须分开的两个量。** 输出处理成本回答“需要多少CPU工作”；交付要求回答“允许等多久、等待造成什么损失”。API类别可作为成本线索，不能推导交付紧迫性。logprobs用户可能急于交付，文本用户也可能容许合并。75ms只是冻结实验的等待参数，没有证明重请求拥有额外等待容忍度；保持完整输出语义也不等于满足服务要求。缺少真实SLO时可研究取舍，但不能事后发明重请求“可以多等”的需求。

**模型与最近邻差异。** 原生stream_interval已消除部分响应对象、交接、封套和序列化调用；逐token停止检测、top-k解码与条目本体仍须完成。T/B在对象构造前按token/原始字节加最老pending计时器门控，S按类别静态配置。唯一候选L沿用S释放规则，进一步保存原始logprob数组、延后合并物化；累计数值每步推进。可省外层调用，需支付合并复制和重复数值累加。[RFC #57479](https://github.com/vllm-project/vllm/issues/57479)已有数组、去中间对象、分块与有界通道思路，主要面向非流式RL；本原型没有复现该新栈，其streaming范围差异本身不构成创新。

**决定性证据。** 与同规则强静态S直接配对（负数为降低）：

| 负载/重复 | 完整server+client CPU Δ | 轻交付P99 Δ | 重交付P99 Δ |
| --- | --- | --- | --- |
| high / 正序 | +0.60% | −2.530 ms（−16.66%） | +4.440 ms |
| high / 反序 | +0.13% | −1.893 ms（−12.90%） | +4.823 ms |
| medium / 正序 | −5.79% | −0.545 ms | −0.050 ms |
| medium / 反序 | +1.25% | +0.232 ms | +0.805 ms |

高负载sample调用从19,456减至9,272/9,276，但19,456个位置仍全部物化，新增约5.04MB数组复制。OutputProcessor局部CPU从4.43/4.22s降至2.12/2.07s，同时timer CPU从0.127/0.135s升至2.106/2.077s；server总CPU仅降1.91%/1.44%，client CPU升7.33%/4.20%，合计未降。中负载完整成本方向不一致。**显著的局部CPU下降主要对应工作移出计量函数，不能当作工作消除。**

**交付收益与代价均保留。** high总体轻P99两次改善，但120个轻请求中仅67个两次均受益，50个两次均变差；24个background轻请求有18个两次变差。40个重请求有34个两次变差，单请求P99最坏增量为11.90/14.92ms。S相对N1本就使全部40个重请求变慢，逐请求P99增量中位数75.87/73.49ms。L是额外的时机取舍，没有证明被所有简单点支配，也没有证明可推广的新隔离原则。全部响应结束、pending清空，未见无限推迟；L重请求最终排空最大9.05ms，但75ms物化期限最大超期68.19ms，故不能宣称硬界或无饥饿保证。内存与CPU使用、完整排空吞吐及所有对照见[主表](results.md)；吞吐受固定输入限制，不是容量收益。

**三层判断与为何停止。** 问题层：回放中的可控干扰获得支持，但成本类别没有给出服务权益。解释层：部分固定成本可合并，延后逐位置工作不等于消除；这些证据削弱的是本候选的工作减少主张。方法层：工作量不变的调度也可能改善隔离；本候选的总体轻P99改善伴随集中退化，尚未证明改善有依据的交付目标或强简单方案可达到的取舍。故结束投入，不把CPU下降设为隔离价值的必要条件，也不把单个总体P99下降当作贡献。

**未来重启条件。** 先说明服务对象需要什么、哪些等待可以合法调整，再检验现有优先级、轮转、分块等方法留下的缺口，并说明新状态如何改变动作选择。目标应是固定资源下满足更多有依据的交付要求，或相同要求下减少资源；没有精确SLO时，也须证明改善已有简单方案的取舍。处理成本与紧迫性须分别表示、分别取得依据，不能由API轻重替代后者。当前没有建立这样的需求与缺口，不为延续F临时补造；仅有新参数或新动作不足以重启。

**边界与交付。** 所有28次源时序通过预定筛查，原始记录、执行源码身份、输入与下载哈希可追溯；每方案仅两次运行，不宣称统计显著。完整CPU指测量窗口内输出前端及客户端，排除初始化、输入渲染、预建engine数组和engine IPC。原GPU未请求top-20，合成候选、原批内顺序缺失、预开连接及共享主机限制外推。Unicode、stop、直接processor abort及无下一token的timer语义通过；HTTP取消链未覆盖。保留[可运行原型与复现](README.md)，不写正向论文摘要，不否定异质输出干扰的一般研究价值。
