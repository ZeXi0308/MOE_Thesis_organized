# CreditReduce：用局部归约的字节额度资助误差门控的宽精度 MoE Combine Partial

> 审计日期：2026-07-17  
> 唯一主方案状态：**P0-CANDIDATE，不是已验证系统**  
> 适用边界：**top-k ≥ 3、hierarchical/high-throughput MoE combine、且同一 token 同时满足 `1 < source-domain 数 D < 有效路由数 K`**  
> 核心纪律：全文区分 `[Observed]`、`[Inferred]`、`[Hypothesis]`；Mac 结果不冒充 GPU、RDMA、TPOT 或 P99 证据。

## 一页硬判决

**[Inferred] 本轮不再选择 QuotaEP-H / PartialGuard 作为唯一主线。** 当前最值得做的唯一 P0 候选是 **CreditReduce（Route-Collision-Funded, Recast-Error-Gated Wide Partials）**：source domain 内先以 FP32 合并同一 token 的 `m` 条 BF16 contribution；若将该 subtotal 落成 BF16 的实测局部 recast residual 足够小，则发送一条 BF16 partial，否则发送一条 FP32 partial。

**[Inferred] 它的关键不是“动态精度”，而是一个 MoE 路由与归约共同产生的不变量。** 对一个有效 top-k 为 `K`、分布到 `D` 个 source domains 的 token，设升级成 FP32 的 collided groups 数为 `n32`，则：

\[
B_{\text{Credit,payload}}=2H(D+n_{32})\le 2HK=B_{\text{late-BF16,payload}}.
\]

该不等式逐 token 成立，因为 `n32` 不超过 collided-group 数 `C`，且 `C ≤ K-D`。因此，即使所有发生 local collision 的 group 都发送 FP32 partial，payload 也不会超过“不做局部归约、把 K 条 BF16 contribution 全部发回”的 late-BF16 基线。

**[Hypothesis] CreditReduce 只有在一个很窄但可测的中间区域里才有论文价值：** static early-BF16 确实伤害严格质量，static collided-FP32 又浪费了可安全保留为 BF16 的大量 groups，而 optimized uniform-FP8 不能在同一质量预算下支配它。任一条件不成立，主方案立即死亡。

**[Observed] 当前证据还没有证明这个中间区域存在。** 现有 grouped-owner 结果只是 Torch 数值 surrogate；四组所谓 formal 数据全部与此前开发/确认输出重合；没有 FP32-partial 实验、GPU kernel、actual wire、RDMA、exposed completion、TPOT 或 P99 证据。因此当前创新成熟度是 **3/10**，不是 7 月 14 日旧报告可以直接继承的系统主线。

# A. 当前 Idea 的真实技术核心，以及最大的新颖性缺口

## A.1 已成立的 observation

1. `[Observed]` patched full 与原模型 bitwise equal；EP=1 grouped combine 与 patched full bitwise equal，最大 logit difference 为 0。这证明 hook/reference 没有在平凡路径上改坏语义。
2. `[Observed]` 在 EP8 owner surrogate 中，OLMoE 的 routed-pair/grouped-vector 为 `1.455–1.475`、pair collision 为 `31%–32%`；LLM-jp 为 `2.106–2.118`、collision 为 `52%–53%`。这证明 top-k≥3 模型存在局部合并的逻辑 headroom。
3. `[Observed]` 在相同 peer/tile quota 和当前 logical-wire accounting 下，output-aware signal 相对 rank 的 KL 改善为 `12.9%–19.2%`，相对 gate 为 `11.2%–22.4%`；当前执行的 document bootstrap 与 Holm 校正后方向成立。
4. `[Observed]` `mixed_contribution` 与 `mixed_qerr` 没有稳定显著差异；grouped contribution 也没有稳定击败 pair contribution。因此已成立的是“late output family 比 routing-only proxy 更有信息”，不是某个唯一公式或 cancellation 机制。
5. `[Observed]` peer/tile fixed quota 相对 global allocation 有 `4.2%–22.3%` KL tax；top-16 更严重。
6. `[Observed]` 当前模拟中 mixed 相对 grouped BF16 的 logical saving 约 `61.5%–61.7%`，相对 uniform FP8 再少约 `23.6%`；但未计真实 header、alignment、padding、reservation、pack/unpack、消息启动与 overlap。
7. `[Observed]` 四个 setting 的 mixed quality 都劣于 uniform FP8。现有结果是 bytes–quality trade-off，不是 Pareto dominance。
8. `[Observed]` grouped-BF16 相对原始模型出现约 `0.0015–0.0019` mean-token KL endpoint shift；它说明 reduction association / intermediate cast 不是严格免费，但尚未证明该差异具有下游任务意义。
9. `[Observed]` 当前代码 [grouped_owner_combine.py](experiments/idea_a_mac/grouped_owner_combine.py) 是 backend-oriented Torch numerical surrogate：exact quota 用于预算匹配，短 tile 不 carry；没有 native codec、lane buffer、collective、RDMA、overlap 或 P99。

## A.2 当前最强 inference

1. `[Inferred]` 真正仍有研究价值的窗口不是“expert output 后随便选 bit”，而是 **source-domain local reduction 已能形成 FP32 subtotal、但它尚未被 cast 成跨域 partial 的瞬间**。
2. `[Inferred]` 对 high-top-k hierarchical combine，局部 collision 同时产生两件事：减少跨域 record 数，以及新增一次 intermediate representation boundary。DeepEP V2 已把它公开描述为 precision–transfer trade-off，而不是本报告凭空制造的矛盾。
3. `[Inferred]` 旧 grouped collision 数可视为“可能存在 route credit”的种子，但 owner surrogate 不是目标 backend 的真实 source-domain trace，不能直接代入实际 bytes 或 opportunity mass。
4. `[Inferred]` 与 output norm、gate 或 rank 不同，`FP32 subtotal - BF16(subtotal)` 精确测量了选择 BF16 partial 时插入的局部表示误差；选择 FP32 partial 会直接删除这一项。它仍不认证 end-to-end quality。

## A.3 尚未验证的 system claims

- `[Hypothesis]` 新鲜数据中存在足够多 `K≥3 且 1<D<K` 的 token/traffic。
- `[Hypothesis]` static early-BF16 在至少两个独立 model/task cells 中违反预注册的严格质量预算，而 static collided-FP32 可恢复。
- `[Hypothesis]` local recast residual 能在 held-out 数据上识别真正有害的 BF16 partial，而不是只反映 BF16 mantissa 落点。
- `[Hypothesis]` BF16/FP32 双 lane 的 certificate、partition、pack 和 receiver epilogue 不会吞掉序列化收益。
- `[Hypothesis]` actual wire、combine completion、TPOT、吞吐、P99 或 J/token 能改善。

## A.4 已失败或必须降级的旧叙事

- `[Observed]` PLTB 对 MXFP4/NVFP4-aligned 模拟不稳定，只能作 format-dependent baseline。
- `[Observed]` fixed rank 不是 quality Pareto winner；它最多保留规整 layout / 低 selector overhead 假设。
- `[Observed]` receiver-aware、Graceful、QTree 没有真实 queue/deadline/topology protocol 证据。
- `[Observed]` additive-KL MILP 已被端到端结果否定，不能用单层误差可加性复活。
- `[Inferred]` QuotaEP-H/PartialGuard 已从“最强主线”降为 mixed-precision treatment；只有新鲜数据和真实 kernel 同时逆转 uniform FP8 时才允许复活。

## A.5 最大的新颖性缺口

**[Observed] 现有工作已经分别占据 uniform FP8/FP4 communication、hierarchical reduction、local dedup/partial、mixed-precision activation、error-bounded collective 与 phase-aware kernel selection。**

**[Inferred] CreditReduce 的可辩护差异只剩一个机制交集：** route collision 产生逐 token 可证明的 byte credit；这个 credit 被用来资助 collided-domain partial 从 BF16 升到 FP32；是否升级由该 BF16 recast 本身的实测 residual 决定；新 ABI 保持一条 record/group，并给出相对 late-BF16 的 payload non-expansion invariant。

**[Hypothesis] 这个差异是否足以发表，最终不由代数命名决定，而由三项结果决定：** dynamic BF16/FP32 split 是否非退化、是否击败 static collided-FP32 与 optimized FP8、以及真实 completion time 是否改善。

# C. 选出唯一主方案

## C.1 选择

**[Inferred] 唯一主方案选择 CreditReduce，但状态固定为 `P0-CANDIDATE`。** “唯一”表示接下来只给它一个主实验漏斗，不表示它已经通过。

**[Inferred] 本报告把 `PrecisionDividend` 只定义为 CreditReduce 依赖的 payload 不变量，并把 `PD-Full` 只定义为最强静态基线；二者都不是第二个可替换的核心。** 若 residual gate 不能形成非退化且更优的中间 Pareto 点，唯一主方案 CreditReduce 直接死亡，而不是改名成静态方案继续。

安全的一句话 claim 是：

> **[Hypothesis] 在 `K≥3` 且 `1<D<K` 的层级 MoE combine 中，CreditReduce 利用 source-domain 局部归约释放的 byte credit，按实测 local BF16 recast residual 在 BF16 与 FP32 partial 间选择，并保证编码 payload 不超过发送全部 late-BF16 contributions。**

## C.2 为什么优于另外两个

- `[Inferred]` 相对 FlushMap，CreditReduce 的 signal 与 action 有更直接因果关系：FP32 action 精确删除被测的 BF16 recast term；FlushMap 的 risk/LUT 仍是普通 codec 预测。
- `[Inferred]` 相对 HRC，CreditReduce 不需要新低比特码本、common-scale 协商、rotation、exception parser 或压缩域 accumulator；Mac 上可用 BF16/FP32 reference 先做干净生死判断。
- `[Inferred]` 相对旧 PartialGuard，CreditReduce 没有 exact-q、top-q、whole-vector contribution heuristic 或 FP8/MXFP4 quality tax；每个 collided group 的 FP32 upgrade 都由其自身 local recast residual 驱动。

## C.3 为什么不是已有模块的简单拼接

`[Observed]` DeepEP 已有 global static multiple-reduction knob；`[Observed]` mixed precision 与 error-bounded collective 也已存在。CreditReduce 不能认领这些组件。

`[Inferred]` 它只能认领下面这一整条 contract，缺一项都退化为已有技术：

1. source-domain route collision 给出 `K-D` 个确定 byte credits；
2. 仅 collided group 有资格消费 credit；
3. local FP32 subtotal 直接产生 BF16 recast residual；
4. residual gate 决定单条 partial 的 BF16/FP32 表示；
5. 两条 homogeneous lane 仍是一条 physical frame、one record/group；
6. `B_payload≤B_late-BF16` 对每个 token 成立；
7. 系统必须在 matched quality 下击败 static collided-FP32 和 uniform FP8。

## C.4 其他方案的去留

- `[Inferred]` Phase/CodecMap 内化为 CreditReduce 的 offline enablement gate 和 negative-result safety net，不计并列贡献。
- `[Inferred]` FlushMap 保留为最强简单 dynamic baseline；CreditReduce 失败后不自动把它升主线，必须先过自己的 oracle gap。
- `[Inferred]` HRC 只保留一次低成本 representation P0；不与 CreditReduce 融合，避免 `reduction × dtype × residual` 状态空间爆炸。
- `[Inferred]` PartialGuard、receiver-aware、bounded borrowing、temporal DPCM 均不进入接下来两周的主实现。

## C.5 最容易被忽略的支配基线

**[Inferred] 最强静态基线不是 uniform FP32，而是 `m=1 → BF16；m≥2 → FP32 partial`。** 记 collided-group 数为 `C`：

\[
B_{\text{static-collided32}}=2H(D+C).
\]

CreditReduce 相对它只节省 `2H(C-n32)`。若绝大多数 collided groups 都升级 FP32，动态方案会退化成该静态基线，却多付 certificate、partition 与双 lane 开销；此时必须杀死动态 novelty。

# D. 主方案的完整设计

## D.1 系统模型与严格适用域

对 MoE layer `l`、token `t`，记有效 routed contributions 数为 `K_t`。每个 contribution 已经满足目标 backend 对 weighting/bias 的语义，记为：

\[
x_{t,e}=g_{t,e}\,o_{t,e}\in\mathrm{BF16}^{H}.
\]

它们按 source topology domain 分成 `D_t` 组 `G_{t,d}`，组大小：

\[
m_{t,d}=|G_{t,d}|,\qquad \sum_{d=1}^{D_t}m_{t,d}=K_t.
\]

记 collided groups 数：

\[
C_t=\sum_d \mathbf 1[m_{t,d}\ge2].
\]

**[Inferred] 真正 opportunity 必须同时满足：**

\[
K_t\ge3,\qquad 1<D_t<K_t.
\]

- `[Inferred]` `D_t=K_t`：每组 `m=1`，没有 local reduction credit。
- `[Inferred]` `D_t=1`：local cast 也是唯一 final cast；按统一 FP32 accumulation contract，不存在额外 intermediate-BF16 boundary。
- `[Inferred]` top-1/top-2：不存在整数 `1<D<K`，因此不属于 CreditReduce 的论文适用范围。
- `[Hypothesis]` 第一版只面向 HT/prefill 与 chunked prefill；LL/decode 默认关闭，除非真实 kernel 证明无新 barrier/launch 且可回本。

## D.2 三个精度—流量端点

### Late-BF16：单次最终归约

每组不先形成跨域 partial，发送全部 `K_t` 条 BF16 contribution，home 端以 FP32 固定顺序累计并最终 cast 一次：

\[
B_{\text{late}}=2HK_t.
\]

`[Observed]` DeepEP 把该全局端点描述为 best precision / more transfer。

### Early-BF16：多层归约

对每个 group 先做 FP32 subtotal：

\[
s_{t,d}=\operatorname{fl}_{32}^{\pi}\left(\sum_{e\in G_{t,d}}x_{t,e}\right),
\qquad p^{16}_{t,d}=\operatorname{BF16}(s_{t,d}),
\]

只发送 `D_t` 条 BF16 partial：

\[
B_{\text{early16}}=2HD_t.
\]

它引入 local recast residual：

\[
\delta_{t,d}=\operatorname{FP32}(p^{16}_{t,d})-s_{t,d}.
\]

### Static collided-FP32：最强静态 precision-dividend 基线

`m=1` 仍发 BF16；所有 `m≥2` group 一律发 FP32 subtotal：

\[
B_{\text{static32-collided}}=2H(D_t+C_t).
\]

`[Inferred]` 它删除所有 collided-group 的 intermediate BF16 recast，同时不浪费 FP32 在 singleton 上。CreditReduce 必须证明只升级其中一部分即可匹配质量并降低实际完成时间。

## D.3 CreditReduce 的 payload 不扩张定理

CreditReduce 为 collided group 选择 `z_{t,d}∈{16,32}`；singleton 强制 `z=16`。设 FP32 collided groups 数为 `n_{32,t}`：

\[
B_{\text{Credit,payload}}
=2H(D_t-n_{32,t})+4Hn_{32,t}
=2H(D_t+n_{32,t}).
\]

每个 collided group 至少贡献一个 `m-1`，所以：

\[
C_t\le\sum_d(m_{t,d}-1)=K_t-D_t,
\qquad n_{32,t}\le C_t.
\]

从而：

\[
\boxed{B_{\text{Credit,payload}}\le2HK_t=B_{\text{late}}.}
\]

**[Inferred] 这个证明只覆盖编码 tensor payload。** header、bitmap、alignment、padding、completion signal 与 transport framing 必须另计；在测到 NIC/transport counter 前不得写成 actual-wire non-expansion。

## D.4 真实 backend 数据流与 integration point

| Backend path | 公开数据流 | CreditReduce 插点 | 需要修改的 contract |
|---|---|---|---|
| DeepEP V2 hybrid / multiple reduction | `[Observed]` local / scale-up 分段归约后再跨 scale-out；`allow_multiple_reduction` 是 buffer/handle 级静态选择 | local FP32 subtotal 形成后、cast/store BF16 token record 前 | 新 FP32 partial plane、mode bitmap、union layout、mixed-load epilogue；不能当作一个 Python flag |
| NCCL EP HT flat / Hybrid-EP | `[Observed]` caller 或 kernel 先形成 rank/node partial，再以 BF16 streaming batch 发回 origin | intra-node reduction store 与 RDMA staging 之间 | 保留 FP32 partial 到跨域；HT handle 当前 BF16-only，需 raw-byte dual plane |
| NCCL EP LL | `[Observed]` expert-major 与 rank-major 是不同 wire contract，receiver 可做 FP32 weight | 第一版不 target | singleton 若仍 receiver-weighted，必须保留原 output + top-k slot；不得偷偷改成 source-side BF16 preweight |
| MORI InterNodeV1 | `[Observed]` `WarpAccum` 形成 node partial 后 cast 到固定 `T`，`tokCombXferBytes` 固定 | FP32 subtotal 到 `ShmemPut` staging 之间 | FP32 staging、变长 record bytes、receiver mixed load；现有 fixed FP8/FP4 不是该机制 |

**[Inferred] 第一实现应选 DeepEP V2 fork。** 原因不是它已经支持 CreditReduce，而是它公开提供 early/late 两个语义端点、reference 与 buffer cost，对公平基线最清楚。

## D.5 sender、expert、receiver 与 network 状态

### Expert/source domain

- `[Observed]` expert kernel 产出 backend-visible BF16 contribution，或产出 BF16 output 加 FP32 routing weight；两种语义不能混用。
- `[Hypothesis]` local reducer 对 collided group 按 frozen expert/top-k order 形成 FP32 `s`。
- `[Hypothesis]` 同一 pass 计算 `p16` 与 `delta`，写一位 mode；不运行全局 sort/MILP。

### Sender

- 持有 canonical `(token, source-domain)` group ordinal、`m`、route epoch 与目标 peer。
- 对 `m=1` 或非 opportunity token 走静态快路径。
- 对 collided group 依据 frozen threshold/profile 选择 BF16/FP32 lane。

### Receiver/home domain

- 从既有 reverse routing handle 恢复 group ordinal；mode bitmap 只描述 dtype，不重新描述路由。
- 以固定 source-domain order 遍历；BF16 load 转 FP32，FP32 load 直接累计；最终一次 BF16 cast。
- 校验 `n16+n32=group_count` 和 epoch；不按“先所有 BF16 后所有 FP32”的物理顺序改变算术顺序。

### Network

- `[Hypothesis]` 一个 physical frame / chunk，内部两个连续 homogeneous subregions；不得为两种 dtype 新增两次 RDMA startup。
- `[Hypothesis]` registered arena 以 late-BF16 payload 上界加 metadata 预留；实际 send length 取 compact frame 长度。

## D.6 可观测信号与决策变量

为避免近零 subtotal 导致相对误差爆炸，主 signal 使用 layer-normalized absolute residual：

\[
c_{t,d}=\frac{\|\delta_{t,d}\|_2}{\sqrt H\,a_l},
\]

其中 `a_l` 是 calibration set 上冻结的 late-output RMS。`[Hypothesis]` 可增加 `D_t,C_t,m` 作为小表索引，但不训练 controller。

为了给 pre-final combine perturbation 一个保守上界，可采用：

\[
\|\delta_{t,d}\|_2\le\frac{\tau_l}{C_t}
\quad\Rightarrow\quad
\left\|\sum_{d\in \mathrm{BF16\ collided}}\delta_{t,d}\right\|_2\le\tau_l.
\]

**[Inferred] 该式只界定 combine-input 前的 local recast residual；它不界定 final BF16 discontinuity、FP32 reassociation、下一层 router flip 或 end-to-end quality。**

决策变量：

\[
z_{t,d}=\begin{cases}
16,&m=1\text{ 或 }c_{t,d}\le\theta_{l,D,C,phase},\\
32,&m\ge2\text{ 且 }c_{t,d}>\theta_{l,D,C,phase}.
\end{cases}
\]

## D.7 优化目标与约束

离线只搜索一个小 threshold table，不使用 additive-KL MILP：

\[
\theta^*=\arg\min_{\theta}\ \widehat{T}_{\text{exposed}}(\theta)
\]

subject to：

\[
\text{UCB}_{95\%}(Q(\theta)-Q_{\text{late}})\le\epsilon_Q,
\]

\[
B^{wire}(\theta)<B^{wire}_{\text{static32-collided}},
\qquad
\widehat{T}_{\text{gross saving}}>T_{\text{certificate+pack}}.
\]

`Q` 是预注册的完整模型指标族；不把单层 KL 相加。`[Hypothesis]` 若 calibration grid 需要逐层独立任意阈值才能成功，视为过拟合并杀死简单机制。

## D.8 Offline 阶段

1. `[Hypothesis]` 建立 SHA-256 exclusion registry；calibration、development、confirmation 按 request/document 完全不重叠。
2. `[Hypothesis]` 捕获真实 pre-local-reduction BF16 contributions、routing weights、source domains 与 canonical order，而非只有 post-grouped vector。
3. `[Hypothesis]` 对每个 layer/phase/placement 统计 `K,D,C,m`、opportunity traffic mass、`delta`、FP32 reassociation 与六个 endpoint 的完整模型质量。
4. `[Hypothesis]` calibration 只冻结 `a_l`、一个小型 `θ[layer bucket, D/C bucket, phase]` 和 enablement profile；confirmation 只跑一次。
5. `[Hypothesis]` CodecMap 记录 `BF16 early / static collided-FP32 / CreditReduce / FP8 early / FlushMap` 的 physical frame、kernel cost 与 exposed completion；online 仅 O(1) 查表决定是否启用整个机制。

## D.9 Online 算法

```text
Frozen:
    enable[layer, phase, batch_bucket, link]
    theta[layer_bucket, D_bucket, C_bucket, phase]
    a_layer, route_epoch, canonical_group_order

for each native token/channel chunk:
    initialize BF16 counter, FP32 counter, mode bitmap

    for each token t:
        build valid source-domain groups from existing route handle
        K, D, C = route statistics

        if not enable or K < 3 or D == 1 or D == K:
            emit native static record(s)
            continue

        for each group g in canonical domain order:
            if m_g == 1:
                emit original BF16 contribution to BF16 lane
                continue

            s32 = ordered_fp32_sum(group contributions)
            p16 = cast_bf16(s32)
            delta2 = sum((float(p16) - s32)^2)
            cert = sqrt(delta2 / H) / a_layer

            if cert <= theta[layer,D,C,phase]:
                mode[g] = BF16
                emit p16 to BF16 lane
            else:
                mode[g] = FP32
                emit s32 to FP32 lane

    compact both lanes inside one frame
    release_fence()
    publish(epoch, group_count, n16, n32, offsets, ready)

receiver:
    wait one ready epoch per expected source-domain frame
    verify counts and route epoch
    traverse canonical group ordinals
    load BF16 or FP32 lane according to bitmap; accumulate FP32
    one final BF16 cast; continue model
```

`[Hypothesis]` GPU kernel不应真正执行 `sqrt/div`；比较 `delta2` 与冻结的平方阈值。伪代码保留直观形式。

## D.10 Wire format 与 buffer contract

```text
CreditFrameHeader (fixed, versioned)
  version | route_epoch | profile_id | flags
  group_count | bf16_count | fp32_count
  bitmap_bytes | bf16_offset | fp32_offset | total_bytes

GroupPrecisionBitmap
  1 bit / canonical group        # 0=BF16, 1=FP32

BF16Region
  bf16_count × BF16[H]

AlignmentPadding
  to backend-required boundary

FP32Region
  fp32_count × FP32[H]

ReadyRecord
  epoch | counts | checksum/error flags
```

**[Inferred] compact arena 容量：**

\[
B_{reserve}=2HK_{max}+B_{header/bitmap/alignment},
\]

不超过 late-BF16 payload 上界加固定 metadata。若实现为了寻址简单而给所有 group 固定 `4H` slot，则 BF16 decision 不会减少 physical bytes，必须判失败。

`[Hypothesis]` 对 group ordinal `g`，lane 位置可由 bitmap prefix-popcount 得到：

\[
pos_{32}=\operatorname{popcount}(mode[0:g]),\qquad pos_{16}=g-pos_{32}.
\]

chunk-level epoch 避免 per-token atomics；mode、payload 写完后 release fence，再发布一次 ready。

## D.11 Kernel / collective integration

### Source kernel

- FP32 subtotal scratch 与 residual norm 在同一 fused pass 生成。
- `[Observed]` DeepEP 对无 bias、有效项≤2 存在 BF16 `hadd` 快路径；CreditReduce 为获得 FP32 subtotal 会关闭或替换该路径，成本必须单独报告。
- mode count 可用 warp/block ballot + prefix；不得调用全 tensor sort。
- 若输出 readiness 不齐，group 必须等待其 local members；HT combine 本来在 expert computation 后调用，但细粒度 overlap 实现仍需测 readiness skew。

### Receiver kernel

- 单一 persistent/epilogue kernel读取两个 lane；不允许两次独立 launch 伪造并行。
- 按 logical group order 累计，物理 lane 顺序不改变 reduction order。
- FP32 partial 必须跨完整 scale-up/scale-out path 保持 FP32；任何中间 recast 会破坏机制。

### Backend API

- 新建 versioned raw-byte frame 或 typed union handle；不修改现有 public BF16 tensor 后假装 ABI 兼容。
- route handle 缓存 group ordinal；threshold/profile 用 epoch 冻结，避免发送方与接收方解释不一致。

## D.12 复杂度

设 chunk 中共有 `P` 个 source-domain groups、`N=Σm` 条 contributions。

- 时间：native subtotal `O(NH)`；额外 recast residual、mode 与 pack `O(PH)`；bitmap scan `O(P/warp)`；无 `O(P log P)` sort。
- scratch：最坏 `O(PH)` FP32；可按 chunk/streaming batch 限界，或以重算换空间。
- registered buffer：payload 上界 `O(NH)`，与 late-BF16 同阶；metadata `O(P)` bits/records。
- 逻辑通信：

\[
B_{payload}=2H(P+n_{32}),
\]

其中跨所有 token/chunk 求和；actual wire 另加 frame/transport overhead。

## D.13 Break-even condition

相对 static collided-FP32，扣除 application-frame metadata/padding 后的 net frame-byte saving：

\[
\Delta B=2H(C-n_{32})-\Delta B_{meta/pad}.
\]

只有下式成立才启用：

\[
\phi\frac{\Delta B}{BW_{eff}}
>
T_{fp32\_subtotal\ overhead}
+T_{cert}
+T_{partition/pack}
+T_{mixed\_load}
+T_{extra\_startup}
+T_{lost\_overlap},
\]

其中 `φ∈[0,1]` 是通信真正暴露在 critical path 上的比例。

**[Inferred] 三个不能回避的结论：**

1. CreditReduce 不可能在 raw bytes 上击败 static early-BF16；它只能在 early-BF16 违反质量预算时形成 matched-quality Pareto 点。
2. 若 optimized early-FP8 在同一完整模型质量预算下更快，CreditReduce 立即死亡。
3. logical payload theorem 不能替代 `φ`、pack、launch 与 overlap；`φ≈0` 时任何 byte saving 都不会成为 serving gain。

## D.14 Fallback 与稳定性

- `m=1`、`D=1`、`D=K`、top-k≤2：静态 native path，不进入 certificate。
- LL/decode、短 flush 或 cost map 预测不回本：static early-BF16 或 backend native best policy。
- profile/epoch 不匹配、header/count 校验失败：fail closed；在发送前回退 static collided-FP32 或 native path，不允许 receiver 猜 dtype。
- buffer：按 late 上界预留，不依赖未来流量，不发生 overflow；actual compaction failure 触发 error flag，不能 silent drop。
- threshold 在 deployment epoch 内固定；不读取 receiver queue、不在线自调，不产生 controller oscillation。
- routing drift 只触发重新离线校准或关闭，不在当前 request 内训练策略。

# E. 三条明确、可独立成立的论文贡献

## E.1 Route-collision precision dividend

- **Observation：** `[Inferred]` high-top-k hierarchical routing 的 local collision 同时减少 record 数并产生 `K-D` 个 byte credits。
- **Mechanism：** `[Inferred]` 只允许 collided partial 消费 credit 升到 FP32，给出逐 token `B_payload≤B_late-BF16` 证明。
- **Evidence：** `[Hypothesis]` 新鲜真实 route/contribution trace 验证 opportunity mass、physical framing 与 static endpoint quality；若只在 synthetic owner mapping 成立则贡献失败。

## E.2 Measured-recast-error-gated wide partial ABI

- **Observation：** `[Inferred]` local FP32 subtotal 到 BF16 partial 的插入误差在发送前可直接测量，选择 FP32 会删除该项。
- **Mechanism：** `[Hypothesis]` residual gate + one-record/group 的 BF16/FP32 dual-plane frame + mode-independent FP32 receiver order。
- **Evidence：** `[Hypothesis]` held-out paired intervention 证明 signal 优于 random、`m`-only、norm/cancellation，并在 matched quality 下优于 static collided-FP32。

## E.3 Reduction precision 的可证伪 system envelope

- **Observation：** `[Observed]` logical-byte reduction、codec/pack overhead 与 exposed communication 是不同层次；DeepEP/MoRI 等强基线会改变 break-even。
- **Mechanism：** `[Inferred]` phase/batch/link/placement cost gate 只在预测可回收时启用 CreditReduce，其他 bucket 明确回退 native static policy。
- **Evidence：** `[Hypothesis]` 单 GPU、单机多 GPU、两节点 RDMA 的分层测量给出胜、平、负边界；即使 CreditReduce 失败，公开其失败 envelope 仍是可复现 negative result。

**[Inferred] “实现了一个系统”不单独计贡献；上述三条分别要求新的 observation、mechanism 与 evidence。**

## F.1 直接终止、降级与有价值负结果

- `[Inferred]` H1、H2、H3、H4、H5 或 H6 任一失败：停止把 CreditReduce 当动态系统主线。
- `[Inferred]` H7 失败：最多保留 numerical/ABI characterization，不写系统加速。
- `[Inferred]` H8 失败：可保留 operator/phase-map 结果，不写 TTFT/TPOT/P99 优化。

## G.5 公平规则

### Matched quality

`[Hypothesis]` 以 late-BF16 为质量 reference。初始预注册非劣 margin：

- `ΔNLL ≤ 0.005`；
- relative PPL regression `≤0.5%`；
- generation/task 指标下降不超过 `max(0.2 percentage point, 2×baseline CI)`；
- request-level tail 另报 p95/p99 token KL、top-1 disagreement 与 router flip，不允许只看均值。

若 pilot repeatability 表明 margin 不合理，只能在查看 frozen confirmation 前一次性修改并记录理由。

### Matched wire

- selector comparison 固定相同 `n32` 或相同完整 physical frame bytes；
- 计入 header、bitmap、route metadata、scale、alignment、padding、ready signal 与实际 message count；
- `logical tensor bytes`、`application frame bytes`、`transport/NIC counter bytes` 三列分报；
- 不用 reserved buffer capacity 冒充 transmitted bytes，也不用 logical saving 冒充 latency。

### Matched system

- 同一 fork、编译参数、SM/QP、CUDA graph、buffer capacity、warm-up、stream priority；
- baseline 与 treatment 交替随机运行；固定 request trace；隔离背景流量；

- request p50/p95/p99，而非 token 当 iid；

- payload/frame/NIC bytes；message/startup 数；

## H.1 碰撞后的 claim 边界

可以写：

> `[Hypothesis]` MoE route collision 产生确定 byte credit；一个 credit 足以把一个多输入 domain subtotal 保留为单条 FP32 record，而 singleton 继续 BF16 不丢信息；由此得到 hidden-vector payload 不超过 flat BF16 的 PrecisionDividend 表示，residual-guided demotion 可进一步节省 payload。

不能写：

- first mixed-precision communication / first accuracy-aware collective；
- bitwise equivalent to late-BF16；
- local residual bound 等于 KL/generation guarantee；
- total wire 或 latency 必然不超过 flat BF16；
- 适用于 top-1/top-2 或所有 MoE；
- 已有 production speedup。

`[Inferred]` 投稿前必须重新检查 DeepEP、NCCL EP、MORI、TensorRT-LLM 最新主线与相关专利/技术报告；当前 novelty 结论仍是 provisional。

# I. 最关键的前置实验（按 expected information gain 排序）

## I.1 P0-1：新鲜 raw-contribution opportunity 与六端点生死实验

- **为什么优先：** `[Inferred]` 一次同时杀 H1/H2/H3；不需要 GPU，也修复现有 formal 数据重用问题。
- **最低资源：** Apple M5 Pro；先 OLMoE，再 LLM-jp；全量目标为每模型 256 requests。
- **控制变量：** 全新 SHA-256 manifest；同 route/output；late、stock early16、FP32sum→BF16、uniform early32、PD-Full、uniform FP8；contiguous/round-robin EP8/16。
- **成功：** 至少两个 independent cells 中 early16 超质量预算、PD-Full/late 通过；`p_opp≥20%`、credit≥15%，且 PD-Full 仍较 late 明显少 physical frame bytes。
- **失败：** early16 全部通过、FP8 支配、或 opportunity 太少。
- **是否终止：** **是。** 任一主失败即停止 CreditReduce，不写 kernel。

## I.2 P0-2：PD-Gated 的 paired intervention 与 oracle-gap

- **为什么优先：** 判断 residual gate 是否有信息，还是 PD-Full/early16 两个静态端点已足够。
- **最低资源：** Mac，同一 frozen holdout。
- **控制变量：** 固定相同 `n32`；residual vs random、`m`、norm、cancellation、true-impact oracle；其他 groups 统一 FP32，逐 group BF16/FP32 paired intervention。
- **成功：** 至少两个 cells `0.1≤p32≤0.9`；held-out residual 明显优于静态/随机，PD-Gated 在质量预算内相对 PD-Full 至少减少约15%完整 frame bytes，且 oracle 仍有可解释 gap。
- **失败：** selector 塌缩、oracle 无中间 Pareto、raw residual 不优于简单规则。
- **是否终止：** 对唯一主方案 **是**；PD-Full 只保留为强基线与 negative characterization，不在本轮升格为替代核心。

## I.3 P0-3：单 GPU dual-plane fused kernel break-even

- **为什么优先：** 直接检验 `m≥2` collided-group FP32 subtotal、certificate、scratch、scan/pack 是否吞掉理论 saving。
- **最低资源：** 1×H100/H200 80GB，约16–24 GPU-hours；不需要模型常驻，可 replay frozen traces。
- **控制变量：** 相同 H/K/D/C distribution、同读写次数、同 frame；early16、PD-Full、PD-Gated、uniform FP8；compact one-frame 与 fixed-slot/two-message 消融。
- **成功：** physical bytes 与模型误差<5%；metadata/padding<8%；控制开销≤gross exposed saving 的25%；PD-Gated 相对 PD-Full 有 kernel-level frontier。
- **失败：** 4H fixed slots、额外 launch、scratch/scan 使 completion 不降。
- **是否终止：** **是。** 失败只保留 numerical paper，不做 RDMA claim。

## I.4 P0-4：两节点 DeepEP operator

- **为什么优先：** actual RDMA、completion 与 overlap 是系统 claim 的最低闭环。
- **最低资源：** functional minimum `2 nodes × 2 H100`；可信 hierarchical paper minimum `2×4 H100/H200 + CX7 200/400G`，约48–72 GPU-hours。
- **控制变量：** 同一 DeepEP fork、route trace、quality point、SM/QP/buffer；native early16、late16、PD-Full、PD-Gated、FP8、FlushMap；交替随机运行。
- **成功：** 相对最佳质量可行 static baseline combine operator ≥10%；actual frame/NIC bytes一致；P99不退化>2%。
- **失败：** overlap 后 `φ≈0`、dual plane拖慢、FP8/static32支配。
- **是否终止：** 对系统优化 claim **是**。

## I.5 P1：端到端 serving 与第三模型泛化

- **为什么优先级最后：** 只有 operator 先活下来，集成成本才值得付。
- **最低资源：** 2×4 GPUs 起；SGLang/vLLM/对应 serving engine；OLMoE/LLM-jp/Qwen top-4。
- **控制变量：** phase/batch/placement/topology、固定 request trace、相同 quality SLO 与 energy protocol。
- **成功：** TPOT/throughput/E2E ≥5%，95% CI 排除0；TTFT/P99/J-token 不恶化；至少两模型两 workload family复现。
- **失败：** 只改善 microbenchmark、只单模型、或收益来自更宽松质量。
- **是否终止：** 失败降为 operator/characterization，不写 serving optimization。

# J. 推荐论文标题、摘要与完整叙事

## J.1 推荐标题

**CreditReduce: Reinvesting Route-Collision Byte Credits in Wide Hierarchical MoE Combine Partials**

中文：**CreditReduce：将路由碰撞的字节红利再投资于宽精度层级 MoE Combine Partial**

副标题可限定：**Error-Gated BF16/FP32 Partials for Top-k≥3 Expert Parallelism**。

## J.2 拟摘要（150–250字）

`[Hypothesis]` 层级MoE在源域内合并同一令牌的多条专家贡献，虽减少跨域记录，却新增一次BF16中间舍入。CreditReduce将合并释放的字节额度用于保留高舍入残差组的FP32部分和，低风险组仍发BF16，并保证向量载荷不超过全部BF16贡献直传。我们用未见请求检验质量与边界，再以单GPU和两节点原型测量打包、实际字节和暴露完成时间，对比静态BF16/FP32、统一FP8及原生EP后端。

## J.3 完整叙事

### Problem

`[Observed]` hierarchical combine 减少跨域 records，且 DeepEP 明确写出了多次归约与一次最终归约之间的 precision–transfer trade-off。`[Inferred]` 在本轮审计到的公开实现中，尚未看到利用 MoE route collision 生成的 byte credit、再按 local recast residual 选择 BF16/FP32 partial 的完整 contract。

### Observation

`[Inferred]` 把 K 条 contributions 合为 D 条 partial 释放 `K-D` 个 BF16-vector credits；一个 collided group 从 BF16 partial 升到 FP32 恰好消费一个 credit。local FP32 subtotal 到 BF16 的 recast residual 又在发送前直接可见。

### Mechanism

`[Hypothesis]` PD-Full 让 collided groups 用 FP32、singleton 用 BF16；PD-Gated 再把低 residual collided groups demote 到 BF16。所有组仍 one record/domain，且 hidden-vector payload逐 token不超过 late-BF16。

### Implementation contract

`[Hypothesis]` local FP32 reducer + residual bitmap + 同一 physical frame 内 BF16/FP32 compact planes + mode-independent FP32 receiver order + late-size bounded arena；DeepEP/NCCL/MORI 均需内部 ABI 修改。

### Evaluation

`[Hypothesis]` 先用全新 raw contributions 判定 opportunity、precision need 与 oracle gap；再以单 GPU kernel、两节点 actual RDMA 和端到端 serving逐级检验 quality、physical bytes、overhead、completion 与 TPOT/P99。

### Limitation

`[Inferred]` 仅适用于 top-k≥3 且 `1<D<K` 的 hierarchical combine；不认证 end-to-end quality，不保证 metadata 后 total wire non-expansion；uniform FP8、static early-BF16 或 PD-Full 任一可能使动态 gate 失去价值。

## K.1 如果完全没有多 GPU，claim 如何收缩

## K.3 最终硬判决

**[Inferred] 当前结论是“有条件继续 P0”，不是“系统方案通过”。**

CreditReduce 比 QuotaEP-H 更值得做，不是因为它已经有效，而是因为它把问题压缩成一个更硬的命题：

> **[Hypothesis] high-top-k MoE 的 local route collision 能否在不超过 flat BF16 hidden-vector payload 的前提下，资助 collided partial 保留 FP32；而 local recast residual 能否把其中足够多的 groups 安全 demote 回 BF16，从而在严格质量下击败 PD-Full、early-BF16 与 optimized uniform FP8 的真实完成时间。**

这条命题在 Mac 上可以先被大概率杀死，在单 GPU 上可以验证实现成本，在两节点上才有资格升级为系统 claim。若两周后仍只有旧 reused-data logical-byte 结果，则论文没有完成创新闭环；若 P0 与 kernel 通过，即使暂缺大规模集群，也已经形成一条诚实、可复现、适合硕士论文继续推进的主线。
