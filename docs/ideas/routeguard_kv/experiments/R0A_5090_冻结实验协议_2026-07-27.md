# RouteGuard-KV R0-A：RTX 5090 冻结机制验证协议

> 日期：2026-07-27
>
> 冻结时状态：`DESIGN_FROZEN / GPU_NOT_APPROVED / SEALED_PREPARED`
>
> 目标 GPU：`NVIDIA GeForce RTX 5090`，32 GiB
>
> 机器配置：[r0a_5090_v1.json](configs/r0a_5090_v1.json)
>
> 证据边界：单 GPU、BF16 权重、teacher-forced decode、KV quantize-dequantize 机制探针；**不是 native INT4 kernel、不是显存/吞吐实验、不是 serving、不是多卡 EP 证据**。

## 0. 直接结论

本实验只回答一个便宜但决定性的前置问题：

> **在同一个 pretrained OLMoE 的真实逐步 decode state 中，INT4 KV-cache 扰动是否造成非平凡的 top-k route-set 变化，并通过 router set/weight 通道解释足够大的一部分 next-token 分布误差？**

它不比较 BCRD/DEPA，不实现 RouteGuard allocator，也不尝试证明吞吐。R0-A 通过只授权 R0-B 跨模型复现；失败则停止 RouteGuard 机制线，不换位宽、数据、模型或指标抢救。

设计选择是：**BF16 prefill 一次，然后从同一 prompt-cache snapshot 深拷贝出彼此独立的 decode 臂。** 这样测到的是“读取并持续写入量化 KV 后，decode 路由如何变化”，而不是把 prefill 路由漂移混进归因。

## 1. 为什么不能直接复用旧 runner

现有共享资产只能部分复用：

- `experiments/shared/capture_moe.py` 能采集 route，但旧 `routing_cache` 只按 `layer` 索引，会覆盖不同 document、prompt length 和 decode step；不能作为本实验的 reference trajectory。
- `experiments/shared/fake_quant.py` 的 `int4` 是通用 per-row 对称 quantize-dequantize；它不等同于目标 KV 后端的 per-head/per-token 非对称格式。
- `experiments/shared/metrics.py` 可复用 float32 KL 核心，但现有接口面向整段 forward；本实验必须逐 decode step 流式累计。
- 旧 `patch_mixtral_moe` 的 full path 已努力复现 expert-id accumulation order，但本实验仍须重新通过“patched BF16 与原生模型 route/logit 等价”资格门。

因此 RouteGuard 专用实现不得直接修改 shared 默认行为。新增代码放在本目录，只有稳定且被其他 idea 需要时才考虑上移。

## 3. Decode 状态机

对每篇文档、每个 prompt length `P∈{512,2048}`：

1. 取 tokens `[0:P)` 做一次原生 BF16 prefill，得到 prompt cache snapshot `C0`；
2. 深拷贝 `C0` 运行 BF16 reference decode；
3. 依次输入 tokens `P ... P+31`，每步输出预测 `P+1 ... P+32` 的 logits；
4. 记录每个 `(document, P, step, layer)` 的 BF16 expert ids、native gate weights、top-k/top-(k+1) boundary margin 与 reference logits；
5. 每个 treatment 从**新的** `C0` 深拷贝开始；先按目标配置量化整个 prompt cache，再逐步 decode；每次新写入的 K/V 也用相同配置量化；
6. 所有 treatment 输入与 reference 相同的 teacher token，不使用任一臂自己的生成 token。

每个臂必须拥有独立 cache object、独立 storage pointer/fingerprint、独立 route cursor 和 journal。teacher forcing 只对齐 token，不能共享状态。

### 3.1 为什么 prefill 固定 BF16

R0-A 的 estimand 是 decode cache-mediated route effect。若 prefill 自身也量化，prompt 内 route 漂移会改变所有层的 hidden state 和最终 prompt cache，使“历史 cache 误差”和“prefill 计算误差”无法分离。

真实 engine 可能在 prefill 中采用不同 quantized attention path，因此本实验不声明与 LMDeploy/vLLM 数值等价。若 R0-A 通过，真实 backend parity 是后续独立 Gate。

## 4. KV 量化语义

### 4.1 Primary quantizer

Primary 使用固定的 **[LMDeploy-family per-head/per-token asymmetric INT4](https://lmdeploy.readthedocs.io/en/latest/quantization/kv_quant.html) quantize-dequantize proxy**。对每个 `[batch, kv_head, token, head_dim]` 向量独立计算：

\[
s=(x_{max}-x_{min})/15,
\]

\[
z=\operatorname{clip}(\operatorname{round}(-x_{min}/s),0,15),
\]

\[
q=\operatorname{clip}(\operatorname{round}(x/s)+z,0,15),\qquad
\hat x=(q-z)s.
\]

- min/max、scale、zero point 与 dequant 在 FP32 计算，输出转换回 BF16；
- `x_max=x_min` 时不执行除法，常量向量必须精确返回原值；
- K 已由模型完成 RoPE 后才进入 Cache API，因此量化发生在 RoPE 之后；
- fake quant 只模拟数值误差，仍以 BF16 tensor 保存，不产生真实 4-bit 显存或 kernel 收益。

该公式是冻结 proxy，不声称 bit-exact 复现 LMDeploy kernel。若后续代码审计发现目标 backend 的数学语义不同，必须在打开 sealed 前生成 `v2` 协议和新的 config hash；不得在同一个 v1 sealed run 中静默更换。

### 4.2 配置与决策层级

| KV target | Prompt length | 角色 |
|---|---:|---|
| `K-only INT4` | 2048 | **唯一 primary confirmatory cell** |
| `K-only INT4` | 512 | secondary dose-response / domain-boundary；不参与 PASS/NO-GO |
| `V-only INT4` | 512 / 2048 | secondary mechanism decomposition |
| `KV INT4` | 2048 | secondary system-facing stress cell |
| identity/no-op | 512 / 2048 | numerical与状态污染负控 |

只有 `K-only INT4 @ 2048` 决定主假设，避免在 K/V/KV 三类中挑最有利结果。V-only 或 KV-only 的正结果不能救回 primary failure；最多生成新问题，必须另行预注册。

## 5. 三个 counterfactual 臂

设 reference 在 `(document, P, step, layer)` 的 expert ids 和 gate weights 为 `(S*, g*)`。

### 5.1 `free`

量化 KV，router 使用 treatment hidden state 正常计算全 64-expert softmax 和 top-k。

### 5.2 `set_locked`

量化 KV，但 expert ids 强制为 `S*`；gate weights 从 treatment 的完整 64-expert softmax 中按 `S*` gather。

OLMoE 的冻结 config 是 `norm_topk_prob=false`，因此**不做 top-k 内重归一化**。若未来模型的 native config 为 true，才按模型原生语义归一化；不能统一写死“locked 后 renorm”。

### 5.3 `fully_locked`

量化 KV，同时强制使用 `(S*, g*)`。该臂移除 route-set 与 gate-weight 两条 router 通道，但仍保留量化 KV 对 attention、residual、expert input/output 和其他数值路径的影响。

### 5.4 文档级 estimand

令 `L_a(d,P,c)` 为文档 `d`、长度 `P`、配置 `c`、臂 `a` 的32步平均 next-token KL：

\[
L_a=\frac1{32}\sum_t KL\left(p^{BF16}_t\Vert p^a_t\right).
\]

定义：

\[
\Delta_{set}=L_{free}-L_{set\_locked},
\]

\[
\Delta_{weight}=L_{set\_locked}-L_{fully\_locked},
\]

\[
\Delta_{router}=L_{free}-L_{fully\_locked},
\]

\[
\Delta_{numeric}=L_{fully\_locked}.
\]

这些是 counterfactual contrasts，不假设严格可加或恒正。原始负值必须保留；禁止先裁零再计算“归因份额”。

总体 router-mediated share 使用 bootstrap 内重算的 ratio-of-means：

\[
R=\frac{\mathbb E_d[\Delta_{router}(d)]}{\mathbb E_d[L_{free}(d)]}.
\]

不使用不稳定的逐文档 ratio 均值。

## 6. 指标

### 6.1 Primary quality

- 每步 float32 `KL(reference || treatment)`；
- 文档级32步 mean KL；
- ground-truth next-token NLL difference 作为 secondary；
- 不使用 free-running task accuracy 解释 R0-A。

### 6.2 Route

- exact top-k set flip rate；
- Jaccard overlap；
- aligned expert-weight L1 drift；
- reference top-k boundary margin `logit_k-logit_{k+1}`；
- non-tie flip rate；tie 定义为任一相关 boundary absolute margin `≤1e-6`；
- 按 layer、step、prompt length 分层报告，不用跨层平均掩盖单层异常。

### 6.3 完整性与资源

- 每个 arm 的 32 steps × 16 MoE layers 必须完整；
- cache sequence length 每步精确增加1；
- reference/treatment token ids、position ids、attention mask 相同；
- CUDA peak allocated/reserved、GPU name、driver、CUDA、Torch、Transformers、model/dataset revision；
- 本实验不把 wall time、峰值显存或 fake-quant tensor bytes写成量化收益。

## 7. 上 5090 前的资格门

### Gate C0：原生模型身份

- model/tokenizer/dataset revision 精确匹配；
- config 结构断言全部通过；
- GPU exact name 为 `NVIDIA GeForce RTX 5090`；
- CUDA capability 为 `sm_120`；
- peak cap 为30.25 GiB，至少保留1.5 GiB guard；OOM 不允许减 prompt、减文档或改 dtype。

### Gate C1：patched BF16 等价

在独立 smoke 文本、两个 prompt length 上比较 unpatched BF16 与 patched BF16：

- route identity mismatch = 0；
- max token KL `≤1e-7`；
- max absolute logit error `≤0.02`；
- cache length、position 与32步 token ledger完全一致。

任一失败则 `INVALID_PATCH_EQUIVALENCE`。

### Gate C2：identity/no-op

- route set flip = 0；
- max token KL `≤1e-7`；
- `free == set_locked == fully_locked` 在冻结容差内；
- cache fingerprints证明三个臂没有共享 storage。

任一失败则 `INVALID_STATE_OR_NUMERICAL_CONTROL`。

### Gate C3：量化语义

- 常量、对称极值、随机 tensor 的量化公式单测通过；
- K-only 时 V bitwise unchanged，V-only 时 K bitwise unchanged；
- prompt cache 初始化和每步新写入都命中同一 quantizer；
- 无 dtype promotion、silent BF16 bypass 或只量化最后一个 token 的错误；
- quantizer 调用 ledger 与 `documents × lengths × arms × layers × steps` 一致。

任一失败则 `INVALID_QUANTIZATION_PATH`。

## 8. Formal pass/fail

独立统计单位为32篇 sealed document；paired document bootstrap 5,000次，seed `2026072702`。只有一个 primary cell，不对 secondary cells 做 rescue 或多重比较后的替代主张。

### 8.1 Primary cell：`K-only INT4 @ 2048`

必须全部满足：

1. **总扰动可测：** `mean_d L_free ≥ 1e-4`，且至少为 `max(identity/no-op mean KL, 1e-12)` 的100倍；
2. **route-set 可操作：** non-tie exact set flip rate `≥1%`；
3. **router contrast 为正：** `mean_d Δrouter` 的95% bootstrap LCB `>0`；
4. **router share 足够大：** `R` point estimate `≥0.40`，95% LCB `>0.25`；
5. **非单文档驱动：** leave-one-document-out 的32个 `mean Δrouter` point estimate 全部 `>0`；
6. **非 tie 驱动：** 至少90%的 set flips 不属于 boundary tie。

`1e-4` 的 absolute KL floor 用于拒绝“统计可见但科学上极小”的扰动；在 identity 上限 `1e-7` 通过时，它至少高出数值控制三个数量级。`1%` set-flip floor 对应 primary cell 至少约164个非 tie `(document, step, layer)` flip，避免用极少量边界事件构造40%归因比例。40% point / 25% LCB 是机制占比门，不从 calibration 重新估计。

### 8.2 长度边界：`K-only INT4 @ 512`

512 cell 只报告 effect size、CI、route flip 和 `R`，不参与 PASS/NO-GO。原因是本方向的目标域本来就是长上下文；要求短上下文也显著为正，会错误杀死一个只在 KV 历史变长后出现的合法机制。

- 512 为正：支持跨长度可见，但不扩大到未测长度；
- 512 为零：将 claim 明确限制到 2048-token prompt 域；
- 512 为负：公开非单调性并在 R0-B 预注册长度交互，但不能救回或推翻2048 primary。

### 8.3 决策码

- `PASS_R0A_ROUTE_MEDIATED_KV_EFFECT_R0B_ONLY`：所有 integrity 与2048 primary 门通过；只授权第二模型 R0-B。
- `NO_GO_TOTAL_KV_EFFECT_TOO_SMALL`：总 KL 未过 materiality floor。
- `NO_GO_ROUTESET_CHANGE_TOO_RARE`：non-tie set flip `<1%`。
- `NO_GO_ROUTE_MEDIATION_TOO_SMALL`：contrast/ratio 未过门。
- `NO_GO_PROXY_FORMAT_DEPENDENT`：只有非 primary symmetric diagnostic 为正。
- `INVALID_*`：数据、patch、state、quantizer、ledger、hash 或完成度不闭合；只允许修实现后以新 run id 重跑，不解释科学结果。

如果 primary 失败但 V-only/KV secondary 为正，decision 仍为 NO-GO；secondary 只能写进报告的 hypothesis-generation 区域。

- 如果必须改任何科学参数，生成 v2 config，并重新生成仍未打开的 sealed manifest 与 approval binding。

### Phase 4：Code Review 与批准

必须产出：

- Code Review 文档；
- 全部测试日志；
- frozen artifact hash manifest；
- `approval.json`，明确写入 `GPU Run Approved`；

### Phase 5：sealed run

- 32篇 sealed，一次性全矩阵；

### Phase 6：analysis

只有全部 cells 和完整性 replay 通过后才允许运行；先生成 `decision.json`，再生成图表和自然语言报告。分析脚本不得接受替代 threshold CLI 参数。

## 11. 5090 资源预算

理论边界：OLMoE BF16 权重约14 GiB；2048 prompt 的16层、16 KV-head BF16 K/V cache 约0.25 GiB。每次只保留一个 treatment cache，reference logits/routes及时转 CPU，预计可在32 GiB内运行。

formal matrix 每篇文档包括：

- 两个 BF16 reference trajectories；
- 两个 identity trajectories；
- K-only 三臂 × 两个长度；
- V-only 三臂 × 两个长度；
- KV 三臂 × 2048。

总计32篇 sealed ×19个32-step trajectories = 608 trajectories，加64次 BF16 prefill。保守预计 smoke+calibration+formal 总 GPU 时间约2–7小时；实际预算以 Phase 2 smoke 为准。该估算不是性能结果。

## 12. 明确禁止的解释

即使 R0-A PASS，也不能写：

- RouteGuard allocator 已成立；
- MoE 比 dense 普遍更不耐 KV 量化；
- INT4 KV 带来2–4倍显存、吞吐或并发；
- fake quant 与 LMDeploy/vLLM bit-exact；
- 单5090证明多卡 EP、TPOT、P99 或生产 serving；
- H1/H2 已足够支持系统论文。

唯一允许的正结论是：

> 在固定 OLMoE、固定数据、2048-token prompt 与 decode-only INT4 KV proxy 域内，观察到跨文档的 route-set 变化，且 router-locked counterfactual 消除了预注册比例的 next-token KL；512-token cell 作为 domain-boundary 单独报告。该结果只授权第二模型复现和真实 backend parity Gate。
