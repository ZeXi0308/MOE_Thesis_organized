## 3. Code Review 发现与处理

| 检查点 | 结论 | 处理 |
|---|---|---|
| 量化对象 | PASS | K 在 RoPE 后进入 Cache；snapshot 和每个新 write 使用同一 per-head/per-token asymmetric INT4 QDQ |
| 常量向量 | PASS | `x_max==x_min` 精确返回输入，无除零或 NaN |
| K/V 隔离 | PASS | K-only 的 V 与 V-only 的 K bitwise unchanged；KV 同时命中 |
| Cache 独立性 | PASS | 每臂深拷贝并检查 storage pointer 无交叉；共享 prompt cache 只作为只读源 |
| Route cursor | PASS | key 为 document/prompt/step/layer；每步必须恰好访问16层 |
| `set_locked` 权重 | PASS | 从 treatment 64-way softmax 对 reference ids gather；OLMoE `norm_topk_prob=false`，不额外归一化 |
| `fully_locked` | PASS | reference ids 和 native BF16 gate weights 同时锁定；执行 route mismatch 必须为0 |
| 原生等价 | smoke PASS | patched BF16 route mismatch=0、token KL=0、logit abs error=0；calibration 仍需重复此门 |
| 统计 | PASS | document paired bootstrap 5,000次；share 在每次 bootstrap 内重算 ratio-of-means；保留负 contrast |
| 主次裁决 | PASS | 仅 K-only@2048 决定；512、V-only、KV 不能 rescue |
| 完成度 | PASS | smoke/calibration/formal 分别要求50/200/608条 trajectory；每条32 steps×16 route records |
| Resume | PASS | config/protocol/source/test/manifest 任一 hash 改变即拒绝；trajectory 原子文件不覆盖 |
| Data provenance | PASS | manifest ordered hash、dataset fingerprint、historical registry 和 config revision 共同绑定；任一变化即拒绝 |
| Formal approval | PASS | 未批准时先于读取 sealed 文本和创建 formal output 目录拒绝；批准必须绑定 exact formal bindings hash |
| 确定性 | smoke PASS | TF32关闭，PyTorch deterministic algorithms 开启，`CUBLAS_WORKSPACE_CONFIG=:4096:8`；v1/v2全部科学字段一致 |
| 性能声明 | PASS | QDQ 仍保存 BF16 tensor；runner 不把时间或显存写成 INT4 收益 |

smoke 已关闭 sm_120 上的包/算子兼容、真实峰值显存、deterministic path、patched/native 数值容差和实际单 trajectory 时长问题。剩余风险是2文档样本不能估计稳定性，并且 tie-robustness 方向性数值略低于预注册门；只能由冻结的8文档 calibration 检查，不得调参救援。
