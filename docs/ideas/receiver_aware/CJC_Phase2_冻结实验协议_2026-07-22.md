## 1. 冻结主张与边界

> 在 fixed routing、top-k、precision、wire bytes 和规范化 reduction order 不变时，receiver 当前的 sibling-arrival / join-deficit 是 sender-local queue、task size、deadline 和 receiver queue depth无法恢复的增量状态。若运行时允许重排 ready combine blocks，则该状态可优先服务能闭合 token/request frontier 的 contribution，降低尾部闭包时间。

本轮只检验两个问题：

1. receiver join state 相对最强 join-blind 基线是否存在足够的信息增量；
2. 在实测 LUT、控制消息和 staleness 收费后，该增量是否仍超过预注册门。

本轮不声称：真实通信加速、TTFT/TPOT 改善、RDMA 拥塞控制、端到端 serving 收益或论文主张成立。

## 2. 假设与递进 hard gates

### H0

任一项成立即接受 H0：

- identity-complete route producer 无法构造稳定 token join set；
- target path 不能在 ready blocks 之间重排，或 early closure 不能释放 buffer、解除 HoL 或推进下游；
- join-aware 策略被 synchronized token order、EDF、SRPT、queue-depth 或 topology-aware join-blind baseline 覆盖；
- 收益只在未来信息、免费 ACK、拍定服务常数或单一人工 hotspot 下成立；
- 两模型、两个主 workload cell 中任一未过 5% / 3pp 门。

### H1

在严格因果、同任务集合、同 bytes、同 service realization 和完整协调税下，`global_causal_join` 相对最佳 join-blind 强基线在两个模型、两个主 cell 均满足：

- P99 token-block closure reduction 的 paired 95% CI 下界 **≥5%**；或
- closure-SLO violation absolute reduction 的 paired 95% CI 下界 **≥3 percentage points**。

### 递进停止门

1. **G0 Identity/closure**：每个有效 token 恰有 `top_k` 个唯一 contribution，且 request/forward/layer/token/slot 身份无碰撞。
2. **G1 Control path**：必须存在可重排的 ready-block queue；若只有不可打破的 full-layer barrier 且早闭包无任何可测作用，本路线停止。
3. **G2 Information necessity**：零协调税下，join-aware 相对所有 join-blind 强基线先过主门；否则不写 controller。
4. **G3 Charged deployability**：加入 ACK bytes、可见延迟、policy time 和 staleness 后仍过同一门。

G2/G3 失败为本机制的 No-Go；producer/硬件能力缺失只可写 `BLOCKED`，不得伪装成科学 No-Go。

## 3. 对象、状态、动作与目标

contribution task：

```text
j = (request_id, forward_id, layer_id, token_id, topk_slot,
     expert_id, sender_rank, receiver_rank)
```

- **receiver**：拥有该 request/token continuation/KV 的 origin rank；不得由 `expert_id` 推导。
- **sender**：在冻结 placement manifest 中执行 expert 的 rank。
- **join set**：同一 `(request,forward,layer,token)` 的全部有效 top-k contributions。
- **状态**：当前时刻已完成/缺失 sibling bitmap、ready tasks、各 resource queue、request slack、fairness debt。
- **动作**：从当前 ready set 选择下一 non-preemptive combine block；本轮不 reroute、replicate、compress、drop 或改精度。
- **目标**：最小化 token-block closure P99/CVaR 与冻结 SLO violation。
- **约束**：release time、resource capacity、exactly-once、固定 routing/bytes、canonical reduction、starvation bound、严格因果。

对 token `u`：

\[
C_u=\max_{j\in siblings(u)} completion_j,
\qquad
L_u=C_u-release_u.
\]

主指标只对 `L_u` 统计；request/layer maximum、mean、CVaR10 为敏感性。

## 4. G0：身份完整的 route producer

现有 `experiments/shared/capture_moe.py` 产物不能直接作为正式输入。它只保存 caller-set `sample_id`、`layer`、flattened `token_position`、1-based top-k `rank`、logical `expert_id` 和 gate weight；缺少 request/forward/microbatch/decode identity、valid mask、物理 placement 和全部时序。`route_rows()` 还丢失 route-batch entry index，重复 key 可碰撞。

正式 producer 每条记录至少包含：

```text
schema_version, model_revision, data_manifest_sha256,
request_id, forward_id, batch_id, phase, decode_step,
layer_id, token_id, token_position, topk_slot, expert_id,
sender_rank, receiver_rank, valid, route_weight,
route_source, placement_manifest_sha256
```

规则：

- 主 capture 固定 `batch=1`、无 padding、每 request 一次独立 forward；`sample_id` 不能单独充当 request identity。
- 每个 `forward_id` 全局唯一；`token_id` 在 request 内唯一；`topk_slot` 为逻辑 slot，不得称物理 rank。
- sender/receiver 由冻结 placement/origin manifests 显式 join；不能从 expert group 代理。
- producer 不提供虚构 arrival/ACK；这些由 replay 在独立字段中生成并带 source 标签。
- closure：每个有效 `(request,forward,layer,token)` 恰有 `top_k` 条，slot/expert 合法，无 duplicate/drop/padding 混入。
- 旧 CSV 仅能做静态 route 分布敏感性，不能打开 G0。

## 5. 物理映射与 service/release 来源

主 topology proxy：EP=8，ranks 0–3/4–7 为两节点；contiguous expert placement；request origin 用 route-blind token-count LPT 固定。round-robin placement 只作敏感性。

主控制资源为每个 receiver node 的一个 shared combine-ingress server。所有 policy 使用相同 contribution release trace 与 service realizations；本轮只改变 ingress service order，从而隔离 join information value。

每个时序字段必须标注：

```text
measured_same_gpu | derived_from_measured_lut | analytic_link | synthetic_stress
```

- `expert_ready_us`：真实 row-count 分布 + 5090 expert/microtile LUT，经冻结 sender FIFO compute schedule导出；不得直接称实测 ready timestamp。
- `service_us`：实测 pack/launch/host-staging LUT与解析 serialization 分栏；H2D 明确标 `NOT_RDMA`。
- link bandwidth 只用于 L2 proxy；主结果同时报告 100/200/400 Gbps sensitivity，不挑最好值。
- synthetic straggler 只允许用实测 trial distribution 的预注册 quantile/stretch，不能拍定任意倍数。

## 6. 冻结策略与信息集

所有 arm 看到同一当前 ready set、task bytes、release time、request slack和 topology。只有 join-aware arms 可见 sibling completion bitmap；所有策略禁止未来 release/route/service realization。

| Arm | 冻结定义 |
|---|---|
| `fifo` | 按 ready time、stable task id |
| `srpt` | 最小 service time；stable id tie-break |
| `edf` | 最小 request/token slack；再按 ready time |
| `receiver_qdepth` | 优先当前 receiver queue 最深者；不可读 sibling bitmap |
| `largest_flow_first` | 最大 block/flow 优先 |
| `sync_token_order` | 全 sender 共享静态 `(request,layer,token,slot)` 顺序；不读 arrival completion |
| `topology_join_blind` | 相同 resource/topology 下最小 projected queue finish time；不读 sibling bitmap |
| `calib_best_static` | 仅 calibration 在上述静态族中选一条，sealed 固定 |
| `global_causal_join` | 读完整**当前** missing bitmap；优先 exact frontier closure，再按 missing count、slack、fairness debt；不读未来 |
| `offline_clairvoyant` | 可读完整未来的 upper bound，只报 ceiling，不能单独支持 GO |

`global_causal_join` 的 tie-break 与 score 在 Phase 3 固定，不允许 sealed 后调权重。若 candidate 与任一 join-blind arm action trace 完全相同，记为 information collapse。

## 7. 协调协议与会计

主口径按 receiver arrival 产生 delta ACK/credit：16 B header + 每更新 16 B record，message 向 16 B 对齐。记录至少含 hashed token-block identity、layer、missing count、epoch；duplicate/stale/out-of-order update 必须可检测。

每个 arm 分栏记录：

- contribution payload/descriptor/alignment bytes；
- ACK header/record/alignment bytes；
- build、aggregate、serialize、transfer、parse、policy lookup；
- visible coordination latency、stale rate、fallback count；
- controller CPU time和 replay wall time。

没有同流 timestamp 证明 overlap 时，全额收取协调 latency。主 staleness=`5 us`；敏感性固定为 `0/20/50 us`。late/malformed ACK 只能回退对应 join-blind order，已发生税不回滚。

reordering 不得改变 reduction 数值顺序：所有 contributions 到齐后按 `(topk_slot,expert_id)` canonical order reduce。candidate 与 baseline 的输出 hash/数值必须一致，否则 run 无效。

## 9. Workload cells、指标与统计

两个主 cell 均使用 route-real DAG 和 measured-LUT-derived release：

1. `steady_rho50`：Poisson request release，target ingress utilization 0.50；
2. `bursty_rho80`：二态 MMPP，长期 utilization 0.80，状态驻留和倍率由 calibration trace 固定。

每 cell 固定 seeds `2026072201..2026072205`；只有 CI 跨门时可追加预留 `...06..10`。主 token block size=1；block size 8 为敏感性。每 run 完整 drain，任务集合/bytes/service samples 在 arm 间逐项相同。正式 replay 按修订 A1 做 outcome-blind 层/token 子采样；不得根据 route skew、expert popularity 或结果选择。

主指标：

\[
Gain_{P99}=\frac{P99(L)_{best\ joinblind}-P99(L)_{join}}
{P99(L)_{best\ joinblind}}.
\]

closure-SLO 在 calibration 定义为最佳 join-blind arm 的 `1.10 × P99(L)`，随后冻结。另报 P50/P95/P99/CVaR、request/layer closure、starvation、fairness、queue utilization、coordination bytes/time。

统计单位为独立 document/request episode；paired hierarchical bootstrap 先重采 document，再重采 seed，`n=2000`。不得把 contribution/task 当独立样本。主报告先报两个模型×两个 cell，不得 pooled 掩盖失败 cell。

## 10. Go / No-Go 与停止规则

`GO_TO_STREAMING_RUNTIME_PROTOTYPE` 要求全部满足：

1. G0/G1 通过；
2. 零税 G2 在两模型×两主 cell 全部达到 5% P99 LCB或3pp violation LCB；
3. charged G3 在同四个 cell 仍过同一门；
4. `sync_token_order` 与 `topology_join_blind` 均未覆盖 candidate；
5. canonical reduction 数值一致、零 drop/duplicate、full drain；
6. 20 us staleness sensitivity 仍为正，50 us 允许失败但必须报告；
7. 收益不依赖 round-robin placement、单一 seed 或 synthetic-only straggler。

任一主 cell 不满足即 `NO_GO_CJC_V1`。不得通过修改 score、删 baseline、降低门、只报 pooled、加入 codec/precision/reroute/replica/bandit 或用 offline clairvoyant 代替 causal candidate 来救。
