# RouteShare Gate-0 快速验证结果（2026-07-23）

## 结论

**NO-GO：当前 RouteShare 核心假设不成立，不进入 VTC replay、调度器或网络拓扑扩展。**

冻结必要条件：只有当强简单模型的 held-out `R²` 95% UCB `< 0.90`，且 matched route-histogram latency effect 的 95% LCB `>= 10%`，才继续。

| 模型 | matched histogram effect | strong simple model held-out R² | 判定 |
|---|---:|---:|---|
| OLMoE-1B-7B, layer 0 | 3.06%, 95% CI [2.49%, 3.31%] | 0.9971, 95% CI [0.9952, 0.9973] | NO-GO |
| LLM-jp optimal-sparsity, layer 0 | 2.35%, 95% CI [0.97%, 3.64%] | 0.9986, 95% CI [0.9911, 0.9994] | NO-GO |

强简单模型使用 `total rows + active experts + max-row fraction + row-count CV + expert identity`。每个模型执行 240 个 route plans、12 个随机顺序 measurement blocks，共 2,880 条独立 CUDA-event timing；统计使用 held-out expert-set replica 和 500 次 block bootstrap。

## 验证边界

- `[Observed]`：RTX 5090 上真实 BF16 模型权重、真实 expert MLP shape、dispatch gather、全部 active expert forward、concat 和 restore permutation 的 CUDA 时间。
- `[Controlled synthetic input]`：route histogram 与 activation 是受控构造，用于测机制必要性。
- **不是** continuous serving、多租户公平、VTC 收益、多 GPU EP、NCCL/RDMA 或网络拓扑结论。
- 结果只否定当前主张：存在简单计量无法解释、且大到足以支撑新调度机制的 route-coalition cost。

## 实现检查

- 同一 `(rows, active experts, replica)` 的所有 histogram 使用相同 expert identity 和相同 dispatch permutation；只改变 per-expert row counts。
- 整数化后相同的 histogram 被视为重复测量，不伪装成 matched contrast；`active_count=1` 不进入 histogram effect。
- measurement block 内 plan 顺序随机；bootstrap 对 block 有放回抽样并保留重复权重。
- 无 CUDA、expert 集不完整、计时非正、输出目录已存在时 fail closed；无 CPU/proxy timing fallback。
- 本地与远端 5 个单元测试通过；两个正式结果各有 2,880 个唯一 `(block, plan)`。
