# AI Infra 研究现状与组织复盘

证据快照日期：2026 年 10 月 9 日，Asia/Shanghai。面向毕业设计推进、独立论文选题和有限 GPU 条件下的研究组织。

当前最重要的判断是：工作区已经积累了真实运行时实现、可复算实验和相当细致的因果诊断，但尚不能据此宣称已经形成一项获得完整支持的原创系统方法。下一阶段应集中完成少量有意义的研究主张，并给新问题保留低成本探索空间。建议保留三个课题负责人会话，加上已有统筹会话；三个课题先有界探索，持续资源再向证据最强的一至两项集中。

这份快照区分三类内容：**已核实事实**来自当前本地结果入口、代码和保存的数据描述；**综合判断**解释这些事实对研究投入和论文的意义；**待检验假设与建议**规定可以尝试的下一步。建议本身不改变历史实验判决，也不代表新会话、GPU 实验或文档重构已经执行。

远端进程、锁和实例可达性没有在本次文档整理中重新探测。B、E、M 等入口中的历史运行或候锁信息，须按各自的时间与核实状态理解。尤其不能由一份旧记录推断服务器此刻仍在运行、仍在等待，或者已经清空。

## 总体裁决

### 当前成果达到哪一层

工作区的主要优势已经从“能否改动运行时”发展到“能够区分合法动作、真实执行、资源后果和完整请求结果”。A 的 victim 干预、B 的资源让渡、C 的异步 MC 适配、D 的 prefill 预算比较、E 的 STORE 语义诊断、F 的逐请求损益、G 的容量边界和 M 的专家搬运记账，都具有可复用价值。

但这些资产的研究成熟度不同。一个运行正确的原型不等于有效方法；一次有效干预不等于目标改善；局部目标改善不等于整体服务收益；已有原则的适配收益不等于新算法；代码与日志打包也不自动成为工具论文。

目前最需要补齐的连接是：

1. 将实际服务需求与所测损失联系起来，说明为什么某种取舍值得改变。
2. 明确合理调优的简单方法与正确最近邻之后，是否仍有值得处理的缺口。
3. 让新增状态、模型或执行机制改变有价值的动作，并计入受损方与后续成本。
4. 形成读者能够使用的判断、方法或工具能力，再组织确认和论文证据。

这不要求在实现前完成全部证明。早期合理猜想、有限实现和测量可以交错推进；关键是每项工作能改变研究决定。

已经提出三个研究委托：容量复用与服务代价、异步 KV 生命周期测试、Agent 工具与 Host KV 主存竞争。当前本地没有 research_new 目录，也未找到这三项分别形成的新执行入口或结果。因此，本快照将它们记为**拟议研究组织与课题假设**，不报告已完成实验或已启动研究进程。

## 工作区与证据口径

### 运行域不能合并成一套配置

各线使用了不同 GPU KV 预算、请求数、同步模式、模型变体、输出合同和测量边界。即使都出现 OLMoE、vLLM 0.26 或 PRO 6000，也不能把绝对时延直接拼接成跨线对照。

| 证据域 | 代表性条件 | 能用于什么 | 不能直接推出什么 |
| --- | --- | --- | --- |
| A 主要完整规则 | 单 PRO 6000，OLMoE base BF16，同步 FCFS，320 请求，约 71.78 GiB GPU KV | 同组 victim 规则的完整取舍 | C 异步域的准入收益，或不同主机绝对时延排序 |
| C v25 | PRO 6000，GPU KV 64 GiB，host KV 16 GiB，384 请求，异步深度 2，量子 1024 | 当前普通 MC 适配的真实动作和代价 | 广泛自然输出服务、完整 MC 原系统复现或所有异步情形 |
| D 当前延续实验 | 独立的固定负载、预算合同和执行代码 | 同组 prefill 策略与完整服务指标 | 将同步近似模型系数直接用于 C 的异步运行时 |
| F 冻结案例 | 开环 CPU producer 回放，固定前端输出路径 | 前端处理与交付、请求群体损益 | 真实 GPU 生产者反馈下的端到端服务收益 |
| G compact | 单次启动容量观测及有限请求长度包络 | 排除该配置的特定容量不足解释 | dense 性能、所有计划的内存排序或完整服务性能 |
| M N4 等实验 | RTX 5090，人工 expert cap24，GPU/CPU KV 各 1 GiB，16 个 GSM8K 请求 | 该压力域的步骤、搬运、任务结果取舍 | 模型天然装不下、真实大模型卸载域的收益或总体质量等价 |

部署条件以各线入口为准。上表只保留影响跨线解释的差别，并非复现命令的替代。

### 指标应如何解释

| 指标或观察 | 准确含义 | 常见误读 |
| --- | --- | --- |
| TTFT | 从声明的外部到达到首输出的时间 | 直接当作纯排队时间 |
| completion flow | 从外部到达到完整完成的时间 | 只看恢复后第一 token 就宣称完成受益 |
| TPOT 与生成 span | 按各线公式计算的生成平均成本或首末输出跨度 | 与 token 级 ITL、host chunk gap 混用 |
| goodput | 满足所声明条件的完成量除以声明时间 | 把探索阈值当真实应用 SLO；把多个不生效阈值当独立证据 |
| 抢占次数 | 执行了多少次抢占动作 | 越少必然越好 |
| host hit 与外部 tokens | 可查找到的前缀或实际分配采用的外部内容，二者需区分 | 查找命中直接等于已 LOAD，或全部驻留内容 |
| STORE 游标 | 某条保存路径的进度语义 | 当前缓存驻留覆盖图 |
| DMA 完成与 ACK | 不同执行边界的事件 | 收到主机通知就能准确计出 DMA 时间 |
| token/s | 实际输出与声明测量时长之比 | 输出内容和长度变化后仍称等工作量加速 |
| 输出长度一致 | 工作量检查的一项事实 | 内容、路由、重算、浮点结果和质量均相同 |
| 两次 ABBA 配对 | 少量运行级开发证据 | 将组内数百请求当作数百次独立系统重复 |

必要时使用每请求恒等分解：

~~~text
完成时间 − 外部到达时间
= 首输出时间 − 外部到达时间
+ 末输出时间 − 首输出时间
+ 完成时间 − 末输出时间
~~~

该分解是时间边界记账，不自动产生排队、GPU 计算、控制开销与传输之间的因果分解。可重叠阶段也不能直接相加为总收益。

## 各线详细现状

### A 线 victim 选择

证据入口：[A 最新结果与收束研究卡](../../MOE_Thesis_organized/refine-logs/expert_saturation/experiments/admission_capacity/victim_selection_20261004_A/RESULTS.md)。

**问题与动作。** A 研究有限 KV 下，选择哪个合法 victim 能让释放容量产生更有价值的后续服务。主要比较只改变 allocation failure 时原生未处理 suffix 内的 victim；恢复目标、传输、准入和其他机制保持原协议。主要目标是全部外部到达请求的平均 completion flow。

**当前完整证据。** 最新研究卡已复算 8 组完成对照；本地清单中 19 个含 raw 的组均有分析。历史 6 组在正式测量前因 GPU 忙或磁盘不足终止，不能作为方法负结果。自然摘要准备材料存在，但本地未见相应原始结果，远端终态未核实。

| 比较 | 动作与局部效果 | 完整结果 | 判断 |
| --- | --- | --- | --- |
| remaining-budget 相对 tail | 每对实际非 tail 改选 10 次；抢占仍为 41 次 | mean flow 差值 −0.364 / +0.061 秒 | 反序换号，未形成稳定主目标优势 |
| max-release 相对 remaining-budget | 非 tail 改选由 10 增至 24；释放中位 135→214 页；抢占 41→27 | mean flow +0.786 / +0.577 秒；gap P95 −8.711 / −8.512 秒 | 有明显取舍，更少抢占未改善声明的平均完成目标 |
| cap-bucket 相对 remaining-budget | 实际非 tail 改选 36 次；抢占 41→43 | mean flow +0.161 / −0.043 秒；每臂少 525 个输出 token | 不能称为稳定、等工作量的收益 |
| 严格等释放 budget 相对 tail | 0→0 次改选 | 小幅时延差异 | 无动作差异，不应解释为机制作用 |
| host-near seeded 相对 tail | 四对中每臂有 32—34 次非 tail 改选 | 四对 mean flow 三次变差、一次变好 | 有动作空间，但新增信号价值未获稳定支持 |

数字来自同组顺序与反序比较，不能跨运行域混合配对。主要完整规则各格均为 320 到达、320 完成、0 失败、0 未完成；仍不据少量开发重复宣称统计显著。

**重要个体证据。** max-release 的某个请求两对晚完成约 21.773 / 21.652 秒。另一个恢复案例在释放 203 页之后，没有实际 LOAD，以冷补算重新占页，又在没有新输出时再次被抢占，完整生成间隔约 33.079 秒。它揭示了即时释放、容量重占与有效输出推进的差别；但强简单预算已在相关前态选择其他候选，不能据此直接证明新保护器有增量。

**研究判断。** 旧说法“合法候选只有一两个，所以 A 几乎无动作空间”不再适用于最新完整规则。准确的困难是：存在真实干预，但新增排序信息尚未稳定改善主目标，且一些局部改善把代价转给了具体请求。

**建议。** 停止继续搜索排序分数、host 代理和首次重入门槛。保留容量重占、受损方和指标取舍作为方法论与恢复语义材料。只有新部署或新动作能解决一个重要缺口时，才重新立题；无需设置“必须发生至少多少次动作”这种跨问题硬门槛。

### B 线恢复顺序与容量交换

证据入口：[B 完整结果与最新断点](../../B_recovery_order_20261004/RESULTS.md)、[恢复时间线工具](../../B_recovery_order_20261004/recovery_timeline/README.md)。

**服务与目标。** 当前容量交换证据来自单 PRO 6000、OLMoE BF16、GPU KV 71.9375 GiB、host KV 16 GiB，256 个交替长度前缀请求，0.1 秒开环到达，固定 1024 输出。主要观察全部到达请求的每请求最大输出间隔分布，同时保留 TTFT、完成、吞吐、donor 和同行代价。它是固定工作量压力诊断，不是自然任务质量确认。

**简单方法具有明显杠杆。** cap256 改为 cap224 后，两次均没有恢复，maxgap P99 从 5.724 / 5.314 秒降到 0.0964 / 0.0958 秒；代价是 TTFT P95 从 2.844 / 2.889 秒升至 27.723 / 27.327 秒，吞吐下降 3.39% / 3.33%。cap224 只是一个筛查点，不是全面调优最优值。

普通 stall8 在另一到达排列上，相对 native 的 maxgap P99 两对下降 37.88% / 44.53%，但完整完成时间、最差请求和吞吐存在取舍，末个 native 还有动作前漂移。因此，“恢复控制完全无用”与“新机制已经成功”都不符合证据。

**已完成的最小容量交换。** 长目标 after-failure 四格完成，共 1,024/1,024 请求，动作数 0/1/0/0。唯一交换释放 83 页，将 free 从 133 变为 216，满足 T204/R0/G12，初始 margin 为 0。以下仅描述有效动作臂 C1 相对相邻基线 S1：

| 指标 | 差值 |
| --- | ---: |
| 最差 maxgap | −0.578320 秒，约 −8.431% |
| 全体每请求 maxgap 均值 | +43.461 毫秒，约 +21.707% |
| maxgap P99 | +47.654 毫秒，约 +1.442% |
| mean flow | +0.236393 秒，约 +0.381% |
| token/s | −0.267% |
| maxgap 改善与恶化请求数 | 24 / 232 |
| flow 改善与恶化请求数 | 46 / 210 |

第二候选臂没有实际交换，其指标变化不能算作该机制的第二次有效重复。

**为什么入场成功没有变成持续服务。** 目标完成 LOAD 与尾部重算后输出一个新 token，约 6 毫秒后再次被抢占，约 6.28 秒后才又有输出。再次抢占由其他 RUNNING 请求扩页触发，当时 free 为 0；并非 LOAD 失败，也不是目标当下历史 KV 自己装不下。donor 最终晚完成约 4.306 秒，抢占从 0 增至 4，其首次恢复同样只维持一个新 token 后再次中断。

后继分析发现，目标恢复末轮有 62 个不同 peer 各欠一页，它们不在最初 G12 所计入的增长集合。这支持本事件的解释：初始时刻可见增长没有覆盖恢复跨轮期间新形成的需求。它尚不能证明新的区间模型可在线预测、能超过普通预留或保护量子，也不能将这些 peer 的等待相加成墙钟。

**最大 donor 一组仍然未知。** 最大释放 donor 已实际启动对照，最新成功观察记录前三格 exit0，动作 0/1/0；末基线当时仍存活。之后连接拒绝，完整 raw 未回收。当前不能判定末格是否完成、锁是否释放、目标是否持续获益以及全体代价。

这组不是一个尚未提交的计划，也不是已证实负结果。B 顶部仍有较早“下一实验未提交”的文字；接续必须使用文末最新断点。若恢复访问，先核实和回收原 session，不重复提交。

**工具资产。** 恢复时间线工具在设计轨迹和规则设计外轨迹上，分别关联 15 / 10 个抢占 episode、12 / 3 次 LOAD，并保留 86 / 74 次 allocator 尝试。某个 job 的重叠归属保留歧义。最长重试观察空档约 5.284 / 6.189 秒，不证明这段时间一直缺容量，也不自动解释未重试的原因。

**建议。** 停止继续微调已失败的最小交换规则。优先解决既有最大 donor 组的证据缺口，而不是提前启动另一套 BAAB。若后续新立题，应围绕持续有效服务、同行增长和让出方成本提出完整问题；“多留一页”或“恢复优先”本身已有大量先例。

### C 线准入与未来容量复用

证据入口：[C 当前研究卡](../../MOE_C_admission_20261004/research/C_admission_20261004/RESULTS.md)、[异步适配](../../MOE_C_admission_20261004/research/C_admission_20261004/async_mc.py)、[近邻索引](../../MOE_C_admission_20261004/research/C_admission_20261004/PRIOR_ART.md)。

**当前结论。** 普通 MC 组件适配已在原生异步域产生真实、有代价的收益；新的执行份额或选择性信用控制器尚无获支持的必要性。当前不能再写成“MC 只有接口适配，没有实际机会”。

**运行与动作。** v25 四臂顺序为全额声明预算 / MC / MC / 全额声明预算。384 请求、0.1 秒开环到达、EOS 或 max1024；单 PRO 6000、GPU KV 64 GiB、host KV 16 GiB、量子 1024、完整在途上限 256、异步深度 2。动作只影响 FIFO 首次 prefill 是否延后，其他路径沿用原合同。

四臂合计 1,536 次请求执行全部完成，无失败、拒绝、超时、未完成和抢占。这是共享一个 engine 的开发 ABBA 块，不能当作 1,536 次独立实验。

### E 线恢复方式与 STORE 覆盖诊断

证据入口：[E 结果入口](../../E_restore_choice_20261004/RESULTS.md)、[STORE 诊断](../../E_restore_choice_20261004/STORE_DIAGNOSTIC.md)、[机器可读状态](../../E_restore_choice_20261004/checkpoint.json)。

**最新任务已完成的部分。** 窄 CPU STORE 覆盖诊断已有代码、自动报告和限定案例主张，恢复策略搜索停止。它没有新增 GPU 性能结果，也没有自动形成上游修复。

**真正定位到的现象。** 旧 off/on 轨迹中，逻辑块 [73,74) 已完整重算，但 off 的 STORE 游标位于 197，观察窗口内 builder 正常返回却没有覆盖该块的新任务。后续连续 host 命中为 1,168 tokens。on 把游标 197→73，实际创建 [73,74)、[189,192)、[194,195) 共五块，ACK 早于后续 lookup，连续命中升至 3,152 tokens。

连续前缀改善 124 块，不代表此前实际缺失了 124 块。少数前缀洞就可能使后方已驻留内容无法作为连续命中使用。

| 游标干预成本 | 数值与解释 |
| --- | --- |
| 局部窗口新建 payload | 0→10 MiB |
| 全程 STORE | 两臂同为 135,499,087,872 字节；局部补写不等于全程净增加 |
| 全程 LOAD | 增加 262,144,000 字节，即 250 MiB |
| 全体重复 scheduled 位置 | 减少 1,974，全部来自目标 |
| 完成均值 | 增加 0.033349 秒 |
| 排空完成时刻 | 增加 0.148412 秒 |

它建立了“特定窗口里未创建任务—游标干预—连续覆盖变化”的因果证据，没有建立净服务加速。

**留出与反例。** 规则设计外轨迹有 38 次成功恢复，但缺 STORE observer，全部保守标为 INSUFFICIENT_EVIDENCE。这不是 38 个独立正例。CPU 满 LRU 反例显示：补 A 一个洞可将 A 前缀 2→8，却驱逐 B0，使 B 连续前缀 8→0；B1—B7 仍驻留。没有后续 B 执行和真实传输，不能据此计算 GPU 服务损失。

**分析器修正。** 旧比较只取两臂请求交集，可能漏掉只在一臂出现的高成本请求。最新工具要求身份唯一、全部到达入账、集合一致及 scheduler 观察存在，否则报告 INCOMPARABLE。这个修正增强本地分析可信度，不能算作原生运行时修复。

**inline Host 分支。** 25 次真实提交/等待干预使目标首个匹配事件更早输出，但全体完成均值增加约 0.291 秒，完整步数不变。一次对照不足以证明稳定变慢，却足以说明局部目标领先不能直接记作全体净收益。

**契约与远端状态。** STORE cursor 是任务枚举高水位，不是永久驻留承诺；NOT_CREATED 是观察窗口内的分类，不等于内容从未保存或上游正确性 bug。默认执行 r01 在 /dev/shm noexec 阶段失败，0 正式请求，不是图模式性能负结果。修正后的 r02 最后观察为 WAITING_FOR_LOCK，checkpoint 当前标记终态未核实。窄 CPU 工具完成，不代表这个旧远端任务已经确认结束。

E 曾做历史自然任务质量评价，因此不能笼统说“从未测质量”；但它不能替代当前固定输出游标与 inline 对照的质量确认。

**建议。** 保留精确 STORE 诊断、原生源码、语义反例和完整人口比较。若要上游报告，先核对实际版本与契约，再准确定位为行为、性能影响或正确性问题。R2 可以借用这些原生边界；R3 可以借用逻辑释放与底层内存持有分离的实现事实，二者都尚需新证据。

### F 线前端输出与隔离

证据入口：[F 当前决定](../../F_output_isolation/README.md)、[冻结交付](../../F_output_isolation/freeze_20261009/README.md)、[逐请求案例](../../F_output_isolation/freeze_20261009/request_case.md)、[直接编码分支判决](../../F_output_isolation/direct_encoding_20261009/verdict.md)。

**两个阶段必须分开。** 旧 C1、分类优先、缓存及物化策略已有各自的 CPU 回放结果。新的直接编码分支完成 CPU 语义与受控依赖检查，GPU 异步组件有编译记录；真实 top-20、CUDA 执行、首次 D2H 前接线、完整 CPU/GPU 路径和端到端性能仍未验证。旧负结果不转移给新分支，编译通过也不是新分支性能支持。

| 群体 | 请求数 | 两对均改善 | 两对均恶化 | 方向不一致 |
| --- | ---: | ---: | ---: | ---: |
| light | 120 | 67 | 50 | 3 |
| heavy | 40 | 0 | 34 | 6 |

light 中较长请求贡献了约 84.21% 的 token，pooled token P99 并不按请求等权。因此，总体轻流 P99 改善与许多轻请求受损可以同时发生。这支持对汇总指标的审慎解释，但不能证明每毫秒收益必然从另一个请求转移，也不能据两对运行作统计显著性判断。

### G 线执行计划与容量取舍

证据入口：[G 当前判决](../../G_execution_plans/DECISION.md)、[服务比较与未测项](../../G_execution_plans/service_comparison.md)。

| 同步 15、异步 414，直接证明异步导致抢占暴增 | 15 为历史不同 victim 数，事件为 24/26；414 是另一策略与组别的事件数 | 若研究 async 因果作用，需要相应受控比较 |
| C 的 39,138 是物理容量或跨模型需求 | 物理预算为 32,768 页；39,138 是开发消融的声明上限 | 不据此宣称未定义的超订比例 |
| C 还停留在适配 | v25 已真实放宽并产生响应收益与生成代价 | 不重复证明动作能发生 |
| D demand 被磁盘卡住，尚未测 | demand 已完成；未运行的是后来的 bounded rollout 探针 | 必须区分两个实验身份 |
| D 只差清理约 470 MB | 最新保存记录磁盘已恢复，探针当时因共享 GPU 忙未提交 | 不沿用旧阻塞，不把旧状态当现场状态 |
| B 最大 donor 仍只是下一计划，或已判失败 | 已启动，完整结果未回收 | 先恢复证据，不能重复提交或提前判负 |
| E 已证明上游正确性缺陷 | 已证明特定保存覆盖行为及干预后果；契约性质仍需核对 | 行为报告、性能问题、正确性 bug 分开定位 |
| E 窄工具完成意味着远端任务清空 | 旧默认执行 r02 终态未核实 | 恢复时先核对原进程与锁 |
| F 旧策略失败，所以直接编码也失败 | 新分支真实执行和性能未测 | 保留未知，但遵守当前冻结决定 |
| G dense 大概率相同，空闲时补一下 | 当前明确决定不再补 dense；dense 未测 | 不能把推测写成结果，不能自动恢复旧收尾计划 |
| M 必须换更大模型才能有研究价值 | 受控压力可用于机制研究；真实卸载部署增强外部效度，但不是普遍前置条件 | 换域要检验具体假设，不用于追逐正收益 |
| wave_src 是原版 WiSP 修复材料 | 修复的是本地 expert-major 扩展的跨 wave 归约 | 不误归因上游 |
| 一次统一质量测试就能完成所有线的质量论证 | 各线语义、任务和候选不同；历史质量不能跨组迁移 | 质量验证应对应保留主张，允许复用输入和框架 |
| 负结果可以自然转投表征或工具轨道 | 仍需要重要新信息或独特工具能力 | 不把投稿类型当作贡献不足的自动出口 |

先前提出的四臂门控、KV 配额轴、Qwen bring-up、固定投稿日期等，属于当时方案。除非某个当前入口已经记录实际执行与新决定，不应把它们列为已完成工作或本次重新授权的任务。

## 跨线复盘与研究洞见

### 局部指标经常没有覆盖动作的主要后果

A 减少抢占但平均完成变差，B 恢复后只维持一个 token，C 更早准入但生成变慢，D 缩短生成 span 却增加总体等待，E 减少重复位置但增加 LOAD，M 少走步骤却搬运更多专家。不同机制都说明：动作评价必须追到足够长的后继阶段。

这不是说所有取舍都不可接受。若应用明确偏重流畅性或某类请求，可以接受完成时间或成本代价。问题在于目标必须有依据，不能看到哪个指标改善才决定优化哪个指标。

后续原型应同时说明：谁获得资源、谁让出资源、效益何时出现、代价持续多久、什么时候资源真正归还。恢复后首 token、局部命中、单层提前完成都只能是中间证据。

### 资源数量与资源兑现时间应同时进入解释

“有多少空闲页”不能完全描述“某请求能否持续推进”。逻辑页、已承诺页、deferred 释放、在途传输和后继增长分属不同边界。B/E 的证据使这种区分具体化，但尚未证明一个统一预测器可以解决所有问题。

值得研究的候选关系是：动作生效与资源归还的时间尺度，是否慢于负载状态改变的时间尺度。如果恢复跨越多个 peer 增长轮次，瞬时账本可能过时；如果工具内存峰值先于可回收区域归还，事后逻辑驱逐可能无效。需要实测这些关系，并检查简单预留、固定余量或现有动态预算是否已足够。

### 预测更准不等于选择更好

D 的模型加入了进入与退出，仍曾错误预测完整收益；重新校准后拟合既有方向，也不代表下一次动作有效。未来应重点评价：

- 在相同或近似状态下，预测是否给出正确动作排序。
- 排序对合理测量误差、长度误差和状态过期是否稳健。
- 错误选择的服务代价是否大于使用简单策略的代价。
- 新信息的采集、计算、执行开销是否值得。

对于自适应策略，找出简单指标相近、合适动作却不同的状态通常有帮助；但它不是所有系统创新的前置条件。数据布局、批次组织或执行机制可以通过减少结构性成本产生价值，而不依赖复杂状态预测。

### 旧实验边界不能成为永久设计边界

按 victim、准入、恢复或 prefill 拆分，有利于归因。若证据表明跨阶段耦合重要，仍坚持所有其他动作永远不变，就可能使每条线只能优化别人留下的残差。

另一方面，把所有控制点一次合并成大控制器，也会使实现、归因和调优失控。更好的扩展是：为了一个具体假设增加一个必要动作，并与简单组合比较。C 的异步守卫与 D 的同步模型必须重新对齐，不能把“联合优化”当作跳过资格检查的理由。

### 生成行为是系统评价中的实际变量

相同 greedy 设置也没有在所有配置下保证逐 token 相同。M 中归约顺序、其他线中的批次与执行路径可能影响输出；具体原因需要对应证据，不能把所有分叉都归因于一个实现细节。

诊断时可用受控 token 路径减小工作量混杂。真实部署主张仍需要自然生成及相应任务效用。两类实验互补：固定回放隔离系统成本，真实生成体现闭环行为。相同正确题数不等于质量等价，相同 token 数也不等于相同计算成本。

### 强简单策略既是竞争者也是问题探针

B 的 cap224、stall8，D 的固定预算，C 的全额预算与普通 MC，都帮助发现哪些取舍由已知原则解释。复杂方法失败时，应检查问题、信号、模型、动作和实现中的具体薄弱环节，而不是继续微调同一公式。

简单方法占优不意味着永远禁止新方案。它要求新方案有明确理由：新的约束、未表达的状态、不同执行成本或旧方法无法实现的动作。这个理由可以先通过低成本原型检验，不必先达到论文级证明。

### 并行会话会改变研究激励

旧的多线组织容易让每条会话维持自己的目标、候选和 GPU 队列。每条线都能找到一个合理的“下一步”，整体却可能长期没有最值得成稿的主张。

因此，并行的单位应是完整问题。课题负责人可以委派短查新、实现或审查，但必须把结果接回同一个中心主张。已有投入不能换取无限续投；同时，统筹不能把每一步都变成审批，削弱早期主动试验。

### 研究资产有复用价值但不自动有论文价值

冻结负载、ABBA 驱动、归档哈希、轨迹分析和原生适配降低后续成本。工具论文还需要证明目标使用者获得了什么以前难以获得的能力。负结果还需要修正重要认识或排除重要解释。工程修复需要核对契约和影响。

最有价值的组合方式是围绕一个读者问题选择资产。不能因为各线都有数据，就把它们拼成一个“全栈联合优化”故事；当前并没有一个运行过的全栈联合系统支持这种叙述。

## 三个新方向

### R1 容量复用与服务代价

**责任范围。** 统一承接 C/D，判断是否存在可形成完整贡献的容量复用问题；可以组织有意义的表征，也可以实现有依据的方法。已有积累使它的启动成本低，但没有证明它的原创空间最大。

**暂定研究问题。** 在容量安全允许接纳请求时，提前开始带来的等待节省，是否值得它对已有请求产生的服务竞争？什么在线信息能使决定优于合理调优的简单规则和正确近邻？

**先处理服务对象。** 交互流式生成、等待完整回答的作业、触发工具的请求，效用并不相同。当前 C 的探索 goodput 和 D 的固定研究合同可用于分析，不能自动代表三类应用。没有可靠应用 SLO 时，报告分布与性能前沿，保留所有人口和成本。

**需要竞争的解释。** 当前差异可能来自普通批处理取舍、控制或观测开销、生成内容与路由变化、提交节奏、当前简单基线未调优，或新信息确有价值。几项解释可同时成立，无须强行归为唯一原因。

**可选 F/S/M 诊断。** F 使用全额预算；S 计算相同 MC 相关状态但保持 F 的真实放行规则；M 执行普通 MC。若采用原建议的 F/S/M/M/S/F，保留此前 45 分钟首轮上限作为本实验的投资安排，而非所有研究的固定流程。

S 应在分配前记录影子判断，不撤销 barrier，不先分配再回滚；影子许可与真实分配分别计数。F/S 可估计在 F 轨迹附近加入计算路径的影响。S 与 M 后续状态、计算次数、内容和路由可能不同，不能用耗时差精确扣出 GPU 竞争成本。若该区分不会改变下一项方法或贡献决定，就跳过此诊断。

**候选模型的正确用途。** 对当前已到达、未完成集合，可以比较动作下的预计完成时间总和，并纳入新请求进入 decode、旧请求退出、物理页归还和异步依赖。若该集合最终全部完成，未来未完成请求数曲线下面积与其剩余完成时间总和对应；有限窗口必须处理终端残余工作，不能把窗口外任务视为消失。

这个记账关系可指导模型，但不是新算法或理论性能保证。自然 EOS 未知，max_tokens 不能直接当真实剩余长度。先验证动作排序与不确定性，再决定模型复杂度。

**最近邻与强对照。** MC 已处理未来容量峰值；WAIT 属于内存约束下的在线调度；Niyama 已有 QoS 与动态分块；JITServe 面向不精确请求信息和 SLO 分配服务带宽。不能把“考虑完成”“容量与计算联合”或“增加预测字段”直接称空白。参考 [MC 原文](https://arxiv.org/html/2502.07115v5)、[WAIT 原文](https://arxiv.org/html/2504.11320v4)、[Niyama 原文](https://arxiv.org/html/2503.22562v1)、[JITServe 官方论文页](https://www.usenix.org/conference/nsdi26/presentation/zhang-wei)。

方法评价可从普通 MC、MC 加调好的简单并发约束、具有明确新增信息的候选开始；依据主张决定是否需要完整近邻复现或组件适配，并披露覆盖范围。不要让比较集合变成无关方法大全。

**首轮交付。** 一个可修改的中心主张、最强反驳、当前数据能支持的图或表，以及一项实际完成的最小行动。该行动可以是已有数据分析、模型纠错或小原型，不自动要求新 GPU 矩阵。

**后续分支。** 新信息改变有价值动作并改善完整目标，继续方法；重要边界改变读者判断，继续表征；仅重复普通取舍或简单方法已足够，结束独立方法投入并保留毕业论文材料。

### R2 原生异步 KV 生命周期测试

**责任范围。** 检验一种测试能力：保留真实控制逻辑并探索内部合法交错，能否降低真实错误的发现、复现或缩减成本。与 B/E 的日志诊断有关，但属于新课题，现有 AST harness 不是已完成的交错探索器。

**中心假设。** 外部请求压力测试难稳定控制的一些内部顺序，可在保持原生依赖的条件下低成本探索，并生成能够解释和复现的见证。经典系统化交错探索不是新概念；本课题需要在真实 serving 语义、抽象可信度或实际能力上建立增量。[CHESS 官方论文页](https://www.usenix.org/conference/osdi-08/finding-and-reproducing-heisenbugs-concurrent-programs)

**初始实现边界。** 单 worker、一个 KV group、等长 GPU block 与 host chunk。保留原生请求、allocator、connector metadata、flush、等待、完成回收和清理逻辑，只替换模型内容执行与底层传输。可复用 E 原生源码与函数加载经验；若无法保留完整引擎，只声明实际组件边界。

执行器需区分提交、数据完成、worker 返回完成、scheduler ACK。wait 保留真实等待效果，不顺便完成所有上层清理。块内容身份应表示逻辑前缀及位置，物理槽复用另记代际；不同 request ID 共享相同前缀可以合法。

**合法事件探索。** STORE 等待必要模型写入；同方向传输保留原生顺序；跨方向仍遵守内容和资源依赖；完成通知遵守原生回收规则。只选择已使能、满足原生先后依赖的事件；不存在既定先后约束、但执行顺序会影响共享状态的事件，也是探索对象。只有能证明交换不改变使能性和结果时，才按独立事件进行等价剪枝。整块复制原子化可作为初始抽象，但需说明不覆盖块内部分复制。

**第一场景的角色。** A 创建 STORE、A 结束、B 自然复用物理块，可检查原生 pending source、jobs_to_flush 和 wait 是否保留。原实现已有保护，预期安全通过只能算原型可信度检查。不能跳过 wait 让 B 覆写，再把得到的污染称原生 bug。

**尽早完成有用能力。** 原型与真实历史案例查找并行。可信修复前后版本可用于校准探索与缩减；人工删除屏障用于灵敏度，不算真实发现。见证应保存版本、有效配置、外部操作、事件选择、必要依赖、首次违反不变量的位置，并从空系统重放。

**公平比较。** 相同原生代码、事件集合、检查器、初始场景和预算下比较系统探索与随机内部调度，测真实案例发现、稳定复现、缩减成本与误报。若对照的观测与控制能力不同，应把能力差异和搜索收益分开。首次出现真实差异后，再决定是否需要剪枝、更多事件或更多版本。

**最强反驳。** 第一是普通随机调度加相同检查器已经足够；第二是 fake executor 制造了不可达错误，或遗漏了关键设备行为。验证应围绕这些具体反驳开展，而不是事先重写完整 CUDA 模型。

**最近邻。** GRIEF 已对 serving 系统进行时序多请求 fuzzing，并使用检查器与控制重放；LMCache 已有故障注入接口。因此“给 serving 写 fuzz”“注入缓存故障”不是新贡献。[GRIEF 原文](https://arxiv.org/html/2605.11202v1)、[LMCache 故障注入文档](https://docs.lmcache.ai/mp/l2_storage/fault_inject.html)。

**投入与判决。** 原先约两个 CPU 工作日可作为首轮投入复盘点，不要求两天必须找到 bug，也不以五个文件完成作为研究成功。得到真实能力差别后再投入扩大验证。没有发现错误，只能说明已探索范围，不能证明整体安全；只复现作者已知固定脚本，也不足以证明探索能力。

### R3 Agent 工具与 Host KV 主存竞争

**责任范围。** 研究工具进程与推理缓存真实共享主存时的任务损失。及时物理回收是优先假设，不是已经确认的问题。工具远程执行、不共享该主存时，该部署假设不适用。

**本地具体依据。** E 保存的原生 CPU manager 释放 block_id 到内部空闲表，worker 则另持底层 tensor 或 mmap。逻辑 slot 释放与归还底层内存不是同一操作。这是实现事实，尚未证明真实 RSS 下降、pin 状态、工具争用或服务收益。

**三层观测。**

| 层 | 应区分的量 | 能帮助回答的问题 |
| --- | --- | --- |
| 缓存 | 已缓存、可淘汰、在途引用、连续前缀 | 哪些逻辑内容允许删除 |
| 分配器 | 已分配 backing、可归还区域、被引用阻塞的区域、注册状态 | 删除后能否真正释放完整区域 |
| OS 与容器 | memory.current、memory.stat、events、pressure，以及必要进程指标 | 物理资源是否及时归还，工具是否因此改善 |

不能简单相加各进程 RSS；共享页和记账范围必须核对。Mac 可用于源码与离线分析，Linux cgroup、实际固定页与 DMA 行为应在相应环境测量。

**真实工具负载。** 先选可重放的测试、构建或数据处理任务，固定仓库、输入、环境、命令及输出检查，测独立运行的内存和耗时。合理部署预算、模型驻留及工具并发应解释为什么可能接近主存约束。受控限容可以研究边界，但应保留容量充足负控制，不能反复缩到出现收益。

**可选首轮对照。** A 工具独立运行；B 真实缓存驻留加工具；C 同状态逻辑淘汰但不增加额外底层回收；D 在安全边界实际归还内存后执行工具。A 是诊断参考，不是最终方法强基线。比较物理占用下降是否早于工具需求、内存压力是否解释等待，以及重新分配和恢复的代价。

代理 KV 内容只验证内存机制，不能冒充完整 LLM 服务。若底层不支持局部归还，先用最小可行适配判断是否有价值，不重写整个缓存框架。

**值得检验的状态。** 可以考察“在未来一段时间内，某个合法动作能够安全归还多少内存，以及未来恢复要付多少成本”。它可能比逻辑空闲字节更有决策信息。但这一关系目前是研究假设，在线方法不能知道真实未来工具峰值或结束时间。

如果少量长寿命引用阻塞很多可回收空间，可考虑区域组织；如果回收生效太晚，可利用当前可见的工具调用阶段；如果同样释放量的恢复成本差别大，可比较有依据的淘汰。一次只增加为解释所需的机制，不同时开发预测器、内存布局和全局调度器。

**强简单方法。** 合理固定 host pool 与依据当前可用内存或压力动态收缩的 pool 都应进入比较。简单方法已覆盖损失时，接受工程结果。物理回收有效但重算与恢复抵消收益时，保留完整取舍，不继续只优化工具耗时。

**最近邻压力。** AgentCgroup 已研究工具驱动的 OS 资源动态；MARS 已协调 GPU 推理和 CPU 工具、准入与 KV 保留；MORI 已考虑工具阶段与两层内存；EfficientAgent 已研究 host 工作集与写入策略。LMCache 的 MP 配置已支持 lazy allocation，按需分配不是新机制。配置文档不能单独证明所有版本已经实现及时物理收缩。[AgentCgroup](https://arxiv.org/html/2602.09345)、[MARS](https://arxiv.org/html/2604.26963)、[MORI](https://arxiv.org/html/2606.00866)、[EfficientAgent](https://arxiv.org/html/2609.33762)、[LMCache 配置](https://docs.lmcache.ai/mp/configuration.html)。

**完整评价。** 保持初始任务、资源和质量要求一致，实际执行工具，允许策略改变后续时间与缓存轨迹。报告任务完成、尾部、失败与重试、必要任务质量、重算、LOAD/STORE、物理占用、回收与重新注册成本。固定 sleep 无法验证真实内存反馈。

**投入与判决。** CPU 机会检查与小干预优先；原先一小时单卡比较只是条件成立后的首轮投资建议。若真实问题不重要，结束当前部署假设；若出现简单方法难区分的状态且候选改善完整目标，再扩展独立条件。R3 不依赖 R2 的测试框架完成。

推荐结构是三个课题负责人会话，加上当前已有统筹会话，合计四个入口。这个数量是基于当前资源与课题成熟度的组织选择，不是长期普遍规则。

第一轮三个课题可并行做独立 CPU 工作。之后依据实证把持续预算集中在最有价值的一至两条，其余保留当前状态与重新投入条件。不要因为开了三个会话就承诺三篇论文，也不要把所有机会按同一 GPU 时间平均分配。

R1 的优势是资产丰富，R2 的优势是可先用 CPU 检验新能力，R3 的优势是可能接触不同部署约束。三者也分别面临已有原则覆盖、工具增量不足、实际问题不成立的风险。组织需要容纳这些不同失败方式。

### 临时分工与课题责任

查新、数值核查、局部实现和独立审查可以委派，但每个短任务应有明确输入、交付、修改范围和结束条件。例如“核对某个近邻是否已有相同动作，给原文段落与源码入口”，比“持续查新”更有用。

课题负责人仍负责把这些结果接回中心主张。不要长期分别设立查新会话、实验会话和写作会话，让完整责任被拆散。独立审查既应找错误，也应指出仍值得尝试的方案；不能只增加否定意见和前置条件。

旧 A—G/M 会话保留为证据入口。需要一次结果回收或局部分析时，给明确短任务，不恢复它们各自的无限研究队列。本建议不执行进程终止、不取消既有任务，也不修改历史目标状态。

### 复盘触发条件

复盘优先由有意义的事件触发：原型产生真实动作、强简单方法覆盖收益、新近邻改变差异判断、重要反例出现、预算到达、或已有证据足以写作。

一次复盘只需要判断：

1. 哪项新信息改变了对问题、模型或方法的判断。
2. 下一项行动如何推进完整贡献，最可能推翻它的解释是什么。
3. 继续当前候选、调整方案、暂存还是改变跨线优先级。

不必固定每天重写所有表格。预算耗尽可以得到“尚未确定”；简单方法获胜可以得到工程结论；一个候选失败不代表整体科研目标已完成，也不意味着必须立即找一个新阈值继续。

## 资源安排与设备迁移

### GPU 实验组织

共享单卡时，一次只推进一项完整实验组，遵守既有锁与配额。CPU 实现和分析可以并行，但不让每个会话都建立长期持有或争抢资源的后台等待队列。

每项昂贵工作应明确：将改变的研究决定、最小比较、初始化与预热、测量与排空、最坏占用、结果回收方式和无效条件。预算内常规执行不逐次请求确认；真实资源上限、对外上传和发布边界仍按实际授权处理。

连接中断后先识别原 session、进程与 receipt，再决定回收或重试。文档排队状态不能替代现场检查；瞬时 GPU 空闲也不能证明另一组已经完成。B 最大 donor 和 E default r02 是当前最需注意的两项历史状态。

磁盘、/dev/shm、CPU RAM、固定页、模型缓存、编译目录及原始结果回收都可能影响实验。只有在具体任务需要时检查，不把完整环境审计变成每个小修改的前置流程。

### PRO 6000 与 5090

已有 PRO 6000 与 5090 结果处于不同实际预算和执行域。C 的 64 GiB GPU KV 合同无法原样放入 M 记录的 32 GiB 5090 域，因此迁移不是仅改设备名。应核对权重、KV、graph、workspace、host pool 与实际可用页，并重新确定可执行配置。

更小预算可能使容量问题更活跃，也可能让原模型假设失效。不能预先断言换 5090 更适合发表，或者保留 PRO 6000 必然更好。选择取决于待验证的机制、所需容量、实验成本和可复现性；需要价格比较时应另查当时实际报价。

若迁移，先做最小运行资格与当地波动检查，记录软件、编译和计时边界。旧硬件的 A/A 极差或所谓噪声地板不能迁移，也不能把两台设备的绝对时延拼成方法对照。

### 投入上限与科学判据

45 分钟 F/S/M、两个 CPU 工作日工具原型、一小时 R3 单卡比较，均是此前针对首轮建议的投资上限。它们不是“到时必须得出正负结论”的科学规则。

预算结束后可能有三种合理结果：关键未知已解、得到明确新信息值得追加、或证据仍不足而暂存。不能为得到显著性无限追加，也不能因预算到达就把未运行或不确定写成方法失败。

## 论文与毕业设计的组织建议

### 现有材料如何形成毕业设计

毕业设计可以围绕“原生推理运行时中资源决策的有效性与边界”组织，而不要求八条线各自成为一项创新。一个可行的论证顺序是：

1. 平台、运行域、测量边界和完整成本方法。
2. 容量与执行预算的服务取舍，使用 C/D 的真实结果。
3. 抢占恢复与缓存生命周期，使用 A/B/E 的可追溯事件及工具。
4. MoE 专家搬运与推测的成本耦合，使用 M 的阶段记账和边界。
5. 评价口径与适用范围，选用 F 的群体损益和 G 的容量界。
6. 若新 R1/R2/R3 获得支持，将其作为明确的新贡献章节，并解释与已有研究的关系。

章节可以按实际中心主张合并删减。不要把 C、D 的不同工作负载或 B/E 的不同观察字段强行统一成不存在的同一实验，也不要将八条线包装为一个已实现的全栈调度系统。

### 独立投稿需要满足什么

| 投稿内容 | 有说服力的中心 | 当前仍需要的证据 |
| --- | --- | --- |
| 系统方法 | 具体约束下，已有方法未表达的信息或动作带来完整价值 | 方法增量、正确近邻、完整成本和适用边界 |
| 表征与复现 | 重要结论或常用做法在明确条件下应被修正，并给出可用解释 | 新知识的重要性、比较范围、可信因果或预测检验 |
| 工具与测试 | 目标使用者获得更有效的发现、复现、缩减或分析能力 | 真实案例、公平对照、误报与成本、可使用实现 |
| 工程行为报告 | 某版本的实际行为、契约、影响与可复现修复 | 契约核对、最小复现、修改代价 |

Workshop、CCF C 或 CCF B 的目标可以影响篇幅、评估广度和受众选择，但不能预定结论。当前不能给出可靠录用概率；也没有必要因尚未形成原创方法，就否定已有结果对毕业设计的价值。

投稿前应按当时实际 CFP 核对范围、类型和截止时间。旧讨论中的日期与工具轨道安排不是本快照已确认的投稿承诺。开源或上游提交还需要整理代码身份、依赖、许可与可公开数据；保存源码与提出 issue 建议不等于已经发布。

### 值得保持的态度

对已有工程与诊断能力可以有信心，对具体论文主张保持可检验的怀疑。当前最可行的进步，不是把每个负结果重新命名，而是用这些资产更快区分重要机会，并让获得支持的机会得到完整实现和写作资源。

新的组织方式只能减少浪费，不能制造不存在的优化空间。三条新方向如果都被强证据收束，也应诚实接受，并据此选择真正不同的问题；如果其中一条显示出明确机会，就及时集中投入，而不是继续维持所有线的均衡活跃。
