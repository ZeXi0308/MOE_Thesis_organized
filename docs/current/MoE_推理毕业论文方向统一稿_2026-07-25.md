## 0. 合并裁决

### 0.1 当前唯一科学任务

当前没有已经被正式实验确认的 MoE 系统主机制。现阶段只推进一条证伪链：

> **在自然连续到达、exact model semantics 和固定 expert replica set 下，先验证路由后的 expert work 是否因 replica fragmentation、小 GEMM、排队和 request fork-join 形成足够大的暴露关键路径；只有现象、exact Oracle 和强简单基线 residual 跨模型成立，才实现最小在线机制。**

第一顺位的待证伪 formulation 是：

> **BCRD-SC：Service-Curve-Aware Batch-Conscious Replica Dispatch。**  
> 在 logical top-k 和 expert identity 已确定后，只决定 contribution 分给哪个等价 physical replica，以及最多等待多久封批；用实测非线性 expert service curve、remote cost、queue 和 request slack 预测 completion，而不是把 token 数均衡、激活副本数或 receiver bytes 当作最终目标。

BCRD-SC 是当前**首个证伪分支**，不是已经选定的论文方法。共同现象 Gate 通过前，不实现完整 controller，不承诺多卡收益。

### 0.2 分支顺序

```text
Gate 0：正式证据资格
  -> Gate 1：共同自然现象与完整 denominator
       -> BCRD-specific fragmentation 过门
            -> BCRD-SC exact Oracle
       -> BCRD-specific 不过门，但 broader expert-pressure/HoL 独立过门
            -> 先做 DEPA prior-art/action-space 收缩审计
            -> DEPA exact SLO-goodput Oracle
       -> 两者均不过门
            -> 停止 expert-pressure 系统线
  -> Gate 3：强简单策略 residual
       -> 仅通过后授予 8×A100 Candidate
```

一次只允许进入一个 Oracle 分支。BCRD-SC、DEPA、Receiver controller 不并行调参竞争。

### 0.3 Receiver-Awareness 的最终位置

Receiver-Awareness 不再是论文核心，也不再扩大成“大一统 runtime-state-aware controller”。

- 原始 Gate-Aware Partial Combine：历史 proposal、motivation 和 quality/byte ablation；
- PhaseMap、FJRC、fixed RankLane：负结果与 baseline；
- receiver queue、remote cost、join pressure：只有在已证实 action space 中才可作为可删除特征；
- optimized return path 是否仍是大瓶颈：单独留给真实 8×A100 existence Gate；
- 在 existence Gate 前：不实现新的 RankLane codec/controller。

核心纪律是：

> receiver 信息存在，不等于 receiver 信息有增量 action value；动作改变，也不等于 request completion 改变。

## 2. 原始方案 A：保留什么，停止什么

### 2.1 原始问题

原始方案研究的是一个质量预算下的 Combine 返回流量削减问题：

\[
y_t=\sum_{e\in S(t)}g_{t,e}o_{t,e}.
\]

它希望根据 `(layer, receiver_group, gate_bucket)` 选择 `BF16/FP8/INT4/drop`，减少热点 receiver 的返回字节，并把收益映射到 queueing/TBT。

原方案包含三条必须分别验证的假设：

1. **结构假设：** Combine 中独立 expert output 和 gate 已知，适合 contribution-level 差分表示；
2. **质量假设：** top-k 内 contribution importance 足够长尾，且 uniform low precision 既不完全支配，也不完全不可用；
3. **系统假设：** optimized backend 下的 Combine return 是足够大的、未被 overlap 隐藏的暴露关键路径。

### 2.2 导师建议的统一解释

导师建议的核心不是认可 `receiver-group + ILP + LUT`，而是要求正确的科学顺序：

| 建议 | 研究含义 |
|---|---|
| 先看 receiver port，不先建完整 spine/leaf/link | 缩小因果边界，先证明真实瓶颈 |
| 先量总体质量损失，再拆 routing drift | 先测 effect size，不让解释性 proxy 替代终点 |
| 先验证 top-k contribution tail | expert-level skew 不能代替 token 内结构 |
| 简化 LUT key | 在线状态必须低维、因果可得、可部署 |
| precision 使用 one-hot 变量 | action 与优化变量必须一一对应 |
| accuracy constraint 绑定离线 profile | 约束来源必须可追溯、可执行 |
| bytes 必须映射到 TBT | 逻辑字节下降不能直接写成 serving 收益 |

### 2.3 仍可继承的研究习惯

- Combine 是进行 output-sensitive representation 的自然位置之一；
- 质量、通信、runtime cost 和完整 denominator 必须在同一收益链闭合；
- 先测上界，再授权机制，最后做系统；
- uniform low precision、简单静态策略和 future-known Oracle 都必须作为对照。

### 2.4 必须纠正的旧表述

1. **“Combine 是唯一能做 gate-aware 差分的位置”过强。**  
   更准确的说法是：Combine 是自然位置之一；Dispatch 也能做差分表示，只是可能引入重复量化、layout 和 nonlinear expert error。

2. **`max receiver bytes` 不是 TBT。**  
   只有被减少的传输处在未隐藏的关键路径，且 codec、metadata、layout、message count 和新瓶颈迁移都被计费，逻辑字节才可能转成 TPOT/P99。

3. **per-layer accuracy profile 不是严格可加上界。**  
   局部独占扰动不能直接证明多层联合策略安全；质量结论必须来自冻结策略的 held-out end-to-end evaluation。

4. **静态 receiver group 不等于在线 receiver queue。**  
   Combine 的 sender 是 expert-owner rank，receiver 是 token-origin rank；按 `expert_id` 或离线热度构造的 group 不能替代真实 endpoint、queue 和 completion。

5. **BF16 不是足够强的 return baseline。**  
   任何差分表示都至少要相对 uniform FP8 或目标硬件/后端公平支持的强低精度路径计算增量。

### 2.5 原方案的当前结论

原始 static receiver-group + partial combine 停止作为论文主线。它只保留为：

- 研究演进和导师反馈的历史来源；
- contribution quality/byte characterization；
- uniform precision、static LUT 和 Oracle 的 baseline；
- “局部 actuator 为什么受 Amdahl ceiling 限制”的反例。

## 3. 当前证据账本

### 3.1 已有窄结论

| 对象 | 状态 | 允许结论 | 禁止外推 |
|---|---|---|---|
| Rank-tail matched-byte 结构 | `[Observed / structural only]` | 两模型存在 gate-rank 相关质量敏感度差异，可作 motivation | 不能写成端到端通信、TPOT 或 P99 改善 |
| RTX 5090 LUT/codec 微基准 | `[Observed / single GPU]` | 单卡串行 primitive 或 connected codec 的局部时延 | 不能写成 NCCL、RDMA、incast、多卡 EP 或 serving 结果 |
| FJRC corrected replay | `[Observed / NO-GO]` | keyed Join-Deficit bitmap 未过跨模型主门 | 不否定所有 receiver-aware scheduling |
| PhaseMap closed-pair | `[Observed / BLOCKED_UNINFORMATIVE_DEADLINE_GRID]`；`holdout_opened=false` | 封闭双请求、work-conserving reorder 中 receiver queue/join 没有增量 action headroom | 不得扩 κ、换阈值、按模型调参或查看 holdout 抢救 |
| fixed RankLane | `[Observed / NO-GO in frozen domain]` | 在 `p_return≤20%` 且所有执行税为零的最乐观域内，相对 uniform FP8 的 E2E 上界为 4.1667% | 不等于真实 8×A100 optimized return path 已测或普遍不存在 |

RankLane 的条件上界为：

\[
G(c\mid b)=\frac{p(s_c-s_b)}{1-p s_b}.
\]

取 uniform FP8 的 `s_b=0.5`、RankLane 的 `s_c=0.6875`、`p=0.2`：

\[
G=\frac{0.2(0.6875-0.5)}{1-0.2\times0.5}=4.1667\%.
\]

仅凭该 actuator 越过 5%，至少要求原始暴露 return fraction：

\[
p_{return}\ge23.5294\%.
\]

### 3.2 尚未形成科学结论

| 对象 | 当前资产 | 缺口 | 标签 |
|---|---|---|---|
| BCRD/BCRD-SC | 三门 Gate、harness、identity/oracle/causality 测试和设计稿 | native continuous-decode routes、正式 5090 service surface、完整 denominator、正式 Gate 结果 | `DESIGNED_AND_IMPLEMENTED / NOT_FORMALLY_RUN` |
| DEPA | 因果 CPU replay、request ledger、小规模 exact Oracle、三门 runner | formal capability、正式 breakdown/episodes/surface、prior-art/action-space 收缩 | `DEVELOPMENT_ONLY_NOT_SCIENTIFIC` |
| optimized EP return-path existence | 8×A100 Gate 设计 | 真实 optimized backend、transport/timeline/identity/accounting | `NOT_TESTED_REQUIRES_8XA100` |

当前不得写：

- “BCRD 已证明有 10% 以上空间”；
- “DEPA 比 BCRD 更优”；
- “5090 virtual replicas 证明多卡 EP”；
- “真实 receiver incast 已存在”；
- “8×A100 会复现单卡 service curve 收益”。

## 4. 问题地图与当前空白

### 4.1 端到端依赖

```text
arrival / prompt / phase / SLO
  -> admission and continuous batching
  -> router produces logical top-k experts
  -> placement/replicas define legal physical destinations
  -> contribution-to-replica assignment
  -> dispatch layout and A2A
  -> per-replica rows, GEMM and execution queue
  -> combine and request fork-join
  -> next layer / next decode step

HBM(KV + weights + replicas + EP workspace) limits admission and replicas
topology and transport alter remote service
prefill/decode alter the rows-to-service regime
```

关键点是：每层/请求完成时间是 fork-join max 或 DAG longest path，不是总 token 数、总字节或平均 rank load。

### 4.2 已被强工作覆盖的动作

- EP primitive、融合、分层 A2A、low-latency/high-throughput path；
- 慢时标 expert placement、replication、migration 和 EPLB；
- token count load balance、activated-expert consolidation；
- per-expert queue、异步 rebatching、persistent expert execution；
- request/KV/prefill/backend-pressure 联合调度；
- quality-changing expert drop、reroute、sharing 和 mixed precision；
- generic KV/expert/offload/HBM portfolio；
- phase-aware disaggregation 和异构 parallel plan。

因此不能把“已有模块的并集”写成创新。新动作必须说明相对最接近系统的独立 residual。

### 4.3 当前唯一值得先验证的窄空白

`[Hypothesis]`

> placement 给定后、kernel 执行前，fixed exact replicas 内的 per-wave contribution assignment 同时改变 remote traffic、replica queue、GEMM rows、weight reads 和 request fork-join。实测 service curve 与 deadline 可能在 token spreading 和 expert consolidation 两个极端之间留下稳定 residual。

这个空白可能真实，也可能只是收益太小：

- 大 batch 或强 grouped/persistent kernel 可能使 service curve接近线性；
- LPLB-like token balance 可能已经足够；
- METRO-like activated-replica minimization可能已经足够；
- remote communication、seal wait、global state 和 decision overhead 可能吃掉 gross gain；
- replicas 太少或 HBM 预算不足时 action space 消失。

所以当前授权的是 existence/Oracle Gate，不是 controller。

### 5.1 换题候选，不是自动 Top 2/Top 3

Guarded Expert Reuse 和 BufferLease-MoE 只作为 expert-pressure 线停止后的**新研究问题备案**：

- **Guarded Expert Reuse：** 先做 opportunity/error/break-even Gate；安全 accept rate `<5%` 或任务质量尾界失败即停止；
- **BufferLease-MoE：** 只有真实 EP backend census 显示 workspace 占 HBM `≥10%` 且可安全借出时间 `≥30%` 才开题。

它们不能与共同 Gate 1 并行推进，也不能在 BCRD/DEPA Gate 失败后无审计地自动接棒。

## 6. BCRD-SC 的统一规格

### 6.1 研究边界

固定：

- model weights、router、top-k、logical expert identity；
- exact replica set 与 placement；
- dtype、optimized communication/backend；
- evaluation arrival trace、SLO 和外围 batch budget。

可控：

- 每个 routed contribution 的合法 replica；
- 每个 `(expert, replica)` microqueue 的 bounded seal time；
- 状态异常时的 deterministic fail-closed fallback。

首版不控制：

- replica 创建、删除、迁移；
- top-k、expert drop/reroute、近似输出；
- collective kernel；
- KV allocator、DVFS、P/D placement。

### 6.2 形式化

对 contribution `i`：

- `e(i)`：logical expert；
- `q(i)`：所属 request；
- `a_i`：ready time；
- `d_i`：由 request slack 下推的局部 deadline；
- `R_e`：expert `e` 的 exact replicas；
- `x_{i,r}∈{0,1}`：选择 replica `r`；
- `h_{e,r}`：microqueue seal time；
- `F_{e,r}(n,phase,dtype)`：在目标 GPU/后端实测的 rows→service curve；
- `C(src_i,r,bytes_i)`：真实多卡阶段测得的通信成本。

唯一合法 assignment：

\[
\sum_{r\in R_{e(i)}}x_{i,r}=1.
\]

预测完成：

\[
\widehat f_i=
h_{e(i),r}
+C(src_i,r,bytes_i)
+Q_r
+F_{e(i),r}(n_{e(i),r})
+J_{q(i)}.
\]

其中 `Q_r` 是 committed queue，`J_q` 是其余 contribution 的 join/remaining-path estimate。目标以 SLO-goodput/request completion 为主：

\[
\max_{x,h}
\sum_q w_q\mathbf 1[\max_{i:q(i)=q}\widehat f_i\le D_q]
-\lambda B_{remote}
-\mu O_{decision}
-\eta T_{seal}.
\]

约束包括 exact identity、message/rows conservation、deadline-safe hold、queue stability、固定 HBM/replica budget、因果信息和 measured-range-only service lookup。

### 6.3 在线机制

对每个 contribution 枚举合法 replicas，计算：

\[
score(i,r)=
\widehat{deadline\ risk}(i,r)
+\alpha\,remote(i,r)
-\beta\,batching\ credit(i,r)
+\gamma\,join\ risk(i,r)
+\delta\,fairness(i,r).
\]

其中：

\[
batching\ credit=
F(n_r)+F(rows_i)-F(n_r+rows_i).
\]

只有当 credit 大于 queue/deadline risk 时短暂等待；达到 rows threshold、最早 deadline、`H_max` 或 GPU idle 条件时立即 seal。

任一情况触发 fallback：

- service lookup 越界；
- replica/weight revision 不一致；
- queue state 缺失或过旧；
- decision P99 超预算；
- message/rows/identity ledger 异常。

在线复杂度应保持 `O(N·R_max)`；不在热路径求 MILP。future-known exact Oracle 只用于小窗口上界，不能伪装成在线算法。

### 6.4 与最接近工作的区别必须落在 residual

| 强基线/近邻 | 已覆盖 | BCRD-SC 必须额外证明 |
|---|---|---|
| LPLB-like | 当前 batch 的 token/rank balance | token count 不能代表 nonlinear service，deadline-aware decision 有稳定 residual |
| METRO-like | memory-bound regime 下减少 activated replicas | consolidation 不是所有 regime 的统一最优 |
| AMoE/QLLM | per-expert queue、异步/rebatch | 固定 replicas 上的窄 assignment+seal 仍有独立空间 |
| ExpertPlex/persistent kernel | tile/expert compute 动态执行 | 上游 work formation 的 residual 未被 kernel 吃掉 |
| Gimbal | request/KV/prefill/backend pressure | 不做通用 frontend/placement，只优化 post-routing exact assignment |
| EPLB/HCRMap/Director | placement、residency、replica mapping | replica set 固定；不把慢时标 placement 当贡献 |

若全文 claim matrix 发现已有工作同时覆盖 exact replicas、per-wave assignment、bounded seal、nonlinear service 和 request fork-join/deadline，BCRD-SC 立即停止。

## 7. 单张 RTX 5090：三道串行 Gate

### 7.1 5090 能回答和不能回答的问题

能回答：

- natural routes 是否产生 rows fragmentation；
- 目标 expert kernel 的 rows→service 是否显著非线性；
- exact Oracle 和强简单策略之间是否存在逻辑/实测 service residual；
- 策略计算开销、accounting 和 service-model robustness。

不能回答：

- NCCL/DeepEP/RDMA/NVLink A2A；
- temporal incast；
- 多 rank fork-join TPOT/P99；
- A100 service curve；
- physical replicas、remote HBM/traffic 和多节点 scaling。

### 7.2 Gate 0：正式资格

必须同时具备：

1. 两模型 native continuous-decode route producer；
2. RTX 5090 原生 expert/grouped path 的实测 service surface；
3. identity-complete、exact-output replay；
4. 冻结 model/workload/revision/seed/arrival manifest；
5. 与目标 accounting boundary 一致、独立测量的 full-path denominator。

缺任一项输出 `BLOCKED_MISSING_FORMAL_EVIDENCE`。smoke、静态 prompt forward、synthetic fixture 或预期 saving 不能补位。

### 7.3 Gate 1：共同自然现象

复用 OLMoE 与 LLM-jp 两种 routing regime；每模型至少采 128 个 fresh requests 的逐 decode-step identity。service surface 每个公共 rows cell：

- 20 次 warmup；
- 至少 200 个原始 CUDA Event samples；
- 保存原始分布、P50/P95/P99/mean/std 和 bootstrap CI；
- 仅在实测 rows 区间内保守插值，区间外 fail closed。

同一冻结证据同时报告：

**BCRD-specific fragmentation**

- common natural cell point estimate `≥10%`；
- 95% LCB `>5%`；
- 至少一个 common cell 两模型均 `≥15%`；
- actionable waves `≥20%`。

**broader expert-pressure**

- 去重后的 fragmentation + route-conditioned straggler + HoL exposed share point estimate `≥20%`；
- 95% LCB `≥10%`。

统一停止：

- 所有共同自然 cell `<5%`；
- actionability `<20%`；
- 只在 synthetic skew、单模型、单层或极端 virtual replicas 通过；
- denominator、identity、rows 或 request ledger 不闭合。

`5%–10%` 只允许降级为 measurement/kernel 结果，不授权 controller。

### 7.4 Gate 2：只运行一个 exact Oracle

若 BCRD-specific 过门：

- 在冻结 trace 上求 bounded-window assignment+seal exact Oracle；
- conservative remote-cost 档为主要裁决，zero-cost 只作上界；
- common natural cells Oracle point estimate `≥15%`、95% LCB `>10%`；
- 保守成本后净空间 `≥10%`；
- action flips `≥20%`；
- 不依赖无限等待、future-unbounded batching 或 service 外推。

若 BCRD-specific 不过门但 broader pressure 过门：

- 先完成 DEPA 与 Gimbal/QLLM/AMoE/EDF/least-laxity 的 action-level 边界；
- 再定义一次性、因果可实现的 small exact SLO-goodput Oracle；
- 不允许用未来 route 作为在线可用信息。

统一判死：

- conservative Oracle `<10%`；
- 只有 zero remote cost 才通过；
- Oracle 与 min-finish/EDF/least-laxity 动作等价；
- 主要收益来自未来信息、无限等待或选择性 workload。

### 7.5 Gate 3：强简单策略残差

冻结比较：

1. framework default/static mapping；
2. deterministic random；
3. hash/least-load/local-first；
4. LPLB-like token balance；
5. METRO-like activated-replica minimization；
6. fixed threshold；
7. earliest/min-predicted-finish；
8. EDF/least-laxity；
9. chosen proposed policy；
10. future-known exact Oracle。

进入 8×A100 前，chosen policy 至少需要：

- 总净收益 `≥10%`；
- 捕获 `≥70%` Oracle；
- 比 best simple baseline 高 `≥3` 个百分点；
- best simple baseline 未捕获 `≥90%` Oracle；
- decision + queue tax `≤20%` gross gain；
- P99 不恶化超过 `2%`，无 starvation、identity 或 exactness 问题；
- 两模型同方向。

若 best simple 捕获 `≥90%` Oracle，取消复杂 controller；`90%–95%` 区间最多实现透明简单策略，不包装复杂算法。

### 7.6 防止单卡 replay 自证

- route 必须来自真实模型和自然 workload；
- service 必须来自真实 5090 kernel；
- consolidated/fragmented 使用同一 total work、output 和 kernel family；
- virtual replicas/streams 只做逻辑必要条件，不写成物理 GPU；
- synthetic skew 只作 sensitivity；
- Oracle 与 online 信息严格隔离；
- calibration/evaluation 文档和阈值隔离；
- 两模型 AND，公开负 cell；
- 单卡 PASS 最高只授予 `8×A100 Candidate`。

## 8. 8×A100 正式路径

### 8.1 先确认“8×A100”是哪种系统

必须记录：

- A100 PCIe/SXM、40/80GB；
- 单机 8 卡还是 2×4 跨节点；
- NVLink/NVSwitch/P2P matrix；
- NIC、速率、NUMA、GPUDirect RDMA；
- NCCL transport/fallback；
- CUDA、driver、NCCL、SGLang/vLLM、DeepEP/backend revision；
- clocks/power policy。

单机 NVSwitch 与跨节点 IB/RoCE 不能混成同一 topology claim。

### 8.2 分阶段扩展

1. **2 GPU correctness：** replica revision、assignment、dispatch/combine conservation、output equality、fallback；
2. **4 GPU topology smoke：** real local/remote cost、queue/timeline、grouped GEMM、policy overhead；
3. **8 GPU formal：** optimized EP backend、fixed replicas、natural continuous serving、request ledger、TPOT/TTFT/SLO-goodput 和完整 timeline。

### 8.3 必要模块

- serving frontend 与 continuous scheduler；
- native route producer；
- exact replica deployment/verification；
- pluggable physical assignment hook；
- per-replica microqueue 与 bounded seal；
- 与 baseline 相同的 optimized A2A/grouped expert executor；
- request/layer fork-join ledger；
- topology/queue/service telemetry；
- no-op policy 零侵入税检查；
- calibration、fallback、evidence manifest 和机器可读 verdict。

### 8.4 公平比较

所有策略共享：

- model revision、weights、tokenizer、router/top-k、dtype；
- fixed replica map、HBM 和 batch budget；
- arrival trace、sampling、SLO；
- communication backend、kernel、fusion/overlap；
- warmup、autotune、clock/power；
- calibration/evaluation split。

只允许 assignment/seal policy 不同。不得关闭 baseline overlap、插入 sleep/barrier、给候选更强 kernel，或把 5090/Hopper 的 FP8 路径外推为 A100 结果。

### 8.5 正式成立标准

最低要求：

- 至少两个不同 routing regime 的开放 MoE；
- 多个自然负载 cell 和至少三个独立 arrival traces/seeds；
- optimized backend 下的 exposed fragmentation 与 conservative Oracle 仍过门；
- 相对 best strong baseline，两个模型在 SLO knee 附近均有稳定净收益；
- 目标优先为 `≥10%` SLO-goodput；若只报告 latency，则需要有统计支持的 `≥5%` E2E/TPOT 改善；
- policy/measurement/synchronization tax不超过 gross gain 的 20%；
- P99、fairness、HBM、remote traffic、fallback 和 exactness 全部报告；
- 收益不依赖 synthetic skew、关闭 overlap、慢链路或不公平 kernel。

### 8.6 多卡立即判死

- optimized baseline 下 exposed fragmentation `<5%`；
- conservative Oracle `<10%`；
- best simple baseline 捕获 `≥90%` Oracle；
- remote communication、seal wait 或 controller state同步抹平 batching credit；
- replica HBM 使可服务 batch/capacity 显著下降；
- P99/fairness 恶化或第二模型不复现；
- 只在单一 topology 或 synthetic extreme 成立；
- 最新全文审计发现同 action/state/objective 已被覆盖。

停止后不得通过动态 placement、quality approximation、多节点或更大 controller 扩 action space抢救。

## 9. DEPA 的条件边界

DEPA 只在以下组合成立时复审：

1. BCRD-specific fragmentation 未过门；
2. broader expert-pressure/HoL point estimate `≥20%`、95% LCB `≥10%`；
3. admission/defer 能改变工作集合，而非只在守恒 workload 内重排；
4. exact Oracle 相对 EDF/least-laxity/queue threshold 有 `≥10%` 净空间；
5. 能明确区别 Gimbal、QLLM、AMoE 等已有 action。

DEPA 的在线信息只能包含历史/当前 route signature、KV、prefill、queue、deadline/slack 和 committed work；future route、future arrivals 只允许给 Oracle。

低负载下 DEPA 的理论空间应自然归零。若收益只来自人工 overload、牺牲 fairness、未来 route 或“拒绝更多请求”，方向停止。

---

## 10. 论文叙事与证据边界

### 10.1 若 BCRD-SC 最终成立

论文可形成四段闭环：

1. **Characterization：** natural route 下的 replica fragmentation、service nonlinearity 和 fork-join exposed loss；
2. **Model/Oracle：** exact replica assignment + bounded seal 的 completion-time 模型和上界；
3. **Mechanism：** causal、低开销、fail-closed 的 BCRD-SC；
4. **System：** optimized 8×A100 EP 上相对 LPLB/METRO/min-finish 等强基线的 SLO-goodput/TPOT/P99。

可用题目：

> **Beyond Token Balance: Service-Curve-Aware Replica Dispatch for SLO-Critical MoE Serving**

### 10.2 若只通过现象、不通过复杂策略

- Oracle 小：写成负结果/measurement，不造 controller；
- 简单策略捕获 ≥90% Oracle：只实现和解释简单策略；
- 局部收益 5%–10%：降为 kernel/engineering thesis，不宣称通用系统创新；
- 多卡 residual 消失：报告 optimized backend 吃掉单卡机会，不用弱 baseline 复活。

### 10.3 一句话答辩版本

> 我不再把 Receiver-Awareness 当作主创新，因为现有负结果和 Amdahl 上界表明局部 return actuator 的空间不足。当前先验证固定精确副本集内的 route fragmentation 是否因破坏 expert batching 而形成可观关键路径；只有真实 route、真实 expert kernel、exact Oracle 和强简单基线连续过门，才在 8×A100 optimized EP 上实现 service-curve-aware assignment 与 bounded sealing。

## 11. 当前最短执行清单

1. 不再生成新的 Top 3/唯一主攻文档；
2. 统一 BCRD/DEPA 输入 schema、manifest 和 accounting boundary；
3. 补齐 Gate 0 的五项正式资格；
4. 只运行共同 Gate 1；
5. 根据现象来源选择一个 Oracle 分支；
6. Gate 失败就记录窄负结果并停止，不改阈值、模型池、指标或 workload 抢救；
7. 单卡三门通过后才进入 2/4/8 GPU；
8. 新 formal result 必须同步更新 [当前研究状态](README.md)和对应 idea README。

## 12. 最终结论

> **当前唯一值得做的不是继续扩展 Receiver-Awareness，也不是立即实现 BCRD-SC；而是用两模型自然 continuous decode、真实 5090 expert service、完整 denominator 和冻结 Gate，证明 fixed-replica fragmentation 是否真的是一个可操作的大问题。证明后只做最小 assignment+seal 系统，证明不了就干净停止。**

## 13. 2026-07-26 RouteGuard-KV 候选补充

2026-07-26 的全空间重探索提出了 RouteGuard-KV：验证 KV-cache 量化是否通过 router-input 扰动引发 top-k/gate 漂移，并据此做逐层 K/V 精度分配。

该候选已完成一轮严格复审，当前登记为：

> `GPU_SMOKE_INTEGRITY_PASS / CALIBRATION_NOT_RUN / KILL_PROBE_ONLY / NOT_CURRENT_MAINLINE`

2026-07-27 在单张 RTX 5090 上完成冻结 engineering smoke v2：50/50条 trajectory、identity/patched/route-lock/quantizer-ledger 负控和完整性全部 PASS，peak allocated/reserved 为 `13.834/14.027 GiB`。K-only@2048 的2文档方向性 router share 为 `47.56%`，但 non-tie flips 占全部 flips 为 `89.37%`，略低于预注册 `90%` 门。该 smoke 只授权进入8文档 calibration，不构成 R0-A 科学 PASS，也不改变当前唯一主线。

它不改变本文和[当前状态](README.md)规定的唯一执行顺序，也不恢复已在冻结域内 NO-GO 的 fixed RankLane。其剩余可能新意被收窄为：

1. 既有 pretrained sparse-MoE 上的 post-training `KV quantization → route drift → quality loss` 因果链；
2. 明确定义的 `free / set-locked / fully-locked` counterfactual 分解；
3. route-drift signal 相对 KVTuner-style attention error 和 skip-sensitive-layers 简单策略的增量价值。

原方案中的 MoE/dense `ΔKL` 比值不再作为主因果门；统一 KV 档的 engine 压测也不能替代逐层 RouteGuard 表的系统验证。只有最小 R0-A 证明 router-mediated effect、R1 证明跨模型分配增量、R2 在 optimized engine 中执行同一张 sealed 表并相对 best deployable simple baseline 获得净系统收益，才允许形成完整机制主张。
