# MoE 系统 / AI Infra 新选题地图（2026-07-13）

> 目标：不再把“已有工作多”当作否决条件，而是判断在成熟问题中是否还能提出不可被现有 baseline 吸收的新机制。本文是候选池，不立即覆盖 `PDF论文的选择.md` 或当前 Idea A 主线。

> **2026-07-13 严格复核后的更正**：旧生死实验因 baseline accumulation-order 不等价、单文档伪重复、test reuse 和 wire 语义混算失效。修正版使用 exact baseline、全新 test split 的 32 篇独立文章、文档级 bootstrap、synthetic token origin 和 frozen routes。结论仍是不推进 Graceful/two-lane QTree：温和 sender-cancel 只比正常 R-layout 多省 `1.68` 个百分点，却额外增加 `0.009799` KL；receiver-ignore-late 不省字节；two-lane 相对 node-FP8 增加 `45.47%/15.85%` 字节。critical-single 在 EP8/16 相对 node-FP8 再省 `2.27%/11.41%`，额外 KL `0.000213/0.000964`，只保留为待跨模型/placement 验证的 hypothesis。完整判决见 `experiments/idea_a_mac/outputs/paper_validation/graceful_qtree_corrected_v3_2026-07-13/严格复核后的生死实验结论.md`。

## 1. 先修正筛选标准

相关工作多不等于不能做。一个选题只要满足下面四条，仍然可以形成论文：

1. 新机制不是给已有方法换超参数或多加一个 loss；
2. 把最强相关工作接入后，新机制仍提供独立收益；
3. 能用一组生死实验隔离“为什么有效”，而不是只报告端到端加速；
4. 实现和指标与 claim 对齐：通信题必须有真实多 GPU / 多节点通信，SLO 题必须有 TPOT/P99/goodput。

真正的雷点是“贡献可被某篇 baseline 的一个开关吸收”，不是“这个领域论文数量多”。

## 2. 候选排序

| 排名 | 候选方向 | 与已有资产复用 | 最小硬件 | Idea 上限 | 当前建议 |
|---|---|---:|---:|---:|---|
| 1 | Criticality-Aware Graceful EP：关键贡献可靠、尾部贡献尽力而为 | 极高 | 2 节点 × 4 GPU | 上限受质量/字节斜率限制 | **降为可选拥塞消融** |
| 2 | QTree-EP：拓扑层级 × 聚合顺序 × 数值精度联合设计 | 极高 | 2 节点 × 4 GPU，最好 16 GPU | critical-single 可作窄 seed | **砍 two-lane，仅短验 critical-single** |
| 3 | Tiered-Fidelity Shadow Experts：拥塞时用本地轻量影子 expert | 中高 | 4～8 GPU | 高风险 B seed | 值得先做模型侧生死实验 |

| 5 | Energy-SLO Precision EP：精度、放置、副本与能耗联合控制 | 可复用 Idea B | 8 GPU，最好跨节点 | C/B 取决于测量 | 独立备选 |

## 3. 方向一：Criticality-Aware Graceful EP（最推荐）

### 3.1 问题

现有 EP 通常把一个 token 的所有 top-k expert contribution 当成同等可靠的通信流。一旦 receiver incast 或 RDMA 排队，低贡献 tail flow 会和高贡献 head flow 一起阻塞整个 combine。

当前 Idea A 已证明：在 OLMoE top-8 中，head 与 tail 对 FP4 误差的敏感性显著不同；MXFP4/NVFP4 的 head-control KL 分别约为 tail 的 `8.75×/2.56×`。这不只适合静态量化，还可以转化成通信服务等级。

### 3.2 新机制

- `head lane`：高 rank contribution，FP8，可靠且高优先级；
- `tail lane`：低 rank contribution，FP4，低优先级；
- 正常负载：两条 lane 都完成，保持固定 rank two-lane 结果；
- 拥塞负载：tail lane 有短 deadline，逾期 contribution 可丢弃、renorm 或由轻量补偿器恢复；
- 控制器按 request 维护累计质量预算，避免同一请求连续多层退化；
- receiver 根据 queue/slack 发出 coarse congestion signal，不依赖预测未来 expert 热度。

它与之前 DeadlineEP 的关键区别是：DeadlineEP 只改变请求顺序，无法消除 receiver 串行工作；本方向允许在质量预算内减少低价值工作，因此有机会真正缓解热点 receiver。

### 3.3 与已有工作的边界

- CAP 做 placement + communication-aware pruning，但不是 EP 数据面的分级可靠性和按拥塞触发的 tail completion；
- SERE / Opportunistic Expert Activation 修改 expert selection，主要减少计算或激活 expert 数；
- FAST / UBEP 优化通信调度，但没有使用 contribution criticality 构造可降级的服务等级；
- QLLM 使用请求/层优先级，不是 token 内 expert contribution 的优先级。

因此论文问题可写成：

> Can MoE EP expose contribution criticality as a first-class transport semantic, guaranteeing head completion while using tail contributions as a bounded, best-effort refinement under congestion?

### 3.4 生死实验

1. Mac：补齐 `tail drop / renorm / learned compensation` 在 1、2、4、8 个连续拥塞层下的 held-out KL/PPL/任务准确率；
2. trace replay：比较 FIFO、request-priority、head-priority、head-priority+tail deadline 的 receiver completion P99；
3. 真实系统：至少两节点，使用两个 CUDA stream / QP 或两类 buffer，测 head 是否真的避开 tail HOL blocking；
4. 保留门槛：热点场景 P99 至少改善 15%，正常负载吞吐损失低于 5%，质量退化受预算稳定控制。

### 3.5 雷点

- 如果 NIC/RDMA 层无法提供真正隔离的优先级，两条 lane 仍可能在底层互相阻塞；
- 如果必须等 tail deadline 才能继续下一层，deadline 本身可能抵消收益；
- 如果连续多层 tail miss 导致误差非线性放大，必须加入跨层质量预算，而不能逐层独立决策。

## 4. 方向二：QTree-EP（最系统、最贴拓扑）

### 4.1 核心变化

不要只问“哪个 expert output 用 FP4”，而要问：

> 在 NVLink → RDMA → receiver 的聚合树上，应该在哪里累加、在哪里量化、哪个 partial sum 使用什么格式？

设计候选：

1. 同一 owner GPU 的多个 contribution 先在 FP16/FP32 累加；
2. 同一 NVLink domain 内形成 per-token partial sum；
3. 只在进入慢速 RDMA edge 前，将安全的 tail partial sum 量化成 MXFP4/NVFP4；
4. head partial 与 tail partial 使用独立格式和 scale；
5. receiver 对少量 node partials 做最终累加。

关键创新不是“hierarchical combine”本身——Hybrid-EP 和 NCCL EP 已经覆盖层次化通信/聚合——而是 **error-budgeted quantization placement**：量化对象从单个 expert output 变成拓扑树上的 partial sum，联合优化量化次数、误差和慢链路字节数。

### 4.2 已完成的 trace oracle

数据：OLMoE held-out trace，`31,312` 个 token-layer，top-8，简单 modular expert placement。

| EP / 每节点 GPU | 平均 distinct owner ranks | owner-rank copy 上限下降 | 平均 distinct nodes | node partial copy 上限下降 |
|---|---:|---:|---:|---:|
| EP=8 / 4 | 5.428 | 32.15% | 1.998 | 75.03% |
| EP=16 / 4 | 6.801 | 14.99% | 3.707 | 53.66% |
| EP=16 / 8 | 6.801 | 14.99% | 1.996 | 75.05% |

这里的 `copy 上限下降` 只是线性聚合后逻辑 contribution copy 数的上界，不是对 Hybrid-EP/NCCL EP 的增量收益，也不是 latency。它说明 topology-level partial sum 的数据形态值得研究；真正的新收益必须相对现有 hierarchical EP，来自 precision placement、scale/metadata 合并和更少的量化误差。

可复现数据：`experiments/idea_a_mac/outputs/paper_validation/new_idea_screening_2026-07-13/hierarchical_combine_oracle.csv`。

### 4.3 生死实验

1. Mac：比较 `quantize-each-then-sum` 与 `sum-then-quantize`，扫描 owner/node 分组和 MXFP4/NVFP4；
2. 证明 quantize partial sum 在相同 RDMA wire bytes 下稳定优于逐 expert quantization；
3. 两节点 kernel：对比 DeepEP / NCCL EP / Hybrid-EP 风格 hierarchical combine；
4. 保留门槛：相对 uniform FP8 hierarchical combine，operator latency 至少改善 10%，且优于简单 fixed rank two-lane。

### 4.4 雷点

- 如果现有 Hybrid-EP 的 FP8 hierarchical reduction 已经完全带宽饱和，FP4 可能只增加 pack/dequant 开销；
- partial sum 动态范围可能大于单 expert output，FP4 scale 反而更难选；
- 新颖性必须落在“精度放置与聚合顺序”，不能声称发明 hierarchical combine。

## 5. 方向三：Tiered-Fidelity Shadow Experts

### 5.1 核心机制

每个节点不复制完整 remote expert，而保存其轻量影子版本：低秩、蒸馏、merged expert 或 shared-base residual。运行时：

- 高 gate rank：仍调用远端完整 expert；
- 低 gate rank且网络正常：远端完整 expert或现有 FP4 combine；
- 低 gate rank且链路拥塞：在 token-origin 节点执行本地 shadow expert，完全避免该次 dispatch + combine；
- shadow 与 full expert 的切换由 congestion + contribution + request quality budget 决定。

### 5.2 为什么不是已有 replication/pruning

- full expert replication 用大量 HBM 换负载均衡；shadow 只占原 expert 的一小部分；
- pruning/drop 直接删除 contribution；shadow 保留输入相关的近似计算；
- expert compression 通常只为减少模型总显存；这里把压缩副本作为 **网络降级路径**。

MoBE、D²-MoE、TD-MoE 等已证明 shared basis / low-rank delta 有可利用结构，但检索中未发现它们把压缩副本用于分布式 EP 的按拥塞切换。这是可争取的交叉创新，必须在正式 related-work audit 中继续核实。

### 5.3 生死实验

先完全不做多 GPU：对 OLMoE 每层 expert 构建 1/8、1/16 参数量 shadow，测低 rank 调用替换后的 KL/PPL。如果相同参数预算下明显优于 drop 和“改路由到本地其他 expert”，才进入系统阶段。

保留门槛建议：shadow 占完整 expert 不超过 12.5%，替代 25% remote tail calls 时 held-out KL 不超过当前 MXFP4 tail 的 2 倍，并在 trace 上减少至少 20% inter-node calls。

### 5.4 雷点

- 代理 expert 的本地 GEMM 可能与 attention/其他 expert 抢计算；
- shadow 训练可能把论文拉向模型压缩而不是 AI Infra；
- 不同 expert/layer 的可压缩性可能很不稳定。

## 6. 方向四：Residual-EP

把 expert 分解为共享基座和 expert-specific residual：

$$E_e(x) \approx B(x) + \Delta_e(x).$$

token origin 只计算一次 `B(x)`，远端 expert rank 只执行/返回 `Δ_e(x)`；最终按 gate weight 聚合。若 residual 的秩和动态范围显著更小，可以同时减少远端计算与 combine bytes。

它与 Shadow Experts 的区别是：Shadow 是拥塞时的近似 fallback；Residual-EP 是常态执行协议和模型结构协同。MoBE、D²-MoE、TD-MoE 已覆盖共享基座/残差压缩，因此独立创新必须是“如何让分解直接改变 distributed execution 和 wire format”，而不能只做新的 SVD。

此方向理论上限高，但需要模型分解、恢复微调和新 runtime，最容易超过本科毕设的时间预算。

## 7. 方向五：Energy-SLO Precision EP

复用原 Idea B，但把目标从泛化的 placement MILP 收窄为可测系统：

- 离线生成少量部署模式：uniform FP8、rank FP8/FP4、不同 expert replica/placement；
- 在线根据负载和 SLO 在模式之间切换；
- 目标不是纯 latency，而是在 `TPOT_P99 <= SLO` 下最小化 GPU + NIC 的 J/token；
- 报告 energy-optimal 与 latency-optimal 的配置差异，以及静态副本功耗和通信功耗的 break-even point。

能耗优化本身并不新，创新点必须是 MoE 独有的稀疏通信/副本/精度三方 trade-off，以及可校准的控制器。没有真实板级功耗和最好有 NIC/交换机计数器时，不要主打通信能耗。

## 8. 方向六：Per-request Quality Isolation（作为方向一的第二贡献）

当系统通过 FP4、shadow 或 tail miss 进行 graceful degradation 时，平均 KL 可能很好，但少数请求可能连续多层受损。可以把“近似预算”做成类似网络公平队列：

- 每个请求维护累计 degradation credit；
- 已经多次降级的请求提升 tail lane 优先级；
- 优化 worst-request / P95 quality loss，而不是只有全局平均 KL；
- 同时维持 TPOT SLO 和租户权重。

它很适合作为方向一的 isolation/fairness 设计，但单独拿出来缺少足够大的系统机制。

## 9. 不建议继续当独立主线的方向

1. **纯 co-activation placement**：CAP、Occult、拓扑 ILP 和 2026 activation-pattern 工作已经直接覆盖；必须叠加新的执行机制才值得做。
2. **纯 local-expert rerouting**：SERE、Oracle-MoE、CommitMoE、Opportunistic Expert Activation 等已经很密集。
3. **纯动态 EP degree**：WideEP、NCCL EP LL/HT、Expert Streaming、NanoCP 等正在快速完善；只做 mode selection 容易成为工程调参。
4. **纯 request priority**：上一轮 DeadlineEP proxy 已表明它不能解决 receiver 串行热点；必须允许减少低价值工作或改变数据路径。
5. **纯 hedge/replication**：receiver incast 下无效，并且 PROBE/EEP/动态 replication 工作很多。

## 10. 原推荐决策（已被 2026-07-13 生死实验否决）

如果希望最大化复用已有工作并增加系统论文上限，首选路线不是完全换题，而是：

> **把当前 FP8-first rank-segmented FP4 combine 升级为 Criticality-Aware Graceful EP；QTree-EP 作为其 topology-aware kernel backend。**

这样可以形成一条连贯但更强的故事：

1. characterization：expert contribution 具有稳定 criticality 差异；
2. abstraction：把 contribution criticality 暴露成 EP transport semantic；
3. mechanism：head reliable / tail best-effort，并用 per-request quality budget 控制降级；
4. kernel：在 hierarchical combine tree 上联合决定 accumulation 与 precision placement；
5. system result：正常时低精度加速，拥塞时 graceful degradation，改善 TPOT/P99 而不是只省理论字节。

Shadow Experts 可作为高风险独立备选。Energy-SLO EP 可作为与主线完全分离的第二选题，不建议一次同时推进。

### 10.1 实验后的新决策

不要把上述整条故事同步进 `PDF论文的选择.md` 或 TaskList。当前应保留已有 FP8-first R-layout 主线，并只进行一次有停止条件的 `critical-single partial` 跨模型/跨 EP 扫描：节点内仍只生成一个 partial，含 head contribution 时用 FP8，仅 tail-only partial 用 MXFP4。若相对 hierarchical FP8 不能稳定再省至少 8% 慢链路字节且额外 KL 控制在 0.001 内，就停止 topology extension。

Graceful EP 只在未来真实多节点实验表明拥塞 P99 收益足够大时，才作为 rare emergency fallback 重新评估；two-lane QTree、mass renorm 和 double quant 不再投入。
