## 一、已判死 / 强降级条目：复核结论 + 脚本路径

### 1. CreditReduce — **证伪**

| 项 | 内容 |
|---|---|
| 复核结论 | 判死证据扎实。`clean_early_bf16` 在 OLMoE/LLM-jp sealed holdout 上 NONINFERIOR（没有“病”可治）；`uniform_early_fp8` 质量合格且字节远少于 PD-Full，支配 CreditReduce 路线。GPU/CPU 同方向同量级，非仿真失真。 |
| 主要脚本 | `run_creditreduce_p0.py`、`creditreduce_reference.py`、`fake_quant.py` |
| 测试 / 预注册 | `test_run_creditreduce_p0.py`、`test_creditreduce_reference.py`；预注册文档：`docs/03_candidate_reports/CreditReduce_P0_预注册_2026-07-17.md` |
| 相关输出 | `outputs/` 下 CreditReduce P0 目录；见 Approach Registry |

### 2. RouteFidelity-EP — **证伪（CCFC 主线）**

| 项 | 内容 |
|---|---|
| 复核结论 | 0/20 seeds 达到 5% placement regret；Holm 下界为 0；regret 上限约 2.5%（门槛一半）。Kendall tau 低但配置选择几乎不变——排序扰动不成决策错误。 |
| 主要脚本 | `run_route_fidelity_p0.py`、`run_route_fidelity_p0b.py` |
| 备注 | 杀掉的是“路由充分统计量 → placement 决策”主线，不是一切路由压缩问题。 |

### 3. additive-KL MILP — **证伪**

| 项 | 内容 |
|---|---|
| 复核结论 | 单层 profile KL 不能加和预测多层 test KL；后续 `lock_routing` 审计显示排除路由漂移后纯数值仍严重不可加，全局漂移校正也救不回来。 |
| 主要脚本 | `run_layer_budget_experiment.py`、`run_additive_kl_modeling_audit.py`、`run_layer_sensitivity.py` |
| 结论文档 | `outputs/additive_kl_audit_2026-07-20/Additive-KL建模审计_最终结论_2026-07-20.md` |
| 背景文档 | `MoE_唯一核心创新_严格研究报告_2026-07-14.md` |

### 4. Graceful degradation / QTree-EP — **证伪（温和路径与 two-lane）**

| 项 | 内容 |
|---|---|
| 复核结论 | 项目内复核最充分之一（v1→v2→v3_corrected）：修 BF16 累加顺序、sampling/bootstrap 单位、sender-cancel vs receiver-ignore-late。温和 sender-cancel 多耗 ~0.01 KL 却只多省 ~1.7pp 字节；two-lane QTree 字节反而多耗 15%–45%，被严格支配。 |
| 主要脚本 | `run_graceful_qtree_survival.py`、`run_hierarchical_combine_oracle.py`、`run_quality_safe_congestion_frontier.py` |
| 结论文档 | `outputs/paper_validation/graceful_qtree_survival_v2_2026-07-13/Graceful_QTree_生死判决_2026-07-13.md` |
| 备注 | critical-single 等窄变体未作为独立主线推进；不等于一切拥塞降级问题消失。 |

### 5. MassCover-EP — **未过门**（不是“机制为零”）

| 项 | 内容 |
|---|---|
| 复核结论 | 代码设计严谨（sparse risk、CVaR-greedy、proxy fidelity）。相对最强静态基线 `gate_mass` 仅再降 4.7%–6.6%，未过预注册 **10%** 门。正确表述是 **FAIL_PRE_REGISTERED_GATE / KILL_OR_REFORMULATE**，不宜写成“完全无效”。 |
| 主要脚本 | `run_masscover_ep_p0.py`、`test_masscover_ep_p0.py` |
| 若复活需什么 | 端到端 failure-domain mask 质量实验 + 重新预注册门槛；当前不建议作为主线。 |

### 6. TokenRace-EP — **证伪**（证据链最长）

| 项 | 内容 |
|---|---|
| 复核结论 | Mac 仿真正收益建立在过低 launch/rebatch 常数上；RTX 5090 P0/P1 测出真实开销后两模型深度净负；自适应触发复查仍不可行。死因是仿真低估固定硬件开销，不是文献碰撞。 |
| 仿真脚本 | `run_tokenrace_ep_p0.py`、`run_tokenrace_ep_topk_sweep.py`、`run_tokenrace_adaptive_p2.py` |

| 审查文档 | `TokenRace-EP_严格性审查与后续方向_2026-07-19.md`、`MoE_新候选_TokenRace-EP_2026-07-19.md` |
| 输出 | `outputs/tokenrace_gpu_p0_2026-07-19/`、`outputs/tokenrace_gpu_p1_2026-07-19/` |

### 7. PLTB — **证伪**（跨模型缺口已补）

| 项 | 内容 |
|---|---|
| 复核结论 | 原报告唯一真实缺口是“只测 OLMoE”。2026-07-20 补 LLM-jp：2 模型 × 2 格式 × 2 种 tail 粒度，从未显著跑赢 fixed-tail；多数配置显著更差。 |

### 8. QuotaEP-H（Gate A/B/C）— **CORE 降级 / 未闭环**

| 项 | 内容 |
|---|---|
| 复核结论 | Gate 框架严谨。Gate B（owner-side output-aware）质量侧通过是真实结论；mixed 相对 uniform FP8 无系统优势；exact-q 有 quality tax；formal 与历史文档池高度重合 → 不能当 sealed confirm。死结在 Gate C（真 GPU kernel）+ 语料污染，不是 Gate B 造假。 |
| 主要脚本 | `run_grouped_owner_combine.py`、`grouped_owner_combine.py` |
| 结论文档 | `outputs/paper_validation/QuotaEP_H_查重与Grouped生死实验结论_2026-07-14.md` |
| 方法论要点 | `wikitext2_docs` 合格文档约 121 篇，多实验复用；真正 holdout 需换更大语料（项目已扩展 `wikitext103_docs`）。CreditReduce 的 SHA-256 registry 是数据隔离正面范例。 |

**本节汇总**：6 条属机制/净收益 **证伪**（CreditReduce、RouteFidelity、additive-KL、Graceful/QTree 温和路径、TokenRace、PLTB）；MassCover 为 **未过门**；QuotaEP-H 为 **CORE 未闭环**。未发现“仅因 Mac 仿真失真而错杀”的案例。

## 四、下一步建议（按信息增益，已去过时项）

1. **Quality Isolation（若继续）**  
   冻结旧 LLM-jp proxy，在 **n≥64** 的 future-decode INT4 上只测迁移；或做 one-step online predictor。脚本：`run_decode_fragility_strict_gpu.py`、`analyze_frozen_prefill_proxy_to_decode.py`。

2. **QuotaEP-H / 任何新 sealed confirm**  
   先换大语料或强制 SHA-256 registry，禁止在 ~121 篇 WikiText-2 池里找“新 offset”。

3. **Prefetch（仅当需要负结果章节补洞）**  
   `run_expert_prefetch_gpu_validity_audit.py --batch-tokens {1,2,4,8}`，避免 batch=32 过杀 decode。

4. **Receiver**  
   无多机 RDMA 前，停止把回放结果写成系统 claim；单卡只保留 codec/质量必要条件脚本。

5. **明确不再投入**  
   CreditReduce、RouteFidelity、additive-KL/PLTB 式单层外推、Graceful 温和路径、TokenRace、training-free Shadow/Residual、WaveCredit 独立实现。
