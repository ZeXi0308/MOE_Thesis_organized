# 2026-07-20 后续任务综合结论：路由预取系统原型 + 4条零代码候选P0

范围：本文档记录用户要求的两项任务的完整结果——①把"MoE路由跨层可预测性"（唯一通过预注册门槛的正结果）推进到系统原型阶段；②为Tiered-Fidelity Shadow Experts、Residual-EP、Energy-SLO Precision EP、Per-request Quality Isolation设计并执行严谨的P0实验。全部在真实RTX 5090 GPU（或本地Mac）上跑出真实数据，无一为估算/仿真替代。

---

## 一、路由可预测性 → 系统原型：真实GPU测量的预取延迟收益

脚本：`run_expert_prefetch_system_prototype.py`。用真实OLMoE/LLM-jp的calibration/test路由数据（与P0/P0-C完全一致的split）+ 真实GPU测量的常数（H2D拷贝延迟、MoE层真实compute延迟），模拟"GPU常驻专家LRU缓存 + 预取"系统。

**方法**：cache容量=8(OLMoE)/6(LLM-jp)，模拟真实decode batch（32 token/批次，切块自同一文档），对比reactive（纯需求驱动LRU）vs predictive（用calibration学到的top-1转移表在当前层compute窗口内异步预取下一层候选专家）。

**结果**（真实硬件常数：OLMoE h2d/expert=248.6us、layer_compute=10.09ms；LLM-jp h2d/expert=81.6us、layer_compute=5.11ms）：

| model | miss rate (reactive→predictive) | 总延迟节省 | 纯换页延迟节省(排除compute) |
|---|---|---|---|
| olmoe | 76.7%→64.3% | 3.08% (CI 2.92-3.22%，显著) | **16.0%** (CI 15.1-16.9%) |
| llmjp | 82.5%→71.5% | 1.89% (CI 1.79-1.97%，显著) | **13.3%** (CI 12.5-14.0%) |

**解读**：预取带来的换页延迟节省本身是真实、显著、且量级可观的（13-16%），跨模型一致，与P0-C的命中率提升方向完全一致。但转化为端到端总延迟节省只有~2-3%，原因是当前用作compute代理的"逐专家Python循环"实现本身开销巨大（10ms/层，远超H2D换页成本250us/次），这与TokenRace-EP GPU P1发现的"kernel launch开销主导"是同一类瓶颈——生产系统会用融合/批量GEMM kernel（compute时间可能缩短一个量级），届时换页节省占总延迟的比例会显著上升。**这是本项目路由可预测性方向第一个真实（非离线统计）的系统级数字，证实信号确实能转化为可测量的硬件收益，但收益大小依赖于底层MoE kernel实现是否足够高效——这是该方向走向真正系统实现前必须解决的下一个工程问题。**

## 二、Per-request Quality Isolation P0：脱离已死Graceful-EP，独立可行

脚本：`run_per_request_quality_isolation_p0.py`（纯本地Mac分析，复用已有`layer_budget`实验的`sample_metrics.csv`，零新GPU时间）。

**关键设计修正**：该候选原本"依附于已死的Graceful-EP"，本次重新设计为挂载在**已验证的均匀降级基线**（`fixed_tail4`/`fixed_tail8`，即PLTB/layer_budget实验里的对照组，本身是活的、真实的机制）之上，从而摆脱对Graceful-EP的依赖。

**Part A（oracle上限）**：给定固定的"全精度配额"M（占文档数10%-50%），比较"把配额给KL最差的M个文档"(oracle,用测试标签)vs"随机给M个"，在匹配总字节预算下测P95 KL降幅：
- OLMoE：oracle比random多降低30.6-35.4个百分点（P95 KL），LLM-jp：多降低20.7-38.6个百分点。

**Part B（信号是否可迁移，即现实中能否拿到这个signal）**：检验文档级"KL风险"能否用**另一个已经算过的机制**的KL来预测（Spearman相关）：结果**相关系数0.75-0.98，全部p<0.0001**——文档的"难度"是跨降级机制稳定的内在属性（很可能与文档长度/内容复杂度相关），不是机制特异的噪声。

**Part C（现实可实现版本）**：用Part B里相关性最强的机制的KL作为**因果合法**的优先级信号（不用测试标签本身），重新分配同样的配额：结果几乎完全复现oracle上限——LLM-jp在全部5个配额档位与oracle完全一致，OLMoE在低配额档位几乎一致，高配额时略低于oracle但仍远超随机。

**结论**：**Per-request Quality Isolation在这批数据上是一个真正可行的正结果**——不需要新机制、不需要训练，只需要在已有的多个降级策略之间共享"哪个文档更脆弱"的诊断信号，就能把P95最坏情况的质量损失降低20-54个百分点（相对随机分配的均匀降级），且这个信号是现实可得的（不依赖oracle）。这是本次任务里第二个（继路由可预测性之后）通过严格检验的正结果。

## 三、Energy-SLO Precision EP P0：真实GPU功耗测量（pynvml + 真实FP8 tensor core）

脚本：`run_energy_slo_power_probe.py`。**重要范围澄清**：项目现有的`fake_quant.py`量化流程是"量化-反量化"代理，用于模拟*通信字节*的下游质量影响，并不改变实际GEMM的计算精度/dtype，因此在单卡上无法体现真实能耗差异；多GPU EP mesh的通信能耗也无法用单卡测量。本P0改为测量单卡上**真实存在**的两个杠杆：

**杠杆1：batch size vs J/token**（真实nvidia-smi功耗读数，OLMoE，seq_len=64）：
| batch | throughput(tok/s) | 平均功率(W) | J/token(mJ) |
|---|---|---|---|
| 1 | 450 | 106.2 | 235.9 |
| 4 | 1705 | 130.9 | 75.9 |
| 16 | 6213 | 169.4 | 27.2 |
| 64 | 19551 | 267.5 | 13.6 |

batch从1到64，能效提升**17.4倍**——这是任何Energy-SLO controller最容易拿到的"免费"能耗收益杠杆（在SLO允许的延迟预算内尽量攒批）。

**杠杆2：真实FP8 tensor core GEMM vs 真实bf16 GEMM**（`torch._scaled_mm`，与expert gate_proj矩阵形状匹配，RTX 5090 Blackwell真实支持）：
| precision | matmul/s | 平均功率(W) | J/matmul(mJ) |
|---|---|---|---|
| bf16 | 9975 | 430.3 | 42.71 |
| fp8_e4m3(真实tensor core) | 20229 | 573.9 | **28.08** |

真实FP8路径吞吐提升2.03倍，功率提升33%，但净能耗**降低34.3%/matmul**——这是本项目第一次给出"精度切换"真实（非仿真代理）能耗数字。

**结论**：Energy-SLO Precision EP的两个基础杠杆（batching、真实精度切换）在真实硬件上都成立且量级可观，为后续设计"在SLO约束下选择batch size + 精度"的控制器提供了真实标定数据。局限：仍未覆盖原方案的"placement/replica"维度（需要多GPU EP mesh，超出单卡范围），也未覆盖真实网络通信能耗。

## 四、Tiered-Fidelity Shadow Experts + Residual-EP：SVD-P0，双双确认KILLED

脚本：`run_tiered_fidelity_residual_svd_p0.py`。用**免训练**的截断SVD构造这两个候选原本需要蒸馏/微调才能得到的"本地代理专家"，在OLMoE真实16层×64专家×16篇sealed文档上跑完整rank扫描（0.05/0.10/0.25/0.50），下游KL用与PLTB/layer_budget完全一致的方法（真实logits KL，paired bootstrap CI）。

**Residual-EP的必要条件检验（先于质量测试）**：残差 Δ_e = W_e − mean(all experts) 的90%能量有效秩与原始专家权重几乎完全相同（gate_proj: 610.5→613.3，down_proj: 632.5→633.6，up_proj: 639.5→640.5，满维度1024），**rank_reduction_frac全部为负值（-0.16%~-0.47%）**——即减去共享基座后残差并没有变得更低秩，反而略微更高秩。**这直接证伪了Residual-EP论证的核心前提**（"若residual的秩...显著更小"）。

**质量-压缩前沿（两种模式）**：
| mode | rank_frac | mean_kl (95% CI) |
|---|---|---|
| shadow (Tiered-Fidelity) | 0.05 | 8.04 (7.69-8.36) |
| shadow | 0.10 | 7.06 (6.73-7.36) |
| shadow | 0.25 | 3.03 (2.85-3.22) |
| shadow | 0.50 | 0.60 (0.55-0.66) |
| residual (Residual-EP) | 0.05 | 8.04 (7.72-8.36) |
| residual | 0.10 | 6.99 (6.69-7.27) |
| residual | 0.25 | 2.93 (2.76-3.14) |
| residual | 0.50 | 0.61 (0.55-0.67) |

对照本项目其他候选的KL门槛量级（`fixed_tail4/8`、PLTB各profile的KL通常在0.005-0.05区间，NLL_MARGIN门槛为0.005），**即便保留50%的秩（参数量减半，通信/计算收益有限），KL仍高达0.6——比可接受阈值高一到两个量级**；rank=0.25时KL≈3.0，rank=0.05时KL≈8.0，已完全摧毁下游分布。且**shadow与residual两种模式在每个rank档位上几乎完全重合**（差异落在CI内），印证了"共享基座没有额外收益"这个必要条件检验的结论——Residual-EP相比单纯SVD压缩没有任何附加价值。

**结论**：**两条候选双双在P0阶段确认KILLED**，且是决定性的：不是"效应量差一点没过门槛"，而是训练-free的低秩代理从根本上不可行（OLMoE的专家权重矩阵在90%能量意义下接近满秩，本身就不适合低秩近似），且Residual-EP特有的"共享基座"设计在此数据上没有任何理论或实证依据。这印证了选题地图当年的定性担忧（"shadow训练可能把论文拉向模型压缩"，"此方向...最容易超过本科毕设的时间预算"），现在有了决定性的定量证据：即使不考虑训练成本，免训练版本的质量下限已经远低于可用标准，实际蒸馏/微调需要克服的起点比通常预期的"专家权重存在冗余可压缩"假设困难得多。

## 五、跨四项任务的汇总

| 候选 | 结果 | 关键证据 |
|---|---|---|
| 路由预取系统原型 | 信号真实存在但当前kernel实现是瓶颈 | 换页延迟节省13-16%(显著)，端到端节省仅2-3%（受limited by 10ms/层的逐专家Python循环compute代理） |
| Per-request Quality Isolation | **PASS，脱离死掉的Graceful-EP独立可行** | 现实可得proxy信号几乎复现oracle上限，P95 KL降低20-54个百分点 |
| Energy-SLO Precision EP | **两个基础杠杆真实存在且量级可观** | batching 17.4x能效提升；真实FP8 tensor core节能34.3%/matmul |
| Tiered-Fidelity Shadow Experts | **KILLED（决定性）** | rank=0.5时KL≈0.6，比门槛高1-2个量级 |
| Residual-EP | **KILLED（决定性，必要条件证伪）** | 残差有效秩与原权重几乎相同，无压缩优势；与shadow模式无统计差异 |

四项任务里，两项（Quality Isolation、Energy-SLO）得到了真实、正向、可继续投入的结果；两项（Tiered-Fidelity、Residual-EP）得到了决定性的免训练否定结果（避免了投入训练/微调这个原本被认为"工作量最大"的坑）；路由预取系统原型验证了信号可转化为真实收益，但暴露出下一个必须解决的工程问题（MoE kernel实现效率）。
