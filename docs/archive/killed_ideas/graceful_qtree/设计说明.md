# 名称

Graceful EP（Criticality-Aware Graceful Degradation）与 QTree-EP（Two-Lane 拓扑聚合）

## 1. 背景与问题

在 rank-segmented FP8/FP4 混合精度 combine（R-layout）的基础上，项目探索了两个升级方向：
- **Graceful EP**：设想在网络拥塞、deadline 逼近时，允许"温和"地取消/忽略部分低优先级（tail lane，低 rank）的贡献，用少传字节换取质量可接受范围内的降级，而不是死等所有贡献到齐。
- **QTree-EP**：设想用两车道（two-lane，head lane 高精度 FP8 + tail lane 低精度 MXFP4）的层级化聚合表示，试图比单一节点级 FP8（node-FP8）在拓扑聚合场景下做得更好。

两者共同的检验标准是：在等质量或近等质量下字节是否严格更好；或在等字节下 KL 是否更好——不能只展示"降级后确实省了字节"就算成功，必须与已有强基线（uniform FP8、node-FP8）做严格的质量-字节联合比较。

## 2. 核心思想 / 机制主张

- **Graceful EP**：正常路径使用 FP8-head/MXFP4-tail 的 two-lane R-layout；在拥塞场景下，让部分 token 的后几个 rank（tail）贡献因 deadline 未到达而缺失，分为两种语义：`sender_cancel`（发送前主动取消，质量受损且真的减少跨节点字节）与 `receiver_ignore_late`（字节已经传输但 combine 不等待，质量受损但字节没有减少——这个区分在早期版本中被混淆，后来被明确修正）。同时测试"按剩余 gate mass 做 renormalization"这种直觉上应该更优的补救策略，以及在 disjoint calibration prompts 上为 (layer, miss-tail-count) 拟合的标量补偿。
- **QTree-EP**：正确的强基线是"节点内精确累加，每节点只发送一个 FP8 partial"（node uniform FP8），而不是逐专家 FP8。原始 two-lane 设计把每节点一个 partial 拆成 head/tail 两个独立 partial 分别量化，即使能保留 rank criticality 信息，也会破坏拓扑聚合"每节点只需一条向量"这个最大的字节优势。修正后提出了 **critical-single partial** 变体：每节点始终只发一个 partial，只有当该 partial 完全由 tail-only 贡献构成时才使用 MXFP4，否则用 FP8——不增加 partial 向量数，只是根据其内部组成有条件地选择精度。

## 3. 实验如何设计

- **第一版（2026-07-13，`survival_v2`，已失效）**：模型为 OLMoE，held-out validation offset 128（16 条样本，seq_len 128，1,218 个有效 next-token），calibration 为 offset 0（8 条，与测试不重叠）；FP8 proxy 与硬件对齐的 MXFP4 fake quant；端到端 token KL 与 corpus PPL；按样本 paired bootstrap（1,000 次，救援策略额外用 10,000 次）；逻辑 combine wire-byte 代理（非实测网络字节/延迟/TPOT/P99）。
- **严格复核发现的问题**：baseline accumulation-order 不等价（patched combine 与 Transformers 原生 expert-id 顺序 `index_add_` 不一致）、单文档伪重复（用行级切分而非 article 级采样导致同一文章多次出现在样本中）、test reuse（复用了已被其他实验用过的切分）、deadline miss 与零字节混算（`receiver_ignore_late` 被错误地当成节省字节）、未区分 local/remote（未按 token home domain 精确统计跨节点流量）、wire comparison 混入 routing drift（不同策略下的路由本应一致但统计口径未锁定）。
- **修正版（`graceful_qtree_corrected_v3_2026-07-13`）**：patched full combine 改为与 Transformers OLMoE 相同的 expert-id 顺序 `index_add_`（运行前强制验证原始模型与 patched full logits 一致，本轮 max/mean abs diff = 0/0）；采样单位从行改为完整 article（calibration 用 validation split 8 篇，test 用此前未运行的 test split 32 篇，每篇最多 256 token，共 8,160 个有效 next-token）；bootstrap 单位为 article（5,000 次）；预先冻结 17 个 finalist 策略，不根据 test 结果事后增加；Graceful 明确拆分为 `sender_cancel` 与 `receiver_ignore_late` 两种语义；为 token 设置跨策略、跨层固定的 synthetic origin，wire 只统计 owner-node 与 origin-node 不同的 combine 流量；full baseline 捕获选中的专家路由，所有 wire 比较使用同一 frozen route；EP8/EP16 分别使用 matching-EP 的 per-expert FP8 和 node-FP8 作为强基线。
- 仍未解决的证据边界：synthetic origin（非真实请求来源分布）、modular expert placement（非真实 placement）、无节点内 reduction 成本、无 dispatch、无真实 pack/kernel/RDMA、无 TPOT/P99——因此是 corrected proxy，不是系统性能证据。

## 4. 代码怎么组织（scripts/ 下文件角色）

- `run_graceful_qtree_survival.py`：唯一驱动脚本，同时实现 Graceful EP 和 QTree-EP 两套生死实验：Graceful 部分建模正常两车道（FP8-head/MXFP4-tail）与拥塞场景（可配置比例的 token 在指定层丢失最低 rank 贡献），对比原始 miss 与 gate-mass-preserving renormalization；QTree 部分对比逐专家量化与"精确节点内累加、只在拓扑下一层前量化"的多种策略（uniform-FP8、rank-segmented FP8/MXFP4、two-lane、critical-single、以及对已量化 two-lane partial 再次量化的反向对照）。该脚本经历了从 v2 到 corrected v3 的完整修正，是本目录唯一保留的实现文件。

## 5. 演进路径

第一版（2026-07-13 v2）判定 Graceful EP 核心机制 NO-GO、原始 two-lane QTree NO-GO、但发现了一个"窄条件 GO"的种子——topology-conditioned critical-single partial。但严格复核发现这个第一版本身存在多处方法论缺陷（accumulation-order 不等价、单文档伪重复、test reuse、deadline miss 与零字节混算、未区分 local/remote、wire comparison 混入 routing drift），因此第一版结论被标注为"已失效，禁止继续引用"，取而代之的是同一天完成的修正版（v3）。修正版复核了全部结论：Graceful EP 和 two-lane QTree 的 NO-GO 判决维持（且证据更干净，因为 receiver-ignore-late 的字节不减少这一点被明确证实），critical-single partial 的种子价值也基本维持（EP16 的 saving 从 v2 的 2.22%/11.18% 略微调整，但方向与量级一致），只是修正版更明确地指出这个种子"尚不能称为 conditional GO 或论文贡献"，需要跨模型/跨 placement 的进一步验证才能进入 kernel 阶段——而这一步验证从未被执行。

## 6. 判死结论与不要再怎么救

**NO-GO（v3 修正版维持，且是本目录最终权威结论）**。
- **Graceful EP**：温和 `sender_cancel`（前 4 层、25% token、tail4）相对正常 R-layout 只多省约 2.19% 跨节点 combine bytes（相对 uniform FP8 的 saving 只从 23.51% 增至约 25.18%-25.29%），但额外 KL 高达约 0.0098（95% CI [0.0085, 0.0112]），且 32/32 篇测试文档全部变差；`receiver_ignore_late` 的 logits 与 `sender_cancel` 逐样本完全相同，但 wire bytes 与正常 R-layout 完全相同——证明"deadline miss"本身不能被解释为省字节，这是一个关键的语义澄清；mass renorm 补救策略反而进一步增加约 0.0101 KL（31/32 篇文档更差），不能被当作无损补救；disjoint calibration 拟合的标量补偿也只能缓解部分误差，不能改变质量/字节的斜率关系。
- **QTree two-lane**：在相同 frozen route 下同时增加字节（EP8 多 45.47%、EP16 多 15.85%）和 KL，被 node-FP8 严格支配（strictly dominated），设计应永久停止。
- **critical-single partial**（唯一保留的窄条件种子）：保持与 node-FP8 完全相同的 partial 数，EP8 相对 node-FP8 再省 2.27% 字节但额外 KL 0.000213（21/32 文档变差）；EP16 再省 11.41% 但额外 KL 已接近 0.001 门槛（30/32 文档变差，CI 上界超过 0.001）。这是一个有干净实验支持的 topology-conditioned hypothesis，但只有一个模型、一个 modular placement、一个 synthetic-origin 规则，**尚不能称为 conditional GO 或论文贡献**。**不要再加更多 lane 变体，也不要把 critical-single 直接写进标题/摘要/贡献列表**——它只有在跨模型、跨 placement、跨 EP/topology 后仍能相对 node-FP8 稳定节省 ≥8% 真实远端字节且质量预算通过（额外 KL 不超过 0.001，不增加 partial 数）才能进入 kernel 阶段验证，而这一步从未执行；homogeneous one-shot codec 方向已转到 receiver-aware 通信线独立测量（见 `progressive` 目录），与本两条机制不是同一条演进路径。
