# 名称

QuotaEP-H / Grouped-Owner Combine（Placement-Conditioned Fixed-Quota Mixed-Precision Hierarchical Combine）

## 1. 背景与问题

在 hierarchical/high-throughput EP combine 中，同一 `(token, destination-origin)` 的多个专家输出常常可以在跨节点传输前先在 source topology domain 内做一次本地 BF16 partial reduction（即"owner-side 本地合并"），这样跨节点传输的是合并后的 grouped 向量而不是逐专家展开的向量，天然节省字节。问题是：合并之后，剩余的字节预算该如何在这些 grouped 向量之间分配精度（哪些用 FP8、哪些用更省的 MXFP4）？旧版本的 Idea A 把"按 rank/head 重要性做静态精度分层"作为核心创新，但这条线（PLTB/R-layout）已被证明不是质量 Pareto winner。QuotaEP-H 尝试的新机制是：在专家输出已知之后（output-aware，late binding），用真实贡献而非廉价的 rank/gate 代理来决定每个固定 peer/tile 内该给多少个 grouped 向量分配 FP8 精度、其余用 MXFP4。

## 2. 核心思想 / 机制主张

- **Owner-side 本地合并（grouped wire unit）**：对每个 token，把同一 owner rank 上的多个专家输出乘以各自 routing weight 后先在本地按专家 id 升序做 BF16 累加，再把这个合并后的向量作为跨域传输的基本单位。这是一个非展开/local-reduction 的 EP combine 路径——DeepEP 等 backend 也支持展开（expanded）布局，LL kernel 常传输逐专家响应，因此这个 grouped 路径必须被明确为一种 backend-specific 的 hierarchical/local-reduction 反事实，而不是"放之四海皆准"的 EP wire unit。
- **Output-aware late binding**：专家输出产生后，用真实的合并后 partial `‖Σ_e g_e o_e‖`（grouped contribution）、`Σ_e g_e‖o_e‖`（pair contribution）、或从 MXFP4 升级到 FP8 时能减少多少局部量化误差（qerr）作为评分，来决定该 grouped 向量是否值得升级到 FP8，而不是用零额外信息的廉价代理（rank、gate mass、input-norm×gate）。
- **固定 quota（fixed quota）**：为了形成规整的、可能对 kernel/queue 更友好的两条 homogeneous 精度 lane，在每个固定的 peer/tile 范围内固定选取一定数量（如约 50%）的 grouped 向量用 FP8，其余用 MXFP4，而不是用全局自由预算（`global_contribution`）任意选择。
- 三层门（Gate A/B/C）：Gate A 检验廉价 selector（rank/gate/input-norm）能否接近 output-aware selector；Gate B 检验 output-aware selector 本身在给定 eligible 集合下是否稳定优于廉价 selector 和随机；Gate C 检验完整融合 kernel（reduce+score+select+pack）在真实系统上是否带来净收益（TPOT/P99）。

## 3. 实验如何设计

- **模型与数据隔离**：OLMoE-1B-7B（E64/top-8）与 LLM-jp（E32/top-16），formal test 与 placement stress 使用互不重叠的冻结 WikiText validation article 切片，每 setting 12 篇独立文章、每篇最多 256 token，独立统计单位为 article。
- **正确性基础**：patched full 与原始模型 bitwise equal；EP=1 grouped path 与 patched full bitwise equal（两模型最大 logit diff 均为 0）；EP=8 grouped BF16 相对逐专家 BF16 累加仍有约 0.0015-0.0019 KL（浮点加法顺序改变，非量化误差），因此所有 mixed 策略统一以同 placement 的 grouped BF16 为 reference，而非原始模型输出。
- **策略族（同预算约 50% FP8 vectors，wire 几乎完全匹配）**：`uniform_fp8`（强基线）、`mixed_rank`/`mixed_gate_mass`/`mixed_inputnorm_gate`（廉价 selector，Gate A）、`mixed_pair_contribution`/`mixed_contribution`/`mixed_qerr`（output-aware selector，Gate B）、`global_contribution`（跨 peer 全局 top-B，仅作配额自由度上界）、`mixed_random`（同预算负对照）。
- **Formal 与 placement stress 对照**：在 contiguous 和 round-robin 两种 expert placement 下分别跑，检验方向是否跨 top-8/top-16、跨 placement 保持一致。
- **统计方法**：文档级 paired bootstrap（10,000 次）+ Holm 多重比较校正，比较各策略相对 rank/gate 的 KL 降低幅度与显著性。
- **三个专项负结果检验**：① group cancellation 是否是核心新现象（比较 `‖Σg_e o_e‖` 与 `Σg_e‖o_e‖` 的差异是否显著）；② 固定 peer quota 是否"几乎免费"（相对 `global_contribution` 的质量代价）；③ rank/gate 能否承担 final selector（output-aware 出现后是否仍然稳定落后）。

## 4. 代码怎么组织（scripts/ 下文件角色）

- `grouped_owner_combine.py`：owner-local MoE combine 语义的核心参考实现，定义所有 `GROUPED_POLICIES`（`grouped_bf16` 及各 mixed/quota 策略）的精确数值行为，是一个纯数值参考，不建模 GPU 打包、对齐、overlap、collective 或 kernel 延迟。
- `run_grouped_owner_combine.py`：离线质量实验驱动，先对每个 token 做 owner-local BF16 加权归约，再对该非展开/local-reduction combine path 使用的 partial 向量应用 fake FP8/MXFP4，测量质量与碰撞结构（而非通信延迟）。
- `analyze_fixed_rate_survival.py`：配对文档级 bootstrap 生死检验分析脚本，把一篇 WikiText article/request 视为采样单位（不把同文章内的 token 当独立证据），用于判定各固定比例 combine 策略相对 baseline 的显著性。
- `analyze_peer_layout_regularization.py`：lane 数量规整性分析（trace/布局分析，不是延迟 benchmark），用 `run_signal_comparison.py` 保存的 routed pair 顺序，检验校准阈值法（threshold-based）在每个 owner-local tile 内造成的 FP8/MXFP4 lane 长度波动，对比固定配额策略（动态成员但精确低比特数量条件于 routed-pair 数）的规整性优势。
- `test_grouped_owner_combine.py`、`test_fixed_rate_policies.py`：分别对 `grouped_owner_combine.py` 核心策略实现与固定比例策略的单元测试。

## 5. 演进路径

QuotaEP-H 是在旧 R-layout（rank-tail 静态精度分层）主线被证明不是质量 Pareto winner之后提出的升级方案，核心转变是把"精度分配决策"从"依赖 rank/gate 这类零信息代理"升级为"依赖专家输出已知后的真实贡献"。三层门槛检验（Gate A/B/C）里，Gate A（廉价 selector 能否接近 output-aware）明确失败——两模型、两 placement 下 output-aware 贡献都显著优于 rank/gate；Gate B（output-aware selector 本身是否稳定有效）通过了质量侧生死实验——四个 setting 全部优于 rank/gate/random，文档级 bootstrap + Holm 校正后成立；但 Gate C（fused kernel 是否改善真实 TPOT/P99）从未在 Mac 环境下验证，需要真实 HT EP backend，属于系统落地阶段，未被执行。此外，实验过程中还澄清了三个此前可能被过度解读的假设：group cancellation 不是核心新现象（差异未稳定排除 0）；固定 peer quota 并非"几乎免费"（相对全局自由预算有真实、有时不可忽略的 quality tax，尤其在 top-16 模型上）；rank/gate 已被证明不能再承担 final selector 角色。

## 6. 判死结论与不要再怎么救

**未过生死门（Gate B 通过，Gate A 与 Gate C 尚未通过，属于"未完成系统闭环"而非纯数值证伪）**。这与本目录其他"数值层前提被证伪"的路线性质不同：QuotaEP-H 的质量侧机制（output-aware late binding）本身是**成立**的——四组 setting 全部显著优于 rank/gate/random（Holm-adjusted p 均 <0.002），跨 top-8/top-16、跨 contiguous/round-robin 保持一致。真正未完成的是系统闭环：Gate C（真实 fused kernel 在真实 HT EP backend 上的 TPOT/P99 净收益）从未在 GPU 上验证，只有 Mac 上的质量与 logical wire 证据。同时三个专项负结果排除了几个可能被误用的"廉价"叙事：不能声称"首次利用 expert cancellation"（group cancellation 效应未显著）；不能声称固定 quota 几乎免费（相对全局自由预算有 4%-22% 不等的 quality tax，LLM-jp 更明显）；rank/gate 不能再作为 final selector（四组全部落后 output-aware）。当前可防守的窄交集是"在 hierarchical EP combine 的跨域 partial wire unit 上做 owner-side output-aware late binding，并用 per-peer/tile fixed quota 把动态 criticality 编译成两条规整精度 lane"。**不要把这条线包装成"已经提高了 TTFT/TBT"**（尚无真实硬件证据），**也不要把 rank-tail 静态分层重新包装成主创新**（已被证明落后）。若要继续投入，下一步必须是真实 HT/hierarchical backend 上的 kernel 实现与 microbenchmark，而不是继续堆离线 selector 变体；若始终无法获得真实多 GPU EP backend，这条线只能停留在"值得实现的候选"而非"已验证贡献"。
