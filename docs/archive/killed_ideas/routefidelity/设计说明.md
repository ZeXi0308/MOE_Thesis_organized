# 名称

RouteFidelity-EP（保持配置排序的最小路由充分统计量）

## 1. 背景与问题

真实 MoE 路由 trace（每个 token 在每层选中哪些专家）体量很大，若要用于 placement/protocol 等系统配置决策，是否必须保存完整的 token 级路由信息，还是存在一种更紧凑但仍能保持配置决策质量的"最小路由充分统计量"？RouteFidelity-EP 试图为不同 EP communication contract 找到这样一种压缩表示：它不追求"表示看起来相似"，而追求"用压缩表示选出的系统配置（如专家 placement）与用完整路由选出的配置，造成的实际决策损失（regret）足够小"。这把研究价值绑定到真实系统后果，而不是 trace 字段还原误差或统计相关性。

## 2. 核心思想 / 机制主张

- 定义一个从完整信息到粗糙信息的"表示阶梯"（representation ladder）：`S0`（仅架构信息，弱 baseline）→ `S1-R`（保留每个 request-layer 内每个专家的精确 degree，但打乱 token 级 coactivation，用 degree-preserving double-edge swap 构造）→ `S2`（保留 request-layer 内完整 hyperedge multiset，只打乱 token 顺序）→ `S3-W`（固定窗口 W=32 的 request-layer-window hyperedge 字典）→ `S4`（完整有序路由 oracle）。
- 定义两种 EP combine wire 计价合约：`C0`（expert-major negative control，每个 (token,expert) 一条记录，对任何 placement 必为 exact）与 `C1`（rank-major unique-owner primary，同一 token 命中同 owner rank 的多个专家只计一条记录，会同时受 token 级专家共现和 placement 影响）。
- 核心可证伪假设：若只保留每个 request-layer 的专家 marginal degree、破坏 token 级 coactivation（即 `S1-R`），系统会频繁选错 placement，在 exact route（`S4`）上造成 ≥5% 的 selected-placement regret；而保留 windowed hyperedge（`S3-W`）能以更小的 artifact 把 regret 恢复到 2% 以内。
- 统计判据：对表示 S，`P̂_S = argmin_P J_S(P)`（用表示 S 选出的最优 placement），`Regret(S) = (J_{S4}(P̂_S) − min_P J_{S4}(P)) / min_P J_{S4}(P)`（把这个选择放到真实完整路由 S4 上算出的相对代价）。

## 3. 实验如何设计

- **P0-A（exploratory）**：在旧 trace 上先探索性比较 architecture/degree/hyperedge/exact route 四种表示，只用于发现信号，不进入正式判定。
- **数据治理与协议冻结**：递归扫描全部历史 `data_manifest`，确保 calibration（32 篇）、sealed（64 篇）、reserve（128 篇）三个 WikiText-2 train-split 切片与历史全部 manifest 零重叠；冻结顺序严格：先冻结协议、documents、seeds、topology、primary metric，再实现并通过 toy/reference 测试，然后只用 calibration route 构造 placement pool，冻结 placement mappings 和 source SHA256，最后 sealed runner 校验全部 hash 后一次性运行，sealed 输出目录若已存在则拒绝覆盖或重跑。
- **Primary cells**：两个模型（OLMoE E64/top-8、LLM-jp E32/top-16）× C1 contract × EP8 两 domain 拓扑，两个 cell 必须同时通过才算过 problem gate。
- **Placement pool**：每个模型固定 132 个 balanced placement（contiguous、round-robin、calibration-only frequency-balanced LPT、calibration-only coactivation-aware balanced hill-climbing（20,000 次 proposal）、128 个独立 frozen seed 的 balanced random），所有表示共用同一 pool，不按 sealed 结果生成或筛选 placement。
- **H-P（problem gate）**：两个模型的 `S1-R`（20 个 seed）都必须满足：≥16/20 seeds 的 point regret ≥5%；seed-median regret ≥5%；10,000 次 request-cluster paired bootstrap 后 Holm-adjusted one-sided 95% lower bound >0。
- **H-M（method gate，仅在 H-P 通过后才检验）**：`S3-W` 的 regret ≤2%、tau-b 下界 ≥0.95、相对 `S1-R` 的 regret 差 ≥3 个百分点、canonical size ≤70% of `S4`。
- **H-T（temporal claim，secondary）**：仅当两模型在固定 W=32 chunk-tail objective 上都出现 ≥5% regret 且 CI 排除 0，才允许论文保留 temporal claim。

## 4. 代码怎么组织（scripts/ 下文件角色）

- `run_route_fidelity_p0.py`：P0-A exploratory 阶段驱动，比较真实路由 hypergraph 与逐步减弱的合成抽象（`real`/`hyperedge_shuffle`/`degree_shuffle`/`uniform_unique`），把不同 workload 抽象降到 rank-deduplicated EP 记录，检验是否改变 receiver-tail 与 buffer 配置决策。
- `route_fidelity_p0b_core.py`：P0-B 的冻结核心原语库，无命令行入口，提供 `C0`/`C1` 计价、`S1-R` degree-preserving swap、cluster bootstrap 等确定性参考实现，是整个 sealed 协议的数值基础。
- `run_route_fidelity_p0b.py`：P0-B 冻结 campaign 的正式 runner，有两个状态改变命令：`build-placements`（只读 calibration capture，冻结 132-placement pool 及全部分析 source hash）与 `evaluate`（若任何冻结 source/artifact 漂移则拒绝运行；sealed evaluation 还会拒绝覆盖已存在的输出目录）。
- `prepare_route_fidelity_p0b_configs.py`、`capture_route_fidelity_p0b.py`、`freeze_route_fidelity_p0b.py`：P0-B 协议的配置准备、路由捕获与冻结辅助脚本，配合 runner 完成"先冻结协议、再捕获数据、再冻结 placement、最后一次性 sealed 评估"的严格流程。
- `test_route_fidelity_p0.py`、`test_route_fidelity_p0b_core.py`、`test_run_route_fidelity_p0b.py`：分别对 P0-A 驱动、P0-B 核心原语、P0-B runner 的单元测试（toy cases、不变量检查）。

## 5. 演进路径

RouteFidelity-EP 走过了本项目里最完整的严谨实验路径：exploratory P0-A → 数据审计 → 协议冻结 → 实现与 toy 测试 → fresh calibration capture → placement 冻结 → calibration engineering run（发现并修复一次 GEMM warning 后重新锁定 v2）→ fresh sealed capture → P0-B sealed evaluation。每一步都设有明确的"进入下一阶段的硬条件"，且 sealed 阶段严格禁止覆盖或重跑。最终 sealed 评估直接命中 H-P 失败，协议规定 H-P 失败后 H-M 不运行，因此实验在 problem gate 就终止，没有进入 GPU/backend P1。

## 6. 判死结论与不要再怎么救

**KILLED（`KILL_CCFC_MAINLINE`）**。两个预注册模型的 problem gate 同时失败：OLMoE 与 LLM-jp 的 20 个 `S1-R` seed 均为 **0/20** 达到 5% selected-placement regret，seed-median regret 均为 **0**，Holm-adjusted one-sided lower bound 均为 **0**。这不是因为反事实没被有效打乱——OLMoE 的 token-set Jaccard 约 0.132、pair-distance 约 0.399，确认了显著的结构扰动；也不是因为两种表示的排序高度相似——两模型的 Kendall tau-b 只有约 0.33-0.41，说明 `S1-R` 与 `S4` 的全配置排序并不相似，但每个 seed 仍然稳定选中与 exact `S4` 相同的最优 placement（`calibration_coactivation_balanced`）。这直接否定了核心叙事：在本轮固定的 C1 rank-major unique-owner contract、EP8 两域拓扑和现实 placement pool 中，request-conditioned exact expert degree 已经足够选出最优 placement，没有证据证明必须保存 token-level hypergraph/coactivation 才能保持配置决策。即使绕过 problem gate 单看 method gate，`S3-W` 的 bit-packed canonical artifact 也没有实现压缩——其大小分别是 `S4` 的 109.72%（OLMoE）与 106.62%（LLM-jp），远未满足 ≤70% 的 method gate。**不要用 tau、P99 maximum 或 hypothetical capacity 代替实际决策损失来复活这条主线；不要把低 tau 改写成"problem 已成立"；不要修改 5%/16-of-20 gate 后重跑 sealed；不要声称 `S3-W` 是 compression（它比 `S4` 更大）**。可以保留的是：一套可复用的实验基础设施（fresh split、route capture、C0/C1 reference、balanced placement registry、exact-degree null、cluster bootstrap）；一个方法学层面的 negative result（trace similarity 与 decision fidelity 不等价）；以及一个前置筛选器——任何新的路由/拓扑假设必须先证明会改变具体系统选择或造成可观测 backend regret，不能只展示分布差异。
