# 名称

PLTB（Precision-Layout Tradeoff Bound）与 Additive-KL MILP（层预算/可加性联合精度分配）

## 1. 背景与问题

这是两个紧密关联但独立可证伪的候选：
- **PLTB**：号称"硬件无关"的核心创新是"层预算/冲突感知的动态尾部精度分配优于固定 fixed-tail"，即按每层的敏感度校准结果，给更敏感的层分配更多高精度（如 FP8）尾部 rank，其余层用更少。
- **Additive-KL MILP**：试图用单层维度可观测的 KL 敏感度，通过"可加性"假设外推到多层联合配置的整数规划（MILP）优化——即假设 `KL(联合扰动) ≈ Σ KL(单层扰动)`，从而不需要枚举所有多层组合就能求解最优精度分配。这条线曾在早期被"3.77× 非可加"的叙事判死，但 2026-07-21 的复核发现这个数字本身是一个记账伪影（重复累加了共享的 FP8 baseline），因此需要区分"可加性叙事"与"PLTB 端到端表现"两件事分别复核。

## 2. 核心思想 / 机制主张

- PLTB 的机制主张：在 calibration 阶段只对单层做扰动（其余层用 FP8，目标层的最后 `base_tail` 个 rank 升级到 INT4/MXFP4/NVFP4），用这个单层 profile 给所有层排序，据此构造若干"层预算分配方案"（如 `kl_profile_3_5`、`gate_mass_profile_7_9` 等命名的 profile），冻结后在互不重叠的 test 切片上端到端评估，与最简单的 `fixed_tail4`/`fixed_tail8`（所有层统一尾部精度）对比，profile KL 从不被当作对 test KL 的加性预测量。
- Additive-KL 的机制主张：用正确的**增量**公式（而非原始 KL 直接求和）检验可加性——`pred_inc = Σ_i (KL_single_i − KL_fp8)`，`true_inc = KL_joint − KL_fp8`，`ratio = pred_inc / true_inc`，ratio 接近 1 支持可加性。原 2026-07-20 版本直接对 `KL(full, single_i)` 求和（未减去共享的 `KL_fp8` baseline），导致 baseline 被重复累加约 n_layers 次，是纯粹的记账错误，而非真的证明了非线性交互。

## 3. 实验如何设计

- **PLTB 主实验（`run_layer_budget_experiment.py`）**：calibration 阶段对每层单独做扰动（全层 FP8 + 目标层尾部 `base_tail` 个 rank 升级），用该 profile 给层排序；冻结若干等 payload 的层预算分配方案，在与 calibration 互不重叠的 test 切片上端到端跑，对比 `fixed_tail4`/`fixed_tail8`，document/sample-level paired bootstrap 给显著性。跨两个模型（OLMoE、LLM-jp）× 两种低比特格式（MXFP4、NVFP4/INT4）× 两种 tail 粒度（base_tail=4/8）全面复现。
- **PLTB 跨模型复现补齐（2026-07-20）**：修复 `run_layer_budget_experiment.py` 里此前未打过的 CUDA 设备迁移 bug（`tokenized_inputs` 未把 tensor 搬到 `model.device`，导致此前只能在 CPU 跑），补齐 LLM-jp（此前只测过 OLMoE）在 MXFP4/NVFP4 两种格式下的完整结果。
- **PLTB 匹配协议重跑（2026-07-21）**：发现历史结果里存在数据集/offset 不匹配的问题（早期 INT4 在 `wikitext2` offset128 上曾显著优于 fixed-tail，与 2026-07-20 MXFP4 在 `wikitext2_docs` offset20 上的结果符号相反），因此在统一的匹配协议（`wikitext2_docs` validation，cal16 offset0，test32 offset20，base_tail=8）下对 INT4 和 MXFP4 重新跑一遍，消除数据切片不一致带来的虚假冲突。
- **Additive-KL 建模审计（`run_additive_kl_modeling_audit.py`）**：用 OLMoE、MXFP4 尾部精度，在 6 个独立层（0,3,6,9,12,15）上分别测单层隔离扰动的 KL（routing 锁定 vs 自由两种），与联合同时扰动的真实 ground truth 对比，检验 `naive_additive`（直接求和自由路由 KL）、`locked_additive`（锁定路由后求和，排除跨层路由漂移这一交互源）、`locked_additive_plus_global_drift`（用校准集学到的全局漂移比例做校正）三个预测器的预测/真实比值。
- **Additive-KL 纠正重算（2026-07-21）**：改用正确的增量公式（减去共享 FP8 baseline）重新计算 `locked_incremental` 和 `free_incremental` 两个预测器的 ratio。
- **匹配冲突表汇总（`analyze_pltb_matched_conflict_summary.py`）**：离线（不加载模型）整理已有 LLM-jp 历史结果里方向相反的 cell（早期 INT4 显著更好 vs 2026-07-20 MXFP4 显著更差），生成匹配协议下需要重跑的精确 GPU 命令。

## 4. 代码怎么组织（scripts/ 下文件角色）

- `run_layer_budget_experiment.py`：PLTB 主实验驱动，calibration 单层扰动 profile 构造 + 冻结分配方案端到端 test 评估，是 PLTB 判死证据链和 Additive-KL 表示复用的共同基础设施（`run_receiver_progressive_quality_gate.py` 也复用了它的 `run_logits`）。
- `run_additive_kl_modeling_audit.py`：Additive-KL 可加性检验驱动，包含已修正的增量公式实现（`locked_incremental`/`free_incremental`）与已废弃的双计公式（`DEPRECATED_DOUBLE_COUNT`，保留用于对比复现旧的 3.77× 错误结果）。
- `analyze_pltb_matched_conflict_summary.py`：纯离线分析脚本，不加载模型，从既有 LLM-jp 运行结果构造匹配前的冲突表，并生成匹配协议 GPU 重跑命令；本身不产生新证据，只是复核流程的中间步骤。

## 5. 演进路径

PLTB 与 additive-KL MILP 最早在 2026-07-13 之前的选题地图阶段就已被端到端实验判死（"单层误差不可简单相加预测多层误差"）。2026-07-19 的复核发现 PLTB 判死证据本身扎实，但存在一个真实缺口——从未在 LLM-jp 上复现，只测过 OLMoE，于是 2026-07-20 用 GPU 补齐了跨模型证据（结果仍是 PLTB 全面落败，且顺带修了一个 CUDA 设备迁移 bug）。同一天，additive-KL 建模审计试图检验"轻量校正能否救回可加性假设"，得到看似决定性的 3.77× 高估结论。但 2026-07-21 的项目级复核（`../errata/判死结论勘误_2026-07-21.md`）发现这个 3.77× 是记账伪影：`sum(单层 KL(full,·))` 重复累加了共享的 FP8 baseline 约 n_layers 次。用正确的增量公式重新在 GPU（RTX 5090）上跑，`locked_incremental` ratio 变成 1.076（95% CI [0.983, 1.165]，包含 1.0），因此撤回"可加性已被证伪"这个叙事——但这不代表 additive-KL MILP 主线自动复活，PLTB 的端到端表现仍是独立的判死门槛。与此同时，PLTB 自己也被发现存在过度概括问题："2模型×2格式从未赢过"这句话本身不成立，因为早期 LLM-jp INT4 在 `wikitext2` offset128 上曾显著优于 fixed-tail，与 2026-07-20 的 MXFP4 结果方向相反——这是数据集/offset 不匹配导致的虚假冲突，因此需要在统一匹配协议下重新判定，而不是简单地"撤回全部结论"或"直接采信旧结果"。匹配协议重跑后，INT4 和 MXFP4 在同一切片上都不再显著优于 fixed-tail（INT4: 0胜4负1平；MXFP4: 0胜5负0平），最终判决收窄为 `KILLED_MATCHED_DOCS_PROTOCOL`。

## 6. 判死结论与不要再怎么救

- **PLTB：`KILLED_MATCHED_DOCS_PROTOCOL`**。在统一匹配协议（`wikitext2_docs`，cal16 offset0，test32 offset20，base_tail=8）下，INT4 和 MXFP4 在 LLM-jp 上都不再显著优于 `fixed_tail8`（INT4: 0 sig_better/4 sig_worse/1 ns；MXFP4: 0/5/0）。跨两个模型（OLMoE、LLM-jp）×两种低比特格式×两种 tail 粒度的完整证据链方向一致：层级粒度的敏感度感知静态重分配，系统性地无法跑赢均匀分配这个最简单的 baseline——校准阶段测出的单层 KL 排序可能是有信息量的，但把这个排序转化成"给敏感层更多 bit"这一朴素策略，在真实的多层联合效果下并不能转化为端到端质量优势。**不要用旧的"一切切片从未赢过"这句话写论文**（早期 INT4/`wikitext2` offset128 上确实存在一个显著为正的历史 cell），但也**不要因此认为 PLTB 已经复活**——匹配协议下的判死结论是独立、干净、且是本次复核唯一改动的措辞是"撤回过度概括"，不是"撤回判死"。
- **Additive-KL：`WITHDRAW_ADDITIVITY_FALSIFIED`**。旧的 3.77× 及"残差流非线性饱和导致 3-5 倍误差"叙事作废（是 FP8 baseline 重复累加的记账伪影），正确增量公式下 `locked_incremental` ratio=1.076，95% CI 包含 1.0，可加性未决/可能成立。**不要再引用 3.77× 这个数字**，但也**不要把这个撤回自动理解为 additive-KL MILP 主线复活**——它只解除了"可加性已被证伪"这一具体错误论断，MILP 是否值得作为独立方法仍需要通过 PLTB 式的端到端门槛检验，而 PLTB 自己在匹配协议下已经判死。
