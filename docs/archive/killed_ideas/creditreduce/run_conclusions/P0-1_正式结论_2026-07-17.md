# CreditReduce P0-1 六端点生死实验：正式 sealed holdout 结论

> 运行日期：2026-07-17（当天完成，紧接预注册后立即执行）
> 数据：`p0_1_holdout` phase，OLMoE / LLM-jp 各 64 篇全新 WikiText-2 train-split 文档（offset 32-95），
> 与历史 24 份 manifest / 121 个唯一 SHA-256 完全无重叠（fresh-data guard 已通过）。
> 拓扑：EP8，`ranks_per_domain=4`（两个 source domain），`contiguous` placement，`seq_len=256`，`bfloat16`。
> 代码：`run_creditreduce_p0.py` + `creditreduce_reference.py`（均为 2026-07-17 预注册文档冻结的实现，未作任何改动）。

## 一句话结论

**P0-1 在 OLMoE 和 LLM-jp 上都判定为 `FAIL`。CreditReduce 作为唯一 P0 主候选，到此正式判死。** 两个模型失败的原因完全一致：机会窗口本身充足，但 (1) 简单本地合并再转 BF16（`clean_early_bf16`）在完整模型质量预算下并不违规，说明本来就没有需要修复的精度损失；(2) `uniform_early_fp8` 在质量合格的同时字节数远低于 `pd_full`，构成明确的支配（dominance）。这正是预注册文档 `CreditReduce_P0_预注册_2026-07-17.md` 第13节列出的三种可能结果中的第一种（"P0-1 失败：杀死动态核心"）。

## 关键数字

OLMoE（64 篇，seq=256）：

- 机会窗口：`p_eligible=99.01%`（LCB95=98.95%），`rho_credit=74.66%`（LCB95=74.61%）——机会本身非常充分。
- `clean_early_bf16` 相对 `late_bf16` 的 `delta_NLL` 95% UCB 为 `0.00145`，远低于 `0.005` 的非劣 margin，判定 `NONINFERIOR`（即"没有问题"）。
- `uniform_early_fp8`：字节数 536.8MB（相对 late payload 节省 87.49%），质量 `NONINFERIOR`（delta_NLL 点估计甚至为负）。
- `pd_full`：字节数 2118.9MB（只省 50.63%），比 uniform FP8 多花约 3.95 倍字节，却没有额外质量收益。

LLM-jp（64 篇，seq=256）：

- 机会窗口：`p_eligible=100%`，`rho_credit=87.50%`——比 OLMoE 更极端（因为 top-16 路由碰撞率天然更高）。
- `clean_early_bf16` UCB95 delta_NLL 为 `0.00112`，同样远低于 margin，`NONINFERIOR`。
- `uniform_early_fp8`：字节数 135.3MB（节省 93.70%），质量 `NONINFERIOR`。
- `pd_full`：字节数 536.9MB（只省 74.99%），比 uniform FP8 多花约 3.97 倍字节。

两个模型的失败模式高度一致：**FP8 几乎"免费"地拿到了比 PD-Full/CreditReduce 更好的字节节省，且没有触发任何可探测的质量问题**。这说明本地合并引入的 BF16 recast 误差在完整模型的端到端质量尺度下根本不构成可探测的伤害——CreditReduce 整套机制想要修复的"问题"在真实数据上并不存在。

## 决策后果（按预注册文档第13节执行）

依据预注册规则，P0-1 任一 gate 为 `FAIL` 即停止把 CreditReduce 当动态系统主线，且 P0-2（动态门控 vs 静态基线的对比）**不得运行**。因此：

1. **CreditReduce 动态核心判死**，不再继续投入单 GPU kernel 或两节点实现。
2. PD-Full（静态最强基线）本身也没有价值：它不仅没有质量收益，字节数还明显劣于更简单的 uniform FP8。
3. 唯一有价值的负结果（negative result）是：在 top-8（OLMoE）和 top-16（LLM-jp）两个真实 MoE 模型上，用全新未污染数据首次严格验证了——hierarchical combine 中 source-domain 本地合并引入的 BF16 中间舍入误差，在完整模型 teacher-forced NLL 的质量尺度下不具有可探测的危害；同时 uniform FP8 在这两个模型上都是比任何 mixed-precision/local-reduction 方案更简单、更省字节、质量更稳的强基线。

## 建议

不建议继续做用户提出的"第二件事"（P0-2 动态门控验证），因为按预注册规则它已经被硬性叫停。下一步如果还想在这个方向继续做文章，只剩两个选项：（a）把这轮结果写成一个诚实的 negative result（可能有一定的论文/附录价值，证明了一个此前未被严格验证过的假设不成立）；（b）回到候选池（`MoE新选题地图_2026-07-13.md`），重新评估其他候选方向。继续在 CreditReduce 上做单 GPU kernel 或两节点系统实现已经没有意义——数值层的前提本身就没有通过。
