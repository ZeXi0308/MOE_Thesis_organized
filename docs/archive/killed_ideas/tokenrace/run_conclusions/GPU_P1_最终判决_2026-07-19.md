# TokenRace-EP GPU P1 最终判决：KILLED（真实实现开销下两模型均深度净负收益）

> 日期：2026-07-19（P0 之后同一天的追加验证）
> 硬件：同一台 RTX 5090 独享实例
> 代码：`experiments/idea_a_mac/run_tokenrace_gpu_p1_overhead.py`

## 一句话结论

**P0 报告里"OLMoE 薄边际(6%-8%)存活、LLM-jp 净负收益"的判决被 P1 进一步推翻——一旦补上 P0 明确承认没算的两个真实开销源中的任何一个，OLMoE 也变成深度净负收益，TokenRace-EP 应判 KILLED，不再是 CONDITIONAL。**

## 两个新测量

**(D) CUDA Graph 的真实代价比重批开销本身还大。** 用真实的 `torch.cuda.CUDAGraph` capture+replay 测得：graph replay 比 eager 模式快一半以上（OLMoE eager≈59-67us vs graph≈23-30us；LLM-jp eager≈60-61us vs graph≈18us），也就是说 `full_barrier`（batch size 固定、可以用预先 capture 好的 graph 库）每层每次调用比被迫用 eager 模式的 `token_race` 要快 **30-44us（均值39.6us）**——这个差值本身就比 P0 假设的最乐观重批开销（26.6us）还大，且 P0 完全没有把它计入。

**(E) 更真实的多组释放开销随组数几乎线性增长，且远超 P0 的2组估计。** 实测（batch=128）：2组=47.9us，3组=68.0us，4组=87.4us，6组=127.2us——每多一组大约再加19-20us。P0 用的"最乐观2组、且用marginal口径"估出的26.6us，实际上比真实测得的2组绝对开销（47.9us）还低了近一半；4组这种更接近真实到达时刻分布粒度的开销（87.4-87.65us）是P0估计的3倍多。

## 门槛重算：两个场景收敛到同一个结论

场景(ii)：2组重批 + CUDA graph代价（合计87.5us/层）；场景(iii)：4组重批、不含graph代价（87.5us/层）——两个独立路径算出几乎相同的总开销量级，绝非巧合，说明**任何一个被 P0 忽略的真实因素单独拿出来，都足以把总开销顶到 87us/层这个量级**。重算后两个模型在所有 batch size 下的 moderate 场景结果：

| model | B | P99改善(场景ii) | P99改善(场景iii) |
|---|---|---|---|
| OLMoE | 32 | -32.40% | -32.39% |
| OLMoE | 64 | -30.78% | -30.77% |
| OLMoE | 128 | -30.59% | -30.58% |
| LLM-jp | 32 | -53.37% | -53.35% |
| LLM-jp | 64 | -52.79% | -52.78% |
| LLM-jp | 128 | -53.31% | -53.30% |

**两个模型、所有 batch size，全部深度净负收益（-30% 到 -62%）。** 这不是"卡边界"或"薄边际"，是彻底的方向性失败：一旦纳入哪怕最保守估计的真实实现开销（CUDA Graph 损失 或 更真实的多组释放粒度，两者单独任一即可），TokenRace-EP 会让两个模型的解码都明显变慢，不是变快。

## 修正后的最终判决

- **状态由 `CONDITIONAL_THIN_MARGIN_K_DEPENDENT` 降级为 `KILLED`。**
- P0 报告里"OLMoE 6%-8%薄边际存活"这个结论，只在一个不现实的假设下成立：既不损失 CUDA Graph，又只需要最少的2组释放粒度。这个假设组合本身概率极低——真实系统里这两个代价至少会出现一个，而任一个单独出现都足以让结果反转超过30个百分点。
- **杜绝了"继续优化实现细节能不能挽回"的希望**：87.5us/层 vs 之前 P0 用的 26.6us，差距是3倍多，而 OLMoE 原本的安全边际只有6-8%，需要把总开销压回到远低于P0乐观值的水平才可能翻正——这在真实生产级 serving 系统里不现实。

## 对论文的价值：仍然是一条完整、诚实、有 GPU 证据支撑的负结果

这条路线现在的价值定位应该是：**一篇 characterization 论文里的一节**，用真实路由 trace + 真实 RTX 5090 硬件数据证明"打破 MoE combine 之后的全 batch 同步屏障、改为逐 token 提前释放"这个直觉上合理的想法，在计入真实 GPU kernel launch 开销、CUDA Graph 兼容性代价、以及现实的多释放组粒度之后，净效果是让两个真实模型的推理都变慧太慢，且这个失败在两种独立的额外开销来源下都保持一致——这是一个有完整因果解释、可复现、有真实硬件证据的负结果，而不是一个模糊的"没做完"。
