# DDRC Phase 2 冻结实验协议

状态：**PHASE2_FROZEN / NO SCIENTIFIC RESULT**  
冻结日期：2026-07-22  
命题：Dispatch-Derived Cross-Sender Return Credits（DDRC）  
本轮证据上限：单 GPU 上的真实模型路由/质量 + 虚拟 EP 拓扑与通信账本；**不是 NCCL、RDMA、真实 NIC/P99 结果**。

本文件独立于旧 `g-1` receiver controller 的历史说明。任何协议修改都必须增加版本、解释原因，并使旧产物状态变为 `SUPERSEDED`；sealed 结果出来后不得改门槛。

## 1. 问题重述与代数天花板

固定 top-k、固定向量宽度、无 token drop 时，receiver `r` 的全部 combine 回程向量数为：

\[
R_{r,\ell,t}=K\,N^{valid}_{r,\ell,t}.
\]

因此 scheduler 在 request-origin 分配后已经知道 receiver 的**总**回程向量数。当前 expert routing 能新增的信息只包括：

- local/remote 比例；
- 精确的 `(expert-owner sender, token-origin receiver)` 来源分解；
- 这些 lane 映射到哪个物理 receive resource。

DDRC 不再声称“发现当前 receiver 总负载”，只检验：

> 在 request-origin balancing 之后，利用同层 dispatch 的精确跨 sender 来源分解，对共享 receive resource 协调 homogeneous FP8→INT4 回程动作；相对 sender-local exact-handle、静态画像和 uniform 策略，是否仍有至少 3 percentage points 的质量约束净关键路径增量。

## 2. 预注册假设与递进门

### H0

任一条件成立即接受 H0：

- origin balancing 已消除可利用空间；
- DDRC 不优于 `sender_local_exact_handle`；
- 增量小于 3 percentage points；
- 只在人工 hotspot、免费 credit 或乐观 codec 口径成立；
- 质量–收益 Pareto 被简单基线覆盖。

### H1

在相同 request-origin balancing、相同 homogeneous FP8/INT4 action family、相同质量约束和完整 codec/credit 会计下，DDRC 相对最佳强基线的质量约束净收益至少增加 3 percentage points，并在 OLMoE 与 LLM-jp 上复现。

### 递进停止门

1. **G0 信息非退化**：DDRC 动作必须使用 sender 来源分解，不能只是 `K×valid_origin_tokens` 的重写。
2. **G1 oracle ceiling**：balanced origin 后，`global_full_matrix_oracle` 相对 `sender_local_exact_handle` 的零-credit 上限必须在两个模型均达到 3 percentage points；否则 sealed quality run 不启动。
3. **G2 deployability**：codec、descriptor、credit、同步和 late fallback 全部计入后，DDRC 仍须通过最终门。

## 3. 身份、拓扑与因果时序

### 对象身份

- receiver：当前 token/request 的 origin/owner rank；
- sender：expert-owner rank；
- lane：`(expert_owner_sender, token_origin_receiver)`；
- remote：跨节点，而不是简单 `sender != receiver`；
- local pair：不上跨节点 wire，保持 BF16；
- 拥塞资源：由冻结 topology manifest 给出的 `(node, NIC, rail_or_qp_group)`，不得用 `expert_id` 或旧 `receiver_group` 代替。

主 topology：EP=8，ranks 0–3/4–7 分属两节点，每节点一个共享 200 Gbps receive resource，contiguous expert placement。round-robin placement 只作敏感性。

必须满足：

```text
sum(lane_count.values()) == remote_pair_count
receiver_all_rows[r] == top_k * valid_origin_tokens[r]
```

padding、已完成请求、capacity drop 和 local pair 必须显式排除或分别记账。

### 决策时序与信息集

1. scheduler 在路由前固定 request→origin 映射；
2. 当前层 router 生成 `selected_experts`；
3. dispatch handle/layout 形成；
4. sender 只知道本 sender 的当前 `(s,r)` counts；
5. 每个 receiver 从自己拥有 token 的 routes 聚合其 receive resource 的跨 sender 来源分解；
6. receiver 产生 credit，并在 expert compute 窗口发送；
7. credit 在 combine-pack deadline 前到达才可生效；
8. late、missing、duplicate、malformed credit 一律回退 FP8；
9. 未来 route、未来 request、当前 combine 完成时间和测试标签不可见。

信息集强制分为：

| 标签 | 可见信息 | 能否支持正式 GO |
|---|---|---|
| `deployable_sender_local` | 本 sender 当前 handle/count + calibration 常量 | 基线 |
| `deployable_receiver_credit` | 上述信息 + 当前 receiver 显式发来的 credit | 是 |
| `oracle_global_same_layer` | 完整当前 `N[s,r]`、全局资源矩阵 | 否，只作 ceiling |

单进程代码中直接读取完整 `receiver_load` 不会自动变成 deployable DDRC；必须显式构造、序列化并收费的 credit 路径。

## 4. 冻结动作 DDRC-v0

对层 `l`、step `t` 构造：

\[
N_{s,r}=\text{从 sender }s\text{ 返回 receiver }r\text{ 的有效向量数}.
\]

对物理 receive resource `q`：

\[
R_q=\sum_{s,r:q(r)=q}N_{s,r}B_{FP8}.
\]

DDRC-v0：

1. receiver coordinator 对其资源计算 `R_q`；
2. 仅当 `R_q` 超过 calibration-only 冻结阈值，才生成 low-precision credit；
3. lane 按可节省 remote bytes 降序，tie-break 固定为 `(sender_rank, receiver_rank)`；
4. 选择最少 lane，使预测 receiver bytes 降至阈值以下；
5. sender 执行本地 positive-net gate；不通过则保持 FP8；
6. 不使用 EWMA、HHI、bandit、未来队列或测试集调参。

每条 active `(sender,receiver)` credit record 固定 8 B；每个聚合 peer message 16 B header，总长向 16 B 对齐。“免费 piggyback”仅为 oracle sensitivity，不是主口径。

## 5. 强基线

所有 arm 使用同一个 deterministic request-origin balancing 结果。

| arm | 冻结定义 |
|---|---|
| `uniform_full` | remote homogeneous FP8，local BF16 |
| `uniform_low` | remote homogeneous INT4，质量/压缩端点 |
| `calib_static` | 只读 calibration profile；使用相同 codec/hardgate |
| `causal_prev_step` | 只读严格过去反馈；历史诊断基线 |
| **`sender_local_exact_handle`** | 每个 sender 只读本 sender 当前 `(s,r)` counts、topology 和 calibration 阈值；禁止读取其他 sender counts/global matrix |
| **`DDRC`** | 相对 sender-local 只多显式 receiver credit |
| `global_full_matrix_oracle` | 完整当前矩阵；只报上界，不是可部署 arm |

`sender_local_exact_handle` 必须使用当前 route handle，不能故意退化为 `g-1`。

Origin balancing 主配置为 scheduler-visible token-count LPT：只使用当前有效 prompt/decode token 与 queue load；不看 expert route；request owner 建立后不免费迁移 KV；tie-break 固定为 request hash、rank id。

## 7. 字节与时间会计

uniform FP8 也计 scale、descriptor、alignment 和 codec：

\[
B_{FP8}=n_8(d+4)+B_{desc8}+B_{padding8},
\]

\[
B_{INT4}=n_4(\lceil d/2\rceil+4)+B_{desc4}+B_{padding4}.
\]

必须分别记录：payload、scale、descriptor、alignment、credit、fallback credit、sender egress、receiver ingress、physical shared-cut bytes。

时间至少包含：credit build/aggregate/transfer/parse、policy lookup、pack、compaction、launch、transport proxy、unpack/dequant、reduction和 stream wait。

\[
T_{credit-visible}=\max(0,T_{credit-ready}-T_{pack-deadline-slack}).
\]

没有 CUDA/transport timestamp 证明隐藏时，收取全额 credit latency。hardgate 拒绝 low action时，lane/controller 状态回滚，但已经发生的 credit 成本不回滚。

现有三段 pack+H2D+unpack 的和不得称为 fused operator：

- 主口径：`serialized_tiles`；
- 乐观敏感性：`amortized_once_per_step_proxy`；
- H2D 一律标 `NOT_RDMA / host-staging proxy`。

每个时间字段必须携带来源：`measured_same_run | measured_other_gpu | analytic | assumed`。Mac 常数不得与 GPU 数字无标签混用。

## 8. 指标与统计

系统代理主指标：

\[
G=\frac{T_{best\ strong\ baseline}-T_{DDRC}}
        {T_{best\ strong\ baseline}}.
\]

同时报告 P50/P95/P99 critical-path proxy、max receiver/sender bytes、fan-in、low exposure、credit bytes/visible latency/miss rate、codec block rate，以及逻辑字节/时间代理分栏。

质量指标：BF16 absolute accuracy/NLL；相对 `uniform_full` 的 incremental accuracy harm；lost/gained correct；answer-NLL harm；positive-harm CVaR10。

对每个预注册 `lambda ∈ {0,0.1,0.2,0.5,1,2,5,10}`：

\[
U_p(\lambda)=net\_saving\_fraction_p-\lambda\,harm_p.
\]

“3%”明确解释为：

\[
U_{DDRC}-\max_{b\in strong\ baselines}U_b\ge 0.03
\]

即 3 percentage points，避免对接近零的 utility 使用不稳定相对比值。

质量按 subject/request 分层 paired bootstrap；P99 proxy 按 forward/burst block bootstrap；`n_bootstrap=2000`。winner 必须形成至少两个相邻 lambda grid point 的非单点区间；单个孤立点不算 GO。

## 9. Go / No-Go

GO 只表示 `GO_TO_REAL_TRANSPORT_NEXT_ITERATION`，须全部满足：

1. G0 非退化；
2. 两模型 oracle ceiling 均达到 3 percentage points；
3. DDRC 相对含 `sender_local_exact_handle` 的最佳强基线，utility margin 点估计 ≥0.03 且 paired 95% CI 下界 >0；
4. 两模型 balanced cell 均复现；
5. 不依赖 synthetic hotspot；
6. `amortized_once_per_step_proxy` 达门，且 `serialized_tiles` 同一 action trace 下优势仍为正、CI 不跨负；
7. 存在非空、非单点质量–收益区间；
8. accuracy/CVaR quality gate 不劣于 matched-quality 强基线；
9. credit、codec、hardgate 使用同一 action trace。

任一失败即 No-Go。不得用 bandit、HHI、EWMA、挑 hotspot/稀疏 lambda、免费 credit 或降低 3% 门抢救。单模型正结果不得进入 RDMA。

## 10. Phase 3 实现验收用例

至少实现并通过：

1. sender/receiver 身份与 remote/local closure；
2. `receiver_all_rows == top_k × valid_origin_tokens`；
3. sender-local 无法访问其他 sender/global matrix；
4. 改变其他 receiver 的本步矩阵时，本 receiver credit 只按其本地信息变化；global oracle 可变化；
5. DDRC 聚合矩阵与独立 CPU reference 完全一致；
6. 改变未来 routes/labels 不得改变当前动作；
7. padding/drop/local pair 不双计；
8. credit header/record/alignment 字节恒等式；
9. wire saving=10 us、codec=8 us、credit=3 us 时 hardgate 必须拒绝；
10. reject/late fallback 后 controller 状态回滚，但 credit tax 保留；
11. high/low payload+scale+descriptor+padding 逐字节闭合；
12. 无 overlap timestamp 自动收取全 credit tax；
13. H2D 产物强制带 `NOT_RDMA`；
14. oracle 不得劣于 deployable DDRC，否则 hard-fail；
15. formal runner 缺 Phase 4 `SIGNED-OFF` 或 code/config/protocol hash 不一致时拒绝执行；
16. partial/dev 状态只能是 `NOT_TESTED/PARTIAL`，不得生成 GO。

正式产物至少包括：`protocol.json`、`environment.json`、`source_manifest.json`、`data_manifest.json`、`topology.json`、`credit_accounting.csv`、`codec_accounting.csv`、`action_trace.csv`、`quality.csv`、`paired_bootstrap.json`、`decision.json`、`status.json`、`report.md`。
