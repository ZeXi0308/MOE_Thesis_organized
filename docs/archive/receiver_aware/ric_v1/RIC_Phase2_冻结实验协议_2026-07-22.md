### Phase-4 前口径补充 I：bucket、公平、资源与 once-only combine

Amendment I **SUPERSEDES** 本文后续任何将 closure 定义为“最后一条 contribution ingress 完成”、将完整 top-k canonical reduction 重复计入每条 contribution，或将资源图写成只有三种可计费服务的表述。主门槛、数据、模型和 arm 不变。

1. **Missing bucket**：`missing_count_bucket = popcount(missing_slot_mask)`，域为 `1..model_top_k`；不允许额外合并为 `{1,2,>=3}`。`last_sibling` 只在 `mask == (1 << chosen_topk_slot)` 时成立。receiver 的 emission signature 为 `(exact_missing_count, slack_bucket)`：跨 timestamp 任一分量变化都发 record；同 timestamp 的全部 completion 视为一个 atomic receiver batch，每 `(join,sender)` 只发最终状态一次并按合并后实际 message 收费。
2. **Slack bucket**：令 `r=(decision_deadline-now)/(decision_deadline-arrival)`；`r<=0 -> 0`，`0<r<=0.25 -> 1`，`0.25<r<=0.50 -> 2`，`r>0.50 -> 3`。timer 固定在 `arrival + {0.50,0.75,1.00} * budget`；精确边界同 timestamp 下必须先 apply bucket transition/zero-delay contract，再执行 sender schedule。R0/Rcmp/Rwire 用同一 bucket 定义。sender 可用公开 `top_k/epoch/deadline` 在 join release 初始化 full-mask 先验状态，不得将“cache 尚无 delta”任意解释为 `17/255`。
3. **Standard DRR baseline**：`sender_age_service_drr` 的 flow 是 `request_id`，每 sender 一个独立 canonical ascending request-id ring。`Q(model)` 等于 calibration service LUT 冻结的逐 contribution `sender_pack_us`，由 `ReplayConfig` 显式携带并绑定 service fingerprint，不读 sealed outcome。flow 无 ready task 时移出 ring 且 deficit reset 为 0；新活跃 flow 按 canonical ring 插入。每次 visit 先加 `Q`，flow head 按 `(enqueue_us, stable_task_id)`；仅当 `deficit_us >= sender_pack_service_us` 才可服务，服务时扣除该 service。若同 flow 下一 head 仍 ready 且剩余 deficit 足够则 cursor 留在该 flow，否则前进到下一 active flow。
4. **Candidate fairness debt** 不伪装成 DRR deficit。它是 sender-local service lag：`max_served_us_among_current_or_seen_flows - cumulative_served_us(flow)`，每条 sender-egress 完成后按实际 `sender_pack_service_us` 更新，值越大越欠服务。不得用 task age 复制充当 debt。
5. **Exact resource view**：B-level topology 使用真实 `resource_id`。sender queue、node-pair shared cut、receiver unpack/ingress 和 receiver combine 分别记账；busy work 只记 `max(0,busy_end-now)` 剩余量。receiver qdepth 可作为另一 exact aggregate，但不得用 receiver 切片代替真正 shared-cut 或 sender resource backlog。
6. **Four-stage closure**：每条 contribution 依次执行 `sender_pack -> shared_cut -> receiver_unpack`；最后一条 sibling unpack 完成时，只 enqueue 一个 join-level `receiver_combine`。combine 在 `receiver:{rank}:combine` 上 FCFS、non-preemptive，service 来自同模型 5090 实测 `canonical_reduce([1,top_k,hidden])`，每 join 只收费一次。`C_u=completion(combine_u)`，`L_u=C_u-release_u`。full drain 需同时满足 `3*N_contribution + N_join` 完成事件。
7. **Bounded comparison arms**：Rcmp0/RcmpD 与 Rwire 共用 bounded record、encode/decode、IdentityTable、按 `(receiver,sender,epoch)` 独立的单调 sequence stream 和 atomic apply。Rcmp0 只把 codec/time tax设为 0；RcmpD 只再加冻结 delay。两者不得携带 Python `JoinIdentity` 直接写 cache。
8. **Accounting/statistics**：contract header/record/alignment、produced/received bytes、四类 resource busy/service、combine count/source必须分栏且守恒。malformed 不退还 produced bytes。paired/bootstrap 必须同时绑定 task/service/resource/score-mask fingerprint、closure count 和 closure budget。deployment decomposition 只接受同 trace 且上述绑定全部一致的 rows。

### Phase-4 前口径补充 L：native top-k tie 与 slot 身份

Amendment L 记录 calibration/dev GPU smoke 在任何 formal outcome 前暴露的校验对象错误。LLM-jp 的 BF16 gate logits 存在 exact ties；原生 `MixtralSparseMoeBlock`/`OlmoeSparseMoeBlock` 在 float32 softmax 后调用 `torch.topk`，而 stable full sort 对同权 expert 采用另一 slot 顺序。二者的 selected set 可以相同，但 `topk_slot` 身份不同；因此 stable sort 不是 native route 的 exact oracle，旧实现和其 `independent_sort` 表述均 **SUPERSEDED**。

1. forward 内必须用只读 `TorchDispatchMode` 捕获当次 native `aten.topk.default` 的实际 values/indices；observer 只返回原 op 的原输出，不修改 model、input、output 或 routing。每个 active MoE layer 必须恰好捕获一次，shape/k/dim/largest/sorted 不符即 hard-fail。route row 以该次 native capture 为唯一 slot 身份来源。
2. 另一 call-site 必须精确复放 `torch.topk(torch.softmax(raw_gate_logits, dim=-1, dtype=torch.float32), k, dim=-1)`，并与 native capture 的 ordered indices 和 pre-normalization FP32 values 分别 `torch.equal`；禁止以 stable sort、set equality、epsilon 或 expert-id 二次排序替代。该 replay 是交叉校验，不冒充第二个独立 router。
3. native effective weight 主口径固定为 `topk FP32 value -> 按模型 optional renorm -> cast(native hidden dtype)`；`route_weight` 必须记录该 effective weight，pre-cast FP32 值只是诊断。每个 request/layer 必须对 ordered expert tensor 与 effective-weight tensor分别做原 dtype/shape/stride/raw-bytes hash，再合成 `(token,slot,expert,effective_weight)` tuple hash；producer 与 consumer 均校验。
4. 可信链还必须包含：gate hook 与 `output_router_logits` 在 flatten 前的原 shape/dtype/stride/raw bytes exact 一致；模型 MoE class 与实际 Python `forward` source hash 和 config exact 一致；另一条 expert execution 重建路径消费 native-captured experts/effective weights后，逐 request、逐 layer 与 unpatched native MoE output 通过冻结 tolerance。
5. `topk_slot` 始终是该次 native `torch.topk` 返回位置；即使 tied experts 的 weight 相同，也不得将 slot 改写为集合或事后 canonical expert-id 顺序。该修正不改 routing、top-k、payload、arm 或 Go/No-Go 门槛。

### Phase-4 前口径补充 N：finite-horizon exact-load workload

Amendment N 记录 calibration/dev scenario smoke 在任何 formal/policy outcome 前暴露的 workload定义不稳定性。原始 continuous-time MMPP生成器数学正确，但固定 `N=512` arrival停止时的短 trace有较大的 realized-rate方差；把 `aggregate realized rho ∈ target±0.03` 当随机硬门，会使同一冻结设计因 seed realization偶然阻断，失败后重采又会造成 selection leakage。旧 dev scenario及其 `0.9066498688` calibration诊断因此为 **SUPERSEDED_WORKLOAD_CONSTRUCTION / NOT SCIENTIFIC EVIDENCE**，不得解释为机制 No-Go。

1. 每个 `role×cell` 对冻结全部 base seeds先在无模型、无 route、无 link、无 policy的 dimensionless `mu=1` 空间生成 raw arrival/state-transition schedules；base seed整数直接作为 `random.Random` seed。原 `derivation_salt` 精确改释为 provenance namespace label，不进入 PRNG，不允许借“补 salt”换一批 realization。
2. 对该 census计算 `r_i=N/raw_last_arrival_i` 与单一公共时间伸缩因子 `s=mean_i(r_i)/target_rho`。同一 `role×cell` 的所有 raw arrival timestamp和 CTMC transition timestamp均乘相同 `s`；映射某模型时再除以该模型 primary-200 reference `mu`。Poisson 0.60、MMPP-shaped 0.85与 Poisson 0.30负对照全部使用同一算法，但各自的数值 factor独立；禁止只修失败 cell、每 trace单独缩放、只缩 arrival不缩 transition、改 seed、改 lambda/dwell、删 outlier或放宽门槛。
3. factor输入只允许 role、cell、sorted frozen base seeds、raw dimensionless schedules与 target；明确禁止模型、route、link variant、arm、policy、oracle、latency/quality或任何实验 outcome。normalized arithmetic aggregate必须在 `1e-12` absolute tolerance内命中 target；raw aggregate只作诊断，不作通过门。
4. artifact必须同时绑定 raw/normalized census fingerprints、每 trace fingerprints、factor、前后 aggregate rho、seed全集和 `NO_POLICY_OR_ORACLE_INPUT=true`。200 Gbps是唯一 normalization reference；100/400必须显式消费并绑定 primary scenario tree的 self hash，exact复用 normalized arrival、transition、block permutation和 primary-200 deadline contract，不得再次 RNG、重算 factor/`mu`或按 sensitivity重定 deadline。sensitivity只改变 contribution shared-cut service与 contract analytic transfer。
5. 由此 workload claim收窄为 **exact-load, time-normalized process-shaped replay，conditional on the frozen workload census**。MMPP cell保留 state sequence、arrival-state identity、high/low burst ratio以及 cell内 trace间相对 mean-rate变化，但不得再称为原 nominal-rate stationary CTMC-MMPP 的无条件有限样本推断。complete-trace bootstrap只量化该冻结 workload census下的 policy paired差异，不外推为 MMPP生成分布的 sampling uncertainty。

## 2. 冻结控制位置、状态与动作

### 2.1 部署候选控制闭环

```text
receiver rank:
  owns token-block join table
  contribution arrival -> update missing state
  priority-bucket transition -> encode contract to remaining sender(s)

sender rank:
  owns only its local ready-result queue
  decode/apply latest valid contract
  reorder only locally ready return tasks
```

禁止：

- 集中式 policy 免费获得跨 sender global-ready census；
- receiver 直接拥有 sender dispatch/grant authority；
- receiver 读取某 sender 尚未公开的 ready state；
- sender 读取其他 sender 的 local queue；
- 本轮加入 expert reroute、replica、precision、activation codec、drop、bandit 或 learned predictor。

本轮唯一 actuator 是：

```text
sender-local ready-result egress / return-service ordering
```

若信息只有在重排尚未 ready 的 expert compute、修改 routing 或集中式 global dispatch 时才有收益，本协议判为当前 actuator No-Go，不能扩大动作空间救活。

### 2.2 Contribution identity

```text
j = (request_id, forward_id, batch_id, phase, decode_step,
     layer_id, token_id, token_block_id, topk_slot,
     expert_id, sender_rank, receiver_rank, epoch)
```

- receiver 是 token continuation/KV owner rank，不得由 `expert_id` 或 receiver group推导；
- sender 来自冻结 expert placement；
- `topk_slot` 是逻辑 slot，不能解释为 physical rank；
- 同一 `(request,forward,layer,token_block,epoch)` 的全部有效 siblings 构成 join set；
- 主实验禁止 token drop；每个有效 token 恰有模型冻结的 `top_k` 个唯一 contribution；
- wire hash 必须通过 collision-checked full-identity table 映射，不能把 Python join tuple直接传给 policy。

### 2.3 Closure 与动作约束

对 token block `u`：

\[
C_u=completion(receiver\_combine_u),
\qquad L_u=C_u-release_u.
\]

所有 arm 固定：相同 tasks、release、service realization、bytes、resource graph、full drain、exactly-once 与 starvation fallback。每条 contribution 执行 pack/cut/unpack；最后一条 sibling unpack 完成后才在 receiver combine FCFS resource enqueue一次 canonical reduction，按冻结 `(topk_slot, expert_id)` 顺序 reduce。

| Level | 可观测信息 |
|---|---|
| `S` | sender 自己的 ready tasks、task bytes/service、receiver、request slack、age、fairness debt |
| `B` | `S` + 当前 aggregate receiver qdepth、per-link/port/shared-cut backlog 与 topology；不含 application-keyed sibling completion |
| `R0` | `B` + 当前精确 receiver join bitmap/missing siblings；零延迟、零收费，只作信息上界 |
| `C` | 完整未来 release/service/arrival；clairvoyant lower bound，只报 ceiling |

最小化目标下必须满足：

\[
J_C\le J_{R0}\le J_B\le J_S.
\]

违反单调性意味着 information API、nonanticipativity、solver 或会计错误，formal run 无效。

### 3.2 Deployment degradation chain

RcmpD: compressed contract / delayed / codec-free

\[

=(J_B-J_{R0})-
[(J_{Rcmp0}-J_{R0})+(J_{RcmpD}-J_{Rcmp0})+(J_{Rwire}-J_{RcmpD})].

### 4.4 完整背景负载

一个 workload trace固定包含 4 个不重复 request、每 request全部 128 个 token-block、所选 layer全部 top-k contributions；即每个 trace 有 512 个 exogenous token-block micro-coflow。calibration 的 64 个 request按冻结 hash分成 16 个不重叠 trace，sealed 的 128 个 request分成 32 个不重叠 trace。同一 model×cell 内禁止跨 trace复用 request/text；同一固定 route-trace group 允许在不同 workload cell 中复用以形成 common-random-number 反事实，统计始终 cellwise，禁止跨 cell pooling。

request origin 在每个 model split 的 64/128 requests 上先做 outcome-blind token-count LPT（request SHA-256 顺序，等 load 时用 `sha256(request_id||rank)` 决胜），再分 trace/cell；禁止每 4-request trace 重置 load。formal artifact 必须报告 per-rank/per-node token counts，覆盖 8 ranks 与两个 virtual nodes，否则 `BLOCKED_ORIGIN_COVERAGE`。

arrival process的单位是 token-block micro-coflow，而不是 contribution。一个 token-block的全部 top-k contributions共享同一 micro-coflow arrival，随后只叠加来自冻结 5090 LUT的 expert-ready offset；禁止把 top-k siblings独立采样为无关 arrivals。这里验证的是 route-real exogenous micro-coflow队列机制，不声称复现 autoregressive跨 token serving DAG。

- task count和 task fingerprint；
- payload/descriptor bytes；
- sender row counts与 ready times；
- service samples；

## 6. Matched-world scenario / nonanticipativity MILP

### 6.1 Matched worlds

每个 pair的 A/B 世界满足：

- 某 sender 的 local ready set、task identity、bytes、service、deadline完全相同；
- aggregate receiver qdepth、per-port/shared-cut backlog与 topology完全相同；
- 只交换两个等大小已到达 sibling的 application join identity；
- A 中 `x` 是 last missing sibling，B 中 `y` 是 last missing sibling。

pair从 calibration route/service pool按冻结 hash outcome-blind构造；每模型至少 16 pairs。

### 6.3 Phase-4 前口径补充 D：matched-world counterfactual 的 release/path

matched-world 是受控 necessity fixture，不冒充从 workload replay截取出的自然同时-ready事件。每个 pair必须从两个不同 application joins中选择两个真实 route identities，且二者共享同一 sender、receiver、shared-cut path、receiver-combine resource、payload bytes、三段 contribution service tuple与 once-only combine service；pair内显式设置相同 counterfactual `release_us=0`，两个 world只交换哪一个 identity已经由其他 siblings推进为 last-missing。选择 hash不得读取任一 arm outcome。

MILP必须表示 sender egress、shared cut、receiver ingress三段 non-preemptive contribution capacity；若用固定同路径、同 service tuple 的 flow-shop position completion预计算替代显式 start变量，必须由独立 recurrence/enumerator证明与三段 capacity formulation逐项等价；然后对 closing contribution 的 unpack completion 加上同一实测 once-only combine service，该 combine completion 才是 matched-world closure。两 world等概率时 empirical CVaR99恰为两者最大 closure，可以写 `empirical_cvar99`，不得泛化为 workload CVaR或真实tail。若 calibration route pool找不到 16 个满足同路径条件的 disjoint source traces，输出 `BLOCKED_MATCHED_WORLD_SUPPORT`，不得放松 identity/path 条件。

### 6.2 MILP variables and constraints

至少包含：

- `x[j,t,omega]`：task在 sender resource开始；
- release、exactly-once、non-preemptive service；
- sender egress、shared cut、receiver ingress capacity，以及 closing contribution 后 once-only receiver combine completion；
- join completion `C[u,omega] = completion(closing_unpack)+join_combine_us`；
- closure-budget violation binary；
- starvation bound；
- fixed task/bytes/service realization；
- information-level nonanticipativity。

对 sender `s` 与 level `L`：

\[
H^L_{s,t}(\omega)=H^L_{s,t}(\omega')
\Rightarrow
a_{s,t,j,\omega}=a_{s,t,j,\omega'}.
\]

scenario-tree node必须由独立 observation-history builder产生。约束按 sender分别施加；不能用 centralized global-ready node替代。

目标 lexicographic：

1. 最小化 closure-budget violations；
2. 固定第一目标最优值后最小化 CVaR99；
3. 再最小化 mean closure。

solver optimality gap必须 ≤1%；否则为 `BLOCKED_SOLVER_INEXACT`，不能输出科学 No-Go。

matched-world necessity门：

- `S/B` 在 information-equivalent node的 action必须相同；
- `R0` 对每 world 枚举全部 lexicographic-optimal order，只有当两 world 的 optimal first-action set 都是唯一 singleton 且 singleton 不同时才计 flip；有多重最优即 `BLOCKED_AMBIGUOUS_FIRST_ACTION_OPTIMUM`，exact flip rate ≥10%；
- 两模型 exact-oracle median normalized CVaR gap `=(B-R0)/B` ≥5%；`B<=0` 即 `BLOCKED_NORMALIZED_GAP_DENOMINATOR`。

### 7.3 Closure budget and starvation

旧 `1.10 × P99` 会使 baseline violation过低，无法诚实检验 3pp改善。本协议冻结：

```text
closure_budget(model, cell)
  = calibration-best join-blind arm 的 pooled P95 closure

isolated_path_us(u)
  = max_{j in siblings(u)}
      [expert_ready_offset_j + sender_pack_j
       + shared_cut_j + receiver_unpack_j]
    + once_per_join_canonical_combine_u

decision_deadline_us(u)
  = arrival_us(u) + 2.0 * isolated_path_us(u)

W_starve(model)
  = 4.0 * median_{u in calibration route/LUT}[isolated_path_us(u)]
```

`isolated_path_us` 只能由 route identity与 review通过的 5090/L2 service LUT在任何 policy replay前计算，不含 queue outcome、arm action或 sealed statistic。decision deadline只供 EDF/slack priority使用；`closure_budget`只供主违约指标使用；`W_starve`只供 oldest-task hard fallback使用，三者禁止互相代用。所有 arms使用同一 `W_starve`；calibration与 sealed语义必须一致。

## 9. Contract codec、因果路径与会计

### 9.1 Frozen wire layout

主 codec：16 B header + N×16 B record，message按 16 B对齐。byte order固定为 little-endian。

```text
header `<4sBBBBII>`:
  magic=`RIC1`, version:u8, sender_rank:u8, receiver_rank:u8,
  record_count:u8, epoch:u32, sequence:u32

record `<QHHHBB>`:
  join_key_hash64:u64, layer_id:u16, missing_slot_mask:u16,
  identity_tag16:u16, slack_bucket:u8, flags:u8
```

两个冻结模型的 top-k 均不超过 16；`missing_count = popcount(missing_slot_mask)`，mask 中高于 model top-k 的 bit 一律 malformed/fallback；`missing_count==1` 时 mask明确指出最后缺失 slot。`identity_tag16` 是 full join identity SHA-256 的下一段 16 bit，lookup必须同时核对 hash、tag、layer和 epoch；任何歧义或 collision均 fallback。header 的 sequence 在 `(receiver_rank,sender_rank,epoch)` stream 内单调；不同 sender 的 stream 独立，不得把发给其他 sender 的序号判为 missing。

receiver只在 priority bucket变化时向仍缺 sibling的 sender发 record。

#### 9.1.1 Phase-4 前口径补充 F：record-count-dependent control tax

同一 timestamp 的 resource completion/release 先作为 atomic receiver batch 全部生效，再应用 timer；每 `(join,sender)` 只保留最终状态 record。同一 emission timestamp、sender、receiver、epoch 的 records 按 full join identity稳定排序后打包，每条 message最多 255 records。控制税必须在 5090运行环境对每个实际可编码 `record_count=1..255` 分别测量，replay按 message的真实 record count做 exact LUT lookup；禁止把每条 message统一按 1-record税收费，也禁止插值、外推或用 end-to-end apply diagnostic与分项税重复相加。若任一所需 count缺 LUT row，formal run为 `BLOCKED_CONTROL_TAX_SURFACE`。

每个 host additive component按 `component median - 同 record_count 的 empty-harness median`记账；raw component与raw harness样本都必须保留。调整后任一 additive host component非正时不得 clamp为 0、不得改用绝对值，而应输出 `BLOCKED_CONTROL_TAX_MEASUREMENT`。`host_apply_wire_contract`只用于端到端诊断，不加入 additive total；analytic transfer不减host harness。

### 9.2 Frozen priority

```text
valid last-sibling credit
-> smaller missing-count bucket
-> smaller slack bucket
-> sender-local fairness debt
-> SRPT
-> stable full task id
```

### 9.3 Required causal path

```text
receiver state update
-> full-identity hash
-> encode
-> wire event / configured delay
-> decode
-> collision-checked lookup
-> epoch/sequence apply
-> sender cache
-> sender-local scheduler lookup
```

formal replay禁止直接构造带完整 Python join key的 ACK/contract event。

duplicate、missing、stale、out-of-order、malformed、unknown epoch和 hash collision均回退到 `calib_best_joinblind`；已产生的 bytes/time不回滚。

主 delay为 5 us；固定 sensitivities为 `0/5/20/50 us`。Rwire 在 per-receiver FCFS `state_build+hash+encode` control resource 完成后才可 transfer，到达后再经 per-sender FCFS `decode+lookup+apply+policy_lookup` resource；最后一项完成才修改 cache。不同 message 不得默认 host-control 无限 overlap。

每条 ledger至少分栏：

- contribution payload、descriptor、alignment bytes；
- contract header、record、alignment bytes；
- state build、hash、encode、transfer、decode、collision lookup、epoch apply、policy lookup；
- sender egress、shared cut、receiver ingress、combine/reduction；
- source enum、stale/fallback/fault count；
- task/full-drain/bytes/service conservation。

### 9.4 Phase-4 前口径补充 B：contribution descriptor 与 alignment

原冻结文本要求 contribution payload、descriptor、alignment 分栏，但未给 descriptor 与 alignment 的数值规则；若由 runner 默认为 0，会留下未预注册自由度。正式运行前、且在任何 calibration/sealed 结果生成前，冻结主口径为：

```text
payload_bytes = 5090 上真实 weighted expert-output tensor descriptor 给出的逐 contribution row bytes
descriptor_bytes_per_contribution = 16 B
alignment_boundary = 16 B
alignment_padding = (16 - ((payload_bytes + 16) mod 16)) mod 16
```

payload 的 dtype/elements/itemsize/layout hash 必须来自 service-LUT artifact；固定 16 B descriptor 与 alignment 是 `analytic_network` 的 virtual-EP framing proxy，不是 RDMA/NCCL 实测。三项必须分别记账，cut service 使用三项之和。不得把 16 B descriptor 隐入 payload，也不得把此口径写成真实网络 framing。该补充只关闭原协议未定的字节口径，不改变任何 Go/No-Go、统计门槛或 claim 上限。

## 10. 主指标、统计与双门

主指标：

1. complete-trace token-block `CVaR99`；
2. closure-budget violation rate；
3. P50/P95/P99只作报告；
4. control bytes/payload；
5. stale/fallback rate；
6. sender ready wait/starvation；
7. full-drain goodput与 queue utilization；
8. action flip/collapse。

统计单位只能是完整 workload trace/seed。一个 trace中的 requests共享 queue，禁止把 post-hoc request、token或 contribution当 IID样本。所有 arm在同一 trace使用相同 arrivals、tasks和 service draws。

32 个 paired traces做 cluster-level paired bootstrap。四个 `2 models × 2 main cells`使用 one-sided 98.75% LCB，等价控制 family-wise 5%；不报 pooled verdict。

相对 `calib_best_joinblind` 的主 GO 双门必须同时满足：

```text
CVaR99 relative reduction LCB >= 5%
AND
closure-budget violation absolute reduction LCB >= 3 percentage points
```

candidate 还必须在每个 model×main-cell 对每个冻结 join-blind arm 逐一 non-inferior：用相同 complete-trace paired bootstrap 计算 `candidate-baseline` 的 CVaR99 relative increase UCB 与 violation absolute increase UCB，两者都必须 `<=0`。实现必须用等价的 reduction LCB `>=0`。两主指标是每 cell 的 intersection-union gate，再对四个模型×main-cell claims 作 Bonferroni，因此 confidence 固定 one-sided 98.75%；每个 baseline 都必须通过，不允许用 calibration selection 掩盖反向结果。

## 11. G0-G3 与停止规则

### G0 — Identity/Data/Load

全部满足：

- identity closure、native-route parity、模型 revision与完整 layer census；
- calibration/sealed/historical hash隔离；
- full 128-token background load进入 resource graph；
- placement/origin可重算且与冻结配置一致；
- task/bytes/service/full-drain恒等式。

artifact缺失、producer错误或 provenance不闭合只能输出 `BLOCKED_G0`，不能科学 No-Go。

### G1 — Actuator capability

必须由可执行 5090 artifacts证明 ready-result reorder、early closure可推进明确状态以及 canonical exactness。

- target path只有 full barrier或 early closure物理效果为零：`NO_GO_CURRENT_ACTUATOR`；
- probe本身缺失/不可复算：`BLOCKED_G1`。

G1未通过不得打开 sealed G2。

### G2 — Receiver information necessity

必须同时满足：

1. matched-world MILP action flip和 exact gap门；
2. `ric_full_zero_delay` 相对最佳 `B`/join-blind baseline在两模型×两主 cell全部通过 5% CVaR99 LCB **且** 3pp violation LCB；
3. oracle monotonicity和 nonanticipativity全部成立。

失败：`NO_GO_RECEIVER_INFORMATION_VALUE_FOR_RIC_V1_ACTUATOR_POLICY`。这只判死本轮冻结 sender-local return-ordering actuator 与 lexicographic RIC-v1 policy，不外推为所有 receiver-aware policy 的信息无价值；但本轮仍必须停止，不执行 charged controller，不加新动作/改 priority 救活。

### G3 — Bounded/charged feedback-path upper bound

`ric_wire_charged` 必须：

- 两模型×两主 cell仍通过相同 5% + 3pp双门；
- charged retention LCB ≥50%，其中 `J` 固定为 complete-trace `CVaR99`：

\[
Retention=\frac{J_B-J_{Rwire}}{J_B-J_{R0}};
\]

- 每 trace 计算 contract bytes/contribution payload bytes，cell 取最大 ratio，并要求 ≤2%；
- 20 us staleness下 CVaR与violation改善 LCB仍非负；
- zero drop/duplicate、full drain、canonical equality；
- 收益不依赖单一 seed、人工-only hotspot或 analytic link的单一点值。

`policy_lookup_us` 在本协议中精确指每条 message 对 N records 执行一次 eager priority-cache refresh，不是每个 sender decision 的 queue scan。当前实现未对 candidate 的 per-decision ready-queue scan/keyed-cache access 增量建立 outcome-independent LUT，因此 G3 只是 **charged feedback-path upper bound**，不是 end-to-end online controller deployability 证据。即使全部门通过，最高 verdict 也只是 `GO_TO_IMPLEMENT_CONTROLLER_PROTOTYPE`；下一阶段必须实测并收费该 hot path。

### 11.1 Phase-4 前口径补充 G：sensitivity completeness

正式 G3必须产出 `0/5/20/50 us`全部 contract-delay sensitivities；主 candidate仍是 5 us，20 us按既有非负 LCB门，0/50只作完整边界报告，不得缺失后选择性补跑。analytic link的 100/400 Gbps sensitivities固定复用 primary-200 Gbps calibration已锁定的 join-blind arm、starvation threshold与closure budget，禁止重选baseline；scenario中的 contribution shared-cut service与 contract tax中的 analytic transfer都必须按该 sensitivity link rate由实际 bytes重算，host tax不得随link缩放。每个 model×main-cell×sensitivity link上，`ric_wire_charged`相对该 baseline的 CVaR改善 LCB和violation改善 LCB均须非负。任一为负则 G3失败，任一 artifact缺失则 `BLOCKED_SENSITIVITY_GRID`。该补充收紧“不得依赖单一点值”的可执行判据，不改变主 200 Gbps 的5%/3pp门。

### 11.2 Phase-4 前口径补充 H：formal action artifact compaction

DES内部仍须执行并验证每 contribution 的 sender-pack、shared-cut、receiver-unpack 三段事件，以及每 join 恰好一次 receiver-combine；acceptance fixture必须保留完整四类 action trace 与前驱/不重复检查。为避免 formal sensitivity grid仅因重复的 policy-invariant downstream FCFS rows产生数十 GB artifact，正式 `action_trace.csv`冻结为只持久化 **sender-egress policy decisions**；`accounting.csv`仍须保存 `3*N_contribution+N_join` completed count、四类 data resource 与 host-control resource busy/service、full-drain、combine source 与 service/resource fingerprints。compaction必须在每个 replay完成全部 conservation 后进行，不得改变 closure、metrics、wire plan、action signature或任何 gate。

通过：`GO_TO_IMPLEMENT_CONTROLLER_PROTOTYPE`。
G2通过但 G3失败：`INFORMATION_VALUE_ONLY / NO_GO_RIC_V1_DEPLOYMENT`。

## Amendment P — matched-world 下游服务纪律与独立等价门（formal 前冻结）

matched-world necessity fixture 的唯一控制动作是 sender-egress 启动顺序。同一 fixed path 上的 shared-cut 与 receiver-ingress 固定为 **work-conserving FCFS / no-overtake**：下游不得故意 idle 等待后发 task，也不得重排 sender 已决定的顺序。因此本 MILP 不声称覆盖可在下游独立 reorder 的一般三资源 job-shop。

`fixed_route_flowshop_position_completions` 的每个 formal 实例必须与独立 literal start-time 线性模型逐位置相等：后者显式包含 release、task-stage precedence、每资源 same-order non-overlap，并以最小化全部 start time 固定 work-conserving schedule。任一不等立即 `BLOCKED`，不产生 oracle verdict。`milp_instances.jsonl` 必须显式持久 `starvation_us`、下游服务纪律与四个 information level 的 observation-history node map。

本 amendment 是 Phase-4 发现的协议歧义修复；它改变 protocol SHA。修改前的 dev-v5 oracle 数字全部标记 **SUPERSEDED / NOT_TESTED**，必须在新 protocol hash 下重跑，不得沿用。
