我搜了 6 个角度。结果不太乐观——你想做的事，相邻工作已经做了不少。下面分类讲清楚撞车程度。

🚨 撞车最严重的两篇

1. MC-MoE (NeurIPS 2024, arxiv 2410.06270) — 几乎是你 idea 的"权重版"

▎ MC-MoE: Mixture Compressor for Mixture-of-Experts LLMs Gains More

它做的事：
- 把 bit allocation 写成 LP 问题（你 §6 的 ILP）
- 用 expert importance 决定 bit-width，importance 三要素：
  - expert 激活重建误差
  - routing/gate scores ← 你的核心信号
  - expert 激活频率 ← 你的 freq(l,R,B) 加权
- 加上 Online Dynamic Pruning（运行时按 token 重要性丢弃）

和你 idea 的差异：MC-MoE 量化的是 expert weights（存储侧），你量化的是 expert outputs（通信侧）。这是真差异——但是：
- "用 LP/ILP + gate value 分配 bit-width" 这个主要方法贡献已经被他们占了；
- 你能讲的故事被压缩到"把同样的方法搬到 combine 阶段的通信上"——这是应用场景的位移，不是方法创新。

2. GEMQ (arxiv 2505.23078) — Global Expert-level Mixed-Precision Quantization

▎ 直接的标题："Global linear programming for expert-level bit allocation"

这就是 LP-based expert-level 混合精度。和 MC-MoE 一起，把"用线性规划做 expert 级混合精度"这条路堵死了。

⚠️ 中等撞车的三篇

3. MxMoE (ICML 2025) — Mixed-precision Quantization for MoE

- ILP 形式化 bit-width 分配
- 决策变量：每个 linear block 一档精度
- 目标函数：accuracy loss + hardware performance
- 输出 mixed-precision GroupGEMM kernels

它和你的真差异：MxMoE 还是侧重 weight-side quantization（GEMM kernel），不是 communication compression。但ILP 形式 + 分块决策这个数学骨架你的 §6 完全一样。

4. REAP (Router-weighted Expert Activation Pruning) — 你的 drop 路径已被覆盖

REAP 给每个 expert 算的 saliency 分数：

$$S_k = \frac{1}{|X_k|}\sum_{x\in X_k}\big[g_k(x)\cdot |f_k(x)|_2\big]$$

这就是你 C1 假设里的 $g_{t,e}\cdot|o_{t,e}|$——一模一样的指标，他们用它做 pruning（>50% expert 修掉，性能掉 <8%）。

这意味着什么：
- 你 C1 假设（top-k 内部按 $g\cdot|o|$ 长尾）的指标设计不是新东西；
- "按这个指标做删减"已经被 REAP 占了 expert-level 这个粒度。
- 你能挖的角度只剩：top-k 内部 vs REAP 的 expert 池整体——这个粒度差别能不能撑起一个论文，我打个问号。

5. EAQuant (2025, arxiv 2506.13329) — 你原版引用过的

- Router-aware：minimize KL divergence between FP / quantized routing — 解决 routing drift
- 你说的 C2（routing drift 是主因）他们已经直接处理了
- 你还想做"两遍前向拆解 drift"——他们论文里已经把 drift 当成已知问题在解，不是在 demonstrate

⚠️ 真的对你致命的一篇
