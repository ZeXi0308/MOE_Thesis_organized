# PLTB跨模型复现补齐：最终结论（2026-07-20）

> 背景：2026-07-19的复核发现PLTB的判死证据本身扎实（有正规配对bootstrap检验支持），但唯一真实缺口是"从未在LLM-jp上复现，只测过OLMoE"。本文档用GPU补齐这个缺口，同时修复了`run_layer_budget_experiment.py`里此前未打过的CUDA设备迁移bug（`tokenized_inputs`未将tensor搬到`model.device`）。

## 结果：跨两模型两格式，PLTB从未显著跑赢fixed baseline

| 模型 | 格式 | 结果 |
|---|---|---|
| OLMoE (base_tail=4) | MXFP4 | `kl_profile_3_5`、`p95_profile_3_5` 显著更差(CI全负)；`gate_mass_profile_3_5`、`anti_kl_profile_3_5`、`kl_profile_2_4_6` 不显著 |
| OLMoE (base_tail=4) | NVFP4 | `kl_profile_2_4_6` 显著更差(CI [-0.001051,-0.000174]) |
| **LLM-jp (base_tail=8, 新补)** | **MXFP4** | **全部5个profile显著更差**(CI完全在0以下：gate_mass -0.00146, kl_profile_7_9 -0.00143, p95_profile_7_9 -0.00143, kl_profile_6_8_10 -0.00125, anti_kl -0.00025) |
| **LLM-jp (base_tail=8, 新补)** | **NVFP4** | `gate_mass_profile_7_9`、`kl_profile_7_9` 显著更差；`p95_profile_7_9`、`kl_profile_6_8_10` 不显著；`anti_kl` 显著更差(负对照，预期内) |

**在全部4个(模型×格式)组合、跨越两种tail粒度(base_tail=4和8)里，PLTB式的"按单层敏感度重新分配INT4/MXFP4/NVFP4 tail rank数量"这个机制，一次都没有显著优于最简单的均匀固定tail baseline。** 效果不是"边界模糊"或"偶尔有效"，而是方向一致地"不显著或显著更差"。

## 解读

这跟本项目其他几条死亡路线的证据模式一致，但提供了更完整的跨模型证据链：**层级粒度的"敏感度感知"静态重分配，在这套系统里系统性地无法跑赢均匀分配这个最简单的baseline**——校准阶段测出的单层KL排序（哪层"更敏感"）本身可能是有信息量的，但把这个排序转化成"给敏感层更多bit"这个朴素策略，在真实的多层联合效果下并不能转化为端到端质量优势。这与今天(2026-07-20)另一个发现（additive-KL建模审计：单层信息线性外推到多层组合系统性失败）指向同一个根本原因——**单层维度上可观测的信号（无论是KL敏感度还是gate mass），一旦要外推/重组到多层联合效果，就会因为残差流里的非线性交互而失真，这是本项目里第二次在独立实验中发现同一个根本机制问题**。

## 最终判定

PLTB **维持KILLED**，且现在是本项目证据链最完整的判死路线之一：2模型×2格式×2种tail粒度，全部方向一致，无一例外。不再有"未复现"这类遗留缺口。
