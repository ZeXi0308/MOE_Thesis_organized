# Idea A 最新文献与硬件格式审计（2026-07-11）

## 结论先行

本轮审计改变了论文主线：**PLTB 不能继续作为无条件核心创新；更可靠的新核心候选是 FP8-first、rank-segmented FP4 combine。**

原因不是 PLTB 的旧结果算错，而是它依赖的 per-row symmetric INT4 proxy 与真实 FP4 数值格式差距过大。换成 MXFP4/NVFP4 风格的 block-scaled E2M1 后：

- fixed tail 本身已经非常稳；
- PLTB 的层间重分配收益缩小到很弱，甚至反转；
- 但同预算 tail/head 强对照仍显著，说明 **rank 的价值保留，layer allocator 的价值暂未保留**；
- gate threshold/oracle 只比 fixed rank 小幅更好，静态 rank segmentation 仍可能用规整布局换取更高净吞吐。

因此论文问题应改为：

> 在 uniform FP8 combine 已成为强基线之后，能否利用 top-k rank 形成固定 FP8-head / block-FP4-tail 两条 lane，在质量接近动态 gate selector 的同时，减少真实 combine wire bytes，并通过融合 pack/communication/dequant/reduce 获得端到端收益？

## 2. 本轮格式对齐实现

新增：

- `fake_quant.py`：MXFP4-style E2M1（32-element power-of-two block scale）与 NVFP4-style E2M1（16-element E4M3 block scale + per-vector FP32 global scale）；
- `run_fp4_format_comparison.py`：INT4 proxy / MXFP4 / NVFP4 的 fixed 与 PLTB 对照；
- `run_signal_comparison.py --tail-precision {int4,mxfp4,nvfp4}`：同预算 rank/gate/tail-mass/oracle/head 对照；
- `run_layer_budget_experiment.py --tail-precision ...`：格式特定 layer profile。

这些仍是 fake quant quality experiments，不是 native FP4 kernel。MXFP4/NVFP4 名称表示数值格式和 scale granularity 对齐，不表示 Mac 已执行真实硬件指令。

## 3. 实验一：硬件格式会改变算法结论

OLMoE top-8，WikiText-2 held-out 32 条，test offset 128：

| 策略 | bit-only saving | scale-aware wire saving | mean token KL |
|---|---:|---:|---:|
| uniform FP8 | 50.00% | 49.61% | 0.00472 |
| fixed tail4，旧 INT4 proxy | 62.50% | 62.26% | 0.03032 |
| PLTB，旧 INT4 proxy | 62.50% | 62.26% | 0.01957 |
| fixed tail4，MXFP4 | 62.50% | 61.52% | 0.00684 |
| 旧 PLTB allocation，MXFP4 | 62.50% | 61.52% | 0.00632 |
| fixed tail4，NVFP4 | 62.50% | 60.69% | 0.00571 |
| 旧 PLTB allocation，NVFP4 | 62.50% | 60.69% | 0.00581 |

洞察：旧 INT4 proxy 下 PLTB 降低 35.5% KL；MXFP4 下只降低约 7.6%；NVFP4 下反而恶化约 1.7%。这说明 **35.5% 不是可直接外推到硬件 FP4 的方法收益**。

PPL 的小幅负 delta 不解释为质量提升；当前可信排序以同输入 token KL 为主。

## 4. 实验二：格式特定 PLTB 仍未成立

为排除“旧 INT4 allocation 不适配 MXFP4”，重新用 MXFP4 做 calibration profile，并冻结新布局在 disjoint test n=16 上复测：

| 策略 | mean token KL |
|---|---:|
| fixed tail4 | 0.007141 |
| KL-profile 3/5 | 0.007529 |
| gate-mass profile 3/5 | 0.006985 |
| anti-profile 3/5 | 0.007055 |
| KL-profile 2/4/6 | 0.007103 |

虽然单层 sensitivity 最大/最小仍约 8.6 倍，但跨层重分配没有转化成稳定端到端收益。说明“存在 layer sensitivity”不自动推出“PLTB allocator 有用”。

当前处理：PLTB 降级为 **format-dependent diagnostic / optional enhancement**，只有在更多模型、更多域和真实格式上稳定优于 fixed tail 才恢复为方法贡献。

## 5. 实验三：rank segmentation 在两种 FP4 下保留

### MXFP4，held-out n=32

| selector | bit-only saving | mean token KL | KL 95% CI |
|---|---:|---:|---:|
| uniform FP8 | 50.00% | 0.00472 | [0.00377, 0.00589] |
| fixed rank-tail4 | 62.50% | 0.00684 | [0.00565, 0.00849] |
| gate threshold | 62.90% | 0.00615 | [0.00489, 0.00790] |
| cumulative tail mass | 62.63% | 0.00633 | [0.00529, 0.00760] |
| contribution oracle | 62.50% | 0.00551 | [0.00480, 0.00641] |
| head4 control | 62.50% | 0.05987 | [0.04811, 0.07652] |

head control KL 是 tail 的 8.75 倍。gate 比 fixed rank 低约 10.1%，oracle 低约 19.5%，但二者需要更不规则的选择/布局。

### NVFP4，held-out n=16

| selector | bit-only saving | mean token KL | KL 95% CI |
|---|---:|---:|---:|
| uniform FP8 | 50.00% | 0.00468 | [0.00334, 0.00638] |
| fixed rank-tail4 | 62.50% | 0.00584 | [0.00433, 0.00780] |
| gate threshold | 62.99% | 0.00577 | [0.00435, 0.00722] |
| cumulative tail mass | 62.65% | 0.00581 | [0.00417, 0.00781] |
| contribution oracle | 62.50% | 0.00567 | [0.00432, 0.00737] |
| head4 control | 62.50% | 0.01499 | [0.01224, 0.01835] |

head control KL 是 tail 的 2.56 倍；动态 selector 与 fixed rank 几乎持平。两种格式共同支持：**tail/head 安全域是真实的，固定 rank 是有竞争力的 deployable proxy。**

## 6. 建议的新方法层级

### 核心候选：Rank-Segmented FP8/FP4 Combine

```text
routing-sorted top-k expert outputs
        -> ranks 1...h: FP8 lane
        -> ranks h+1...k: block-FP4 lane
        -> fused pack + EP combine
        -> fused dequant + gate-weighted reduction
```

建议暂名：**RaCo-FP4: Rank-Segmented Communication for MoE Combine**。

可防守的贡献拆分：

1. **Characterization**：在 MXFP4/NVFP4 对齐条件下，证明 combine tail/head quantization sensitivity 分离，并量化 fixed rank 与动态 gate/oracle 的质量差距；
2. **Method/layout**：利用 router 已排序 rank 构造静态 FP8/FP4 two-lane，无 per-output precision tag、无 token-wise scan；
3. **System**：实现 fused quant-pack / collective / dequant-weighted-reduce，计入 scale、padding、alignment、launch 与 overlap；
4. **Optional**：只有真实 P99 有额外收益，才加入 receiver-side load-aware budget；PLTB、sender oracle、MILP、drop 均不进入标题。

### 创新点不应再这样写

- “首次使用 FP8 做 MoE combine”：已有实现；
- “首次按 layer sensitivity 做 mixed precision”：MxMoE/AdapMoE 已覆盖更广义版本；
- “PLTB 已经证明优于 fixed rank”：只在旧 INT4 proxy 成立；
- “62.5% 通信下降”：目前只是 bit-only payload，含 scale 后约 60.69%～61.52%，真实净收益更低；
- “拥塞优化已改善 P99”：目前仅 trace/bandwidth proxy。

## 7. 下一轮最有信息量的实验

1. **真实 GPU kernel 生死实验**：uniform FP8 vs fixed-rank FP8/MXFP4（若硬件可用）或 FP8/NVFP4；首先测 operator latency、wire bytes、pack/unpack 占比和 crossover message size。
2. **rank split sweep**：`h/k = 1/7, 2/6, ..., 7/1`，形成真实 accuracy-wire-latency frontier，而不是只测 tail-half。
3. **格式 × 模型 × 域 transfer**：至少两个 serving MoE、general/code/math 三域；calibration 与 test disjoint，固定 split 后跨域复用。
4. **static vs dynamic layout**：fixed rank 对 gate threshold，显式测 mask、scan、variable-size buffer、metadata 和 divergence；这是论文最关键的模型—系统协同对照。
5. **端到端门槛**：相对 uniform FP8，operator ≥10%、TPOT ≥3% 或 P99 ≥5%，且任务质量在预设容忍区间；否则收缩为 characterization/workshop，而不是完整系统论文。

## 8. 当前论文级判断

- **算法证据**：比上一版更诚实，也更接近真实硬件；rank claim 保住了，PLTB claim 被削弱。
- **创新性**：单靠 Mac fake quant 仍不足 CCF B；如果实现真实 two-lane combine kernel，并证明相对现有 uniform FP8 combine 的端到端收益，有 CCF C 到 B- 的合理空间。
- **最大风险**：FP4 多省的约 11 个百分点 wire bytes，被 scale/pack/dequant/小消息开销吃掉。
- **最重要资产**：不是某个 allocator，而是已经形成了能证伪自己方法的实验闭环；当前主线比“PLTB + receiver + MILP”更窄、更可信。
