# Idea A 第二轮创新实验：Profiled Layerwise Tail Budget

> **第三轮硬件格式审计后的边界修正**：本文记录的 PLTB 收益在旧 per-row symmetric INT4 proxy 下成立，但不能直接外推到 MXFP4/NVFP4。MXFP4 下旧 allocation 只比 fixed-tail 降低约 7.6% KL，NVFP4 下反而高约 1.7%；重新做 MXFP4-specific profile 后也未稳定优于 fixed-tail。因此本文作为历史实验/negative-result 记录保留，PLTB 当前降级为 format-dependent optional enhancement。最新主线与完整数字见 `论文Idea最新文献与硬件格式审计_2026-07-11.md`。

## 结论

第二轮实验在旧 INT4 proxy 下找到了比“所有层固定 tail 数”更好的候选方法：

> **Profiled Layerwise Tail Budget（PLTB）**：在 calibration 上测量各层相对 uniform FP8 的增量量化敏感性；保持全模型 INT4 layer-rank slots 总数不变，把较少的 tail-INT4 ranks 分配给敏感层，把较多 ranks 分配给低敏感层；冻结每层 `m_l` 后在独立 test 上端到端复测。

它没有恢复旧 additive-KL MILP：单层 KL 只用于排序和生成少量候选，不被相加成端到端质量预测。运行时仍是：

```text
LUT[layer_id] -> num_int4_tail_ranks m_l
```

因此每层的 FP8/INT4 lane 长度固定，不需要逐 token gate mask、precision tag 或 variable-size selection。

## 1. OLMoE top-8 主实验

### 设置

- model：`allenai/OLMoE-1B-7B-0924`；16 layers；top-8；
- calibration：WikiText-2 validation offset 0，先 8 条、再扩大到 16 条；
- held-out test：offset 128，32 条文本、1,925 个 next-token positions；
- profile perturbation：其他层 uniform FP8，只将目标层 tail4 升级为 INT4；
- profile reference：uniform FP8；
- test reference：full/bfloat16 model output；
- 所有候选均有 64 个 INT4 layer-rank slots，理论 payload saving 均为 62.5%；
- 2,000 次 sample-level bootstrap，并进行 paired bootstrap against fixed-tail4。

### Layer sensitivity

- 最敏感：layer 15，增量 KL `0.01102`；
- 次敏感：layer 0，增量 KL `0.00636`；
- 最低附近：layer 13，增量 KL `0.00129`；
- max/min 约 `8.5×`；
- mean-KL 最优 `3/5` 和 `2/4/6` 布局在 calibration 从 8 条扩大到 16 条后完全不变。

最终 `2/4/6` 布局：

```text
m_l = [2, 2, 2, 4, 4, 4, 4, 4, 4, 4, 6, 6, 4, 6, 6, 2]
```

### Held-out 结果

| strategy | saving vs BF16 | corpus PPL | PPL Δ | mean per-token KL | KL 95% CI |
|---|---:|---:|---:|---:|---:|
| fixed-tail4 | 62.5% | 19.2381 | +0.4466 | 0.03032 | [0.02604, 0.03606] |
| KL-profile 3/5 | 62.5% | 18.9863 | +0.1948 | 0.02368 | [0.02036, 0.02830] |
| P95-profile 3/5 | 62.5% | 19.1059 | +0.3144 | 0.02411 | [0.02080, 0.02942] |
| gate-mass profile 3/5 | 62.5% | 19.1590 | +0.3675 | 0.02553 | [0.02170, 0.03100] |
| anti-KL profile 3/5 | 62.5% | 19.4425 | +0.6510 | 0.04091 | [0.03581, 0.04752] |
| **KL-profile 2/4/6** | **62.5%** | **18.9982** | **+0.2067** | **0.01957** | **[0.01759, 0.02205]** |

主要效应：

- PLTB 2/4/6 相对 fixed-tail4 降低约 `35.5%` KL；
- paired `fixed − PLTB` KL 差为 `0.01075`，95% CI `[0.00734, 0.01588]`，candidate better probability `1.0`；
- anti-profile 比 fixed 更差约 `34.9%`，支持“保护敏感层”而不是任意换层；
- PLTB KL `0.01957` 仅比动态 gate threshold 的 `0.01836` 高约 `6.6%`；
- 相对于 fixed-rank 到 gate 的质量差距，PLTB 追回约 `89.9%`。

### 机制观察

tail gate mass 与真实 layer KL sensitivity 的 Spearman 相关约为 `-0.56`。这说明“某层 tail gate mass 较大”不等价于“该层更怕 INT4”；层敏感性包含后续误差传播、残差路径和最后输出位置等影响。单纯用 router statistics 替代端到端 calibration 不够可靠。

## 2. LLM-jp top-16 跨 top-k 验证

### 设置

- model：`llm-jp/optimal-sparsity-math-d512-E32-k16-920M-A520M`；16 layers；top-16；
- calibration：8 条；test：32 条；max sequence length 128；
- fixed baseline：每层 tail8 INT4；
- PLTB：敏感层 6、普通层 8、低敏感层 10 个 tail ranks；
- 所有候选仍保持 62.5% 理论 payload saving。

冻结布局：

```text
m_l = [6, 6, 6, 6, 8, 8, 8, 8, 8, 8, 8, 10, 8, 10, 10, 10]
```

### 结果

| strategy | saving vs BF16 | corpus PPL | PPL Δ | mean per-token KL | KL 95% CI |
|---|---:|---:|---:|---:|---:|
| fixed-tail8 | 62.5% | 25.7345 | +0.3089 | 0.01739 | [0.01500, 0.02083] |
| KL-profile 7/9 | 62.5% | 25.6425 | +0.2170 | 0.01607 | [0.01405, 0.01927] |
| P95-profile 7/9 | 62.5% | 25.6994 | +0.2739 | 0.01533 | [0.01336, 0.01825] |
| gate-mass profile 7/9 | 62.5% | 25.6486 | +0.2231 | 0.01534 | [0.01340, 0.01828] |
| anti-KL profile 7/9 | 62.5% | 25.7781 | +0.3526 | 0.01702 | [0.01471, 0.02043] |
| **KL-profile 6/8/10** | **62.5%** | **25.6062** | **+0.1806** | **0.01397** | **[0.01224, 0.01637]** |

- PLTB 6/8/10 相对 fixed-tail8 降低约 `19.7%` KL；
- paired `fixed − PLTB` 差为 `0.00342`，95% CI `[0.00255, 0.00452]`，candidate better probability `1.0`；
- calibration 从 4 条扩大到 8 条后，mean-KL 的 7/9 和 6/8/10 布局完全一致；
- top-16 anti-profile 略好于 fixed，未形成 OLMoE 那样的强反向对照，因此跨模型机制结论仍需更多模型/数据域。

结论：PLTB 的收益不是 top-8 单模型特例，但跨模型证据仍属于中等强度。

## 3. Quality-Safe Critical-Flow Frontier

在 EP=8、2 nodes × 4 GPUs、16 concurrent jobs 的 bandwidth-only trace replay 中，将四种质量 selector 与 flow spending 组合：

- fixed global rank；
- PLTB layer rank；
- gate threshold；
- cumulative tail mass。

以 PLTB 为例：

| origin | spending | total saving vs BF16 | bottleneck proxy saving vs uniform FP8 |
|---|---|---:|---:|
| balanced | all safe pairs | 62.50% | 23.52% |
| balanced | random 50% safe budget | 56.25% | 11.93% |
| balanced | critical 50% safe budget | 56.25% | 23.52% |
| hotspot | all safe pairs | 62.50% | 24.83% |
| hotspot | random 50% safe budget | 56.25% | 12.42% |
| hotspot | critical 50% safe budget | 56.25% | 24.83% |

gate threshold 也呈现相同结构：critical 50% safe budget 在 trace 中保留全部 bottleneck proxy benefit，而 random 只有约一半。

严格边界：这个结果部分来自模型只把 inter-node bytes 计入瓶颈；没有 collective schedule、queueing、pack/unpack、metadata 或 overlap。因此它是 **topology-aware lane/模板设计的动机**，不是独立性能 claim。子集策略也尚未做端到端质量复测，不能直接继承 full-selector KL。

## 4. 当前最合理的论文主方法

```text
Uniform FP8 baseline
        ↓
Calibration: single-layer tail perturbation
        ↓
Profiled Layerwise Tail Budget m_l
        ↓
Static per-layer rank-segmented FP8/INT4 two-lane combine
        ↓
[optional] topology-aware remote/critical-flow template
```

建议贡献层级：

1. **Characterization**：tail/head sensitivity 与 layer sensitivity 同时存在；gate mass 不能替代真实 layer sensitivity；
2. **Method**：固定全局 INT4 budget 下的 PLTB，避免旧 additive-KL 预测，只用少量候选做 held-out 端到端复测；
3. **System**：实现静态 per-layer rank-segmented two-lane kernel，与动态 gate layout 正面对比；
4. **Optional extension**：topology-aware critical-flow template，只有真实 collective/P99 有额外收益才保留。

## 5. 下一步

- 增加 general/code/math 跨域 calibration→test transfer；
- 在更大 serving MoE 上验证 `m_l` 稳定性；
- 将 profile 成本从 16 次单层测试进一步降为少量 probe 或在线部署前快速 calibration；
- 实现 R-layout（PLTB）与 G-layout（gate threshold）的真实 kernel；
- 报告 mask/scan/metadata/variable-size buffer 与定长 two-lane 的完整成本；
- 多 GPU 上达到 operator 相对 uniform FP8 `10%～15%`、TPOT `3%` 或 P99 `5%` 门槛后，才能写系统加速 claim。
