## 2. 两条技术轴

1. **Combine / Dispatch 通信** — Idea A（结构基础）+ Receiver（条件性在线控制）。  
2. **Expert 计算精度** — Idea B 影子验证；Energy-SLO 为能耗备线。  
Quality debt 可作第二贡献/附属，不撑主线。

## 3. 各 Idea：演进 → 现状 → 下一步

### 3.1 Rank 长尾 + FP8-first（Idea A）

| 阶段 | 内容 |
|---|---|
| 早期 | Mac 仿真 + rank/LUT/tail-INT4 扫描，主张「尾部可压、头部不可乱压」 |
| 强化 | GPU LUT 严格复核 + bootstrap CI（OLMoE / LLM-jp），尾相对头安全边际大 |
| **现状** | **结构质量证据 GO**；约 62.5% 低比特饱和的 FP8-first Pareto 可写进基础章 |
| **不做** | 把它包装成多卡 RDMA P99 系统贡献；不做在线自适应（那是 Receiver） |
| **下一步** | 维持为 motivation / 基础章证据；新实验优先级低于 Existence Test 与 Energy/B |

### 3.2 Receiver-aware

| 阶段 | 内容 |
|---|---|
| v1–v2 | 用 receiver 压力选 low-bit lane；hotspot 下**静态 calib profile** 可拿大部分字节收益 |
| v3 HHI | 「自适应全面优于固定」→ **因果审计撤回**，勿再当主结果 |
| Progressive | 等 wire / residual 路线 → **判死**（归档） |
| Codec 2026-07-21 | 均质 FP8→INT4 微基准 serving 点仍紧；纠正会计后，**`once_per_step` 主口径下 hotspot 可正净收益**；serialized 仅敏感性 |
| **现状** | **结构画像可信；在线控制器条件性**。已有 CPU/pilot 规模 Existence Test 结果倾向「粗粒度策略覆盖」；正式全配置 GPU 复现若未齐，不以单次 pilot 单独封死论文叙事 |
| **下一步** | 核对/补齐 Existence Test 正式 GPU 跑数；仅明确 Go 后再谈多节点 RDMA。详见 next_direction 与 [`../ideas/receiver_aware/设计说明.md`](../ideas/receiver_aware/设计说明.md) |

Codec 要点（全文见专文）：主配置 `require_positive_net_saving` + `codec_tax_mode=once_per_step` + `homo_int4`；H2D ≠ RDMA。

### 3.3 Verify, Don’t Predict（Idea B）

| 阶段 | 内容 |
|---|---|
| H1 | 短 horizon 量化风险**弱持续** → 杀「预测脆弱专家」路线 |
| H2 | 固定 period≈4 影子验证 + 精度上调：OLMoE harm 降幅过线；LLM-jp 近门槛 |
| 附属负结果 | AIMD 自适应周期、双轴联合 POC → **不扩展** |
| **现状** | **条件 GO**：反应式验证比预测更干净；离线质量 ≠ 已证 wall-clock 吞吐 |
| **下一步** | 真实 in-loop 双算 / 切换开销 + wall-clock；**不依赖多 GPU** 亦可推进 |

### 3.4 Energy-SLO Precision EP

| 阶段 | 内容 |
|---|---|
| P0 | batch 1→64 ≈17× J/token；FP8 vs BF16 ≈2× 吞吐、~34% matmul 能耗降；expert FFN KL 小 |
| **现状** | **单卡杠杆真实，最稳备线**；缺 arrival×batch×precision 联合 Pareto |
| **下一步** | 可先单卡做联合 Pareto；多 GPU 再计入 NIC/通信等待能耗 |

### 3.5 Quality debt / Isolation

| 阶段 | 内容 |
|---|---|
| Oracle | 文档配额显示 P95 KL 改善空间 |
| Leakage 纠正 | 「test 上选 best_proxy」作废 |
| Debt | predictor-free 约 11–12%，**未过预注册 20%** |
| **现状** | **弱正 / 第二贡献候选**，非主杀也非主线 |
| **下一步** | 仅在主机制需要「租户公平」附属章时引用；不单独立项抢救 |

## 4. 验证与多 GPU 优先级

1. **Receiver Existence Test** →（仅 Go 后）多节点 RDMA / critical-path lane。  
2. **Energy-SLO 联合 Pareto**（可先单卡 arrival）。  
3. **Idea B in-loop + wall-clock**（可单卡）。  

明确**不因「有多 GPU」重启**已归档路线（TokenRace、Prefetch 系统、CreditReduce、PLTB 主创新、Progressive、RouteFidelity、MassCover、WaveCredit 等）。

---

## 5. 论文收束（诚实版）

- 主机制在 **Idea B 影子验证** 与 **Energy-SLO** 中二选一写深。  
- **Rank 长尾** 做 motivation / 基础章。  
- **Receiver** 写清：结构证据 + 条件性边界（或 Existence Test 负结果）；勿展开已归档判死路线。  
- **Quality debt** 最多作第二贡献一句。
