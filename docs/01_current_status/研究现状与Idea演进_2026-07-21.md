## 3. 各 Idea：演进 → 现状 → 下一步

### 3.1 Rank 长尾 + FP8-first（Idea A）

| 阶段 | 内容 |
|---|---|
| 早期 | Mac 仿真 + rank/LUT/tail-INT4 扫描，主张「尾部可压、头部不可乱压」 |
| 强化 | GPU LUT 严格复核 + bootstrap CI（OLMoE / LLM-jp），尾相对头安全边际大 |
| **现状** | **Claim 1 结构证据 GO**；`SUPERSEDED`：「62.5% Pareto 已严格跨模型 GO」。Claim 2 实现按全扫描最差点判决，OLMoE 安全边际 4.6519<5，跨模型 NO-GO |
| **不做** | 把它包装成多卡 RDMA P99 系统贡献；不做在线自适应（那是 Receiver） |
| **下一步** | 只把 matched-byte 头/尾结构写为 motivation；62.5% 仅作探索性点，需 metadata-aware wire + 强动态 selector + 真 kernel 才能升格 |

### 3.2 Receiver-aware

| 阶段 | 内容 |
|---|---|
| v1–v2 | 用 receiver 压力选 low-bit lane；hotspot 下**静态 calib profile** 可拿大部分字节收益 |
| v3 HHI | 「自适应全面优于固定」→ **因果审计撤回**，勿再当主结果 |
| Progressive | 等 wire / residual 路线 → **判死**（归档） |
| Codec 2026-07-21 | 均质 FP8→INT4 微基准 serving 点仍紧；纠正会计后，**`once_per_step` 主口径下 hotspot 可正净收益**；serialized 仅敏感性 |
| **现状** | **结构画像可信；在线控制器未定**。`SUPERSEDED`：把已有 Existence Test 当作纠正后主配置的最终 NO-GO；实际入口未启用 `require_positive_net_saving`且未记 H2D tax |
| **下一步** | 仅重跑一次冻结的 `once_per_step + homo_int4 + positive-net-saving + H2D` 两模型协议；不过就停，过了再谈 RDMA |

Codec 要点（全文见专文）：主配置 `require_positive_net_saving` + `codec_tax_mode=once_per_step` + `homo_int4`；H2D ≠ RDMA。

### 3.3 Verify, Don’t Predict（Idea B）

| 阶段 | 内容 |
|---|---|
| H1 | 短 horizon 量化风险**弱持续** → 杀「预测脆弱专家」路线 |
| H2 | `SUPERSEDED`：固定 period≈4 「OLMoE harm 降幅过线」。代码只对 all-INT4 KL 轨迹掩码，没有执行策略自身的 KV 状态演化 |
| 附属负结果 | AIMD 自适应周期、双轴联合 POC → **不扩展** |
| **现状** | **H1 NO-GO；H2 未验证**。现有 per-step CSV 不能修复混合精度导致的 KV/路由状态反事实错误 |
| **下一步** | 从同一 KV 状态 low+high 双算，每个 policy 独立 in-loop 执行并记 cache/计算/能耗；**不降低原门槛** |

### 3.4 Energy-SLO Precision EP

| 阶段 | 内容 |
|---|---|
| P0 | 固定 seq=64 full-forward 下 batch 1→64 约 17× J/token；预 cast 的 FP8 GEMM-core 约 2× 吞吐、~34% 单 GEMM 能耗降；单独质量路径 expert FFN KL 小 |
| **现状** | **硬件 characterization，非 serving GO**；无 KV decode、arrival/queueing/P99，FP8 能耗与质量两条路径未端到端合并 |
| **下一步** | 单卡真 decode + 冻结 arrival trace + P99；计 activation quantize/scale/cast 的完整 FP8 路径，再对比最佳单轴 controller |

### 3.5 Quality debt / Isolation

| 阶段 | 内容 |
|---|---|
| Oracle | 文档配额显示 P95 KL 改善空间 |
| Leakage 纠正 | 「test 上选 best_proxy」作废 |
| Debt | 表面 predictor-free，但 realized KL harm 需 BF16 reference 才可观测；仅 16 个值上合成请求流，点估计约 11–12%，**未过预注册 20%** |
| **现状** | **NO-GO**；「方向真实显著/零代价」不成立，不作第二贡献 |
| **下一步** | 停止抢救；只有新的可部署 harm estimator 或显式计入 shadow 成本时才是新问题 |
