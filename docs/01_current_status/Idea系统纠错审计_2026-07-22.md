> 口径：只用仓库现有文档、代码和产物；未重跑 GPU/RDMA 实验的地方标为「未验证」。  
> 严重度：**P0** = 足以推翻当前主结论；**P1** = 必须收窄 claim/重跑才能继续；**P2** = 可复现性或表述边界问题。

## 2. P0 纠错与最小验证

### 2.1 Idea B：离线掩码不是闭环策略执行

**错误证据**

- `docs/ideas/B_verify_precision/experiments/run_expert_precision_persistence_shadow_verify_p0.py:235-268` 对同一 full-precision prefill 分别独立跑完 all-BF16 和 all-INT4 decode，两条 KV 历史从第一个 decode step 后就分叉。
- `:377-412` 没有重跑 `reactive`；它只在固定 all-INT4 KL 轨迹上用 `kl_trajectory[~high_reactive]` 把 high step 设为零。这等价于假设「经历过 low KV 历史的某个 high step = all-BF16 reference」，不成立。
- `high_frac` 把 verify step 记为一次 high，未记同一状态上 low+high 影子双算、KV clone/切换和被拒路径成本。

**结论级别**

- 文档写错：「OLMoE H2 GO」和「当前主线核心机制」应标 `SUPERSEDED`。
- 代码做错：代码实现的是 off-policy counterfactual masking，不是文档所说的 in-loop controller。
- 科学结论翻了：H1 仍 NO-GO；H2 从「条件 GO」改为「未验证」，现有 CSV 不能事后修复。

**最小重跑**

1. 每个 verify step 从**同一当前 KV** clone 出 low/high 两路，同时前向一次得到即时 KL。
2. 按策略选定 served logits 和唯一 canonical KV；此后路径必须从该 KV 继续，每个 policy 端到端独立执行。
3. 对照 `always_low`、纯 fixed-period（不 escalate）、`reactive`、`always_high`；周期/阈值只在 calibration 冻结，两模型 held-out 判决。
4. 账本同时记 low/high kernel、cache clone/switch、显存峰值、TPOT/P99 和 J/token。不用「理论权重字节」替代实际成本。

### 2.2 Energy-SLO：双微基准不等于 serving Pareto

**错误证据**

- `docs/ideas/energy_slo/experiments/run_energy_slo_power_probe.py:104-145` 重复调用 `model(input_ids)`，每轮把 `batch×64` 全部计 token；这是 prefill-like full forward，不是 KV-cache decode TPOT，也没有 batch accumulation 等待。
- 原始 CSV 给出 batch=1 为 450.07 tok/s、235.87 mJ/token，batch=64 为 19550.99 tok/s、13.5869 mJ/token。这证明固定 shape 下利用率提升，不证明 arrival-aware SLO 控制。
- 文档同时给出 142.2ms 和 209.5ms，后者更大；「SLO>210ms 时 batch64 在延迟和能耗两维严格支配」是概念错误。正确表述是「batch64 在该代理 latency 门槛下可行，并在已测点中 J/token 最低」。
- `run_energy_slo_power_probe.py:188-207` 在计时前一次性构造 `x_fp8/w_fp8`；但真实质量路径 `run_energy_slo_fp8_compute_quality_gate.py:177-195` 每次都做 float/amax/scale/cast。因此 34.3% 只是 GEMM-core 数，不是端到端 FP8 机制能耗。

**最小重跑**

1. 用 prefill + 逐 token KV decode，引入冻结的 Poisson/bursty arrival trace，记 queueing + accumulation + service 的 P50/P99 TPOT。
2. batch 顺序随机交错，多次 trial；同时报 total J/token 和减 idle-power 后 dynamic J/token。
3. 计时 actual FP8 path：activation quantization、scaling、dispatch/GEMM/dequantization 全含；与最佳 batching-only 和 precision-only controller 比增量。
4. 保持原先 10% 能耗改善、P99 不恶化 >3% 的门槛；不放宽。

### 2.3 Idea A：结构 GO，预注册 Claim 2 跨模型 NO-GO

**错误证据**

- 脚本文档字面 `run_idea_a_rank_lut_gpu_rigorous_verify.py:42-50` 同时写了「every point」和「closest to 62.5%」；真实实现 `:254-268` 取所有 `fp8top*` 的 `worst_fp8_tail_ci_high`。设计文档的预注册口径也是扫描最差点。
- OLMoE report：Claim 1 比值 48.11×，paired diff CI [0.193556,0.214369]，GO；Claim 2 最差安全边际 4.6519，**NO-GO**。LLM-jp 对应 117.35×、CI [0.193177,0.207602]，Claim 2 边际 5.7825，GO。
- `experiments/shared/policies.py:636-639` 的 `byte_saving()` 只加标量 `BYTE_SIZES`，没有 scale metadata/header/padding/alignment。文档所称「含 scale metadata 的 wire bytes」与代码不一致。头/尾对照仍因 matched action 而成立，但 50/62.5/75% 是逻辑 payload 比例。
- 设计文档残留的旧 additive 倍数/「可加性证伪」已被 2026-07-21 增量会计纠正推翻，必须 `SUPERSEDED`，不再重述作废数字。

**结论级别**

- 科学结论不是 A 整体死：Claim 1 是本仓库最干净的 matched-byte 结构证据。
- 翻转的是「Claim 2 严格跨模型已 GO」；62.5% 可报探索性 point estimate，不可代替已冻结扫描门槛。

**最小重跑**

1. 事前只选一个门槛：若主张是 62.5%，就在全新 holdout 只测该点；若主张是 frontier，保留全扫描最差点。不用当前数据事后改门。
2. 实现 metadata-aware serialized bytes，显式列 scale granularity、header、padding/alignment；逻辑 payload 仅作敏感性口径。
3. 同 budget 对比 fixed-rank 与已显示更低 KL 的 gate-threshold/tail-mass；固定 rank 只能靠实际 kernel 规整性获得系统增量。

### 2.4 Quality debt：「predictor-free」隐藏了标签可观测成本

**错误证据**

- `run_quality_debt_fairness_p0.py:153-185` 先从经验 KL 值生成每轮每租户的反事实 harm matrix，debt 再根据累积 harm 选人。但这个 harm 是 degraded logits 相对 BF16 reference 的 KL；真系统若没有 BF16 shadow，并不能读到它。
- 产物每个 action 仅 `n_documents=16`；200 rounds/2000 trials 只是对这 16 个值合成重抽样，不是请求总体的采样不确定性。
- `cvar_fraction=0.1`、`num_tenants=12`，代码 `round(12×0.1)=1`，所以报告中 CVaR 与 worst 完全相同，不是独立 tail-risk 证据。
- 即使按该乐观模拟，四个 action 也只改善 10.63%–12.45%，全部未过预注册 20%。

**判决**

这是「实验逻辑错误 + 纠错后仍死」：现有「方向真实显著」不能作总体统计声明，而点估计本身又没过门。不要通过降到 10% 门槛或增加合成 rounds 抢救。

### 2.5 Receiver-aware：当前「最终」实验没跑纠正后的 action policy

**错误证据**

- `receiver_lane_policy.py:65-76` 默认 `require_positive_net_saving=False`、`codec_h2d_us=0`。
- 修复前的 `run_receiver_aware_task_quality_gpu.py:125-145,912-932` 无 hard-gate/H2D/measured-rows CLI，构造 `ReceiverPolicyConfig` 时也没传这些字段。因此已有 OLMoE/LLM-jp 产物实际是乐观 no-hardgate policy，不是文档声称的 `require_positive_net_saving + once_per_step + homo_int4` 主配置。
- 已有乐观跑数中精细 arm 仍无稳定 GO 区间，是重要负向信号；但 hard gate 会改变动作序列和质量，不能由旧 trace 直接宣告纠正策略已 NO-GO。

**已做代码纠正**

`run_receiver_aware_task_quality_gpu.py` 现在默认开启 positive-net-saving hard gate，显式传入 H2D tax 和 measured rows，并保留 `--no-require-positive-net-saving` 仅供复现旧乐观口径。该修复尚未执行 GPU 重跑。

**最小重跑**

1. 用相同端到端任务脚本、两模型相同样本数/学科，冻结 `once_per_step + homo_int4 + require_positive_net_saving + H2D`。
2. 保留 `serialized_tiles` 仅作悲观敏感性；不把 H2D 称 RDMA。
3. 事前冻结 harm 主口径和 lambda/Pareto 判决；不从稀疏 lambda 网格事后挑孤立 winner。
4. 只有两模型/工作负载复现且相对最强粗粒度基线过原 3% 门，才进真 RDMA。

## 3. 归档结论的范围纠正

1. **Additive-KL**：旧的非可加倍数及「残差流非线性已证伪」全部 `SUPERSEDED`。只可引增量口径 ratio=1.076、95% CI [0.983,1.165]；结论是可加性未决，不是 MILP 已复活。
2. **Residual/Shadow**：证据只支持杀 `mean(all experts)` shared base + training-free truncated SVD。它不支持「训练也无法改变表示能力」；学习 shared base/蒸馏 shadow 未验证，但也不建议在本论文时间窗重开。
3. **QuotaEP**：Gate C 从未跑，所以是「归档/未闭环」，不是「系统主张已被实验证伪」。
4. **WaveCredit**：是 prior-art/novelty 层面毙掉的未实验 idea，不是实证负结果。
5. **Placement/RouteFidelity/MassCover**：负结果只对冻结 topology、placement pool、proxy 和逻辑会计成立；不外推为「placement/路由结构/影子副本在任何 serving 中都无用」。

## 4. 代码可复现性审计

- 静态编译初始失败 14 个归档脚本：目录迁移脚本把 shared-lib bootstrap 插到 `from __future__ import annotations` 之前，触发 `SyntaxError`。已只移动 future import 到模块 docstring 之后，全库 `compileall` 通过。
- `experiments/shared/capture_moe.py` 仍顶层 import 已迁入归档的 `creditreduce_reference.py` / `grouped_owner_combine.py`，导致任意活跃脚本在 import 阶段失败。已加入明确的归档兼容路径；Receiver 入口 `--help` 已可正常解析新 hard-gate 参数。
- 用项目 `.venv` 直接执行现有 10 个 dependency-light test entrypoint（Receiver、CreditReduce、MassCover、QuotaEP、Residual、RouteFidelity），全部 exit 0；本次没有运行需模型权重/GPU 的实验。
- 多个归档脚本的 CLI default/冻结 protocol 仍指向迁移前 `experiments/idea_a_mac/...`；这些是**历史配置或失效默认路径**，不能不经 manifest 核对直接重跑。
- 本次没有用修复后脚本生成新科学数字；归档 verdict 仍以原始产物和已有 errata 为准。

## 5. 当前收束建议

1. 论文立即可写的只有 **Idea A Claim 1 matched-byte 头/尾结构性结果**；不把它升格为 RDMA 系统贡献。
2. 若只允许一条新实验，先做 **Idea B 正确 in-loop falsification**：它当前是最严重的假正结果，而且单卡可验证。
3. Receiver 只做一次硬门槛配置重跑；不过就停，不进多节点 RDMA。
4. Energy-SLO 若无法补齐 arrival/P99/端到端 FP8 账本，就只作硬件 characterization，不作主机制。
5. Quality debt 与 12 条归档路线不再抢救；仅保留负结果、勘误和可复用实验基础设施。
