## 1. 当前状态

### 当前研究问题

在单张 RTX 5090 可完成必要性验证的约束下，寻找具有明确动作空间、可形成强
baseline、且成功后能自然扩展到多 GPU MoE serving 的机制。Receiver-awareness 与
Energy-SLO 是两条独立命题，不以“联合大控制器”拼接。

### 已知结论

- `[Observed]` OLMoE 与 LLM-jp 已有完整 router logits、expert identity、token/
  request 文档指标、NLL/KL，以及 BF16/FP8/INT4/drop 资产。
- `[Observed]` LLM-jp prefill router/NLL 对 fixed-tail INT4 文档 KL 风险存在中等、
  可冻结复现的排序信号；到达时预测、首 chunk、worst-request、跨模型与公平闭环
  尚未成立。OLMoE 不稳定。
- `[Observed]` RouteShare Gate-0 为 NO-GO：matched histogram latency effect 仅
  2.35%–3.06%，强简单模型 held-out R2 为 0.9971–0.9986。
- `[Observed]` route-row 动态 FP8 为 NO-GO：真实 expert path 中 activation
  quantization 吞掉 GEMM 收益；只有不现实的 4096 rows/expert 局部交叉。
- `[Observed]` QuantizeOnce/Fused-dispatch 的 Python/现有算子版本仍比 BF16 慢
  76%–98%；但成本分解显示预量化 FP8 GEMM 本身在大 row 有 36%–48% headroom。
- `[Observed]` receiver 固定目的地、全任务 full-drain 重排为 NO-GO：CRQM 的
  headroom 与首动作翻转均为 0。
- `[Observed]` synthetic matched receiver tail 有 13%–16% oracle gap，但首动作
  翻转仅 0%–12.5%，不足以证明 early receiver information necessity。
- `[Observed]` native route 结构中 many-to-one fan-in 很强：两个模型 1024 个
  receiver-wave 均为多 join、多 sender；这只是结构证据，不是真实 temporal incast。

### 尚未解决的问题

1. 自然 expert-ready 时间关系下是否真的存在 receiver busy period 与早期 credit
   冲突；若存在，join state 是否胜过 request-FCFS/EDF/receiver credit。
2. 能否通过改变目的地、工作量或 admission，而非固定任务重排，产生物理 headroom。
3. 弱风险排序如何转化为预算分配/回退收益，而不是追求精确 KL 回归。
4. 在显存受限时，route locality 是否足以支持 residency/prefetch，且错误预测代价
   是否低于 PCIe/加载收益。
5. 能否通过真实 fusion 去除 dynamic FP8 的 activation-quantization 税。
6. Energy-SLO 尚无完整 board-energy、同质量、同完成任务的闭环。

### 可复用代码

- route capture、router logits、expert selection 与完整 identity validator；
- OLMoE/LLM-jp 两模型加载及真实 expert 权重 benchmark；
- BF16/FP8/INT4/drop、NLL/KL、bootstrap/permutation test；
- receiver queue calibration、matched MILP、CRQM 与 incast route census；
- route-row FP8 cost decomposition 与 QuantizeOnce gate；
- NVML/CUDA Event 相关测量骨架，但 Energy-SLO 正式会计仍需重审。

### 主要风险

- 单卡虚拟 receiver 只形成 L2/L3 证据，不能外推 NCCL/RDMA；
- 路由对齐构造的 wave 不等于真实时间重叠；
- 学习型 predictor 容易被简单 ranking/abstention baseline 覆盖；
- residency 方向与已有 expert caching/prefetch 工作拥挤；
- 动态量化若没有 fused producer kernel，控制策略没有可用执行区间；
- quality/energy/latency 三者若不使用同一完成任务与同一时间窗，会产生伪 Pareto。

## 2. 候选 Idea 池

### I1 — Join-Deficit Credit（Receiver 主线候选）

- **研究问题：** bounded receiver ingress 下，当前 join 缺口能否为下一枚 credit
  提供 aggregate queue/slack 无法恢复的信息？
- **核心假设：** 在自然 temporal incast 窗口中，优先发给可闭合 join 的 sender，
  相对 RR、oldest-ready、EDF、request-FCFS 将 closure CVaR95 降低至少 10%。
- **差异/机制：** 不是改 router，也不是 receiver 内部重排；receiver 发出有限 credit，
  动作发生在 contribution 进入拥塞域前。只使用当前 bitmap，不读未来。
- **为什么可能有效：** native route 已确认多 sender fan-in；旧 NO-GO 明确缺少的正是
  multi-sender、bounded buffer 与 early admission。
- **5090 验证：** 真实 route + 实测 pack/unpack/expert service；捕获单卡真实完成间隔，
  构造不改变相对 ready order 的 L2 replay。不得称网络结果。
- **最小实验：** 先做 temporal-overlap existence gate；若自然冲突不足 10% 即停。
- **指标：** action flip、closure CVaR95、deadline miss、starvation、总 work。
- **负结果：** request-FCFS 覆盖 candidate；ready skew 使 buffer 从不饱和；bitmap
  信息到达太晚。
- **论文价值：** 若单卡信息门和后续多 GPU 物理门都过，可形成 receiver-driven
  join admission 系统；单卡正结果本身只够机制证据。
- **难度/成本：** 中高；Level 0/1 一天内可判方向。

### I2 — Alternate-Receiver Rescue（改变目的地的拓扑机制）

- **研究问题：** 当 closing sibling 将进入热点 receiver 路径时，是否值得在已有
  expert replica/等价执行位置中选择另一条返回路径？
- **核心假设：** 只对预测为 last/critical sibling 的少量任务 reroute，可在额外
  work <=3% 下减少至少 10% closure tail。
- **差异/机制：** 固定路由语义与 expert 权重不变，改变物理 replica/destination；
  与纯 expert placement 不同，动作由在线 join frontier 触发。
- **为什么可能有效：** 旧重排 NO-GO 的根因是固定目的地和固定工作量；本机制明确
  改变该不变量。
- **5090 验证：** route replay + 5090 实测 expert/transfer service，枚举两个 replica
  的 causal upper bound；单卡只证明机会成本是否存在。
- **最小实验：** 每个真实 join 至多允许一个 sibling 使用 alternate replica；与静态
  balanced placement、least-queue replica、no-replica 对比。
- **指标：** tail gain、reroute率、额外 bytes/work、错误 rescue 率。
- **负结果：** least-queue 已覆盖；复制权重显存成本过高；critical sibling 在决策时
  不可识别。
- **论文价值：** 高，但 prior-art/实现风险高；需要真实多 GPU 才能完成 claim。
- **难度/成本：** 高；单卡 oracle gate 数小时。

### I3 — Receiver Admission Necessity Test（建模候选）

- **研究问题：** 不直接优化 tail，而是判断 receiver state 何时必然改变首动作。
- **核心假设：** 可由 `(fan-in, ready skew, buffer occupancy, join deficit)` 的可解释
  区域刻画 action-flip support，并在 holdout route windows 保持稳定。
- **差异/机制：** 目标从预测 latency/KL 改为预测“是否值得查询/传播 receiver state”；
  否则走零协调 baseline。
- **为什么可能有效：** matched MILP 有 oracle gap但 action flip稀少，说明信息价值
  是稀疏事件，平均 controller 会浪费协调成本。
- **5090 验证：** exact small-horizon enumerator 生成标签；用规则树/logistic 与
  always-query、never-query 比较。
- **最小实验：** request-disjoint split，特征只含决策时可见量；测 flip precision/
  recall 与 net value after query tax。
- **指标：** action-flip AUCPR、net saved service、false-query tax、coverage。
- **负结果：** flip support 太小或简单 occupancy threshold 已完全覆盖。
- **论文价值：** 单独偏建模；更适合作 I1 的低开销控制面，不单独立主线。
- **难度/成本：** 低；半天内可判死。

### I4 — Route-Set Residency Admission（显存/缓存主线候选）

- **研究问题：** 显存只能驻留部分 experts 时，是否应按 ready requests 的 expert-set
  overlap 决定 admission，而不是只按 LRU/LFU 淘汰？
- **核心假设：** 在相同显存上限和质量下，route-set admission 相对 LRU/LFU 与
  popularity prefetch 将 PCIe weight bytes/P99 降低至少 10%。
- **差异/机制：** 不改变 token route；把 request admission 与 expert cache working
  set 联动，并显式计 starvation debt。不能把简单 overlap packing 当 novelty，增量在
  memory-capacity miss 与 admission 的闭环。
- **为什么可能有效：** 已有 route trace；模型 expert 数与 32GB 可通过人为但明确的
  cache cap 形成可控 residency 压力。
- **5090 验证：** GPU/CPU 两级 expert store，真实 pinned-memory H2D 与真实 expert
  execution；先用 trace replay筛选 cap。
- **最小实验：** cache cap 10%/25%/50%，连续请求；LRU、LFU、Belady oracle、
  overlap-only、candidate。
- **指标：** H2D bytes、miss stall、P95/P99、throughput、starvation。
- **负结果：** working set 无局部性；Belady headroom <10%；调度等待大于加载节省。
- **论文价值：** 中高，但与 expert caching/prefetch prior art 碰撞大，需证明新的
  admission/cache coupling necessity。
- **难度/成本：** 中；Level 0/1 一天内。

### I5 — Abstaining Prefetch with Regret Budget（预测/缓存建模）

- **研究问题：** prefill 信号不够精确时，能否只在预期 regret 为负的请求上 prefetch？
- **核心假设：** 带 abstention 的集合预测在相同 recall 下，比 top-N popularity/
  always-prefetch 减少至少 20% wasted bytes，且不增加 P99 miss stall。
- **差异/机制：** 不追求 expert heat 精确回归；输出 `prefetch / abstain`，损失函数
  直接计 false-prefetch bytes 与 false-negative stall。
- **为什么可能有效：** LLM-jp 有中等 prefill-to-tail 信号，但跨模型不稳；abstention
  正适合弱、模型依赖的信号。
- **5090 验证：** 现有 prefill/decode route trace + pinned H2D cost LUT；先离线 replay，
  再小规模真实 offload。
- **最小实验：** logistic/规则阈值、conformal set、popularity、last-window、oracle；
  model-specific calibration，禁止宣称跨模型泛化。
- **指标：** regret、wasted bytes、miss stall、coverage、P99、calibration error。
- **负结果：** abstention 后 coverage 太低；last-window 已同样好；真实 H2D 无法 overlap。
- **论文价值：** 中；需要和 I4 二选一，不能硬拼。
- **难度/成本：** 低中；数小时。

### I6 — Risk-Ranked Precision Budget（Energy-SLO 主线候选）

- **研究问题：** 弱风险信号是否足以做跨请求预算排序，即使无法精确预测 KL？
- **核心假设：** 在固定 BF16/低精度执行配额下，风险排序 + 不确定时回退，相对随机、
  FIFO、长度/NLL阈值降低 worst-request violation 至少 20%，总能耗不劣化。
- **差异/机制：** 问题从 KL 回归改为稀缺高精度机会的 opportunity-cost 分配；输出
  排序/分层而非连续误差。
- **为什么可能有效：** LLM-jp 已有冻结 proxy 的中等相关性；排序可能比 worst-case
  精确识别更容易。但 OLMoE 不稳，必须允许模型特定结论。
- **5090 验证：** 复用 BF16/FP8/INT4/drop 与文档级 KL/NLL；先离线 sealed allocation，
  后用真实 latency/board energy 执行。
- **最小实验：** 每批固定 q% BF16，其余低精度；random、NLL、router entropy、
  length、oracle ranking、candidate。
- **指标：** violation@budget、CVaR KL、worst-decile recall、J/token、latency。
- **负结果：** 排序不胜 NLL；在 OLMoE 反向；dynamic execution无能耗收益。
- **论文价值：** 中高，前提是执行策略本身有真实 energy operating region。
- **难度/成本：** 低中；Level 0 数小时。

### I7 — Hierarchical Verify-and-Fallback（质量控制备选）

- **研究问题：** 能否用少量在线 audit 判断请求是否需要从低精度切回 BF16，而无需
  预测整段风险？
- **核心假设：** 首 chunk 的 exact paired discrepancy 能以 <=5% shadow work 识别
  大部分高风险请求，使 violation 降低至少 20%。
- **差异/机制：** 不是 prefill predictor；对同一 canonical state 做受限双分支 audit，
  之后只保留一条 trajectory。必须完整计 shadow 与状态复制成本。
- **为什么可能有效：** 到达时预测尚未成立，而首 chunk 更接近真实受损行为。
- **5090 验证：** 小模型同 KV/同输入的 BF16与低精度短窗口 paired execution；校验
  不发生 KV/route state 污染。
- **最小实验：** audit length 1/4/8/16；always-low、always-high、random audit、
  prefill proxy、oracle。
- **指标：** violation、shadow overhead、fallback率、J/token、P99。
- **负结果：** audit信号到来太晚；复制/双跑成本超过节能；非 canonical shadow。
- **论文价值：** 中；实现 correctness 是最大风险。
- **难度/成本：** 中高；一天以上。

### I8 — Fused Quantize-at-Dispatch（GPU kernel 高风险候选）

- **研究问题：** dispatch producer 能否直接生成一次可复用的 FP8 activation，并融合
  down-input quantization，使 FP8 expert 在真实 decode row 区间超过 BF16？
- **核心假设：** fusion 后 rows 64–256 的完整 expert path latency至少降低 10%，而
  expert-local MSE 不高于现有 E4M3 路径。
- **差异/机制：** 不再做 route-row controller；直接消除已实测的 56%–78% dynamic
  quantization tax。与单纯调用 FP8 GEMM不同，创新点必须是 producer/consumer fusion
  与 activation复用。
- **为什么可能有效：** 5090 成本分解显示预量化 GEMM 有 36%–48% headroom，理论
  rows=256 上限约20%；这是明确但未实现的物理空间。
- **5090 验证：** Triton/CUDA microkernel，真实 expert weights/shapes；先验证计数、
  数值与单层端到端 path。
- **最小实验：** BF16、PyTorch dynamic FP8、quantize-once、fused candidate；rows
  1–512，两个模型多层。
- **指标：** CUDA time、kernel count、HBM bytes、peak memory、MSE；energy仅次指标。
- **负结果：** fusion仍受小M GEMM/launch限制；中间SwiGLU必须materialize；编译后
  baseline覆盖。
- **论文价值：** 高风险高收益，成功可形成独立 kernel/system paper；失败也能关闭
  dynamic precision主线。
- **难度/成本：** 很高；首 microkernel 1–3天，非数小时。

### I9 — Energy-Normalized Expert Batch Controller（Energy-SLO 系统候选）

- **研究问题：** 在相同完成任务下，expert batch size 是否存在由静态功耗、利用率与
  deadline共同决定的 race-to-idle 区间？
- **核心假设：** deadline-aware coalescing 相对 fixed batch 与 immediate execution，
  在 P99 SLO 内降低至少 10% board J/completed token。
- **差异/机制：** 不改精度/route；以完成能耗而非瞬时功率为目标，在 deadline允许时
  聚合相同 expert rows。
- **为什么可能有效：** 小 row kernel低利用率；但等待会增加静态能耗，存在可证伪
  trade-off。
- **5090 验证：** 真实 expert kernel + NVML高频采样，固定到达trace；完整时间窗含
  idle/coalescing/drain。
- **最小实验：** immediate、fixed timeout、fixed rows、EDF batch、oracle；arrival
  load 0.3/0.6/0.9。
- **指标：** J/token、P99、throughput、GPU active/idle time、deadline miss。
- **负结果：** NVML分辨率不足；race-to-idle始终优；固定 timeout覆盖控制器。
- **论文价值：** 中，机制清楚但 batching/energy prior art拥挤。
- **难度/成本：** 中；一天。

### I10 — Tail-Protected Expert Drop Budget（问题定义候选）

- **研究问题：** 与其预测逐请求 KL，能否在固定 drop预算下保护尾部请求并最小化
  opportunity regret？
- **核心假设：** 分层预算（safe/uncertain/protected）相对统一 drop比例，在相同
  average quality与计算量下把文档级 KL CVaR95 降低至少 15%。
- **差异/机制：** 不是新的 drop score；新问题是请求间预算隔离与最坏请求保护，
  uncertain请求自动进入保守层。
- **为什么可能有效：** 已观察到请求敏感性差异与弱风险排序；tail目标比精确预测
  更符合 SLO。
- **5090 验证：** 现有 expert drop、KL/NLL与bootstrap全部可复用；Level 0无需新kernel。
- **最小实验：** uniform、random、rank-tail、NLL、router proxy、oracle budget；固定
  global dropped contributions。
- **指标：** KL CVaR95/max、task score、drop work、protected覆盖、公平性。
- **负结果：** tail保护只把误差转移给多数请求；NLL baseline完全覆盖；OLMoE不成立。
- **论文价值：** 中低到中；若没有真实 latency/energy执行收益，只是allocation论文。
- **难度/成本：** 低；数小时。

## 4. 选择

### 主线：I1 Join-Deficit Credit

原因：它直接越过固定目的地 full-drain 重排的 NO-GO边界，动作发生在 receiver
拥塞域之前；真实 route 已通过 fan-in结构门，下一步 temporal-overlap gate又能快速
判死。限制：单卡只能决定是否值得进入多 GPU，不得形成 RDMA/serving claim。

### 备选：I4 Route-Set Residency Admission

原因：完全可在单卡用真实 CPU/GPU层级和 H2D 测量验证，系统指标明确，并复用 route
trace。立项前必须证明 admission/cache coupling 胜过 Belady headroom与简单 overlap，
否则只是已有 caching/prefetch 的改名。

### 高风险高收益：I8 Fused Quantize-at-Dispatch

原因：已有成本分解给出最明确的真实物理 headroom，成功后不会依赖弱 predictor；但
需要 Triton/CUDA fusion，且小M区域很可能仍被 launch/中间materialization吃掉。

### Energy-SLO 独立保留
