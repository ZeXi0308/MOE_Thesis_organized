## 0. 证据标签与选择原则

- **[Observed]**：仓库代码/产物或一手文献直接支持。
- **[Inferred]**：从系统控制域、对象身份或依赖关系推出，尚未实测。
- **[Hypothesis]**：入选后才允许预注册验证。
- 单卡 L1、代理 L2 和校准模拟 L3 必须分开；L2/L3 不能升级为多 GPU/RDMA claim。
- `Novelty` 不来自换 predictor、dual variable、controller 或 loss；必须增加新状态、新系统能力或新的可执行问题形式。
- 强基线先于复杂策略。若 sender-CQ、EDF、best static、AMoE/Festina-like 或 transport retry 已等价，候选立即淘汰。

## 1. Phase 4 对新探索施加的硬边界

### Receiver

**[Observed]** CJC-v1 免费汇总跨 sender 的 global ready set 并直接拥有 dispatch authority；只给 completion ACK 收费，未给 ready announcement、grant/command、所有权和同步收费。A1 又删除 112/128 background tokens，G1/canonical reduction 可用环境布尔值自证，bootstrap 还把共享队列请求视作独立样本。

因此不再探索：普通 receiver queue/load controller、join-credit/pull、泛化 buffer credit、receiver shadow price、低比特 congestion controller。邻近空间也已被 [FAST](https://www.usenix.org/conference/nsdi26/presentation/lei-yiran)、[ExpertPlex](https://arxiv.org/abs/2607.18002)、[UCCL-EP](https://arxiv.org/abs/2512.19849) 与 [DeepEP](https://github.com/deepseek-ai/DeepEP) 显著覆盖。

### Energy-SLO

**[Observed]** JouleQueue-v1 用不同 repeat 分母摊固定计量 envelope，把同一 activation prefix 的重复测量当独立 input event；无 route→job producer、policy-dependent DAG、真实 queue board-energy executor和可复核强基线，且 `max_exact_jobs=12 < LLM-jp top_k=16`。

因此不再探索：isolated expert surface 求和、固定 32-row 冒充 AMoE/Festina、扩大 subset exact oracle、PowerCap+μ-queue、route-set packing、再叠 FP8/DVFS/bandit。邻近空间已由 [AMoE](https://arxiv.org/abs/2505.08944)、[Festina](https://arxiv.org/abs/2606.30391)、[PALS](https://arxiv.org/abs/2605.21427) 与 [Mixture-of-Experts Serving](https://arxiv.org/abs/2607.17880) 挤压。

## 4. 主线 R1：CommitMap-EP

### 4.1 一句话论文主张

> 将每个 MoE top-k contribution 表示为 receiver 端可幂等提交的 `(request, forward, layer, token, slot, epoch)` 槽位，并只对未提交槽位走备用路径或存活 expert replica 重放，可把 transient EP 故障从整请求重试收敛为 layer-local selective recovery，同时保持 routing、top-k、权重和输出语义不变。

### 4.2 系统创新点

新增的不是 receiver 拥塞分数，而是应用级完成语义：

1. receiver staging buffer按完整 identity + epoch 放置 contribution；
2. payload write 与 commit 分离，duplicate只能幂等覆盖同槽，不能重复累加；
3. receiver proxy维护 committed bitmap，超时/异常时只 NACK 未提交 slot；
4. sender在 commit前保留 output/activation，或由相同 revision 的存活 replica重算；
5. 所有 slot commit 后按 canonical slot/expert order reduce；
6. 正常 fast path只支付 bitmap/epoch bookkeeping，不做额外重放。

改变的关键路径是 `fault/stall → client/full-request retry`，变为 `fault/stall → receiver missing-slot certificate → selective replay → same-layer commit`。这不依赖逐 token提前进入下一层，因而不重复 TokenRace/CJC 的 barrier 主张。

### 4.3 建模创新点

- **决策对象**：`j=(q,f,l,u,k,e,s,r,epoch)`；
- **状态**：receiver commit `c_j(t)`、sender CQ、path/rank/replica availability、request slack、retained buffer residency、replay cost；
- **动作**：`wait / retransmit_same_output / recompute_on_replica / abort`；
- **目标**：最小化 recovery completion 的 P99/CVaR，同时收费 replay bytes、recompute、retained memory 与无故障 fast-path tax；
- **约束**：每个 logical slot 恰好提交一次；fixed route/top-k/gate weight；replica revision一致；canonical reduction；容量/deadline/memory上限；
- **可观测**：commit bitmap/epoch、receiver proxy completion、sender CQ/path health、当前 deadline；
- **禁止信息**：未来故障、未来 route、故障后才选择的“最优”timeout；
- **关键假设**：故障能在有用窗口检测；至少有备用 path 或同 expert replica；receiver仍保有重放所需状态。

模型输出恢复动作；receiver commit/NACK、重放完成和真实 recovery time反向更新状态。bitmap update应为 O(1)；实际 atomic、metadata bytes、poll/ACK、buffer retention必须实测。

### 4.4 与最强简单基线的本质差异

必须比较：

- RC/NCCL/UCCL transport retry；
- sender仅按本地 CQ timeout做 deterministic-slot overwrite；
- alternate-path static hedge；
- full-layer retry；
- client full-request retry；
- [EEP](https://arxiv.org/abs/2605.10670) 修 membership 后让当前请求失败；
- 完整冗余发送；
- fault-aware clairvoyant selective oracle。

必要性 witness 是“transport 已发送/完成”和“receiver 已按正确 epoch应用提交”不等价。若 sender-CQ + deterministic overwrite能无 receiver反馈地恢复完全相同状态，receiver-awareness没有信息价值，本候选直接淘汰。

[EEP](https://arxiv.org/abs/2605.10670) 已处理 live membership/expert coverage，但其论文把 in-flight request交给 client retry，并将 transient performance degradation排除在外；[LUMEN](https://arxiv.org/abs/2606.17787) 处理 interrupted-request/KV recovery，但不是 per-expert slot commit。这是当前 novelty 的窄边界，不能写“首个”直到完成系统性文献复核。

### 4.5 必要条件与最大风险

必要条件：

1. transparent transport retry不能在 SLO 内解决目标 stall；
2. sender-CQ无法辨认 application commit；
3. alternate path或同 expert replica真实存在；
4. receiver/请求状态未同时丢失；
5. commit bookkeeping、retained buffer和检测延迟小于恢复收益；
6. fault/stall分布有真实注入或公开/生产证据校准。

最大风险是问题根本不存在：可靠 transport已恢复所有有意义的软错误，而 rank fail-stop又让当前 receiver状态/请求一起失效。此时不要加入更复杂 detector、replication policy或 learned hedge来救。

### 4.6 Oracle headroom 与最小判死实验

当前 headroom：**[Unverified]**。

Phase 2 前先冻结 Gate 0 oracle：同 route、service与 fault trace下，只让 oracle知道实际未 commit slots；对比全部强基线，完整计入正常路径 bitmap/metadata/atomic税、retained memory造成的batch/KV容量损失、duplicate bytes和replica recompute。

建议不低于既有研究门：

- fault-free TPOT/P99 overhead 95% CI上界 `≤1%`；
- service-wide P99改善 95% CI下界 `≥5%`，或 SLO violation绝对下降下界 `≥3pp`；
- 结果必须对有依据的 fault incidence成立，不能只报 fault-conditioned赢家。

任一条件成立即判死：transport baseline透明恢复；sender-CQ动作与receiver oracle等价；没有备用恢复动作；只有拍定高故障率才正；全 workload门不过。

### 4.7 5090 证据与尚不能验证的 claim

**L1 可做：** route-real slot基数；duplicate/out-of-order/missing注入；幂等 staging、epoch隔离、canonical reduction exactness；commit bitmap/atomic/retained memory；真实 expert re-execution latency/energy。

**L2 可做：** 真实 route DAG + measured LUT的 delayed/missing completion replay，只证明协议与 upper bound。

**5090 不能证明：** transport fault semantics、alternate QP/NIC、rank failure、真实 multi-GPU retry、多节点 RDMA SLO/availability。至少 L3 双 GPU fault injection后才可声称机制存在，L4 才能写集群可靠性论文结论。

### 4.8 成功后的论文故事

1. transport completion与application commit的不可区分 witness；
2. exactly-once MoE slot/epoch recovery model；
3. normal-path低税的 commit map runtime；
4. sender-local/transport/full-retry强基线与fault-aware oracle；
5. 双 GPU fault injection；
6. 多节点 EP 下 recovery P99、SLO violation、goodput、bytes、memory与正确性闭环。

## 5. 高潜候补 E1：ForkJoin Energy Contracts（FJEC）

### 5.1 一句话论文主张

> 在 routing、precision、admission和完成集合不变时，将 request-level TTFT/TPOT slack作为可守恒执行合同，经 MoE fan-out/join DAG分配给异步 expert queues；以局部 energy bid和全局合同仲裁只合并真正有安全 slack的 rows，从而在 exact-quality与尾延迟硬约束下降低 GPU board J/completed token。

### 5.2 系统创新点

1. routed row携带 request/token identity、absolute deadline与剩余合同预算；
2. expert queue生成多个候选 batch，不自行启动；
3. candidate提交 marginal board-energy gain与 SLO-budget consumption bid；
4. global arbiter只执行合同可行 action，避免把共享 GPU board energy错误拆成 per-expert可加账；
5. urgent rows走 fast path，max-age防 starvation；
6. realized TTFT/TPOT deficit更新 contract price。

这里的 fork/join 是同一 serving engine内的 request execution DAG，不读取远端 receiver ACK/network状态，因而与 Receiver 命题独立。

### 5.3 建模创新点

- **动作**：`launch(e,B)` 或 `defer`；
- **状态**：expert queues、row/request/token identity、age、absolute deadline、remaining service envelope、GPU phase/clock/thermal；
- **目标**：同一 continuous run 的 `board energy / completed output token`；
- **约束**：same admitted/completed identities、full drain、exactly-once、TTFT/TPOT absolute SLO、violation budget、starvation、fixed routing/weights/BF16、independent KV、canonical numerical gate；
- **可观测**：当前 DAG frontier与历史 service/energy profile；禁止 future route/arrival；
- **关键假设**：underfilled launch能量非凸性可重复；request slack足以合批；contract分解不会遗漏共享GPU interference。

local model输出候选 bid，global arbiter输出系统动作；realized board energy只用于校准/反馈和最终统计。LUT/模型**不得**作为正式结果分母。

### 5.4 相对最强简单基线的本质差异

至少包括：immediate、calibration-frozen best fixed timeout、best static rows、EDF/oldest-first、AMoE-style μ-queue + defrag、Festina-like profile-fixed energy-safe batching、slack-only、energy-only、best SLO-qualified baseline、小实例 exact / 大实例 bounded oracle。

[AMoE](https://arxiv.org/abs/2505.08944) 已有 μ-queue与 adaptive rebatching，[Festina](https://arxiv.org/abs/2606.30391) 已联合 SLO、batching、SM与 operating point；“使用 dual/shadow price”也被一般在线模型和 [Mixture-of-Experts Serving](https://arxiv.org/abs/2607.17880) 覆盖。FJEC 只有在 matched `(rows, age, earliest deadline, load)` 下，DAG/contract state造成强基线无法恢复的 action flip，才有 novelty。

### 5.5 必要条件与最大风险

必要条件：

1. real continuous BF16执行中存在可复现的 underfill/fixed energy tax；
2. route/arrival产生可等待的 overlap；
3. full drain与同完成集合后仍节能；
4. contract相对 EDF/AMoE/Festina-like改变 action；
5. schedule-conditioned energy模型误差显著小于 headroom；
6. arbiter/control overhead和等待期间 board energy不吃掉收益。

最大风险：best fixed/AMoE/Festina-like已接近 oracle，所谓 contract只换了打分公式；或者 isolated kernel存在能效曲线，但 continuous board energy没有净收益。此时不要叠加 precision、DVFS、offload或学习策略。

### 5.6 Oracle headroom 与最小判死实验

当前 headroom：**[Unverified]**。

1. real continuous BF16 executor上用相同 logical denominator、同窗 raw counter/power trace验证合批能量；
2. 真实 route构造 policy-dependent 1–2 layer DAG，覆盖 `top_k=16`；
3. 小 episode exact MILP/DP，大 episode输出 `LB ≤ E* ≤ UB`，gap未闭合不得称 exact；
4. held-out action sequences验证 energy model误差；
5. 两模型 × Poisson/bursty cells比较全部强基线。

门槛不比旧协议宽：oracle相对每个 SLO-qualified强基线的 J/token改善 LCB `≥10%`，P99 ratio UCB `≤1.03`，violation增量 UCB `≤1pp`。AMoE/static/EDF覆盖、模型误差吃掉headroom、contract不产生action flip、full-drain收益消失或只有idle-subtracted/kernel-sum口径为正，任一即杀。

### 5.7 5090 证据与尚不能验证的 claim

**L1 可做：** continuous decode、raw board energy、TTFT/TPOT、controller overhead、independent-KV exact-quality；**L2 可做：** route-real fork/join replay和 bounded oracle。

**不能证明：** 多 GPU overlap、NIC/CPU能耗、真实 async EP、跨节点 P99与长期drift。L3只能用L1测量校准模拟；L4必须真实多 GPU/RDMA。

### 5.8 成功后的论文故事

1. MoE fork/join中 request SLO budget无法由普通 queue age充分表示；
2. contract decomposition与可行性/稳定性分析；
3. local bid/global board-aware arbiter；
4. full continuous board-energy执行与强基线；
5. bounded oracle证明剩余空间；
6. async EP与多节点能量/延迟扩展。

## 6. 交汇与归档判定

### 6.1 交汇 reserve：现在不合并

`Join-Slack Energy Coalescing` 的完整因果链是：receiver join frontier → contribution defer budget → expert launch/coalesce → energy下降且closure不破。但它必须先分别证明：

1. Receiver状态在物理可实现控制 locus 下相对 EDF/SRPT/AMoE有独立 P99增量；
2. 固定合法 slack时，Energy机制相对 immediate/best timeout/AMoE/Festina-like有独立 J/token增量；
3. 2×2 factorial联合策略胜过两个单轴及其最佳简单组合。

当前两个独立门都未过，故只保留为未来 reserve，不列入前二。

### 6.2 归档路线：零复活

- CreditReduce、TokenRace、Prefetch、Progressive、PLTB、Residual mean-base、RouteFidelity、MassCover、Graceful/QTree：纠错后机制仍不过原门或简单基线已吃掉空间。
- Additive：旧错误否定被撤回，只说明一个建模原语未决，不构成系统机制复活；禁止引用作废数字。
- QuotaEP：Gate C未执行，不是错误判死；fixed-quota quality tax与owner-local backend前提仍未闭合。
- Mean-balance placement：仅撤回“所有 placement 都无效”的过度外推，不重开 static LPT。
- WaveCredit：未实验且与 UCCL-EP / FAST 邻近，不复活。

## 7. 最终推荐

1. **主线：CommitMap-EP，条件是允许 Receiver-awareness 转向 SLO resilience。** 下一步只能先做 Phase 2 的 Gate-0 protocol：故障模型、application commit vs sender-CQ witness、exactly-once identity、强基线与正常路径税。若研究仍限定“无故障常态 latency scheduling”，本轮 Receiver 应空缺，不重开 CJC。
2. **高潜候补：FJEC。** 下一步先冻结 bounded oracle与 real continuous board-energy估计；不过 10%/1.03 与 action-flip necessity门就停。
3. **交汇和归档均不入选。** 不通过合并 blocked idea 或放宽门槛凑论文故事。

本文件结束于 Phase 1；没有写两条候选的正式实验代码，也没有将分析模型、代理 replay 或单元测试写成科学结果。
