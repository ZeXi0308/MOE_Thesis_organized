# C 一页研究卡与当前判决（2026-10-08）

**贡献说明。** 中心问题：只控制首次 prefill 时，何时值得复用未来 KV 释放？[MC-Benchmark](https://arxiv.org/html/2502.07115v5)已有未来峰值准入；“执行条件破坏时选择性收紧信用”仍是候选原则，尚无重要失信事件支撑。近邻适配和结构匹配消融已实测，发现极尾停顿与排队/控制成本的取舍；**原创方法、一般性新规律及可投稿中心主张尚未成立**。最新v20对照已完成：阶段适配实际改变156/152次准入；P95 TTFT改善2.10%/2.59%，mean flow恶化.58%/.33%，联合goodput取舍不一致。这是已知近邻的工程适配与开发取舍证据，不重开失信机制或原创贡献主张。

## 当前最小模型与投资边界

可观测量为实际空闲页 F、完整在途集合 A（包括暂停/恢复）、各请求已知 token 数 n_i、声明剩余上限 r_i、当前是否驻留/本步获1个decode token，以及等待队首的prompt p和声明输出 B。真实EOS、未来到达和每轮墙钟成本未知。动作只有本步允许或延后队首；允许会增大已知占用和后续decode集合，延后把成本转给新请求。原生资源检查与完整cap仍生效，旧请求不受新门控阻挡。

在本机 guard 成立时，以未来轮 h 为索引，旧请求占用为 `ceil((n_i+h)/16)`（h<r_i，否则为0）；新请求按 `ceil((p+min(h,B))/16)` 计费，达到平台后不假设其已完成释放。MC适配检查所有必要拐点峰值<=32768；普通静态消融只保留共同终身声明和<=39138。它是**容量模型**，不含轮成本、队列效用或质量，因此没有理由自动预测完整服务更快。抢占、rollback、异步未完成token和decode eligibility变化均可能破坏适用条件；分块prefill本身在已测旧decode优先域没有导致轮次承诺失信。

本轮最关键未知是尾部损失是否广泛影响人口、以及它是否要求已知MC之外的新机制。最低成本下一步已执行：只读现有两静态臂的抢占记录和逐请求结果，按预先已有.25s网格点分层；本阶段GPU投入上限0；实际新增人口分层命令约4.3s，随后综合现有证据，未扩展模型/到达率/阈值矩阵。若发现大量未抢占请求同样受停顿，才有理由重新定位公共关键路径；实际超.25s的14/8个请求全部属于15个victim集合，未出现该证据。**这是后验人口描述，不是单事件因果归因，也不是把少数请求认定为不重要。** 结合已知方法已能保护它们，停止同域微观诊断和GPU调参。

重新投入需要新的、可检验的损失与动作依据，例如强简单配置及MC仍留下的准入代价，或正常部署中有代价的执行承诺失信。可靠应用SLO不是探索门禁；没有SLO仍可事前冻结目标做取舍比较，但仅更换效用权重不能建立新方法缺口。文章续写的任务名也不能决定应优先整篇完成还是逐token交付，后者需要消费方式的依据（参见[JITServe正式版§2.1/§3](https://www.usenix.org/system/files/nsdi26-zhang-wei.pdf)）。固定内部调度、只门控首次prefill是当前动作范围，本身不构成已有方法遗漏的部署需求。

2026-10-08按更新后的[工作区科研基准](../../../AGENTS.md)续接：复用v17—v19，不重跑、改阈值或新增控制器。当前保留的开销疑点是：MC额外控制wall与均值差同量级；未经干预不能直接相减。优化这一实现可作为有具体需求时的基线工程，尚不足以支撑新系统原则或下一组GPU投资。当前没有同时具备“已观察损失、首次准入有影响力、强简单/近邻仍未解决”的新残差，故继续收束本机制与已测运行域；这不是设备/权限阻塞，也不要求用户提供创新点。新证据出现时由本线自主重选问题，再做最小动作探针。本轮无新增性能数据或GPU占用，历史结果及其不确定性不变。完整论文目标未完成，英文投稿包尚不具备可辩护的中心主张。

## 2026-10-08 轮次容量模型与墙钟代价的区分

当前未知：v20等待减少而flow增加，是否支持“未来释放进度不可信”，还是已有容量模型之外的普通墙钟取舍？
主要竞争解释：prefill只拉长共同轮时而未使旧请求丢失decode轮次；此外自然EOS/输出差异和运行波动参与完整时延变化，不能全归因于容量信号。
最小实验：只读v20逐请求结果，按同一外部时钟分解flow=TTFT+(首token后到完成间隔)，并核对MC原论文的时间轴及本机归纳条件；CPU/源码/定向文献上限20分钟，GPU上限0，不再检查已经充分验证的接口或扫描阈值。
不同结果将如何改变决定：如果仅是轮时与排队代价，撤销以此重开“释放失信”机制的依据；只有找到合格准入之后真实破坏轮次推进的合法路径及重要代价，才值得另行最小干预。分解只是准确记账，不能单独证明因果或形成方法贡献。

**已执行结果（CPU，GPU=0、在线动作=0）。** [自动分解](analysis/westd-mc-budget-phase-r01.phase-accounting.json)保留全部384请求/臂，严格使用同一host时钟：`flow = TTFT + completion-minus-first-token`，最大逐请求恒等式残差约7.1e−15s。后项包含首token之后的等待、调度、控制和生成，不是纯GPU decode耗时；不把重叠阶段相加，不相加分位数。两次配对的mean TTFT减少.113216/.076879s，而首token后到完成间隔增加.542342/.323682s，净mean flow增加.429126/.246803s。

按既有fixed177参考切分外部到达前177与后207个请求，仅作描述：前组TTFT +.008849/+.013228s、首token后间隔+.512225/+.568837s、flow +.521075/+.582065s；后组TTFT −.217591/−.153927s、首token后间隔+.568095/+.114057s、flow +.350504/−.039870s。这表明不能只用较晚到达者的首token尾部改善代表总体服务。分组没有隔离策略导致的后继轨迹，输出差异与运行波动仍在；不能由恒等式断言全部变化由prefill干扰引起。

**条件性执行模型。** [当前门控](mc_budget.py)要求事件中的全部已接纳请求在running，旧请求已安排1个decode token，或本步已安排完整剩余prompt。[固定scheduler](vendor/scheduler.py)先处理running再append新请求（469–509、1011行）；在正常单token输出之后，未结束旧请求只需下一token，旧cohort人数≤256、量子1024，后续新prefill位于尾部，因此token预算本身不使该旧cohort跳过轮次。这只是顺序与token预算的条件性归纳，**不是一般内存安全或墙钟SLO定理**。容量失败触发抢占、invalid-KV rollback/空输出、async/spec/PP eligibility、全局暂停和延迟释放均可使推理不适用；guard/profile排除了其中部分，其余必须依正常执行/容量条件。v18的354个已观测承诺兑现和v20的零抢占与此相容，不等同于每轮物理释放证明。本次未重跑逐轮审计。

**近邻澄清及判决变化。** [MC原论文§2、§4](https://arxiv.org/html/2502.07115v5)以连续执行轮次建立未来峰值，且早已用外部到达到完成作为目标；[§5.2–5.2.1](https://arxiv.org/html/2502.07115v5#S5.SS2)还用Vidur评估可变batch时长。故“prefill拖慢墙钟轮时”不是MC未来释放失效的证据，不能声称MC从未考虑完整flow或可变轮时。[近邻说明](PRIOR_ART.md)已补准确边界。式(5)未显式比较边际墙钟代价，但JITServe已有剩余带宽/时间调度原则；仅给MC加一个延迟惩罚也不能预先视作新贡献。

本次消除了一个不成立的重开理由：不得因v20首token后间隔变长，就投入“修复释放信用失信”的控制器。当前正常同步、decode优先的已测运行域不支持继续这条方法路线；保留全部适配和取舍结果，不把它扩大为一般准入问题无价值。下一次昂贵实验需要新的真实残差与合法动作依据，不能用更复杂预测器、改变SLO权重或再选近邻阈值替代。全文论文贡献仍未建立。

原生已包含部分恢复优先：vendor/scheduler.py L666在当步发生抢占时跳过waiting阶段，L935–956在队首恢复分配失败时break；但L682–693的未完成remote、L978–1009的刚启动async恢复及L772–778的lookup暂不可判定会continue，仍可能考察后面的新请求。因此不能仅凭恢复优先就断言新信号必然冗余。恢复集合在每步begin观测，latch每100ms更新；decision中的recovery_count沿用步首快照，同一步已有请求恢复后可能仍非零。changed_by_recovery说明步首观测触发的迟滞门控改变了决定，不单独证明gate当刻仍有真实pending恢复。

没有可靠应用SLO，因此原始分布为主。预先完整报告20点探索面：TTFT={2,5,10,20,40}s、maxgap={.25,.5,1,2}s、flow<=120s。goodput分母覆盖到达、服务、排空，失败不从请求分母移除；不事后选获胜阈值。自然EOS或1024上限，输出token数/stop原因/逐请求序列变化同时报告；暂无任务质量结论。
