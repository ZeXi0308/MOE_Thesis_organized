Session E: native remaining-token-budget selector
Status: CPU_PASS_GPU_UNRUN (2026-10-07)

policy=budget chooses native recomputation iff the recovery is already jointly
eligible under the existing Host-readiness/capacity checks and known_tokens is
at most the current native schedule's remaining token budget. Otherwise an
eligible recovery uses native Host restoration. Existing native fallbacks are
unchanged. The budget rule has no fitted threshold, future-output input, second
branch execution, or scheduling/transfer changes. One-event target mode remains
restricted to host/recompute.

The observer wraps the original schedule(*args, **kwargs) and allocate_slots
calls without copying schedule. Each schedule starts from the native
max_num_scheduled_tokens (zero for PAUSED_ALL). Only successful positive-token
allocations consume the observed budget; failed allocations and zero-token
async LOAD allocations do not. Every successful schedule must match native
SchedulerOutput.num_scheduled_tokens exactly by request ID and match its total.
FCFS preemption of an already charged request fails explicitly. Exceptions and
normal completion both clear the active observation context.

Guards require FCFS, APC off, synchronous scheduling, no speculation/lookahead,
no encoder/multimodal compute or encoder connector, no LoRA, no Mamba, and
scheduler_config.long_prefill_token_threshold == 0. Existing one-group full-
attention, native CPUOffloadingManager and full-history capacity guards remain.
Unsupported configurations fail instead of silently approximating a budget.

All policies, including fixed host/recompute/length and common warmup, receive
the same observer. Decisions record remaining_budget_tokens and budget_step.
Per-step checks are serialized through the existing episode field
target_selection.budget_observation, containing checked/error counts and steps.
This record is a deep snapshot, so later clear() calls cannot mutate prior arms.
Mismatch exceptions include observed and native per-request token maps.
