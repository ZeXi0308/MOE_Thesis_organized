## 结论

MaxGate-v1 的 `-3` 对 frozen balanced shuffle 的 `+3`，排除的是一个很窄的 selector 叶子，不是 execution-shape intervention 本身。最值得立即回答的问题是：

> 假如 hindsight oracle 知道每个 cell 应保护哪个 top-k contribution，单贡献稳定化动作是否存在明显、稀疏且跨 victim 的正收益？

因此 Top‑1 是 **Stability-budget oracle/action frontier**。最小 runner 已实现并通过 6/6 本地单测与 frozen-input hash closure；唯一发现的 P1——abstaining oracle 与 random baseline 动作预算不匹配——已经修正。当前没有 GPU empirical result：向远端发送四个新实验文件尚待用户明确授权。

如果 Top‑1 显示 action upper bound，下一步不是再换一个 MaxGate 分数，而是研究 stability budget 的分配对象与 runtime mechanism。如果 Top‑1 为负，只削弱当前“单 contribution M1-in-M64”动作面；仍应分别测试直接 canonical shape 和 natural pack surgery。

## MaxGate-v1 精确排除边界

被排除的 hypothesis 是：

> 在冻结的 16 个窗口、240 个 victim-layer cells、all-M1 自监督 reference，以及“恰好一个 contribution 走 M1、其余七个走 M64”的动作面上，用当前层最大 gate weight 选择唯一受保护 contribution，能够比该次预先冻结的 balanced-shuffle rank 获得更高的聚合 downstream route-membership reward。

结果为 MaxGate-v1 `-3`、frozen shuffle `+3`；MaxGate 有 13 个正 cell、18 个 harm cell。因此它具体说明：当前层最大 gate weight 与该动作的 downstream value 不对齐。

它没有排除：

- 该单贡献动作存在 hindsight oracle upper bound；
- 收益集中在少数 cell、layer、expert 或 victim；
- 多贡献保护、canonical shape、pack surgery、stable kernel 等其他动作；
- pair/set-level composition relation，而不是 row-local score；
- numerical stability 作为有限 runtime resource；
- route-aware batching 或 execution-shape-aware runtime。

## Recommended Ideas（ranked）

### Idea 1 — C01 Stability-budget Oracle/Action Frontier

- **Method（实际做什么）**：对现有 240 个 frozen cells 分别执行 all-M1 reference、all-M64 no-intervention 和 8 个“只保护 rank r”的 action；在所有 outcome 产生后才让 hindsight oracle 选 rank 或 abstain；按实际 action budget 同时计算全局随机 cell-rank 与 oracle-selected cells 内随机 rank 的精确期望；复跑所有正 oracle action。
- **Hypothesis**：若单贡献稳定化动作空间本身有价值，hindsight oracle 应能用少量 cell-rank actions 恢复显著 downstream route agreement，并同时优于两种等动作预算 random comparator。
- **Why it may work**：已有 35 个 opportunity cells；MaxGate-v1 同时出现恢复和伤害，更像 action selection 失败而非 action 恒无效；8-rank sweep 能直接分离 selector failure 与 action failure；abstention/budget curve 能发现稀疏收益；完整 action matrix 可直接支持下一步 allocator。
- **Minimum experiment**：单 RTX 5090、同一模型与 240 cells，执行 `R/U/A0..A7`；主比较为 no intervention、budget-matched random、oracle；frozen shuffle 与 MaxGate 只用于历史 closure。预计 8–15 GPU 分钟。
- **Expected outcome**：支持信号为 recovery fraction ≥25%、相对每一种 budget-matched random 的优势均 ≥8、正收益覆盖 ≥4 victims；若正 action 为零或仅是孤立微小收益，则否定当前单贡献 action upper bound。
- **Scope of failure**：只削弱 frozen synthetic same-cell 的 single-contribution M1-in-M64 action；不否定 multi-action、natural pack、canonical shape、stable kernel 或 route-aware scheduling。
- **Novelty**：作为论文 headline 单独较弱；价值在于建立“numerical stability budget”的 action-value frontier，并决定 selector/controller 是否值得研究。
- **Feasibility**：高；复用现有 runner、assignment ledger、patched contribution 与 outcome metric。
- **Risk**：LOW（实验辨别力）/ HIGH（正 signal 未知）。
- **Contribution type**：causal diagnostic + controller foundation。
- **Pilot result**：`IMPLEMENTED / LOCAL_QUALIFIED / REMOTE_NOT_RUN_PENDING_TRANSFER_APPROVAL`。6/6 unit tests PASS；frozen lock 中 10 个输入/代码 hash 全部闭合；没有 GPU outcome。
- **Reviewer objection**：hindsight oracle 不可部署。回应是本实验不声称 online policy，只回答 action space 是否值得继续。
- **Why do it**：成本最低，且能立即区分“selector 错”与“动作本身没有价值”。
- **Next action**：获得四个文件的明确远端传输/执行授权后，重查 GPU 空闲、运行并回收 `summary.json`；不调整 MaxGate-v1。

### Idea 2 — C07+C12 ShapeABI / VirtualShape + PadCap

- **Method（实际做什么）**：把 variable logical M 映射到固定 M64 physical template；用 deterministic slot 和 masked filler 保持同一 target row 的 arithmetic path；以 dummy-FLOP token bucket 限制 padding；与 native variable-M 和 serial M1 比较。
- **Hypothesis**：固定 physical shape、slot 和 reduction path 可以消除大部分 spectator-composition-induced route variation，同时保留优于 serial M1 的 expert execution efficiency。
- **Why it may work**：它直接控制已观察到的 causal variable；不需要预测哪个 victim 会 flip；固定 slot 隔离 co-row composition；显式 padding budget 形成 stability–cost tradeoff；可以演化为 executor ABI 与 scheduler contract。
- **Minimum experiment**：选择 6–10 个 confirmed unstable rows，冻结多种 spectator composition；三臂执行 native variable-M、fixed M64 masked padding、serial M1；只测 raw hash、downstream route 和 kernel time。预计 35–55 GPU 分钟。
- **Expected outcome**：fixed template 显著降低或消除 route variation，并且 per-real-row time 优于 serial M1；若仍随 composition 改变，或成本不优于 serial M1，则该 template 实现失败。
- **Scope of failure**：只否定当前 template/slot/masking stack，不否定其他 canonical arithmetic 或 stable kernel。
- **Novelty**：provisional；fixed padding 本身只是 primitive，论文贡献必须是 ShapeABI + budgeted runtime contract 和测得的稳定性/性能 frontier。
- **Feasibility**：中高；先复用现有 expert call 做 M64 masked-padding prototype，不先写 custom kernel。
- **Risk**：MEDIUM。
- **Contribution type**：runtime mechanism + systems abstraction。
- **Pilot result**：`DESIGNED / NOT_IMPLEMENTED / NOT_RUN`。
- **Reviewer objection**：可能退化为普通 padding/deterministic kernel 工程。必须证明固定 shape 对 route stability 的因果作用，并测到非平凡效率点。
- **Why do it**：它不依赖 predictor，最接近完整的 executor + scheduler 系统机制。
- **Next action**：Top‑1 完成后做 fixed-M64 prototype；不先扩到多模型或 custom kernel。

### Idea 3 — C06 RouteStress WitnessPatch

- **Method（实际做什么）**：在 natural heterogeneous expert packs 中寻找可复现的正例；用 delta debugging 移除 spectator rows，得到最小 conflict witness；fresh pack 命中冻结 predicate 时只把 witness rows 切到 protected M1，并重新 compact 其余 rows；与等预算 shuffled surgery 比较。
- **Hypothesis**：传播分歧由小型 co-row conflict subset 触发，保护/切开该 witness 会比等预算随机拆行阻止更多 downstream divergence。
- **Why it may work**：static row-local selector 已弱，relation/composition 可能才是正确对象；witness minimization 能把现象变成可执行 action；只拆少量 rows 可保留 batching；fresh predicate 防止 outcome oracle 偷渡；能自然形成 pack transformer 与吞吐/稳定性 tradeoff。
- **Minimum experiment**：exploration split 生成并最小化 natural positive packs，冻结 predicate；在 4–8 个 fresh victims 上执行 native、WitnessPatch、budget-matched shuffled patch。预计 60–90 GPU 分钟。
- **Expected outcome**：每 protected row 避免的 reproducible downstream divergence ≥ shuffled 的 1.5×，且覆盖 ≥4 victims；fresh split 无法触发或与 shuffled 持平则否定当前 witness predicate/surgery。
- **Scope of failure**：只否定该 witness predicate 和 minimal surgery，不否定其他 composition action、canonicalization 或 multi-row mechanism。
- **Novelty**：provisional；区别于泛化 expert-aware batching 的关键是 counterexample-guided conflict witness 与实际 pack transformation。
- **Feasibility**：中；需要 natural pack generator 和 delta-debug loop，但可复用现有 capture/intervention path。
- **Risk**：MEDIUM-HIGH。
- **Contribution type**：scheduler/runtime method。
- **Pilot result**：`DESIGNED / NOT_IMPLEMENTED / NOT_RUN`。
- **Reviewer objection**：witness 可能只在 exploration pack 过拟合。fresh split 与 matched shuffled surgery 是最小必要对照。
- **Why do it**：若单点 oracle 较弱，它仍能测试完全不同的多行 composition mechanism。
- **Next action**：Top‑1 之后构造第一批 natural heterogeneous positive packs；Top‑1 为负不能自动取消本实验。

明确淘汰的弱变体：

1. `MaxGate-v2 = margin / entropy / norm / local L2`：只换 score，未先回答 action upper bound。
2. 在同一 frozen 数据上调 MaxGate threshold、筛 cell 或换 seed 救结果。
3. 没有 stability-specific action 的泛化 expert-aware batching/load balancing。
4. 把全局 deterministic/batch-invariant mode 当 headline；仅保留为 control 或 stable path。
5. 没有实测 action state 的 generic bandit、primal-dual 或 MINLP。
6. 把旧编号 C09/C02/C04 的 novelty 分数映射到本轮同编号候选；编号语义不同。
