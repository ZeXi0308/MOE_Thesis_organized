## Candidate cards

### C01 — Oracle RankSweep + Stability Budget Frontier

- **Hypothesis**：即使不知道 online selector，完美选择一个受保护 contribution 也能以很小 action budget 恢复大量 downstream route agreement。
- **Mechanism**：每个 victim-layer cell 穷举 8 个 `1×M1 + 7×M64` 动作；oracle 可 abstain；按正 marginal reward 生成 B=1/4/8/16/32/... 的 budget curve。
- **Minimal experiment**：复用当前 240 cells，执行 R、U、A0..A7；比较 no intervention、uniform-random exact expectation、frozen shuffle、MaxGate 和 oracle；正 oracle 动作复跑确认。
- **Success**：oracle recovery fraction ≥25%，相对 random 期望优势 ≥8，并覆盖 ≥4 victims。
- **Failure scope**：只削弱“单 contribution M1-in-M64”动作空间，不否定 pack surgery、multi-action、canonical shape 或 stable kernel。
- **Cost**：约 8–15 GPU 分钟。
- **System abstraction**：把 numerical stability 作为有成本的 runtime resource，并先测其 oracle cost-benefit frontier。

### C02 — Oracle Sparse Protection Cover

- **Hypothesis**：少数 layer-expert/action sites 可同时覆盖多个 victims，存在跨请求复用的保护热点。
- **Mechanism**：构造 action→victim restoration matrix；对 B=1..4 解 maximum coverage；随后真实联合执行所选 action set 检查干扰。
- **Minimal experiment**：先在 10–20 个已确认 victims 上收集单点覆盖，再只执行少量 joint-set replay。
- **Success**：远小于 victim 数的 action set 恢复多个 victims，且联合执行不破坏孤立收益。
- **Failure scope**：只否定共享热点/稀疏 cover，不否定 per-victim intervention。
- **Cost**：90–110 GPU 分钟。
- **System abstraction**：stabilization budget 的 maximum-coverage allocator。

### C03 — Source-Expert Canonical Replay

- **Hypothesis**：只重算 oracle-known causal token-expert contribution，就能让下游 router 自然回到 reference path。
- **Mechanism**：定位最早 source expert delta；用 canonical shape 计算该 contribution；仅在 combine 前替换这一项，不改 router/gate/expert identity。
- **Minimal experiment**：对 6–10 个 causal cells 执行 native、source replay、matched wrong-source replay。
- **Success**：source replay 恢复 downstream routes，而 wrong-source 不恢复。
- **Failure scope**：只说明单 source contribution 不充分，相关多贡献或更早状态仍可能是原因。
- **Cost**：约 45 GPU 分钟。
- **System abstraction**：expert data plane 的 sparse canonical recompute。

### C04 — First-Divergence Route Clamp

- **Hypothesis**：最早 route flip 是传播级联的主要离散放大点；只 clamp 一次 oracle-known router decision 可恢复大部分后续 route。
- **Mechanism**：定位首个 route divergence；只在该 token-layer 注入 reference top-k/weights；继续普通 forward。
- **Minimal experiment**：8–16 个 confirmed cells 的 reference、untreated、one-site clamp 三臂。
- **Success**：一次 clamp 恢复多个后续 routing decisions 或显著缩小 final-output delta。
- **Failure scope**：只否定 single-first-flip correction；它是因果诊断，不直接证明可在线部署。
- **Cost**：约 35 GPU 分钟。
- **System abstraction**：稀疏 routing control-plane repair。

### C05 — Downstream Precision Island / Amplifier Cut

- **Hypothesis**：在误差即将跨过离散 route boundary 的局部区域使用 FP32 combine/router projection，比重算 source expert 更便宜。
- **Mechanism**：定位最后稳定边界；只升级 victim token 的 combine accumulation 与紧邻 router projection；之后 cast 回原 dtype。
- **Minimal experiment**：6–12 个 causal chains 比较 source repair、downstream precision island、matched wrong boundary。
- **Success**：局部 island 以更少 protected compute 恢复相同或更多 route agreement。
- **Failure scope**：只否定所测 boundary/action，不否定更宽 island 或非 precision action。
- **Cost**：50–60 GPU 分钟。
- **System abstraction**：以 route amplification boundary 为单位的 selective numerical hardening。

### C06 — Counterexample-Minimized Witness Pack Surgery

- **Hypothesis**：自然 heterogeneous pack 的传播分歧由一个小 conflict subset 触发；只切开这个 witness 可保留其余 native batching。
- **Mechanism**：生成 natural positive pack；delta-debug 移除 spectator rows；fresh pack 命中 witness predicate 时，将 witness rows 送 protected M1，recompact remainder。
- **Minimal experiment**：native、WitnessCut、budget-matched shuffled cut 三臂，4–8 victims。
- **Success**：每 protected row 阻止的 reproducible downstream divergence ≥ shuffled 的 1.5×，覆盖 ≥4 victims。
- **Failure scope**：只否定该 witness 的 fresh transfer，不否定 composition-level intervention。
- **Cost**：60–90 GPU 分钟。
- **System abstraction**：counterexample-guided expert-pack transformer。

### C07 — ShapeABI / VirtualShape Invariant Execution

- **Hypothesis**：把 variable logical M 映射到固定 physical shape、slot 和 reduction path，可消除 composition-induced route variation，同时不串行化所有 row。
- **Mechanism**：固定 M template；deterministic slot assignment；masked filler；物理 block 可重新打包但逻辑 arithmetic path 不变。
- **Minimal experiment**：同一目标 row 在多种 spectator composition 下比较 native shapes、fixed template 和 serial M1；测 raw output、downstream route 与 kernel time。
- **Success**：fixed shape 显著减少/消除 route variation，且 per-real-row time 优于 serial M1。
- **Failure scope**：只否定当前 template/stack，不否定 canonical arithmetic 的其他实现。
- **Cost**：35–55 GPU 分钟（prototype 若需 custom kernel 另计）。
- **System abstraction**：stack-versioned expert execution-shape ABI。

### C08 — BucketLock Canonical Expert Microbatch Ladder

- **Hypothesis**：只允许 M∈{4,8,16} 等 canonical ladder，可在稳定性与 batching opportunity 之间形成更好折中。
- **Mechanism**：per-expert queue 只在 canonical size launch；deadline 到达后降到更小 bucket 或 M1；禁止 arbitrary M。
- **Minimal experiment**：冻结 arrival permutations，执行 canonical ladder 与 arbitrary-M native，比较 route divergence、M>1 coverage 和 simulated hold。
- **Success**：matched work 下 route divergence 更少，且非零 M>1 work 保留。
- **Failure scope**：只否定该 ladder，不否定 fixed shape、padding 或 pack surgery。
- **Cost**：45–70 GPU 分钟。
- **System abstraction**：expert queue 的 semantic size-class compiler。

### C09 — RouteCohort Layer-Frontier Composition Control

- **Hypothesis**：按 current-layer route signature 相似度组 cohort，能形成更稳定 expert shape sequence，优于 matched random composition。
- **Mechanism**：层边界读取当前 top-k set/order；构造同 size high-overlap cohort；不改 router 输出；执行后比较 next-layer route。
- **Minimal experiment**：fresh windows 的 high-overlap 与 frozen-random matched cohorts。
- **Success**：相同 call count 下 downstream route divergence 和 shape-sequence variance 均下降。
- **Failure scope**：只否定 route-overlap grouping feature，不否定其他 composition relation。
- **Cost**：55–80 GPU 分钟。
- **System abstraction**：带 semantic stability objective 的 layer-frontier batcher。

### C10 — PairGraph Stability Compatibility Matching

- **Hypothesis**：stability 是 pair/set compatibility relation，而不是 row-local risk；matching 可找出 FCFS 漏掉的 safe M>1 packs。
- **Mechanism**：在同 layer/expert 构建 stack-bound compatibility graph；只匹配已验证 edge；unknown→M1；stack epoch 变化时 invalidate。
- **Minimal experiment**：partner permutation replay + held-out matching，与 FCFS/random pairing 比较。
- **Success**：held-out edge 无 route violation 且 M2 coverage 非零并优于 FCFS。
- **Failure scope**：只否定当前 relation/features；若 safety row-local，则 graph 应降级。
- **Cost**：50–80 GPU 分钟。
- **System abstraction**：expert-row composition compatibility matcher。

### C11 — FrontierLock Coupled Request–Expert Queues

- **Hypothesis**：request frontier 与 expert queue 联合控制可避免跨层 shape oscillation，优于独立 per-expert bucketing。
- **Mechanism**：state 包含 request frontier、expert queue、最近 shape epoch 和 age；形成 canonical cohort；age cap 强制 M1 fallback。
- **Minimal experiment**：offline trace replay决定 schedule，再用现有 harness 执行所选 schedules，对比 FCFS/independent bucket。
- **Success**：matched max-hold 和 executed work 下，victim route divergence 与每请求 shape transitions 同时下降。
- **Failure scope**：只否定 coupled queue 复杂性，可能退化为简单 bucket policy。
- **Cost**：65–95 GPU 分钟。
- **System abstraction**：semantic shape epoch 驱动的 multi-stage queue controller。

### C12 — PadCap Budgeted Canonical Padding

- **Hypothesis**：用显式 dummy-FLOP budget 填到 canonical shape，比等额 M1 fallback 更有效地换取 route stability。
- **Mechanism**：underfilled expert call 加 deterministic masked rows；token bucket 记账 padded FLOPs；预算耗尽后 wait 或 M1。
- **Minimal experiment**：固定多个 padding budget，比较 zero-budget native 与 equal-extra-work M1 fallback。
- **Success**：至少一个预算点在 stability/added-work 上同时支配两种 control。
- **Failure scope**：只否定 padding 作为控制杆，不否定 waiting/repacking/canonical arithmetic。
- **Cost**：45–70 GPU 分钟。
- **System abstraction**：可消费 dummy computation 的 stability budget controller。

### C13 — RouteGuard / RouteFence Stable-Kernel Mux

- **Hypothesis**：route-changing numerical risk 稀疏集中；只在 causal boundary 切 stable kernel/fixed reduction tree，即可接近全稳定执行。
- **Mechanism**：fast/stable 两路径；定位 risk/first-divergence boundary；只在命中位置重放 stable path；其余保持 fast。
- **Minimal experiment**：known unstable cells 的 fast-only、stable-only、oracle-mux 三臂，先不用 predictor。
- **Success**：stable path 覆盖 <20%，却消除 ≥80% recoverable route divergence。
- **Failure scope**：只否定局部 mux/fence；若必须保护大部分网络，则 selective determinism 不成立。
- **Cost**：90–150 GPU 分钟，取决于 stable path 是否已有实现。
- **System abstraction**：numerical determinism 作为动态 kernel-dispatch resource。

### C14 — CanonicalCombine + Amplification Sentinel

- **Hypothesis**：固定 combine 的逻辑 reduction topology 可切断一类 shape dependence；有限差分可识别剩余高放大边界。
- **Mechanism**：token-expert slot 固定 reduction tree/accumulation；对 combine delta 做小扰动，测未来 route Hamming gain；高增益点触发局部 stable action。
- **Minimal experiment**：先只替换 combine；再对首分歧前 2–3 层做少量 finite-difference probe。
- **Success**：canonical combine 消除一批 route divergence，sentinel 能提前命中剩余分歧且局部 action 有效。
- **Failure scope**：分别否定 combine 来源或短视窗 amplification proxy，不否定其他 kernel/action。
- **Cost**：90–160 GPU 分钟。
- **System abstraction**：composition-invariant reduction API + route-amplification sensor。

## 明确排除的弱变体

以下不进入 jury 候选：

1. `MaxGate-v2 = margin/entropy/activation norm/local L2`：只换 score，没有先证明 action upper bound。
2. 在 `doc016..031@512` 上重新调 MaxGate threshold 或筛选正 cell：同数据救负结果。
3. 泛化的 “expert-aware batching/load balancing”：若 semantic stability 不改变决策，就被 AMoE/Gimbal/RaMP 等已有系统覆盖。
4. 全局 deterministic/batch-invariant mode：已有 vLLM 等近邻；只能作为 control 或 stable path。
5. generic contextual bandit/primal-dual/MINLP：没有实测可用 action state 时只是 OR 模板。
6. raw-bit row certificate C09、selective rescue C02、grouped M1 C04：保留为邻近支线/基础设施，不替代当前 route-level oracle-first 问题。
