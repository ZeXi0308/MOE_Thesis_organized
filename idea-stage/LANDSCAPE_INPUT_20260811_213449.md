# MoE 系统方向候选评审输入（2026-08-11）

> 用途：为机械候选合并、fresh jury 与查新提供事实输入。本文不排名、不授权实现、不包含新实验结果。

## 当前本地权威边界

- 当前系统/方法级 formal GO：`0`。
- RCBA：`PRIMARY_NEXT_CANDIDATE / UNVALIDATED / BLOCKED_PROTOCOL_AMBIGUITY / FORMAL_GATE_NOT_RUN`；缺 identity-complete full-request DAG、双模型自然 continuous-decode trace、完整 service surface 与 matched denominator。
- SemanticFence-v2：fresh route/top-k-stability proxy action space 存在，但 witness-v1 在 5 个执行 pair 中 4 个 unsafe，net projection `-183.3504%`；裁决 `PIVOT_TO_SHADOW_VERIFY`。只允许 fresh no-actuation SFV2-O2，不允许调阈值或恢复 pre-action selector。
- StableBatch：hindsight Oracle 正，但 static 与 online pre-action selector 均为 `-7`，裁决 `STOP_PREACTION_STABLEBATCH`。固定 C8 的 correctness primitive 保留，但 continuous cost Gate 为 `NO_GO_D10_HEADLINE_COST`。
- JoinStream：局部 action legality 与自然 tail window 存在，但 safe benefit `0/4`，当前 formulation 已 `FREEZE`。
- 反复失败模式：局部/代理收益未进入 full-request critical path；action space 有值但 outcome 前不可选；固定开销吃掉收益；复杂方案不超过简单基线；证据缺 full-DAG identity/denominator/serving closure。

## 本地 PDF 前三页提取的拥挤区

- HOBBIT：mixed-precision expert offloading、cache、prefetch。
- AdapMoE：按输入动态选择 expert 数量，结合 prefetch/cache。
- Aurora：MoE deployment 与 communication scheduling。
- Lina：all-to-all priority、micro-op scheduling、expert popularity。
- 本地旧 proposal：gate-aware partial combine 与 Energy-SLO。

因此 ordinary offloading/cache/prefetch、dynamic top-k/expert count、generic placement、communication priority、近似 combine 不能仅凭组合换名成为新方向。

## 2025–2026 近期一手工作边界

- Numerical-state divergence: [From Expert Reduction to Behavioral Divergence](https://arxiv.org/html/2607.28097) 已系统证明数学等价的 expert reduction order 可导致 state、route 与 text divergence，并提出 numerical compatibility contract；其公开实验是受控 CPU DeepSeek-V4-Flash，不是 GPU production incidence 或 performance-aware runtime enforcement。
- Determinism via verification: [LLM-42](https://arxiv.org/html/2601.17768) 已有 nondeterministic fast path + fixed-shape verify + rollback；[MarginGate](https://arxiv.org/html/2605.30218) 已有 low-margin selective verification/KV repair。
- Routing-aware kernel polymorphism: [RaMP](https://arxiv.org/html/2604.26039) 用 live routing histogram 选择 fused-MoE kernel/config；[DA-MoE](https://arxiv.org/abs/2607.23099) 也做 distribution-aware GPU-resident kernel dispatch。二者主要优化性能，没有把 numerical compatibility 作为 dispatch constraint。
- Numerically consistent adaptive megakernel: [UniEP](https://arxiv.org/abs/2604.19241) 已在 MoE 训练的 expert-parallel megakernel 中把多种优化配置统一为自动适配搜索空间，并用 deterministic token ordering 保证与 sequential execution 的 numerical consistency。它对“自适应 kernel + 数值一致性”形成强碰撞；剩余 claim 必须限定为 inference、routing-histogram-conditioned 多 configuration equivalence classes、分层 state/route/token conformance，而不能泛称 consistency-aware megakernel。
- Cross-layer scheduling/elasticity: [Gimbal](https://arxiv.org/html/2606.15177) 协调 request scheduling、expert pressure 与 placement；[MoEless](https://arxiv.org/html/2603.06350) 做 load prediction 和 elastic serverless expert replicas；[Mixture-of-Experts Serving](https://arxiv.org/html/2607.17880) 研究带 reconfiguration cost 的 online expert capacity allocation；[FinDEP](https://arxiv.org/html/2512.21487) 做 disaggregated expert-parallel fine-grained compute/communication task scheduling。
- Uncertainty-aware scheduling: [TIE](https://arxiv.org/html/2604.00499) 处理 output-length uncertainty；[Robust scheduling under prediction uncertainty](https://arxiv.org/html/2508.14544) 给出 prediction-error-aware scheduling。
- Router fragility / speculative MoE: [When Are Experts Misrouted?](https://arxiv.org/html/2605.07260) 研究 counterfactual routing gap；[AcceptMoE](https://arxiv.org/html/2608.02989) 研究 speculative decoding 的 verifier expert-set selection。

## 由文献交叉产生、尚未排名的候选

### Conformance-Aware MoE Kernel Polymorphism

1. 离线对同一自然 routing/shape cell 的多个 fused-MoE kernel、tactic、reduction configuration 同时测 latency 与分层 conformance（post-expert、post-combine、next-route、persistent state/token，按适用边界）。
2. 把 configuration 划分为 stack-versioned conformance-equivalence classes；未知/未覆盖 signature fail closed 到 canonical implementation。
3. 在线只根据 live routing histogram 在当前 compatibility class 内选最快 configuration；新 signature 先 shadow/canary qualification，不直接提交用户可见状态。
4. 与 latency-only RaMP/DA-MoE dispatch、single canonical kernel、always-verify/rollback 比较完整成本和 zero-unsafe-commit。

Hypothesis：性能最优 configuration 与 numerical-conformance 安全集合并不总是重合；显式 compatibility constraint 可保留大部分 kernel polymorphism 收益，同时避免 route/state/token divergence。

最小否证：若在跨模型自然 cells 中所有性能候选均与 canonical conformance 等价，或安全 class 无法跨 holdout 泛化，或 fallback/qualification 成本消灭收益，则停止作为独立系统方向。

## 评审硬约束

1. 任何新机制都必须区分 phenomenon、oracle/action space、selector/verifier、actuator、implementation 与 workload failure。
2. 不能用 local expert-stage projection 代替 full-request completion、TPOT/P99/goodput。
3. 不能把论文中的现象或现有 verify/rollback、routing-histogram dispatch 单独声称为 novelty；新意必须落在可验证的 residual claim。
4. 本轮不跑新 GPU pilot；候选只获得 `PROCEED_TO_FROZEN_GATE`、`CAUTION` 或 `STOP`，不获得方法 GO。
