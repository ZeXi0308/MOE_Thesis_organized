## Candidate cards

### C01 — Certified compatibility matching

- **Hypothesis**：exactness 是 pair/hyperedge relation；重排等待窗口能比 arrival order 找到更多 exact M=2 work。
- **Mechanism**：以 input-only pair features 建边，做 maximum-cardinality/weight matching；无证书行走 M1。
- **Cheapest falsification**：同 layer/expert/M 内对 repeat-safe 与 unsafe rows 做 frozen partner permutation replay。
- **Kill**：row label 对新 partner 保持不变，或 certified edge 出现任一 false admission；前者会把问题退化为 row classifier + pooling。
- **Compute**：1×RTX 5090，约 30–45 min；CPU graph simulation 2–4 h。

### C02 — Asymmetric safe-row recompute

- **Hypothesis**：2,526 个 exactly-one-safe M2 packs 可被 input-only row certificate 识别，执行 M2 后只补算 unsafe partner。
- **Mechanism**：row-wise certificate → M2 speculative execution → safe row commit → unsafe row M1 rescue → content-addressed stitching。
- **Gate**：fresh false-safe=0；至少一部分 pack 只需一次 M1 rescue；assembled output raw-BF16 exact；总时间低于 two-M1 baseline。
- **Boundary**：若必须先看到 M2 output 才能判断，则会碰撞通用 verification/rollback；必须明确 pre-execution certificate。

### C03 — Exact executor portfolio

- **Hypothesis**：不同 cuBLASLt algo/tile/layout 的 exact regions 互补。
- **Mechanism**：枚举少量 stack-bound executor；输入证书选择 exact-and-fast variant，否则 M1。
- **Gate**：held-out raw-BF16 false admission=0，且 portfolio coverage 严格高于任一单 executor，并有 latency benefit。
- **Collision**：RaMP 已做 routing-aware kernel selection；新意只能来自 semantic-risk hard constraint，而不是 portfolio 本身。

### C04 — Lane-exact grouped M1 arithmetic

- **Hypothesis**：吞吐收益可在不改变每行 M1 reduction tree 的情况下，通过 grouped GEMM、persistent row lanes 或 weight residency 获得。
- **Mechanism**：逻辑上仍是独立 M1 problems；只合并 launch、queue 与 weight reuse，不共享 accumulator/reduction state。
- **Gate**：sealed rows 在 grouped count 2/4/8 下全部 raw-BF16 hash 等于 serial M1，且 per-row time 或 launch count 改善。
- **Compute**：窄 one-expert prototype 需 2–7 implementation days；GPU qualification ≤2 h。

### C05 — Verified rounding envelope + repair

- **Hypothesis**：exact rows 远离 BF16 rounding boundary，可用 sound arithmetic bound 认证；ambiguous rows 才补算 M1。
- **Mechanism**：基于 operand exponent、固定 weights 与 reduction metadata 计算误差区间；区间落在同一 BF16 cell 才 commit。
- **Gate**：certificate 绝不能 unsound；需在多个 layer-expert cells 有非零 coverage 与净执行收益。
- **Risk**：最坏界可能全 abstain；实现成本高，适合作为数值理论支线。

### C06 — Certified temporal/frontier hypergraph packing

- **Hypothesis**：跨 arrival time、layer frontier 与 deadline 的 safe hyperedge 选择，优于逐 cell greedy。
- **Mechanism**：time-expanded hypergraph/MINLP 或 decomposition；节点是 ready expert rows，hyperedge 同时满足 certificate、capacity、deadline、request-DAG state。
- **Gate**：在真实 continuous trace 上，相对 AMoE-like queue policy 和 simple certified greedy 有显著 SLO-goodput 增益，solver overhead 小于收益。
- **Collision**：AMoE/Gimbal 已覆盖 dynamic rebatching/cross-level scheduling；证书必须改变最优决策而非只是普通约束。

### C07 — Content-addressed exact-pack cache

- **Hypothesis**：相同 prompt prefix、retry 或 deterministic replay 会重复出现完全相同 pack identity，可摊销一次 shadow certification。
- **Mechanism**：key 绑定 ordered hidden hashes、layer/expert、model/stack/executor/layout；warm hit 才走 M2。
- **Gate**：warm hit raw exact，且自然 workload hit rate超过 break-even；否则只是正确但无用的 cache。

### C08 — Graph/stream M1 co-scheduling

- **Hypothesis**：isolated M1 的 launch overhead/under-utilization 可通过 CUDA Graph 或固定 multi-stream schedule 回收，而无需 arithmetic coalescing。
- **Mechanism**：每个 canonical M1 call 保持不变，固定 event/output slot 并发调度；未知 signature fail closed。
- **Gate**：8,192-row A plan 零 hash mismatch、trace closure，paired latency/launch count 优于 sequential A。

### C09 — Frozen-input row/shape certificate

- **Hypothesis**：约 8.6% safe-row rate 由 row value composition 与 execution shape 决定，可从 pre-call features 保守识别。
- **Mechanism**：BF16 exponent/sign histograms、norm、near-zero mass、route rank/weight 等；calibration-only support envelope，unknown→M1。
- **Gate**：先做 partner-permutation；若 row-local 成立，再做 document-disjoint fresh false-admission=0、跨 ≥4 cells 的非零 coverage。
- **Bound**：即使 perfect oracle，冻结分布的 call-count ceiling 仅 4.7621%；不能以此承诺 10% latency。

### C10 — Routing-margin-certified rebatching

- **Semantic boundary**：不再要求 raw expert-output bits；保护 next-router top-k set/order。
- **Mechanism**：传播 expert-output perturbation bound，只有 bound 小于 next-router margin 才放行 M>1，否则 M1。
- **Gate**：fresh certified route mismatch=0、非零 coverage；必须清晰区分 raw-exact branch。
- **Collision**：MarginGate 已覆盖 margin-triggered sparse verification；差异必须是 MoE 内部 pre-execution/propagation certificate，而非通用 token verification。

### C11 — Canonical batch-invariant expert arithmetic

- **Semantic boundary**：迁移到显式算术 oracle：固定 K blocking、FP32 accumulation、activation/cast points 与 expert-order combine。
- **Mechanism**：任何 M 都实现同一 per-row function，fusion 发生在算术边界之外。
- **Gate**：M=1/2/4/8 与 oracle bitwise equal；同时报告相对 native M1 的 migration delta 与性能。
- **Collision**：vLLM 已有 batch-invariant mode；贡献必须是 MoE-specific arithmetic contract/efficiency，而非“首次 deterministic”。

### C12 — Selective-abstention exact admission

- **Hypothesis**：conformal/selective rule 能在 shift 下给出可审计的 coverage–risk tradeoff。
- **Mechanism**：输入风险分数 + abstain threshold；risk budget 为硬约束，objective 最大化 saved calls/goodput。
- **Gate**：document/workload split 下零或预先冻结的极低 violation，coverage 非零；必须胜过简单 shape-only threshold。

### C13 — Distributionally robust admission + deadline chance constraints

- **Hypothesis**：workload shift 下，nominal threshold 会同时破坏 semantic risk 与 tail deadline；DRO ambiguity set 可保护二者。
- **Mechanism**：联合选择 stable/fast execution、pack/defer/fallback；约束 worst-case mismatch risk 与 deadline violation。
- **Gate**：在预注册 shift suites 上，相对 threshold/greedy 降低 risk/SLO violation，且 nominal goodput 代价可接受。
- **Risk**：DRO/chance constraint 是通用模板，必须由真实可校准的 MoE mechanism state 驱动。

### C14 — Safe online primal-dual rebatching

- **Hypothesis**：semantic-risk budget、GPU capacity 与 deadline 可用 online prices 协调，优于 myopic greedy。
- **Mechanism**：arrival 时更新 capacity/risk/deadline dual prices；只在 certificate shield 内做 pack/action。
- **Gate**：trace replay 上同时报告 regret/competitive proxy、risk violation、deadline violation、fallback 与 solver overhead。

### C15 — Shielded contextual bandit scheduling

- **Hypothesis**：在 hard safety shield 内，online learner 可适应不同 layer/request 对稳定化动作的 downstream reward。
- **Mechanism**：shield 先删除不安全动作；bandit 只在 safe set 中分配有限 stabilization budget。
- **Gate**：多 workload/seed 下严格不越 safety gate，cumulative downstream reward 优于 random、MaxGate、greedy/load-only；否则学习器无必要。

### C16 — Compatibility-aware semi-Markov queue

- **Hypothesis**：等待会改变 compatible-set、deadline slack 与 future frontier，决策不能只按瞬时 queue state。
- **Mechanism**：semi-Markov state 包含 layer/expert queue、risk class、age、frontier；action=pack/defer/stable/fallback。
- **Gate**：真实 continuous trace 上相对 FCFS、AMoE-like rebatching 与 certified greedy 改善 SLO-goodput，且 policy computation 可在线化。
- **Collision**：若 certificate 最终是 row-local 且 action 可逐行分解，这个 MDP 很可能退化，不应保留复杂模型。

## Non-merge guards

- certificate construction（C09/C12）与 scheduler consumption（C01/C06/C14–C16）是不同控制层，不机械合并。
- pre-execution admission 与 post-execution repair（C02/C05）不同。
- raw-BF16 exact（C01–C09/C12–C16 的相应版本）、next-route equivalence（C10）与 canonical-arithmetic migration（C11）是三条不可混写的 semantic branch。
- cache（C07）、kernel/runtime construction（C04/C08）与 online OR policy 不因共享输入特征而合并。
