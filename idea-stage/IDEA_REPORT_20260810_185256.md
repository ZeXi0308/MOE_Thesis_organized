**生成时间**：2026-08-10 18:52:56 +08:00

**方向**：execution-shape-induced route instability 的 action upper bound、canonical execution 与 stability-aware MoE runtime  
**候选流程**：两个互补搜索面（10 个 D-series 方法候选；21 个 shard ideas → 14 个 C-series 机械聚类）→ 11 个广义 survivor families → 3 个优先方向 → 2 个 GPU Pilots 完成

## 结论

现在最像系统论文方法的方向是：

> **Stability-Aware Expert Shape Lanes（D10 / C07+C12）**：router 产生 rows 后，runtime 不再允许任意 expert M，而是把 rows 放入少量固定 physical-shape lane；deadline 到达时用 masked dummy rows 补齐，并用 padding/waiting budget 控制成本。

它不是换一个 MaxGate predictor，而是直接控制已经观察到的 causal variable——expert execution shape。新的 GPU 结果使它从“假设”推进到“通过最小正确性 Gate 的方法候选”：固定 `C=8` 在 21 个 enriched cells、16 个 victims 上，对三组真实 companion、不同 focal slot、zero padding 和 expert 调用顺序均保持 bitwise invariant；raw、post-combine、后续 route、final logits mismatch 均为 0，既有 M1/M64 sensitive hashes 32/32 复现，独立重算 PASS。

这个 invariant C8 output 不是 M1/M64 的“恢复值”：32 个 prior-sensitive contributions 中，C8 仅 1 个等于 M1、0 个等于 M64、31 个与二者都不同。当前支持的是 **fixed-C8 context invariance**，不是 M1 equivalence、canonical ground truth 或模型质量提升。

这仍不是性能或 serving 结果。下一道 D10 Gate 只问 fixed-C8 lane 是否能在 zero-divergence 前提下形成优于 serial M1 / global Batch Invariance 的成本 Pareto。

并行完成的 **single-contribution oracle/action sweep** 得到强正信号：33/240 个正 actions 恢复 `37/43=86.05%` 的 route distance，覆盖 8 victims；相同 33-action 预算下，global random 仅 `0.309375`，即使先给 random 正确的 33 个 cells、只随机 rank，也只有 `19.5`。因此 action space 有价值，MaxGate-v1 失败是 selector failure，不是 intervention failure。

现在有两个分别成立但尚未连接的事实：M1 protected action 有强 oracle value；固定 C8 output 对 companion/slot/order invariant。最小的新系统机会是 **SparseShapeLane**：用 stability budget 把少量 contribution 送入 fixed C8 protected lane。下一轮只需先验证 C8 能否替代 oracle-M1 action，不先发明在线 predictor。

## MaxGate-v1 精确排除边界

被排除的是：

> 在冻结的 16 个窗口、240 个 victim-layer cells、all-M1 自监督 reference，以及“恰好一个 contribution 走 M1、其余七个走 M64”的动作面上，用当前层最大 gate weight 选择唯一受保护 contribution，能够比该次预先冻结的 balanced-shuffle rank 获得更高的聚合 downstream route-membership reward。

实际结果是 MaxGate-v1 `-3`、frozen shuffle `+3`；MaxGate 有 13 个正 cell、18 个 harm cell。它只说明当前层最大 gate weight 与这个动作的 downstream value 不对齐。

它不排除 hindsight oracle、多 action、canonical shape、pack surgery、stable kernel、stability budget、route-aware batching，或 numerical stability as a runtime resource。

## 明确排除的弱变体

1. `MaxGate-v2 = margin / entropy / activation norm / local L2`：只换 row-local score。
2. 在同一 frozen 数据上调 MaxGate threshold、筛正 cell 或换 seed 救结果。
3. 没有 stability-specific action 的泛化 expert-aware batching/load balancing。
4. 把全局 deterministic/batch-invariant mode 当 headline；这里只作为 comparator。
5. 没有实测 action state 的 generic bandit、primal-dual 或 MINLP。
6. 把 fixed padding 单独包装成贡献；headline 必须包含 ShapeABI、lane scheduler 和端到端 tradeoff。

## Top 3（按当前系统论文潜力）

### Top 1 — Stability-Aware Expert Shape Lanes（D10 / C07+C12）

- **Method（实际做什么）**：router 后按 `(layer, expert, dtype, backend-plan, C=8, stack-epoch)` 建 lane queue；凑满 8 rows 即发射，deadline 到达则 masked padding；PadCap 同时约束 dummy FLOPs 和 row wait；executor 只执行 ShapeABI 允许的 fixed shapes，stack 变化时 PlanFence 失效并回退。
- **Hypothesis**：固定 expert physical shape 能提供 batch-context invariance，并以小于 serial M1/global invariance 的成本保留 continuous batching。
- **Why it may work**：直接控制 observed execution shape；不依赖 MaxGate；correctness primitive 已有真实 GPU signal；MoE expert-ready queue 提供了普通 dense LLM 不具备的 lane-formation action；padding/等待可形成明确性能–稳定性 frontier。
- **已完成最小实验**：固定 `C=8`，21 enriched cells × 8 ranks × 4 contexts × 3 repeats；从 target windows 与 document-disjoint donors 构成的混合 pool 中选三组互不重复 real companions，slots 0/3/7，另有 zero padding slot 5。
- **Observed result**：21/21 eligible、16 victims、0 rejected；32/32 M1/M64 sensitive hashes 复现；raw mismatch 0；post-combine/downstream route/final-logit mismatch 0；94.22 秒；independent recompute PASS。
- **结果支持什么**：支持 fixed-C8 capsule 是 context-invariant executor primitive。
- **结果不支持什么**：不支持 C8 等价于 M1/M64 或模型 ground truth，也不支持自然发生率、latency、TPOT/P99/goodput、优于 vLLM、跨模型/跨 GPU、EP/NCCL/RDMA。
- **下一最小实验**：冻结 C=8，在 continuous-decode 上比较 native variable-M、serial M1、global Batch Invariance 与 C8 lane；同时测 policy 内 invariance、相对 native/serial-M1 两个 behavior references 的 route/logit/greedy-token 差异与最小 next-token NLL、expert GPU time、padding、queue wait、p99 token-step delay。
- **支持下一节点**：policy 内 zero mismatch；没有明显 next-token quality degradation；expert GPU time 比 serial M1 低 ≥20%、比 global invariance 低 ≥10%；新增 p99 token-step delay ≤5%。
- **否定范围**：correctness mismatch 只杀当前 fixed-C8/stack；correctness 通过但成本失败时，D10 不作 headline，只保留 fixed-M capsule baseline，不在同一结果上改 C/deadline 救活。
- **Contribution type**：runtime mechanism + scheduler/executor contract。

### Top 2 — StabilityBudget + SparseShapeLane（C01+C02，连接 C07/C12）

- **Method（实际做什么）**：默认 contribution 走 native fast lane；有限 stability budget 只把被选中的 contribution 送入 fixed C8 canonical lane；后续 online rule 必须使用 request trajectory / pack relation，不使用 margin、entropy、norm 等 scalar score。
- **Hypothesis**：C8 canonical output 能充当 oracle 已证明有价值的 protected action，从而把 13.75% 的稀疏预算转化为可实现的双路径 runtime。
- **Why it may work**：M1 oracle 已证明 cell allocation 与 rank allocation 都有价值；C8 已证明 context invariance；33 个正 cells 跨 13 layers、22 experts，任一 expert 最多 3 次，却在 8 victims 上聚集，指向 request/pack relation 而非静态 expert table。
- **Minimal bridge experiment**：只在已确认的 33 个 oracle-positive cell-ranks 上比较：oracle rank 用 M1、同一 rank 用 fixed C8、等预算 shuffled rank 用 fixed C8；保持相同 R/U/downstream reward。预计 5–10 GPU 分钟。
- **支持**：C8 保留大部分 M1 oracle reward，且不产生明显新增 harm；随后才进入 fresh natural-pack relation selection。
- **否定范围**：只否定 C8 作为 single-contribution protected path；不否定全局 fixed-C8 scheduler，也不否定 M1 WitnessPatch。
- **状态**：`TWO_PARENT_SIGNALS_SUPPORTED / BRIDGE_NOT_RUN`。
- **Contribution type**：stability-resource abstraction + sparse runtime allocator。

### Top 3 — RouteStress WitnessPatch（C06）

- **Method（实际做什么）**：在 natural heterogeneous packs 找可复现正例；delta-debug 到最小 conflict witness；fresh pack 命中冻结 predicate 时只把 witness rows 切到 protected M1/C8，recompact 其余 rows；与等预算 shuffled surgery 比较。
- **Hypothesis**：route propagation divergence 由小型 co-row conflict subset 触发，最小 witness surgery 比随机拆行更有效。
- **Why it may work**：oracle positives 在 victim/request 上聚集、却不集中于单一 layer/expert；relation/composition 比静态 row score 更符合该结构；只拆少量 rows 可保留大部分 batching。
- **Minimal experiment**：bridge 通过后，在 4–8 fresh victims 上执行 native、WitnessPatch、budget-matched shuffled patch，预计 60–90 GPU 分钟。
- **支持**：avoided divergence per protected row ≥ shuffled 的 1.5×，覆盖 ≥4 victims。
- **否定范围**：只否定该 witness predicate/minimal surgery，不否定其他 composition action 或 canonicalization。
- **状态**：`DESIGNED / NOT_IMPLEMENTED / NOT_RUN`。
- **Contribution type**：scheduler/runtime method。

RouteGuard/precision-island 保留为第四顺位 protected path；当前 C8 与 M1 actions 已有更直接证据，不先开发 custom stable kernel。

## Oracle GPU Pilot — Stability-Budget Action Frontier

- **Method（实际做什么）**：对 240 frozen cells 执行 all-M1 reference、all-M64 no-intervention 与 8 个“只保护 rank r”的动作；所有 outcome 产生后才让 hindsight oracle 选 rank 或 abstain；按实际 action budget 同时比较全局随机 cell-rank 与 oracle-selected cells 内随机 rank；复跑所有正 oracle action。
- **Hypothesis**：single-contribution action 若有价值，oracle 应用少量 actions 恢复显著 route agreement，并同时优于两种 budget-matched random。
- **执行**：240 cells × `A0..A7` = 1920 candidate actions；430.21 秒；33 个 positive actions 全部复跑确认。
- **结果**：oracle reward 37、action budget 33、recovery `37/43=86.05%`；global/conditional budget-matched random 为 `0.309375/19.5`；33 positive cells、8 victims、31 full restorations。
- **结论**：`STRONG_ORACLE_ACTION_VALUE_SIGNAL`。cell 与 rank selection 均有独立价值；MaxGate `-3` 仍失败。
- **审计**：`WARN / P0=0 / P1=1`。P1 仅说明 MaxGate/shuffle `-3/+3` 在 oracle config freeze 前已知，不能称全候选 outcome-naive preregistration；不改变穷举数值。
- **范围**：retrospective self-supervised same-cell proxy；不支持 online selector、serving、quality 或泛化。

## System 设计：从 fixed capsule 到 SparseShapeLane runtime

```text
router/top-k rows
      ↓
StabilityBudget allocator（未来：request/pack relation）
      ├─ default → native fast lane
      └─ protected → fixed-C8 ShapeLane
                       key = layer × expert × dtype × plan × C8 × epoch
                       full → launch
                       deadline → masked pad under PadCap
      ↓
normal unpermute / combine / next layer
```

最小系统增量不是再加 selector，而是四个明确组件：

1. **ShapeABI**：把“稳定”定义为 stack-versioned physical execution contract。
2. **Lane Former**：只在 router 已给出 rows 后重组，不改变 top-k/expert identity。
3. **StabilityBudget / PadCap**：分别约束 protected contribution、padding FLOPs 与 queue delay。
4. **Relation compiler**：从 request trajectory / pack witness 产生 action；不退化为新 scalar score。
5. **PlanFence**：backend/kernel/driver epoch 变化时让已验证 contract 失效并安全回退。

## 实验执行优先级

1. **M1→C8 protected-action bridge**：5–10 分钟，直接判断两条正证据能否合并为 SparseShapeLane；不测试 selector。
2. **D10 continuous-decode 最小 Pareto Gate**：固定 C=8，比较 native、serial M1、global invariance 与 C8 lane，同时报告 behavior-reference 差异、padding/wait、TPOT/P99/goodput。
3. **Fresh WitnessPatch**：仅在 bridge 通过后测试 relation-aware selection；若 bridge 失败，仍可使用 M1 protected path。
