## Verdict

有一个目前能立住的方法候选：

> **D10 Stability-Aware Expert Shape Lanes**：连续批处理调度器不改变 token 的 top-k/expert identity，而是在路由后把每个 expert 的 ready rows 放入少量固定形状 lane；通过稳定 row placement、deadline flush 和 dummy masking，在执行前约束会引起数值变化的 expert M，同时避免全局 deterministic kernel 和事后 verify/rollback 的固定成本。

它不是 MaxGate-v1 的改名版本。MaxGate 试图预测“保护哪个 rank”，冻结实验已经 NO-GO；D10 直接控制已观察到的因果变量——expert execution shape。

当前等级是 **Promising method candidate**，不是论文结论。最小 `C=8` 正确性 Gate 已通过；系统成本与 serving Gate 尚未运行。

## Observation → Insight → Mechanism → System → Evaluation

1. **Observation（Observed）**：同一 expert contribution 在 M1/M64 下可出现 raw-BF16 delta；在富集目标中，该 delta 能穿过 combine，并在 12/32 targets、8 victims 上改变下游 route。MaxGate-v1 的 signed reward 为 -3，弱于 matched shuffle 的 +3。
2. **Insight（Inferred）**：当前 gate weight 不是可靠 action-value signal；但 scheduler 本身决定每个 expert 的 live row count M，因此可以在执行前改变 shape，而非事后猜 victim 或回滚。
3. **Mechanism**：把 expert rows 映射到固定 `C` 的 shape lanes；real rows 不足时用 masked dummy padding，超过时 split；row identity 和 slot 规则固定。
4. **System**：continuous batcher → expert-ready queues → deadline-aware lane former → fixed-shape executor → normal unpermute/combine。D03 execution-signature fence 只作为未来兼容/回退模块，D01 fixed-M capsule 是 executor primitive。
5. **Evaluation**：在相同 zero-divergence 标准下，比 native variable-M、serial M1、vLLM global Batch Invariance；主要系统指标是 TPOT/P99、goodput、padding、kernel calls/GPU time，正确性指标是 raw hash、post-combine、route trajectory 与 final logits。

## 为什么还有新意空间

- vLLM Batch Invariance 是全局 deterministic-kernel 模式，并明确接受性能代价；D10 的问题是能否借助 MoE 的 routed expert-row queue，在 scheduler 层只形成少量稳定 shapes，以更低成本达到相同 invariance。
- LLM-42/MarginGate 是 fast path 后 verify/rollback/repair；D10 在 expert 执行前形成 shape，不需要完整 token replay。
- RaMP/DA-MoE 按 routing histogram 选择最快 kernel；D10 把**数值等价性**作为 hard scheduling constraint，性能只在可行集内优化。
- 因此论文贡献不能写成“固定 padding”或“一种新 kernel”，必须是 **numerical-stability-constrained MoE batching contract + lane scheduler + end-to-end tradeoff**。

## Fresh Jury Top 3

### 1. D10 — Stability-Aware Expert Shape Lanes（`ADVANCE`）

- Jury：novelty 6.5/10，evidence fit 7/10，system depth 8.5/10，two-week falsifiability 8.5/10。
- 最大风险：若 fixed shape 不能保证 row invariance，或 padding/等待成本不能优于 global invariance / serial M1，则只剩工程技巧。
- 新证据：`C=8` correctness Gate 在 21 cells、16 victims 上 0 raw mismatch、0 route/final mismatch，32/32 既有 M1/M64 hash 复现。

- 单独只是 fixed-shape/padding implementation，系统与 novelty 深度不足。

## Pilot Result

### run01：INVALID，保留不改

- 仅 4/21 cells 每个 top-8 rank 都有 21 个不同 real companions。
- 已计算的 4 cells 为 0 mismatch，但覆盖门槛失败，不能据此 PASS。

### run02：Correctness Gate PASS / CONTINUE

- Target：21 个此前 shape-sensitive victim-layer cells，16 个 target 文档。
- Donor：doc016..031、每文档 512 tokens，与 target 文档不重叠，只提供同 layer/expert companion rows。
- Context：三组 disjoint real companions（slots 0/3/7）+ zero padding（slot 5）；每组 3 repeats，并轮转 expert 调用顺序。
- 结果：21/21 eligible、0 rejected、raw mismatch 0、combine/route/final mismatch 0、既有敏感 hash 32/32 复现。
- 判定：`CONTINUE_D10_FIXED_C8_CORRECTNESS_ONLY_COST_AND_SERVING_GATES_PENDING`。

这只证明 fixed-C8 primitive 在当前 OLMoE/RTX5090/BF16 eager 富集面上的 context invariance；不证明自然 prevalence 或性能收益。

## Paper Readiness

- **CCF-C 潜力**：如果下一 Gate 在真实 continuous decode 上保持 zero divergence，并相对 serial M1 与 vLLM Batch Invariance 得到明确 TPOT/P99/goodput Pareto，且至少再复核一个 MoE 模型，则方向可形成完整 systems paper story。
- **CCF-B 潜力**：还需要更强的 vLLM/SGlang 端到端集成、多个 serving workloads/模型、真实 continuous batching，以及机制分析说明何时 lane 等待与 padding 值得；当前证据远未达到。
- **当前禁止表述**：不能写“提升模型质量”“自然请求普遍翻转”“优于 vLLM”“多 GPU/EP 有收益”或“已达到 CCF-B”。

## 唯一下一 Gate

在不改 `C=8` 的前提下，运行 continuous-decode cost Gate：

- arms：native variable-M、serial M1、vLLM Batch Invariance、D10 C8 lane；
- correctness：所有 repeat/context raw 与 route mismatch 必须为 0；
- cost GO：expert GPU time 比 serial M1 低至少 20%，比 vLLM Batch Invariance 低至少 10%，新增 p99 token-step delay 不超过 5%；
- 任一 correctness mismatch：杀 fixed-shape family；
- correctness 通过但 cost/queue gate 失败：D10 不作 headline，只保留 D01 baseline，不在同一证据上改 C 或 deadline 救活。
