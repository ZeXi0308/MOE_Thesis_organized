# Targeted novelty input: C09, C02, C04

**Date**: 2026-08-10  
**Status**: search input for an independent same-family reviewer; no novelty verdict is encoded here.

## Proposed methods

### C09 — Pre-execution MoE row/shape safety certificate

At fixed model, stack, layer, expert and candidate batch shape, derive conservative features from a routed hidden row before expert execution. Admit the row to a fast M>1 path only when the frozen rule predicts raw-BF16 equality to canonical isolated M1; otherwise use M1. First require partner-permutation evidence that row safety is stable across co-rows and slot order.

### C02 — Asymmetric exact-row commit with selective M1 rescue

For a two-row expert batch, use a pre-execution row certificate. Execute M2, keep only rows certified safe, recompute uncertified partners at M1, and stitch by sealed row identity. The result must be raw-BF16 equal to two isolated M1 calls and faster after certificate, M2, rescue and stitching overhead.

### C04 — Grouped execution that preserves canonical M1 arithmetic

Submit many independent logical M1 expert GEMMs through one grouped or persistent kernel. Share scheduling, launches and weight residency, but preserve each row's M1 K traversal, accumulator, activation, cast points and output slot. Qualify bitwise equality against serial M1 before measuring speed.

## Core claims requiring novelty

1. **C09 mechanism claim**: pre-execution, input-derived MoE expert-row safety prediction/certification for batch-size-induced raw-BF16 invariance is not already an established method.
2. **C02 mechanism claim**: using that pre-execution row certificate to commit one exact row and selectively recompute its unsafe co-row is distinct from generic post-output verification/rollback.
3. **C04 mechanism claim**: grouped/persistent execution of independent M1 expert problems, explicitly preserving the serial-M1 arithmetic identity while sharing dispatch/weights, is more than ordinary grouped GEMM or persistent MoE kernels.
4. **Contribution-unit claim**: the combination exposes a new MoE system tradeoff only if it beats global batch-invariant execution, generic verify/rollback, and ordinary grouped GEMM under the declared exactness boundary.
