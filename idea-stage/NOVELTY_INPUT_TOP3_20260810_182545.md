## C01 — JoinStream

**方法**：一个 expert whole batch 仍只 launch 一次，batch membership、最终 finish、总 service 与 executor busy interval 保持不变；runtime 以冻结且与请求结果无关的 row milestone curve 暴露 prefix completions。完成的 row 立即进入原有 top-k join；Oracle 只选择物理 row order，不选择 milestone 数值。

**核心 claims**：

1. MoE serving 中，把同一个 whole expert batch 内的 row completion 暴露为 token join 事件，是区别于 input re-batching/queue ordering 的 completion contract。
2. token 的两个 top-k rows 可在不同 expert executors 上被 co-prioritized，使该 token 的下一层与同 batch 尾 rows 重叠，而不拆 batch、不增加总 service。
3. 新颖性若成立，应位于 AMoE 的 layer µ-queue、ExpertFlow 的跨 batch token rearrangement、ExpertPlex 的 tile scheduler之间的未覆盖交叉点。

**必须检查的近邻**：

## C07 — QuantumYield

**方法**：expert batch 启动后，在冻结 service quantum 上 cooperative preempt，保存已完成 work 与 remaining service；先执行随后 reveal 的 urgent join-closing whole queue，再 resume 原 batch并支付 penalty。动作不切 ready rows，也不丢 work。

**核心 claims**：

1. running-state preempt/resume 是 whole-ready/HOLD 无法表达的动作。
2. MoE join-closing blocker 与 exact remaining-work conservation 可能构成区别于通用 request priority 的新调度合同。
3. 若已有 expert/layer-level preemption，其 method novelty 应降级；只能保留更窄的 join-aware finding。

**必须检查的近邻**：

- [QLLM: Priority-Aware Preemptive Scheduling for Mixed-Priority Workloads in MoE Inference](https://arxiv.org/abs/2503.09304)
- [ExpertPlex](https://arxiv.org/abs/2607.18002)
- [AMoE / AEP](https://arxiv.org/abs/2505.08944)
- [FastServe](https://arxiv.org/abs/2305.05920)
- [Gimbal](https://arxiv.org/abs/2606.15177)

## C12 — ShapeLease

**方法**：logical whole queue 不变；每个 replica 维护 resident execution tactic，scheduler 可在 native/padded/persistent tactics 间 reconfigure 并付成本。Expanded Oracle 必须击败三个 fixed-tactic exact Oracles的最佳值，并在最优轨迹实际使用至少两种 tactics。

**核心 claims**：

1. tactic residency/reconfiguration 是跨连续 waves 的状态，而非只按当前 row histogram 做 stateless kernel dispatch。
2. action-space signal 要求动态切换严格击败最佳 fixed tactic，不允许选择弱 baseline。
3. 若现有 runtime 已进行 stateful adaptive persistent-kernel selection，method novelty 应降级为 baseline/benchmark finding。
