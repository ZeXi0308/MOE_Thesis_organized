# Top-3 Novelty Input（2026-08-11）

> 范围：fresh jury 选出的 C10 / C07 / C02。这里只整理 core claims、三种检索表述和最近邻；不预设 novelty verdict。

## C10 — Canonical Segmented Epilogues

### Core claims

1. 在保留 dynamic packed expert GEMM 的前提下，按 request/token/expert/contribution identity 的 segmented canonical epilogue 可让 MoE 结果独立于 companion 与 packing shape。
2. 该 by-construction 路径不依赖 universal fixed shape、pre-action selector 或 verify/rollback。
3. 在 full-request accounting 下，它能优于 serial canonical、universal batch-invariant 和 verified-speculation baselines。

### 三种检索表述

- `mixture of experts segmented epilogue canonical accumulation dynamic batching deterministic`
- `fused MoE shape independent numerical consistency reduction order kernel`
- `MoE deterministic token ordering megakernel inference accumulation`

### 最近邻与直接碰撞

- [UniEP](https://arxiv.org/html/2604.19241) 是最强碰撞：训练 EP megakernel 中已有 deterministic global token mapping；GroupGEMM+Combine 的 Reduce-Worker 等待同一 token 的全部 top-k contribution，再按 baseline order reduction，从而保持 bitwise consistency。它还在统一参数空间中自动选择优化配置。
- [From Expert Reduction to Behavioral Divergence](https://arxiv.org/html/2607.28097) 已建立 reduction order → state/route/text divergence 及 hierarchical conformance contract，但明确不测 GPU deployment incidence 或 performance。
- [vLLM Batch Invariance](https://docs.vllm.ai/en/stable/features/batch_invariance/) 已提供 batch-size/order independent deterministic inference，代价是禁用部分 nondeterministic optimizations。
- [LLM-42](https://arxiv.org/html/2601.17768) 与 [MarginGate](https://arxiv.org/html/2605.30218) 是 verify/rollback 与 selective verification 强基线。
- [RaMP](https://arxiv.org/html/2604.26039) / [DA-MoE](https://arxiv.org/abs/2607.23099) 覆盖 routing-aware fused-MoE config dispatch。

### 关键本地冲突

本地 StableBatch 的 M1/M64/C8 证据显示 raw expert output 已随 expert GEMM physical M 改变；若 first divergence 位于 GEMM 内部，则“只改 epilogue”不能修复。这是 C10-G0 必须先做的 source-localization kill condition。

## C07 — Causal Repair Cones for Sparse MoE Divergence

### Core claims

1. MoE route/row identity 可以生成 dependency invalidation certificate，把已验证失败后的 repair scope 缩到严格小于 token/full-request suffix 的 causal cone。
2. cone replay 能在 frozen boundary 与 all-canonical reference 重合，证明 zero unsafe commit；无法证明 closure 时 fail closed 到 full rollback。
3. verifier、ledger、invalidation、replay 全部计费后，full-request headroom 仍为正。

### 三种检索表述

- `LLM inference dependency scoped rollback partial recomputation repair cone`
- `transformer inference selective replay layer state dependency graph rollback`
- `MoE partial recomputation divergence repair row identity`

### 最近邻与直接碰撞

- [LLM-42](https://arxiv.org/html/2601.17768) 已用 fixed-shape verification 和 rollback 保证 deterministic inference。
- [MarginGate](https://arxiv.org/html/2605.30218) 已用 low-margin trigger 选择性验证，并替换当前 KV column 修复确认的 mismatch。
- [Predict, Reuse, and Repair](https://arxiv.org/abs/2606.30389) 在 dynamic sparse attention 中用 incremental repair kernel 把漏掉的 blocks 合回 partial attention state；它说明“partial state repair”本身并不新。
- [Efficient LLM Inference with I/O-Aware Partial KV Cache Recomputation](https://arxiv.org/abs/2411.17089) 已覆盖 performance-oriented partial KV recomputation。
- 本地 SFV2-O2 已提出 selective repair；C07 只有证明 `MoE identity + exact dependency cone + closure certificate` 严格缩小 full suffix，才有 residual。

## C02 — Intervention-Calibrated Request-DAG Trace

### Core claims

1. MoE full-request trace 必须用真实低幅度干预进行 held-out blind calibration，才能作为 counterfactual Oracle/repair substrate。
2. request/step/layer/route/resource-order/service identity 足以预测 intervention 的 completion-delta sign、affected request set 与 order；失败能输出有限 missing-edge class。
3. 同一 contract 可同时支撑 numerical feedback、critical-path Oracle 与 repair closure，而不是只做异常解释。

### 三种检索表述

- `causal profiling perturbation performance critical path request latency`
- `LLM inference causal profiling perturbation request DAG`
- `LLM inference trace validation intervention dependency graph`

### 最近邻与直接碰撞

- [COZ](https://www.usenix.org/conference/atc16/technical-sessions/presentation/curtsinger) 已通过 performance experiments/virtual speedup 建立 causal profiling。
- [CRISP](https://www.usenix.org/conference/atc22/presentation/zhang-zhizhou) 已对 large-scale microservice traces 做 request critical-path analysis。
- [TELLER](https://arxiv.org/abs/2608.01975) 已为 LLM inference 重建 per-request call-chain、dependency-aware causal-context slices，并在多节点 GPU workload 上做 root-cause localization。
- C02 的 residual 只能是 `MoE-specific identity-complete DAG + real intervention blind validation + fail-closed Oracle qualification`；不能把 trace collection、causal slicing 或 RCA 当 novelty。

## 必须回答的裁决问题

1. C10 是否被 UniEP 的 deterministic mapping/reduction contract 直接覆盖？如果没有，residual 的 exact scope 是什么；本地 raw-GEMM divergence 是否已使 epilogue-only mechanism 不成立？
2. C07 相对 LLM-42/MarginGate/PRR 的新增部分，是否足以构成 method，还是只能算 full-DAG implementation refinement？
3. C02 是否只能作为 infrastructure，且是否值得先做；它最小可发表 residual 是否仍存在？
