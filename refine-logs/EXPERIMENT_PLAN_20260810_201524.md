# StableBatch Selectability Decomposition Gate 实验计划

**Problem**：execution-shape 传播机会能否由 calibration 后冻结、执行前可见的信息在新请求上选出。  
**Method Thesis**：把相同稀疏 action budget 下的 hindsight Oracle、静态 compatibility map、row-level observable 浅层模型和 matched shuffle 放在同一 held-out action surface 上；只有静态或在线 selector 明确恢复 Oracle–shuffle gap，StableBatch 才继续作为系统机制。  
**Date**：2026-08-10  
**Evidence type**：单 RTX 5090、单 OLMoE revision、BF16 eager、self-supervised all-M1 reference proxy；不是 ground truth quality、serving、跨模型、多 GPU、EP/NCCL/RDMA 证据。

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Block |
|---|---|---|---|
| C1：held-out action space 仍有足够 Oracle 上限 | 没有上限就不应继续研究 selector | exact-B Oracle reward 为正、优于 matched shuffle，恢复至少 25% unprotected route distance，覆盖至少 4 个 victims | B1 |
| C2：风险具有 request-transferable 静态结构 | 直接决定 compatibility envelope / partition planner 论文链条是否成立 | Static Map reward > 0、> shuffle、Recovered Oracle Gap ≥ 0.30，且 leave-one-victim-out 不翻转 | B1 |
| C3：若静态结构失败，row-level pre-action signal 仍可选择 | 决定是否转为 row-conditioned execution-risk scheduling | Online Ridge 通过与 C2 相同的 held-out Gate；模型与特征在 outcome 前冻结 | B1 |
| Anti-claim：收益来自 held-out outcome 泄漏或未匹配工作量 | 若成立，Gate 无法解释 | selector lock 早于 outcome ledger；四策略恰好 B=33 unique cells、每 cell 一 rank、相同 M1+7×M64 action signature | B0/B1 |

## B0：预冻结数据、动作与选择器

### 数据边界

- **Calibration only**：`oracle_action_sweep_20260810_run01/cell_results.jsonl` 的旧 240 cells / 1,920 candidate actions；允许学习表与浅层模型，禁止继续称为 held-out。
- **Held-out**：`semanticfence/experiments/data/fresh_eval_20260809_v1/eval_manifest.jsonl` 按既有顺序取前 16 个文档，`token_offset=512`、`window_tokens=16`、victim position 15、layers 0–14，共 240 cells。
- fresh manifest 与 StableBatch 既有 32 个文档 text SHA256 交集为 0。它只声明 **fresh-to-StableBatch**；该 manifest 曾服务于另一个方向，不声明全工作区从未运行。
- cell identity 必须绑定 manifest SHA256、document text SHA256、offset、layer；不能只用数值 document index。

### 统一 action surface 与预算

- candidate action：某 cell 的一个 top-k rank 使用 `M=1`，其余 7 ranks 使用 `M=64`；all-M1 为 reference，all-M64 为 unprotected。
- 主预算固定为 **B=33 个不同 cells**，每个 cell 最多一个 rank；33 来自 calibration 中 positive-best unique-cell 数，在任何 held-out outcome 前冻结。
- 四策略均视为在其余 207 cells abstain（reward 0）。全 8-rank sweep 只是测量 instrumentation，不改变策略级 action budget。
- action reward：`recovered downstream route memberships - newly harmed memberships = D_U - D_action`；同时独立记录 recovered、harmed、persistent。

### 四个冻结策略

1. **Outcome Oracle (exact-B)**
   - 每 cell 先取 net reward 最大的 rank；再在 240 cells 中取最优 33 个，固定 tie-break 为 reward 降序、harmed 升序、rank 升序、cell identity。
   - 即使正收益不足 33 个，主 Oracle 仍精确使用 33 个 action；另报 `at_most_B_abstaining_oracle` 仅作诊断。

2. **Static Compatibility Map v1**
   - 只用 calibration 的 `(layer, expert, topk_rank, M1+7M64 signature, kernel signature)` 与 signed reward。
   - 固定 `lambda=4`、global calibration mean 为 prior。分别计算 `(layer,expert)`、`(expert,rank)`、`(layer,rank)` posterior mean；三者平均作为 exact tuple prior，再计算 `(layer,expert,rank)` posterior mean。未见 key 自动回退到 prior，不做 threshold 或超参搜索。
   - held-out 每 cell 取 score 最大 rank，再全局取前 33 cells；hash 只用于等分 tie-break。

3. **Online Observable Ridge v1**
   - calibration signed reward 上一次性拟合 closed-form L2 ridge regression，`alpha=1.0`，intercept 不惩罚；不做 CV、模型搜索或阈值调参。
   - 特征仅含执行前字段：layer/expert/rank one-hot、Static Map score、gate weight、top-8 内归一化 weight、该 rank 相对 top-8 最小 weight 的差、top-8 mass、top-8 normalized entropy、current-layer top-k cutoff margin。连续特征只用 calibration 均值/方差标准化。
   - 禁止 document/token/cell ID、M1/M64 side-call 差异、future route、final logits 或任何 held-out outcome。
   - 同样每 cell 取预测最高 rank，再全局取前 33 cells。

4. **Action-budget-matched Shuffle v1**
   - 在 outcome 前用固定 seed 对 240 cells 作 SHA256 排序，取前 33；用独立 seed 对 selected cells 排序并循环分配 rank 0–7，使 rank counts 相差不超过 1。
   - 主指标使用这一个预封 deterministic realization；另报 exact uniform cell/rank expectation 作为诊断，不替代主 shuffle。

### 泄漏防线

- GPU runner 顺序强制为：验证 calibration/freshness → native-only held-out feature scan → 拟合并写出 `SELECTOR_LOCK.json` → fsync/hash seal → 才允许创建 `cell_results.jsonl` 和执行 M1/M64 side-calls。
- selector lock 必须包含 training ledger hash、fresh manifest/text/window hashes、算法常量、normalizer、table/model parameters、四策略的 33 个 action identities，以及 `outcome_rows_existed_at_seal=false`。
- 若 lock 前出现 held-out action outcome、text overlap 非零、预算/identity 不闭合或同臂不稳定，实验判为 INVALID，不解释 reward。

## B1：Fresh held-out GPU Selectability Gate

### 最小执行

- 16 requests × 15 layers = 240 cells；每 cell 执行 R、U、A0–A7，必要时只对 positive Oracle selected action 做一次稳定性确认。
- 所有 arm 固定同一 input window、同一 target router/gate weights、同一 seven-M64 background、同一 side-call schedule 与相同 full-forward shape。
- primary policy aggregation 只读取 sealed plan 对应的 33 个 actions；Oracle 在全部 outcomes 完成后计算。

### Primary metrics

- `R_p = Σ(recovered_p - harmed_p)`，p ∈ {oracle, static, online, shuffle}。
- `RecoveredOracleGap(p) = (R_p - R_shuffle) / (R_oracle - R_shuffle)`；若 denominator ≤ 0，selector Gate fail-closed。
- opportunity：Oracle recovery fraction、Oracle positive victims、Oracle–shuffle gap。
- robustness：per-victim reward/recovered/harmed；逐个移除 16 victims 后重算固定策略聚合与 recovered gap。

### 冻结判据

- **Oracle opportunity PASS**：`R_oracle > 0`、`R_oracle > R_shuffle`、Oracle 恢复至少 25% unprotected route distance、positive Oracle actions 覆盖至少 4 victims。
- **Selector GO**（static 或 online 分别判定）：held-out `R_selector > 0`、`R_selector > R_shuffle`、RecoveredOracleGap ≥ 0.30、positive-net victims ≥ 4，且删除任意一个 victim 后前三项仍成立。
- 不依据 held-out 结果调整 B、lambda、alpha、特征、seed、tie-break、offset 或文档。

## 方向决策

| Outcome | Verdict | Direction |
|---|---|---|
| Oracle opportunity FAIL | STOP_STABLEBATCH_HEADLINE | 传播现象保留为窄数值证据；停止 selector 与 runtime 主机制 |
| Oracle PASS，Static/Online 均 FAIL | STOP_PREACTION_STABLEBATCH | 问题存在但执行前不可选择；若未来研究 shadow probe，必须作为新机制重开 |
| Static GO | GO_STATIC_COMPATIBILITY | 进入最小 expert partition planner；核心是 stable compatibility envelope |
| Static FAIL，Online GO | GO_ROW_CONDITIONED | 改写为 row-conditioned execution-risk scheduling，删除静态 graph 核心叙事 |
| 两者 GO | GO_STATIC_COMPATIBILITY | 优先较简单静态机制；online 只作诊断，不扩展模型 |
| integrity FAIL | INVALID | 只修复改变结果正确性的 P0/P1 后原协议重跑 |

## Run Order and Budget

| Milestone | Goal | Runs | Decision Gate | Cost | Risk |
|---|---|---|---|---|---|
| S0 | freeze plan/data/model/shuffle semantics | CPU validation + unit tests | hashes、B=33、zero overlap、no future fields | <1 min | outcome leakage |
| S1 | pre-action scan + selector seal | 240 native cells | selector lock exists before result ledger | 约 1–3 GPU min | accidental outcome creation |
