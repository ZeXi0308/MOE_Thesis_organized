# H1 精确底座候选包（CPU 已检，GPU 未运行）

此目录由 root 从已接受 H r02 的 **35/35 manifest 文件匹配**原件单独复制 `pkg/`，只改 `pkg/staged_store_rotation.py`、`pkg/run_recovery_cadence.py`、`pkg/run.sh` 三处。原 H r02、G、LTR r02 包均未修改。共同旧版 `staged_store_rotation.py` 的 CPU 补丁不能替代这里的 G/H 精确 adapter；此目录依次使用 C 的 `../c/accepted_gh_commit_recheck.patch` 和 `../c/candidate_h1_async_receipt.patch`，来源和差分 SHA 见 `provenance.json`。`manifest.json` 固定候选文件，`verify_package.py` 在运行前逐文件验 SHA。

唯一机制开关是 `commit_recheck`。`eager/off` 与 `eager/on` 在同一 selected-native 保存底座、cooldown 0、相同 H 输入和同一 runtime 下比较；两臂共同接受请求身份与未知 victim job 安全取消。`native_full_native/off` 为独立系统参照，不安装轮转 adapter。`diagnostic` 用完整记录核实际 direct/admission/首新输出及 peer 后果；`performance` 记录完整请求。保存的 H128 输入已经看过，**仅作开发/资格输入，不作盲确认**。LTR-style 的已接受 r02 单格生命周期诊断另行串行执行；此包不实现或并跑 LTR controller。

执行前由唯一 GPU 执行者核用户授权的 GPU UUID、host cgroup 进程树硬限、每格与总预算、共享锁、模型本地缓存、pinned vLLM 源码和实际物理 KV/host 分配。`run.sh` 每次只执行一个显式 cell 和**绝对且位于候选包外**的输出目录，要求环境变量 `H1_AUTHORIZED_GPU_UUID`、`H1_PYTHON`、`H1_HF_CACHE_DIR`、`H1_LOCK_PATH`、`H1_MAX_WALL_SECONDS`、`H1_APPROVED_HOST_BYTES`、`H1_CGROUP_MEMORY_MAX_FILE`、`H1_EXPECTED_MANIFEST_SHA256`；最后一个值由 root 在现场读取前固定为 `04ad1217287491813be3c85839de00ff80ee2ec60011bdf762c58e52b3e3a6d4`。入口要求锁文件预先存在，打开时不截断，亦可核 inode 后复用父执行者已持有的 fd 9，使外层锁覆盖换格与归档；在锁内核物理 GPU UUID、manifest 身份、精确 25 文件集合与 pinned 源码。所给 `memory.max` 必须属于**当前进程所在的 cgroup v2**，有限硬限不超过批准字节；离线缓存目录和 pinned Python 路径须存在。每个 cell 的 `launch-once-*` 标记阻止同一 staging 换输出目录重跑，预检失败也消耗该格身份，须保留失败收据而不可原地重试；哈希预检、源码预检与 runner 均按剩余墙钟受限。`PYTHONDONTWRITEBYTECODE=1` 避免前格产生未列入 manifest 的本地 bytecode。root 另记录整个串行活动预算和实际模型缓存/revision、现场占用；这些参数与预检仍不能自证用户授权。当前新机器这些值未授权且未核，**不得运行任何 GPU cell**。没有 controller/PID、上传或测量结果。

CPU 复核已通过：C 针对 G/H 精确 adapter 的 4 项 closure fixture（含 streaming session 占槽与字段未知）及 4 项异步 load 收据 fixture、候选源码编译、shell 语法、包 25 文件 SHA、128 输入身份、runner off/on 参数传递与非法 native/on 拒绝。`DIRECT_READY` 仅是即时资源前置筛选；原生 running 分配和 connector lookup 仍可能延期 target。`direct_commit` 必须有目标正调度 token，或同时有匹配的原生 load job 与目标物理块；缺收据资格运行 fail-fast 为 `INCOMPLETE`。异步 load 的 direct 计数仅表示目标已准入，仍须真实核 load 完成、首新输出和所有 peers 的成本。未验证安装期 vLLM 类型、native/worker 加载完成、EOS 分支或真实资源占用。若首次诊断无合法 `direct_commit`，按 [RUN_PLAN.md](../RUN_PLAN.md) 停止 H1 性能扩展，记录 `NO_ACTION`；不可调整输入制造动作。真实 off/on 必须各从同一冻结输入独立演进，不从旧 trace 扣除 victim gap。
