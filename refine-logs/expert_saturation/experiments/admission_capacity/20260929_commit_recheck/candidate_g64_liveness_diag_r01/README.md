# G64 T30/Q1 原生准入拒绝诊断

状态：准备中；GPU 未运行。独立实验身份，原 T30/Q1 失败及成功的性能原件不改。

唯一问题：r02 已观察到的同一目标优先→原生未准入→释放循环，是否由适配器的目标 KV 保留与原生 inflight prefill 保留冲突造成？条件 CPU 反例提示这种可能；r02 轻量日志没有记录实际分配拒绝原因。

本包沿用固定 G64 自然请求、模型、资源、预热与三项 LTR 策略模块；只在原策略外增加有界只读观察。记录 target lookup 的实际结果、allocate_slots 实参/返回、raw free、native reserved blocks、inflight 请求、hold 决策和全局调度 token。所有被包裹方法照常调用，直到固定诊断停止条件触发。若捕获重复全局无调度且无待处理传输的快照，则保留原始部分请求并以 DIAGNOSTIC_CAPTURED 结束；该状态只说明取得诊断证据，不说明请求完成或性能合格。

支持假说需要同一真实快照同时证明：适配器按 raw free 接受目标，native 异步加载因 free-reserved 不足拒绝，而 inflight 运行请求因目标保留被 hold。若拒绝发生在另一分支，按记录定位；若未复现，记录 NOT_REPRODUCED，不把单次未发生当修复。观察与输出时间会受附加记录影响，禁止性能排名。

仅执行 T30/Q1 一格；采集最多180秒、单格墙钟900秒、整组2100秒，同一非阻塞共享锁覆盖模型核验到归档和GPU退出。诊断不会修改调度策略、增加资源或延长原性能格。
