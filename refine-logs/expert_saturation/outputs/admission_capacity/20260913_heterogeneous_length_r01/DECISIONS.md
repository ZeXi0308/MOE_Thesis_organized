## 研究问题（不变）

固定单卡显存、计算与传输预算下，怎样安排新请求入场与恢复，减少对已有 decode 的
不成比例停顿，同时保住有效服务量。本轮只控制**准入 + 恢复顺序**（轮转动作），
prefill 预算、缓存策略、精度、后端全部固定。

## 本轮要证伪的对象

`20260913_completion_dispersion_r01` 建立的两项成本模型：

```
Δwall = Δ边际重算 + Δ尾部浪费
尾部浪费 = Σ(低宽度步) [ c(w) − w·g_high ]
```

它在四臂上闭合（safe29 解释 87.7%、headroom 71.1%），并解释了轮转为何近乎免费：
`+0.326 s` 重算被 `−0.336 s` 尾部节省抵消。

**但它的全部证据建立在一个未被检验的前提上**：32 个请求全部 3072 输入 / 1024 输出，
完成时刻天然聚集（完成跨度 2.1–2.5 s），排空段因此很短。

若输出长度异构，完成本就离散，尾部项可能主导一切，**轮转的「免费」可能消失**。
这是对该模型最直接的证伪测试。

## 负载设计：赤字对齐，异构是唯一变量

原运行域（N=32, P=3072, L=1024）在 `max_model_len=4096` 下 `P+L` 已满额，
**没有向上的输出长度方差空间**。赤字 `D = N·⌈(P+L)/16⌉ − 7671` 只依赖 `P+L` 之和，
所以「同均值 + 增方差」在该域内不可实现。用 `N` 与 `P` 换取自由度：

| | 请求数 | prompt | 输出长度 | 每请求预留 | 总预留 | 赤字 |
|---|---:|---:|---|---:|---:|---:|
| 原域 | 32 | 3072 | 1024 (固定) | 256 块 | 8192 | +521 块 = **2.035 请求** |
| **同构臂** | 42 | 1024 | 2048 (固定) | 192 块 | 8064 | +393 块 = **2.047 请求** |
| **异构臂** | 42 | 1024 | 21×1024 + 21×3072 | 128 / 256 块 | 8064 | +393 块 = **2.047 请求** |

两臂**总预留块数相同（8064）、赤字相同（2.047 请求足迹）、总输出 token 相同（86,016）、
均值相同（2048）**。差别只有 `CV = 0 vs 0.500`。这是本实验成立的核心。

赤字以「请求足迹」计与原域几乎一致（2.047 vs 2.035），使结论可以与原域对话。

### 这是新运行域，必须承认

1. prompt 3072→1024：prefill 工作量降至 1/3
2. 输出 1024→2048：decode 相占比上升
3. N 32→42：`max_num_seqs` 与 cap 须为 42
4. 每请求足迹 256→192 块：抢占释放的量变了

因此**同构臂必须同批跑，作为该域自己的基线**。不得用原域 native32 的数
直接与本轮异构臂比较。原域四臂结果不因本轮改变。

## 四格与顺序

每格独立 fresh engine，统一 3 项预热，保留全部 warmup raw。

- `block0`: homo/native → homo/rotate → het/native → het/rotate
- `block1`: het/rotate → het/native → homo/rotate → homo/native

共 4 个组合 × 2 block = 8 格。正反序用于估噪声底，**不作统计显著性**。

共同条件：OLMoE-1B-7B-0924 revision `6d84c48581ece794365f2b8e9cfb043c68ade9c5`、
BF16、vLLM 0.26.0、单 RTX 5090、`max_model_len=4096`、`max_num_batched_tokens=1024`、
`enable_chunked_prefill=true`、`enable_prefix_caching=false`、`async_scheduling=false`、
`stream_interval=1`、FCFS、50 ms 到达、`gpu_memory_utilization=0.9`、
**固定实际 KV 16,089,350,144 bytes / 7,671 usable blocks**（与原域逐字节相同，
不只传 utilization）。轮转参数沿用已预选值：等待 30、交换冷却 20、恢复后驻留 30、
进度保护 0.90、每请求最多 8 次缺席——**不因本轮改阈值**。

输出长度由 `SamplingParams(max_tokens=L_i, min_tokens=L_i, ignore_eos=True)`
逐请求给定，长度确定、不依赖 EOS，两臂同一 seed 20260905。
长度到请求的分配按 request ID 升序交替（`1024,3072,1024,3072,...`），
在冻结的 `workload.json` 中写死并计入 `workload_sha256`，不在运行时随机。

## 预注册判据

阈值取自 `completion_dispersion_r01` 的**绝对**噪声底，运行前给定，不从结果反选：
`|Δwall| 0.2684 s`、`|Δmax-ITL| 0.2126 s`。本轮另用自己四格的同臂正反序差重算一份，
两者都报告；若本轮噪声底更大，以本轮为准。

| # | 预测 | 证伪条件 |
|---|---|---|
| **H1** | 异构臂的完成跨度显著大于同构臂（>3×噪声底） | 若相近 → 异构未真正制造离散，负载设计失效，实验 INVALID |
| **H2** | 两臂内轮转相对 native 的 max-ITL 降幅仍超噪声底 | 若异构下不再超 → 动作在离散域失效 |
| **H3** | 异构臂中 `Δwall ≈ Δ边际重算 + Δ尾部浪费` 的残差与同构臂同量级 | 若异构残差显著更大 → 模型缺项，**两项模型仅限同构域** |
| **H4** | 异构臂轮转的吞吐代价仍在噪声底内 | 若显著变差 → 轮转不是通用机制，如实收窄适用范围 |

**我的预期是 H3 会被证伪**（异构下尾部项主导，残差变大），那会把模型的适用范围
限定为「完成时刻聚集的同构域」。这是对我自己上一轮结论的收窄，不是抢救。

三种结局的下一步已固定：

- H2 且 H4 成立 → 轮转跨负载成立，进入驱逐排序/冷却的消融（与其他会话协调，不重复）
- H2 成立但 H4 失败 → 记录为「停顿改善需付吞吐代价」的权衡，不称方法 GO
- H2 失败 → 轮转仅限同构域；停止该动作扩展，转而测量离散域自身的瓶颈

## 度量

完整请求：TTFT、平均 TPOT、**每请求 max-ITL**、完成延迟、恢复等待、最长排队、
episode wall、吞吐、goodput，以及全部失败/拒绝/未完成。

不得据此声称停顿问题已解决。

会计：完成跨度、逐宽度 `c(w)`/`g(w)`、低宽度步与尾部浪费、边际重算、抢占/恢复事件、
互斥 host 区间。step 时长用相邻 `start_s` 差（`end_s` 仅为 `schedule()` 返回时刻）。
`g_high` 为同臂相内均值，含重叠的 prefill 与记账，**不称 kernel 时间**。

- `REQUEST_LEVEL / NATIVE_INPROCESS_GPU_INTERVENTION`，单模型、单卡、
  一个新运行域、每格 n=1（重复仅正反序一对，与顺序效应混淆）。
