### Full-cost, non-overlapping accounting: WARN for phase attribution; PASS for request totals

Mean completion and wall include the complete request interval from arrival through completion. Engine calls are ordered and non-overlapping, and `outside_engine_seconds = request wall - summed engine.step wall` (`refine-logs/expert_saturation/experiments/admission_capacity/analyze_repeated_staged_probe.py:35-45`). ### P1

1. **Terminal-status metadata contradicts the completed evidence.** Root `STATUS.md` still says `GPU_UNRUN` and environment pending (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/STATUS.md:1-5`); each copied config still says “GPU unrun” (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/results/save-off/config.json:38`; `refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/results/save-on/config.json:38`), and each qualification file says `NOT_YET_RUN` (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/results/save-off/safe-cap-qualification.json:2-4`; `refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/results/save-on/safe-cap-qualification.json:2-4`). Machine terminal evidence resolves the run as complete, but status-only consumers can misclassify it. This is a state-synchronization problem, not a machine-result ambiguity.
2. **`preemption_mode=native_recompute` is not the save-on recovery mode.** `memory_telemetry.py` assigns that string solely from the `allow_preemption` flag (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/pkg/memory_telemetry.py:145-147`) and `run_probe.py` propagates it into status (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/pkg/run_probe.py:199-208`). Save-on then reports `native_recompute` (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/results/save-on/status.json:2-6`) despite 43 completed connector loads and only 3,731 recompute tokens. Interpret the field as “native preemption allowed,” not proof of all-recompute execution.
3. **Phase seconds are mixed-call buckets.** The priority classifier and retained mixed calls prevent isolated prefill/recompute/decode cost claims. Full-request time remains valid.
4. **The timing deltas are one fixed-order observation.** Structural resources match and boundary isolation passed, but one off→on pair with different thermal starting states cannot establish a stable causal timing benefit, SLO acceptance, or performance GO.
5. **Quality/correctness equivalence is unverified.** `request_pair.json` reports only 26/32 equal output sequences (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/request_pair.json:38`). Six requests diverge, with first differences at token indices 379, 627, 396, 479, 567 and 396 (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/request_pair.json:198-199,221-222,336-337,520-521,566-567,658-659`). The runtime explicitly disables batch invariance (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/pkg/run_probe.py:95-97`), and no bitwise KV, reference-quality or semantic check separates expected batch-sensitive numerical divergence from a correctness defect.

### P2

1. **Original dataset lineage is declared but not independently reproducible from this bundle.** The prepared inputs, row identities and token hashes are retained and internally consistent; the named Arrow shard itself is absent.
2. **Save-on does not require a positive store delta before commit.** `staged_store_rotation.py` records `inspect_store_delta` but does not reject `NO_NEW_STORE`, and calls `commit_reason(..., save_enabled=False)` (`refine-logs/expert_saturation/outputs/admission_capacity/20260915_repeated_staged_probe_r02/execution_weste_26862/readback/pkg/staged_store_rotation.py:75-86,126-139`). This latent fallback was not triggered: all 38 retained store deltas are `NEW_STORES_VALID`, and all 38 store job IDs were flushed and completed. The current execution-existence claim is unaffected; “every future save-on rotation requires a new store” is not a code invariant.
3. **Post-readback derived artifacts are reproducible but not part of the readback receipt.** `analysis.json`, `analyze_request_pair.py`, and `request_pair.json` are outside the sealed readback archive/receipt. Exact recomputation from receipt-hashed raw files mitigates this, but the derived-file hashes in `EXPERIMENT_AUDIT.json` are required to identify this audit snapshot.

## Scientific boundary

- **Strongest baseline:** not accepted here; save-off is the paired mechanism ablation, and the retained scope explicitly excludes strongest-immediate-baseline acceptance.
- **Oracle/headroom:** not evaluated.
- **What was measured:** one complete native serving pair with repeated interventions, full request timing, scheduler token accounting, connector jobs/bytes and boundary GPU state.
