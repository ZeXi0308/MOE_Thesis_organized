# 专家保护：即时执行代价与后续替换收益

2026-09-15。结论：**停止当前 cap24 频率保护的参数细调，交付成本边界与分析工具。** 已执行结果没有确认可利用的稳定完整收益；本次诊断解释了组数规则为什么不足，但没有把条件少加载升级为秒级收益或证明整个 paging 问题无空间。原 Qwen r04 按既定合同完成，除此之外不新增 GPU 组。

## 新增证据

输入只取已经完成的 `../group_guard_performance` 两引擎、12 个 measurement episode；同一 OLMoE BF16、384 专家槽（每层24）、1 GiB KV、3个短请求。已有 frequency、guard、复用寿命、层预算、共享池、fullstage、fresh、logical P/V 均直接继承，没有重新执行旧计划。

本次从每个真实调用的槽位、LRU 与当前路由出发，复现其实际状态转移，再对实际 applied 调用局部分叉普通无保护分组。原调用之后的执行不分叉，只用该策略的下一次同层真实需求作条件标签。全部1,236个 applied 事件保留在 [conditional_displacement.json](conditional_displacement.json)，不跨 episode/reset 拼接未来。

`F_P` 是实际保护末态，`F_0` 是同一前态执行普通分组后的末态：

```text
受益身份 B = F_P − F_0
被挤出身份 V = F_0 − F_P
下一真实需求 N 下的条件 miss 差
  = |N − F_P| − |N − F_0|
  = |N ∩ V| − |N ∩ B|
```

**保护不减少当次加载。** 所有局部分叉两侧均只加载当前 `A − C` 一次；收益只能来自后续驻留差异，即时代价则来自分组、映射、执行形状与控制。

下表按每个 repeat 计数，同模式四次相同；不是四批独立新样本，也不是完整无保护策略的反事实结果。

| 实际模式 / 分层 | 事件 | 当次额外组 | 受益身份被下次需求使用 | 被挤出身份被下次需求使用 | 条件净 miss 差 | 条件更好 / 持平 / 更差事件 |
|---|---:|---:|---:|---:|---:|---:|
| frequency 全部 | 190 | 78 | 1,078 | 893 | −185 | 113 / 54 / 23 |
| frequency，组数不变 | 112 | 0 | 517 | 436 | −81 | 61 / 34 / 17 |
| frequency，多一组 | 78 | 78 | 561 | 457 | −104 | 52 / 20 / 6 |
| guard 全部 | 119 | 0 | 522 | 454 | −68 | 59 / 39 / 21 |

这排除了两个过度简化：多一组并不自动失去后续搬运机会；组数不变也不保证少搬运，更不保证净收益。guard 的21个条件更差事件在尚未计入控制成本前就已增加下一需求的 miss。

具体例子为 forward repeat1、step4、layer0：实际3组、普通2组，两者当次均26次加载。保护多保留 `[3,4,6,17,18,33,37]`，挤出 `[0,1,22,23,29,40,63]`；下一需求实际使用其中5个受益者、4个被挤出者，只剩条件净少1次加载。不能把保护的7个驻留身份都算成收益。

frequency 的条件净差中−178出现在旧请求仍未完成的下一步，−7落在旧请求完成后的首步；guard 分别为−65/−3。机会并非全部发生在没有请求等待的尾部，但位于依赖路径不等于已量出可消除的等待。

## 已执行结果与成本归属

已有 [retention_reuse.json](../group_guard_performance/retention_reuse.json) 的跨真实策略账保持不变：frequency 共同需求少/多 miss 为1278/1153，计入各策略独有需求后净−134；guard 为973/931，净−47。它与上表的同前态单调用分叉回答不同问题，不能相加或用−185/−68替换真实−134/−47。

已执行 frequency 相对 none 少搬2.395%、多78组；guard 少搬0.840%、总计多1组（后续真实路由变化）。四块实测如下，单位毫秒，差值为处理减基线：

| 模式 | 加载 CUDA 包络差，四块 | capture 差，四块 | 平均完成差，四块 |
|---|---|---|---|
| frequency | −19.21 / −17.07 / −19.16 / −20.08 | −8.82 / +39.05 / +28.09 / −55.35 | −4.40 / +39.48 / +24.92 / −46.92 |
| guard | −5.39 / −8.78 / −12.17 / −7.07 | +4.44 / −5.94 / −15.29 / −24.30 | +6.28 / −4.09 / −14.05 / −20.22 |

加载包络不是纯 H2D：原源码将事件放在 `ensure_resident` 两端，其中包含复制、映射和 host 提交间隙。它与 host apply 重叠，不能相加、扣除或按节省字节线性缩放成时间上界。日志没有单独测得暴露 H2D 等待和 policy 控制耗时，这两个量在新数据中保持 `null`。

[service_cost.json](service_cost.json) 新增精确请求区间分账：

```text
每请求完成延迟 = [到达, 完成] 与全部引擎调用的交集
                 + 该请求区间内调用之外的时间
```

12个 episode 的平均完成延迟有99.60%–99.73%落在引擎调用内。八个处理/none比较的调用外差异绝对值均不超过0.610 ms；例如 frequency 的+39.480 ms中+39.413 ms在引擎内。因此外部提交、轮询及调用间记账不能解释该对的主要退化；引擎内计划、复制、kernel、同步与其观察成本仍待区分。没有将外部时间从真实结果扣掉。

完整 repeat cycle 仍保留五次预热、采集、写盘和收尾；frequency 四块 cycle 差−235.78/+38.24/+117.12/+16.44 ms，guard −177.53/−96.79/+193.37/+200.31 ms。它不等同稳态请求分母，不替代平均完成目标，也不据预热成本要求所有指标同时下降。

## 最小决策成本模型

状态只使用当前已知的路由、行数/阶段、物理索引与 kernel 形状、精确驻留/LRU、可用槽与传输状态。动作是普通分组或选定集合的保护；当前 guard 是其中一个诊断动作。资源守恒、每个当前所需专家只执行一次、top-k 贡献和独立策略状态不变。

选择目标为完整平均完成 `J = mean(completion_i − arrival_i)`，同时保留生成间隔代价。对于保持请求到达和服务依赖的局部诊断，用请求区间与每个引擎调用的交集确定其权重；不能把所有层的时间无权相加到所有请求。在线部署还必须用当时状态预测后续依赖，不能使用本次真实 next-demand 标签。

保护相对无保护的最小近似成本为：

```text
ΔJ ≈ −后续可避免加载的暴露成本
      +被挤出专家后续重载的暴露成本
      +执行形状成本差
      +控制与同步成本差
      +调用外成本差
```

每个后续身份的价值取“在仍有价值的驻留期内使用的概率 × 此状态下重载对请求的边际成本”。概率只能来自此前观测或独立校准；边际成本要考虑传输等待、是否被隐藏及同组共享，不能只用字节/峰值带宽。执行形状项必须包含组内专家数、row/token形状、排序/映射索引域和kernel配置，不只用组数。各项按互斥 critical-path 成本计费，原 ensure/host 包络不能直接充当参数。

因此允许多一组但净成本下降：未来避免的暴露成本大于替换债务和新增执行成本时接受。也允许组数不变但放弃：替换债务、映射或控制成本已超过可避免的暴露成本时拒绝。条件结果证明两种判断都必须能表达，**并未校准出可执行的秒级分界**。

## 改变的决策与交接

当前 cap24 frequency/guard 不进入新参数扫描或成本规则 GPU 实验。已有独立执行没有确认其稳定完整收益；本次单步条件机会不能替代强基线后的完整成本空间。后续共享池/逻辑对齐也已完成：fresh X/F没有一致完整收益，logical Y/X增量未在第二文档组保持；这些旧失败不重新解释成待运行计划，跨底座数字不拼成排名。参见 [fresh](../fresh_cohort_r01/REPORT.md) 和 [logical validation](../logical_alignment_validation_r01/REPORT.md)。

交给主会话的是：身份级收益/替换债务工具、请求区间成本归属、一个允许组数与净收益不一致的模型，以及停止本 formulation 细调的边界。当前最强执行底座需按具体运行域取同预算已测基线；本旧保护实验并未测试在后续 X 底座上的保护增量。

原在途 [Qwen r04](../../20260912_native_pager_r01/phase_baseline/qwen3_new_gpu_20260913/attempt04/REPORT.md)现已完成真实超单卡显存域资格和冻结static32/16/16/32对照，16次请求执行、416输出。static16两块多搬4.801%/3.000%、平均TTFT增加39.545%/34.436%，观察最大ITL下降6.741%/14.407%，平均完成+9.062%/−6.432%方向翻转。该结果补充执行组织的真实权衡，不是新保护机会或稳定效率优胜。

本轮唯一在途组已闭合，B支线完成交接，不增加GPU组。只有主会话选定的新运行域在强无保护底座之后出现明确、可由当时状态区分的完整成本差，才重新讨论一个最小成本感知动作。否则保留测量结论，不扩大为整个paging家族失败。
