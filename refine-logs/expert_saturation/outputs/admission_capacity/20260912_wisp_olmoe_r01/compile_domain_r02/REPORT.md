# 编译覆盖后的 F/X：复制量下降，稳定完整请求收益未成立

Verdict：`MEASUREMENT_ONLY`。四格全部完成，声明的编译覆盖检查通过；X/F 测量总时长仍为 −3.873% / +0.086%，不足以确认稳定净收益。它也不能证明 X 在所有工作负载无效。

本轮唯一问题：在计入编译准备成本、测量期无新增 Triton 编译后，X 相对同预算的普通全量 stage F 是否保留完整请求优势？证据层级为原生 vLLM 进程内有限到达请求、定制专家分页执行；不是客户端网络服务或生产 SLO。

测量时长从首个计划到达算至观测结束；平均完成按各自计划到达计费。完整进程包含引擎启动、显式编译/handle 准备、原单请求预热、测量和最终输出/退出；不从中扣除编译时间。load section 是原代码的嵌套 CUDA 区间，不能再与 apply 或完整时长相加。

**覆盖与资源。** 四个新引擎各用独立空 Triton 磁盘 cache；其它 backend 缓存不宣称冷。M1…160 × 双 GEMM，每格 320 次 compile-only + handle 初始化：F 每格 26 个唯一 key，其中准备期 22 次新 compiler pipeline；X 每格 22 个唯一 key，其中准备期 18 次新 pipeline。四格初始化各 7 次新 pipeline，随后测量期 compiler_call / 新 pipeline 均为零。CPU pager 状态与 KV 请求/存储/池快照前后相等。这里仅证明本有限 cohort 未观察到新增 Triton 编译，不代表整个 runtime 已稳态或所有 shape 都覆盖。

F 使用 private20×16+stage64，X 使用 private21×16+stage48；真实 kernel E 分别为 64 和 384。两者均 384 专家槽/4,831,838,208 字节、1 GiB 实际 KV、同 CPU0–7/OMP8、token budget160/prefill32。临时准备 buffer：F 8,572,420 字节，X 8,733,700 字节；结束后 CUDA allocated 均回到 6,885,147,648 字节，完整 reserved/peak 在原 JSON 保留。X 同时改变私有容量及执行/写回路径，因此不能把全部差值单独归给消除 D2D 写回。

**覆盖范围。** 使用源池此前未进入测量的后16篇文档，P128/O32、0.25秒到达间隔；同一16文档、F/X/X/F，两新引擎/模式。64/64请求、2048输出、10176实际调度位置、3584测量层调用/4032全阶段层调用；4个初始预热请求另计8输出。12次GPU边界检查通过、整组共同flock；不据此宣称持续物理隔离。四格均无抢占、无已开始输出请求的观测调度缺席，不把本轮解释成恢复抢占策略效果。

**可分辨性。** 同臂重复 F capture −1.076%、X +2.999%；平均完成分别 −0.473% / +4.627%，最大 ITL +6.458% / +8.187%。这些是各两次相关运行的已见漂移，不是总体噪声底、置信界或独立重复。X/F 两block输出逐请求仅8/16相同；F同臂12/16、X同臂11/16相同，route hash 均不同。每臂独立推进自己的实际状态，不共用未来trace。正序X全部16请求完成更早，反序仍4/16更慢；两block的平均完成下降与最大ITL下降均保留为描述性数值，不升级为显著改进或非劣。

这次结果关闭的只是“观察到的波动完全由测量期新增 Triton 编译解释”这一解释：即使该事件数为零，X重复仍漂移，配对capture仍变号。不能由此定位剩余波动为某种硬件、host、数值或到达效应；需要在已有互斥计时区间中继续定位，不能从字节差直接反推时间收益。

**失败保留。** [r01](../compile_domain_r01/REPORT.md) 初始化后 snapshot 使用 vars(slotted state) 失败，0/320覆盖、无请求测量；42.951954032秒完整成本与62成员原件保留。r02只修正六项stats读取与真实23slots CPU fixture，原11份runtime、资源、数据和四格顺序不变。不能将r01当作科学失败，也没有删除一个不利测量格。

**完整性。** [analysis_rebuilt.json](analysis_rebuilt.json) 本地按冻结代码复算，与远端 analysis 语义完全一致，issues=[]。134归档成员中133 payload的大小/SHA逐项匹配；archive 6,318,591字节，SHA256 `acf66ad7688296778dfdcdc969d67b190f956b8eb2fe2153caa77b3cf6754cf1`。[限定结果审计](EXPERIMENT_AUDIT.md)为PASS、P0/P1=0；复用同族reviewer，验收为provisional，不冒充跨模型独立复核。测量期compiler_call和handle-load事件本身均为0，108次真实编译/加载全部在初始化或准备期。

**结论边界与唯一下一步。** 最强本轮基线是普通F；旧U/M、旧cohort结果仅背景，不拼入本次配对。Oracle/headroom尚未测，质量、SLO、稳态持续服务、显著性及纯D2D因果收益均未测。失败类别是完整请求收益未稳定确认，不是编译覆盖失败或整个paging family NO-GO。[CPU互斥成本定位](OBSERVED_COST_LOCALIZATION.md)已闭合：X第二次额外243.390ms主要在非ensure apply与engine其余部分，前3步可观察状态匹配时已慢44.793ms，随后跨0.5s到达边界。唯一下一实验为同X条件的observer off/on/on/off，复用CPU/GC计数区分前缀成本来源；当前仅CPU准备、GPU UNRUN。

本轮回答：显式覆盖消除了本cohort的测量期新编译，X的D2D下降约54%仍未稳定转化为完整请求净收益。
