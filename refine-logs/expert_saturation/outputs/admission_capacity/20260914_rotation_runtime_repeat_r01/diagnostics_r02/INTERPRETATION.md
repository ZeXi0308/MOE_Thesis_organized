## 新两次 wall 差的定位

[new_block_difference.json](new_block_difference.json)按新 block1 − block0保留全部调用，得到：

`0.848332 s = scheduler 0.163471 + engine 内 scheduler 外 0.555316 + engine 外 0.129545`。

最大单调用差为 step823 的 0.027485 秒，只占 wall 差 3.24%；该调用宽度31、31 decode、无重算，两次跨度0.116197/0.088712秒，差额主要落在scheduler。前五大增量合计0.089749秒（10.58%），其余1,157个调用净差0.629039秒，加引擎外0.129545秒闭合完整差额。没有第二个单次长调用主导本次差异。接手方独立使用同一旧脚本产生的[定位文件](../most_same_path_after_finite.json)保留，不把重复计算计为新增证据。

## 研究边界与唯一下一步

最强基线：本四项直接比较 native；同域 fast-headroom 的真实强对照已经包含在原八项，没有在本四项补跑。当前没有全动作空间 Oracle 或物理 headroom 上界。

失败类别：完整服务量的稳定净收益未建立，运行间计时差仍存在；不是动作不成立或整个 KV 调度问题被否定。最大暂停降低也不等于每请求都受益，参考 SLO 全通过不形成停顿约束下的容量证据。四次同文档、顺序相关观察不能用来估计生产尾延迟、统计显著性、非劣或可靠噪声上界。

当前重复已回答其问题，不按结果追加同配置重复或阈值扫描。下一最小实验沿用接手会话正在准备的同资源 native APC 开/关对照：现有 baseline 关闭前缀缓存，先验证原生历史 KV 复用能改变多少恢复成本和完整请求权衡，再决定轮转还剩什么增量；原会话不重复实现或提交。若后续实际执行再次出现特定长调用，再用能区分 host/device 等待的最小观测重开内部原因定位。

四项复核状态以接手方最终结果审计为准；本解释不继承原八项的审计通过状态。结论保持：**本配置能减轻最大暂停，但尚未证明稳定保住完整服务量；单次恢复慢调用不是吞吐波动的充分解释。**
