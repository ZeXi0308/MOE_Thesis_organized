# 中期记录：步下界度量、一处归因更正、压力扫描就绪

2026-09-13。新主机 `connect.westc.seetacloud.com:53036`，RTX 5090 / 32607 MiB，
Python 3.12.3、vLLM 0.26.0、torch 2.11.0+cu130、transformers 5.15.1，
与全部封存基线逐位一致。**本文件写于扫描 GPU 执行之前，扫描结果不在此。**

本轮至此的 GPU 执行为 0；以下全部来自既有封存数据的重算。

## 1. 一处归因更正（撤回我自己上一轮的说法）

上一轮我把异构负载的 23.6% wall 代价归为「宽度塌缩」。**这是错的。**

decode 逐 token 串行：需要 `L` 个 token 的请求至少占 `L` 个 decode step。
全部请求在首个完成之前入场时，episode 的纯 decode 步数因此不可能少于

```
floor = max_i L_i
```

实测：

| 臂 | max(L) | 纯 decode 步数 | 超出下界 |
|---|---:|---:|---:|
| 同构 42×2048 | 2048 | 2189 | +6.9% |
| 异构 21×1024 + 21×3072 | 3072 | 3156 | +2.7% |

步数差 `3156 − 2189 = 967`，而 `max(L)` 差 `3072 − 2048 = 1024`——
**106% 由下界差解释**。两臂各自都跑在自身物理下界的 2.7%/6.9% 以内，
调度侧几乎没有可回收量。

推论：固定均值下，任何长度离散都必然抬高 `max(L)`（均值 2048 且 max=2048
⇒ 全部等于 2048）。所以异构的 wall 代价是 **makespan 被最长请求锁定**，
不是调度低效。宽度塌缩是高下界的*结果*，不是独立原因。

`RESULT_LEDGER.md` 的 `step-count-law` 行已追加更正行 `het-wall-penalty-corrected`，
原行保留不改。

## 2. 新度量取代旧口径

```
step_efficiency = 纯 decode 步数 / max_i L_i
```

它有绝对参照（1.0 = 一步不浪费），跨负载可比；此前的「尾部浪费」只相对本臂
高宽度相，换个负载就不可比，且正是它掩盖了上面那处错误归因。

同 `max(L)=1024` 的原域四臂给出干净排名：

| 臂 | 步数/下界 | max-ITL s | 吞吐 |
|---|---:|---:|---:|
| **rotate** | **1.092** | 1.006 | 1.3956 |
| native | 1.212 | 4.444 | 1.4032 |
| headroom | 1.310 | 1.382 | 1.3624 |
| safe29 | 1.913 | 0.308 | 1.1926 |

## 3. 独立验证：无赤字时系统恰好跑在下界上

`20260912_kv_budget_r01` 的两档 KV 池是一个现成的对照，回溯应用该度量：

| 格 | usable blocks | 赤字 | 步数/下界 | max-ITL s | 抢占 |
|---|---:|---:|---:|---:|---:|
| budget95 ×2 | 8425 / 8473 | −233 / −281 | **0.998 / 0.998** | 0.083 / 0.099 | 0 |
| budget90 ×2 | 7671 | +521 | 1.212 / 1.212 | 4.591 / 4.560 | 2 |

**赤字消失时 step_efficiency 落到 0.998。** 这独立确认了下界概念，
并提供一个天然的「零赤字」物理参照。两次重复的步数逐位一致（1022/1022、1241/1241）。

（0.998 略低于 1.0 是因为最后一个 prefill chunk 步也产出首个 decode token，
下界有约 2 步的边界误差，不影响量级。）

## 4. 由此得到目前最强的结果陈述

把机制收益放在两个参照之间——物理下界，与「多买显存」这一已测的完全解法：

| | 步数/下界 | max-ITL |
|---|---:|---:|
| 零赤字（物理参照） | 0.998 | 0.091 s |
| 赤字 521，原生 | 1.212 | 4.444 s |
| 赤字 521，轮转 | 1.092 | 1.006 s |

赤字 521 块（2.04 个请求足迹）的代价是 **+21.4% 的额外 decode 步** 与
**4.353 秒的停顿**。

- **加显存**（+754 blocks）：两者都回收 100%，代价是改变资源预算
- **轮转**（同显存）：回收 **56% 的步浪费** 与 **79% 的停顿**，
  吞吐 −0.55%（小于已观测重复差 1.01%）

这是第一次能用绝对口径陈述这条线的收益。

## 5. 仍然只有一个压力点

上述全部结论都在赤字 = 521 块这一个工作点上。**一个点无法区分「这是一个机制」
与「这是该点的巧合」**，也说不出机制在哪里失效。

因此下一实验是结构赤字扫描，设计与四条预注册判据已冻结于
[DECISIONS.md](DECISIONS.md)，执行包 SHA256
`acf67a5200f24036d6a453fd72236c45207f47699d389b040bdbe5799a74afd3`（16 格）。

只改 `fixed_kv_cache_memory_bytes`，其余（N、输入、到达、cap、轮转参数、
引擎 flag）逐字节不变。`d2` 点的字节数精确等于已测点 16,089,350,144，
作为内建的复现检查。

| 点 | usable | 赤字 | 同时可驻留 | 预期 |
|---|---:|---:|---:|---|
| d0 | 8192 | 0 | 32/32 | 抢占 0、步/下界 ≈1.00、轮转 `INVALID_NO_ACTION` |
| d2 | 7671 | +521 | 29/32 | 复现 native 1.212 / rotate 1.092 |
| d4 | 7168 | +1024 | 28/32 | native 应 >1.212 |
| d6 | 6656 | +1536 | 26/32 | native 应进一步恶化 |

**最关键的证伪点**：轮转靠主动轮换维持高宽度，赤字越大需要轮换的请求越多、
重算成本越高。若在某个赤字上 `rotate 的步/下界 > native`，就找到了机制的上界拐点，
即预注册 P2 的证伪条件。**我预期 P2 会被部分证伪**，那将给出适用区间而非否定机制。

## 6. 边界

- 本文件零 GPU 执行，全部来自既有封存数据重算。
- 下界假设「所有请求在首个完成前入场」；分析器会输出 admission span 与首个完成
  时刻，使该假设的违反可见。
- 每格 n=1，正反序只给出**已观测重复差**，不是噪声界或显著性。
- 单模型、单卡、32 条重复文本输入、同构长输出域。异构域已证明会自行削平 KV 峰值
  而使轮转无动作，不在扫描范围。
- 不主张任务质量、输出一致性、Oracle/上界、HTTP 服务、多卡 EP、专家信号增量。
