# 补充更正：本目录方案已被同次配对实验取代并否证

2026-09-08 追加。原 [REPORT.md](REPORT.md)、[DECISIONS.md](next_experiment/DECISIONS.md)、
全部分析文件与 `next_experiment/gpu_results/` 的 24 个原始 episode 一律保留，不覆盖。
本补充只登记两件事：本目录方案的设计缺陷，以及后续实验对其结论的裁决。

## 1. 本目录的 24-episode 实验有两个设计缺陷

由独立审阅指出，经核实成立：

- **跨日比较。** 本目录把新引擎的 aligned ladder 与 2026-09-06 旧引擎的 legacy ladder
  相比，无法分离档位收益、运行漂移与引擎差异。
- **`--caps` 同时改变预热路径。** runner 的 warmup 集合由 `--caps` 派生，故两次实验的
  CUDA graph 预热形状不同，构成混淆变量。

因此本目录 REPORT 中 F2/F3/F4 的跨日数值**不构成档位对照证据**，其中 steady
`+21.26%` 尤其不可引用（本目录已记录其落在 static16 重复间 58.36% 的噪声内）。

## 2. 表述更正

- 原 REPORT 早期版本称失败的反馈控制器"把宽度压到 9–15/17，全部落在桶 16 内部"。
  按已确认的捕获集合，**width 17 属于桶 24，不属于桶 16**。归桶叙述应以逐宽度
  实测为准；`0.301` 的 waste 数值本身可重算，不受影响。
- `0.301` 是 forward steady 单个 cell。同族其余为 reverse steady `0.157`、
  两个 bursty `0.0014` / `0.0387`。**不得把 0.301 当作旧规则的稳定常量。**
- 本目录称"沿错误坐标轴控制导致失败"，在当时只是待检验解释。它现已被同次配对
  实验支持，但支持来源是后续实验，不是本目录数据。
- 重建残差 `0.0169–0.1534 ms` 仅界定 host 时间重建与请求 TPOT 的一致性，
  **不界定运行漂移、因果归因或统计推断误差**；"统计不可区分"不能仅由中位数比值得出。

## 3. 仍然成立的部分

以下不受上述缺陷影响，且已在后续独立引擎上继续成立：

- pure-decode step 成本随 CUDA-graph 捕获桶呈阶梯，桶内平坦、跨桶跳变；
  捕获边界经耗时反推与引擎日志两源确认。
- 按**实际宽度**分组时，w17–24 平台在两次独立运行间最大差 `0.125 ms`。
- 接纳干扰税 `tax = 3.853 + 0.008826 × prefill_tokens`（宽度≥7，R²=0.8498）。
- 接纳 cap 控制宽度上界而非执行宽度：steady 域"目标在捕获点、实际宽度不在"占 `0.845`。

## 4. 裁决归属

档位替换的科学裁决**不在本目录**，而在
[`../20260908_capture_ladder_paired_r01/REPORT.md`](../20260908_capture_ladder_paired_r01/REPORT.md)：
同一引擎、共同预热、legacy 与 aligned 直接配对、完整反序重复，32/32 episode。

其结论为 `NO_GO`：steady 变号（forward `−44.43%` / reverse `+118.74%`），
bursty 稳定改善 legacy（`+54.62%` / `+61.38%`）但未胜同次最强静态点
（`−4.63%` / `−0.11%`）。

本目录的价值因此限于：**零新执行的成本结构重建**，以及一次被自身后续实验否证的
动作设计。两者都保留。
