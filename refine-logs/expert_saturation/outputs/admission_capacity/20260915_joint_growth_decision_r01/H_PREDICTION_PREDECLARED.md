# H 事前预测：停顿收益是否延续到较晚到达的独立请求

状态：`PREDECLARED / UNRUN`。H 的包尚未接受、GPU 尚未启动；本文不改变执行合同或主评价指标。

**唯一新增预测：在同一 GPU/host 预算和 0.2 s 到达间隔下，selected/eager 对 current20 的最大生成间隔优势，会延续到 H 较晚到达的 64 个请求，而不只出现在最先到达的一批。** 这是独立输入与更长到达期的联合迁移预测，不是新的在线 predictor，也不预测精确秒数。

分组在结果前固定：early 为排定 arrival_s=0…12.6 的前 64 请求，late 为 arrival_s=12.8…25.4 的后 64 请求。只按已知到达计划分组，不使用 EOS、实际最终长度、请求 ID 或事后困难样本；两组都保留。晚到达请求的最大间隔可能发生在停止到达之后，因此该指标不能称为“到达期内最大间隔”。

现有轻量主分析已提供每请求 `arrival_s` 和 `max_engine_return_gap_s`，无需改计量。每一配对分别计算 late 组最大间隔的 `eager/current` 比值；两对均小于 1 才支持本预测，一正一负保持未确认，两对均不改善则否定该预测。0/1 输出请求的未定义间隔保持未定义并报告数量，不填 0、不替换样本。全部 128 请求的原主结果照常保留，不能以分组结果替代。

主方已经事前选择 H 的完整服务成本预算：**每一配对 tokens/s 损失≤3%，平均完成增幅≤5%；两对都满足才确认该域的简单取舍。** 这是看过 G 开发数据后选择的容忍范围，不是统计噪声界或业务 SLO。性能迁移与成本预算分开判定：

| H 结果 | 预测/预算状态 | 对研究选择的影响 |
|---|---|---|
| 全部请求和 late 最大间隔均两对改善，成本两对达标 | 全域效果、late 持续性与成本均支持 | 确认 H 简单取舍，继续使用 eager 基线，停止机制加法 |
| 全部请求最大间隔两对改善、成本达标，但 late 混合或不改善 | H 总体取舍可以成立；late 预测未确认或被否定 | 保留 eager 的整体结果，收窄“持续到达后仍普遍有效”的主张，不包装为 host turnover 结论 |
| 最大间隔改善，但任一配对成本不达标 | 性能迁移与成本接受分离；简单取舍未确认 | 不挑 favorable repeat，不自动把 G 的默认选择外推到 H；保留 current/eager/native 前沿 |
| 最大间隔混合或不改善，或实际没有相应干预 | 迁移未确认/不支持；无动作是合法边界 | 保存结果并限制适用域，不通过加压或新 controller 强行制造收益 |

**H 的 episode 变长不足以检验 host-history turnover。** 16 GiB host 对应 8,192 个 16-token blocks，即 131,072 token slots；这只是容量。128 请求可能让累计历史更多、到达期由 12.6 s 延至 25.4 s，但完成请求的缓存也可能占用末态，selected 又不会保存所有历史。不能据此推断仍有用的历史被驱逐。

现有轻量 host 观测是初始化、请求结束和 drain 等端点占用及生命周期峰值；没有逐次 eviction、缓存身份/再访问、load 命中和重算的完整观测。端点占满不能区分首次填满、完成历史占用与活跃历史周转。`prompt+已返回输出` 即使构成某种 live 逻辑需求，也不能直接充当 computed、驻留量或实际 host 命中；本轮不为维持 turnover 叙事另做这项估算。

因此，H 能改变的是 **eager 在独立新输入、较长到达期、既定服务成本预算下是否仍值得选用**。若结果退化，也不能单凭它归因于 host 缓存周转。native/full-native 完整系统参照独立保留；各臂实际输出量不同就不称等工作量加速。后续是否研究资源预算，应由 H 的真实事实决定，而不是预设“128 一定触发 host-history 缺口”。
