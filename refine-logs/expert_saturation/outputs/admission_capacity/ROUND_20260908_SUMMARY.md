本目录汇总 2026-09-08 一整轮的三个实验产物与最终裁决，不取代任何原始记录，
也不改变 `docs/current/README.md`。所有原始 raw、失败尝试与两次重复均保留。

## 一句话状态

> 在原生 vLLM 非抢占接纳语义下，MoE decode 的 step 成本随 CUDA-graph 捕获桶呈
> **真实、可复现、有请求级后果**的阶梯；但接纳侧动作既无法把批次放到量化点上，
> 剩余错位也不足以覆盖动作成本。`capture-alignment via admission-side actions`
> 这一 formulation 关闭，**无方法 GO**。
>
> **续轮补充：** 前三轮的负结果被定位为**运行域缺失稀缺资源**——54,622 个 step 零抢占、
> KV 利用率约 12%。换到长上下文域后，接纳上限首次改变**可行性**而非仅快慢：
> `cap32` 完成 0/32（KV 超容量 6.7%），`cap16` 完成 32/32。实测专家权重占参数
> **93.1%**（12.00 GiB），闲置专家常驻 10.50 GiB = KV 区域的 **70.0%**。

## 本轮实际投入

- **新 GPU episode 56 个**（24 个 aligned-ladder + 32 个同引擎配对），共约 1,792 次
  完整请求执行；一张 RTX 5090，全部 `COMPLETE`，全部保留。
- **零成本重建 100 个 episode**、52,708 个 pure-decode step。
- 新增代码：1 个调度策略、5 个分析器、28 个测试（56/57 通过，唯一失败需 torch）。

## 成立的结论

1. **量化成本阶梯。** pure-decode step 成本按捕获桶分级：桶内平坦 2.1–4.0%，
   跨桶跳变 12.4–30.1%。捕获边界经两个独立来源确认——从耗时反推得
   `[1,2,4,8,16,24,32]`，引擎日志打印 `cudagraph_capture_sizes` 且 `decode FULL: 7/7`。
2. **跨引擎独立复现。** 按实际宽度分组，w17–24 平台在两次独立运行间最大差
   **0.125 ms**。
3. **KV 长度不是解释。** 按上下文分层后 w1 在 ctx128→224 为 2.807→2.809 ms，
   w16 为 8.325→8.408 ms。
4. **有请求级后果。** 同桶内 cap12 与 cap16 付相同每步代价（比 0.9949/0.9764），
   goodput 相差 **+3.44% / +142.58%**。
5. **接纳干扰税可分解。** `tax = 3.853 + 0.008826 × prefill_tokens` ms
   （宽度≥7，n=268，R²=0.8498），128-token prompt 下 73% 为固定成本。
6. **重建可核对。** 非抢占下请求 TPOT 应等于其所跨 step 的平均执行时间；
   重建值与实测最大偏差 **0.1534 ms**（相对 8–10 ms TPOT < 2%）。

## 被本轮实验推翻的

1. **档位对齐无效。** 同引擎配对 32 episode：steady **变号**
   （forward −44.43% / reverse +118.74%）；bursty 稳定改善 legacy
   （+54.62% / +61.38%）但**未胜同次最强静态点**（−4.63% / −0.11%）。
   四组配对无一满足预冻结的"两重复均 ≥3% 净增益"。
2. **机制原因已定位。** 非抢占 cap 只限制新接纳，实际宽度由到达/完成/cap 平衡决定。
   steady 域 **84.5%** 的 step 目标已在捕获点、实际宽度不在。
3. **逐步宽度动作也不可行。** 100 个 episode 中合法可填充机会仅
   **0.00%（bursty）/ 0.39%（steady）**；79.4% 的 step 本已在捕获点；
   padding 仅占 pure-decode 总时间 **6.42%**。最佳单案例省 0.609 ms 却要付
   4.982 ms（**8.2 倍逆差**），**0/100 个 episode 正收益**。

## 形成的系统规律

```text
quantised cost structure != exploitable scheduling headroom
```

量化成本阶梯真实存在且可测量，但在非抢占接纳语义下，自然运行宽度已基本落在量化点上
（`max_num_seqs` 与常用 cap 本身取在 2 的幂），剩余错位向下需抢占（非法）、
向上常无队列可填，且单次调整成本与收益同量级。

该边界是**建设性的**：要利用此类量化成本，必须改变*不变量*（允许抢占或 batch
组装期重排）或*量化点本身*（改捕获集合），而不是在接纳侧增加任何控制器、档位或
predictor。这排除了一整类看似合理的机制设计。

## 明确不外推

- 覆盖范围：OLMoE-1B-7B / 单张 RTX 5090 / vLLM 0.26.0 / BF16 / `max_num_seqs=32` /
  固定 128 prompt + 128 output / 32 条重复文本 / steady 与 bursty 两个到达域。
- **不否定**：抢占或 batch 重排类动作；修改捕获集合的工程手段；offload 或高 HBM
  压力域；长/变长上下文；EP/多卡；其他引擎或 kernel 后端。
- **不否定**接纳调度问题族，**也不否定专家感知调度**：U/C 专家信号在本轮三个实验中
  **从未被测试**，仍为 `UNRUN`。本轮不含任何专家感知贡献。
- padding waste **不单调预测** goodput（steady cap32 waste 0.161 却曾 goodput 最优）。
  阶梯是一个新的成本项，不是新的目标函数。
- "最强静态点"是同次探索性 hindsight 上包络，不是 action Oracle 或可在线选择的策略。
- 不主张首次发现 CUDA graph padding；候选残差只是那条被实验界定的适用边界。

## 下一轮

不再在档位/宽度机制族内继续。运行域转向已完成定位，下一步是唯一有依据的实验：

**在长上下文域做 KV 可行性接纳的三臂对照** —— `cap32`（已知越界）、`cap16`
（已知可行）、以及一条只用 KV 占用与队列长度、不使用延迟信号的接纳规则。
这是本仓库第一次有依据地期待接纳动作产生请求级收益，因为它现在有一个**可行性
边界**要守，而不只是一个宽度要调。需先冻结设计并要求正反序受控重复。

被本轮排除、不再重试的：更换档位/阈值/反馈规则/predictor；接纳侧的捕获点对齐；
在短上下文域继续找接纳收益。

仍然未测、且不得由本轮数据推得的：KV 可行性接纳的实际收益、paging 成本、
抢占与重算的策略比较、U/C 专家信号增量、第二模型、EP/多卡。
