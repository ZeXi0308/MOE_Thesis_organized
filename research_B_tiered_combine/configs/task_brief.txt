读完写一页事实快照，然后开始写 codec。
- 同 token top-k 内 contribution 长尾：GPU 复核头/尾比 OLMoE 48×、LLM-jp 117×（文档级 bootstrap CI）。
- FP8-first + tail-INT4：combine 字节 −62.5%，PPL +0.30（+1.4%），MMLU 200 题不掉分；62.5% 点安全边际 10.3×/22.1×；超过 68.75% 边际迅速收窄。
- INT4 代理换成 MXFP4 / NVFP4 block-scaled 后，头尾排序不变，倍数收窄。
- 在线自适应不必要（Existence Test NO-GO）：静态逐层策略即可；2 卡没有 receiver-group 维度，不做 LUT/MILP。
- 分组 partial 单元（QuotaEP-H）：output-aware late binding 在 top-8/top-16 上显著优于 rank/gate/random，固定 quota 有 4–22% KL 税。因此 2 卡稠密交换的分层信号用 gate 质量（免费、路由后即得）为主，partial 范数（late binding）为变体。
- 旧 codec 58 µs（128×512）是 pack→pinned H2D→unpack 的 host staging，对 GPU-GPU 通信无效；本课题 codec 必须 GPU 驻留。
- DeepEP 生产默认 FP8 dispatch、BF16 combine；最近邻是把 all-to-all 压成 MXFP4 的训练工作（arXiv 2603.02731，训练、非重要性分层）。
- 同策略 kernel 微基准 5 次取中位数即可；系统端到端每配置 2 次。
每元素字节（hidden 维 d）：BF16 = 2；FP8 e4m3 + 每行 FP32 scale ≈ 1 + 4/d；NVFP4（4 bit + 每 16 元素一个 E4M3 scale + 每张量 FP32 scale）≈ 0.5625。 两 lane 平均：k 个单元中 h 个 head 走 FP8、其余走 NVFP4：$\bar{B}=(h\cdot 1+(k-h)\cdot 0.5625)/k$。OLMoE k=8，h=4 → 0.78 B/元素（−61%）；h=2 → 0.67 B/元素（−66%）。
通信时间：每层每方向 $T=\alpha+\text{bytes}/\text{BW}_{\text{eff}}$，α 与 BW_eff 由 2 卡 nccl-tests 拟合。每步节省 $\Delta T = L\cdot\Delta\text{bytes}/\text{BW}_{\text{eff}}$（L 为 MoE 层数）。先用这个式子算每个模型/batch 的预期收益，再与实测对照，论文里放预测 vs 实测。
逐层策略：每层 tail 深度 $r_l$（走 NVFP4 的最低 rank 数），目标 $\min\sum_l \text{bytes}(r_l)$ s.t. 端到端 KL ≤ ε；用 7 月逐层敏感度贪心初始化，端到端复验一次即可。
两种通信模式（论文第 3 节要讲清）：
- 模式 I，稀疏 all-to-all（DeepEP/pplx，大 EP）：单元是 (token, expert) 输出行，rank = 该 expert 在 token top-k 中按 gate 排序的位次；字节 = tokens × k × d。
- 模式 II，稠密 partial 交换（vLLM 非 DeepEP 后端的 DP+EP：all-gather 分发、reduce-scatter/all-reduce 合并，先在 all2all.py 核实）：单元是 (token, 源 rank) 的本地 partial 和；分层信号 = 该 rank 本地 expert 对该 token 的 gate 质量之和；字节 = tokens × EP × d。EP=2 时每 token 恰有 2 个 partial，gate 质量大的走 FP8，小的走 NVFP4。
- 两种模式的字节模型都写出来；2 卡真机测模式 II，模式 I 用仿真与（若有）4 卡。
