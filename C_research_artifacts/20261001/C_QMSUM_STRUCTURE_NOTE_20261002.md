# LongBench QMSum input structure (CPU only, 2026-10-02)

Source: the [LongBench test archive](https://huggingface.co/datasets/zai-org/LongBench/blob/5e628be450b7e67fb7ae6e201bd6d8f7056f7672/data.zip), revision `5e628be450b7e67fb7ae6e201bd6d8f7056f7672`, archive SHA-256 `cb45b11a4133c6bc1d6a44b0f8e701335ff1e543195db1103472e575857f7f64`. Only `data/qmsum.jsonl` was extracted from the already verified archive; its SHA-256 is `e992f5157679b0c1ca281d0da19d1a8b3496117630ae639c9683ed3dab029113`. The pinned [official prompt](https://github.com/THUDM/LongBench/blob/2e00731f8d0bff23dc4325161044d0ed8af94c1e/LongBench/config/dataset2prompt.json) asks for a query-based meeting summary, and [official max generation](https://github.com/THUDM/LongBench/blob/2e00731f8d0bff23dc4325161044d0ed8af94c1e/LongBench/config/dataset2maxlen.json) is 512 tokens.

The 200 source-order test rows contain **35 exact meeting contexts**. Of those, 34 meetings have multiple questions, covering 199 requests; group sizes range from 3 to 11, plus one singleton. Source order has 197 meeting-context runs, so questions from one meeting are mostly interleaved. With the pinned OLMoE tokenizer, reference answers have median 77 tokens, 95th percentile 145, maximum 201; 128/200 exceed 64 tokens. These are reference lengths, **not measured model output lengths**.

The frozen 3500-token LongBench head-tail truncation applies to 199/200 rows. Rendered prompts have a 36-token global common prefix. Each multiquestion meeting has 1755–1756 common rendered tokens, yet **all 200 prompts across all 35 meetings share their first 32 tokens**. A first-32-token group therefore does not identify a meeting and cannot be used as a meeting-continuity label. All 200 constructed prompts plus the official 512-token cap fit the 4096-token model context; the maximum is 4025. Independent full-cap reservation sums to 50,366 16-token blocks across all 200 requests, a structural upper bound rather than observed allocation.

Inputs are source-order, all 200 rows, no inference filtering or arrival-trace selection. `qmsum_structure_v1.json` records distribution details and SHA identities; `20261002_c_qmsum_inputs_v1` contains the frozen CPU input bundle. Larger groups and longer references justify one natural-domain output/EOS observation. They do not establish decode overlap, cache benefit, capacity pressure in a run, or a useful scheduling action.
