# LongBench150：固定组粒度排序的开发格

同机主 GPU 上的 **whole → q1 → q2** 三格均完成150/150条官方源序已见输入，且共同执行1023-token形状warmup、正式测量前APC reset、相同模型与128 seq／1024 batch token／4096可用KV块／64输出上限。各策略只改已知prompt的入队排列：whole保持相同首32 token组完整连续；q1、q2分别每次取该组1或2条。原生FCFS、APC和请求内容未变。这是各臂**单次开发格**，不是多次配对或未见输入确认。

相对whole，q1、q2的平均完成时间分别多 **2.087409s（+46.05%）**、**0.781111s（+17.23%）**，p95多1.964288s、0.393856s；全批时间也变长。q1虽有100/150条问题flow改善、50条恶化，恶化者的**正延迟**均值／中位／p95／最大为 **8.385／7.967／10.834／11.121s**；q2有127条改善、23条恶化，恶化者对应为 **6.797／8.709／8.991／8.991s**。q1最坏源序#55的输出ID、长度和结束原因都与whole相同；q1全部50条flow输家也都没有输出ID或长度变化，因此不能用生成变长解释这批输家。q2的23条输家中有4条输出ID、3条长度、2条结束原因变化。全请求比较相对whole，q1有3条输出ID、1条长度、1条结束原因变化；q2有4／3／2条变化；不作严格等输出工作量比较。

按原始`context_sha256`计算同文档最晚题完成时刻，112组等权平均为 **whole 5.429773s、q1 7.490705s、q2 6.376290s**，p95分别9.764398／11.642333／10.141806s。29个多题文档的平均为 **2.690451／10.783651／5.981410s**：q1全部29组更晚，q2有12组更晚、17组更早，但均值仍更差。这是[逐文档辅助统计](long_document_qa_fixed_grain_document_completion_v1.json)，不预设生产用户必须等同文档所有题目。

[首次分配行动回执](long_document_qa_fixed_grain_actions_v1.json)证实三臂150条请求的首次成功KV分配顺序均与冻结提交顺序完全相同；该事件只是**准入代理**，不是GPU开始执行时刻或主动组配额。相对whole，q1、q2记录的新前缀缓存token少93,200、26,512，恰与各自额外prompt调度token数值相同；这说明当前运行中少了实际可复用前缀工作，但**不自动证明**是哪次cache逐出、组切换或其他生命周期事件造成命中损失。分组交错程度与损失同向，是行动机会的观察，不是可获益的新控制器。

[可复现重访诊断](long_document_qa_fixed_grain_revisit_v1.json)按每请求最多`P−1`的完整16-token前缀块计算，三臂先前prompt提供的相同可重用机会均为107,152 token。50次同组重访中，whole有0次、q1有50次、q2有13次发生在前一同组请求首token之后；q1和q2分别有93,200、26,512 token机会在此前已有请求完成prompt计算后仍未命中。强例是q1的完全重复prompt #38→#123：前者0.748s已有首token，后者8.702s首次分配时3504个可重用token仅命中16；q2的#141→#63共享3264 token，亦仅命中16。重访间隔内累计调度token是工作量，**不是**缓存占用或逐出计数；现有日志支持迟到重访时先前前缀不再可命中，未记录具体块的逐出事件或时刻。

**判定与剩余问题。** 两个事前固定的有限组粒度在这组已见输入上均输给完整组的平均flow、p95和prompt工作；不继续扩大粒度网格或凭这三格设计动态规则。重访诊断已证实，一部分曾完成计算的共享前缀在重访时不可复用；尚未记录具体块及其失去驻留的时刻。继续增加逐块埋点不会自动产生有利动作，因此当前先做有限CPU机会检查：经典树先后约束排序能否在相同理想缓存工作模型中胜过“完整子树”密度。这只是加强基线或提供结构性反例，不是新控制器或GPU收益。实际输出变化与全文F1均保留。
