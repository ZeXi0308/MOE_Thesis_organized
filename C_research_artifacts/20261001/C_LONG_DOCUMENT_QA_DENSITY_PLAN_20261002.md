# C：相同前缀计算量下，直接优化请求等待

## 一个假说、一个动作

作者默认 DFS 已使 prompt scheduled work 达到本150请求队列的受限理想值386498；前缀重复计算方向到此停止。它按子树请求数安排顺序，仍可能先执行单位请求所需工作更多的分组。新开发假说：在全部请求已到达、可看到prompt IDs的当前运行域，保持每个16-token前缀子树连续，按 **子树独有prompt工作量 / 请求数** 升序安排兄弟子树，可在相同总prompt计算量下减少平均TTFT与到达至完成时间。

这是已知Smith规则的树排序启发式开发参照，暂不主张新颖性或原生连续批处理最优性。每个子树工作量包括进入该节点的16-token边、所有后代独有边及各请求必须计算的尾部；尾部作为独立叶。比率相同按最早source index打破平局。只使用已到达prompt IDs，不能读取答案、EOS或实测输出长度。无深度阈值、参数搜索、未来到达或请求删除。

## 最小实验

单格 `c-instruct-longbench-density150-dev-v1`，与已经完成的作者DFS格比较；完整150同输入、所有arrival=0、同模型/greedy/64上限/EOS、128seq/1024batch/4096KV/APC/full-ISL/原生FCFS，仅提交顺序改变。实际排序在服务计时起点后计算，计入CPU成本，并核对本地固定置换。复用DFS cell与完整生命周期，只变排序；不改公共vLLM。保留全部输出、全部等待及排空。非阻塞沿用现有GPU锁、360秒子进程上限、180秒测量上限。

主要判断：平均TTFT、平均flow是否降低；同时报告逐请求改善/恶化、p95、全批完成、每请求最大host返回间隔、实际prompt计算量、所有输出变化及F1。如果实际prompt工作大于386498，则“同计算量改善”等式不成立；如果平均等待不改善，停止此比率，不扫权重或回退选择有利请求。正信号仅允许进行紧邻配对的确认开发实验及机制分析，不自动形成论文贡献或未见数据确认。

CPU串行无限cache模型只作可检验预测：两种顺序均386498总prompt token；平均prompt完成位置由192451.42降至154010.6267（约20%）。实际GPU是否兑现、CPU排序成本及decode批处理是否抵消，由本格回答。完整GPU结果优先于这个模型。
