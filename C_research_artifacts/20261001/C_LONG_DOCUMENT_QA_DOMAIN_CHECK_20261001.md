# C：LongBench MultiFieldQA-en 运行域可行性检查（2026-10-01）

**决策：可作为一个新的、尚未执行的开发资格候选；不能据此宣称长上下文方法或官方 LongBench 成绩。** MultiFieldQA-en 是 LongBench 作者构造的英文**单篇长文档问答**，150 条 test 问题，平均长度 4,559 **词**（不是 OLMoE tokens），用词级 F1；文章来自约 10 个来源，每篇可能对应多道问题。因此它在任务类型和文档输入上独立于目前的 GSM8K 短数学题，但行级问题并不必然代表彼此独立的文档。[ACL 2024 论文](https://aclanthology.org/2024.acl-long.172/)、[官方 task.md](https://github.com/THUDM/LongBench/blob/2e00731f8d0bff23dc4325161044d0ed8af94c1e/LongBench/task.md#L1-L48)。

**4096 上下文的最小适配。** 固定已用 OLMoE Instruct 修订 `7f1c97f440f06ce36705e4f2b843edb5925f4498`，其 [`max_position_embeddings=4096`](https://huggingface.co/allenai/OLMoE-1B-7B-0924-Instruct/blob/7f1c97f440f06ce36705e4f2b843edb5925f4498/config.json)。官方 LongBench [`model2maxlen.json`](https://github.com/THUDM/LongBench/blob/2e00731f8d0bff23dc4325161044d0ed8af94c1e/LongBench/config/model2maxlen.json#L2) 只给其他模型；其 4k Llama2 项用 `max_length=3500`。建议为 OLMoE **预先固定 3500** 作为格式化原始提示的首尾截断预算（超长时各取 1750），然后用该模型已固定 tokenizer 的单个 user chat 模板与 generation prefix 包装；在任何 GPU 运行前，对预定的**源序前 16 行**逐行重编码并核验 `P+64<=4096`，保存截断前后 token 长度、最终 token IDs、模板与哈希。任何行失败都停止并在看输出前修订统一规则，不能丢行；若以后另取固定行段，同样先做 CPU 检查。生成用 greedy、自然 EOS、64 token cap；保存全文、token IDs、停止原因；按官方 F1 评分并报告 EOS/cap。作者的 [`pred.py` chat 分支](https://github.com/THUDM/LongBench/blob/2e00731f8d0bff23dc4325161044d0ed8af94c1e/LongBench/pred.py#L18-L43) 没有 OLMoE，故 **3500 预算、OLMoE chat 包装、vLLM 实现均为本地适配**。它不能与原论文列出的模型成绩当作同协议主张；尤其被截去的文章中段可能包含答案，不能称为完整长文档理解。

**头尾截断后的证据边界。** 作者公布的 4k Llama2 在这项任务的完整 150 行上得到 [36.8 F1](https://github.com/THUDM/LongBench/blob/2e00731f8d0bff23dc4325161044d0ed8af94c1e/LongBench/README.md#L157-L166)，说明相近的短上下文截断协议仍可能产生可评分问答输出；它不预测 OLMoE 的分数。若答案证据位于被删除的中段，低 F1 不能归因于模型、调度或检索能力。将来即使运行 16 行输出资格，也只能描述这套固定适配下的 EOS、输出与 F1，不能证明保留了答案证据或完整文档理解。

**唯一下一步：CPU 输入资格检查。** 按固定源序只取 `0–15` 的 16 行，保存原始问题/文档/答案、`_id`、文档哈希、截断前后模型 token 长度、最终 chat token IDs 与 `P+64`。对每行记录任一参考答案字面是否出现在保留文本内，**仅作证据损失的弱诊断，不据此筛选或改变提示**：字面出现不保证可以回答，缺失也不证明证据全失。若 16 行的固定适配可完整复现且都在上下文内，再根据这份 CPU 检查决定是否运行一次完整输出资格；若运行，须对 16 行全数报告官方 F1、EOS/cap 和截断状态，不以单个非零 F1 作为任务有效性的门槛。重复文章上下文公开计数，这 16 行仅是开发数据。此备忘不冻结任何 GPU 格、容量实验或新控制器；容量压力和策略收益均尚无此任务的运行证据。
