# PEEK-offline Phase 1 author-source subset

Source: [xiexbing/peek](https://github.com/xiexbing/peek/tree/3aca72b63c1dd6433193c0857b965acecdbfbb8a), commit `3aca72b63c1dd6433193c0857b965acecdbfbb8a` (HEAD observed 2026-10-02). The six retained author files are byte-checked against Git blob SHA-1 in `SOURCE_RECEIPT.json`, with SHA-256 for local identity. Author `LICENSE` and `NOTICE` are included. This directory is a read-only source subset; no PEEK package was imported, patched, built, or run.

The [paper's A.3.1](https://arxiv.org/html/2607.02525v1#A3.SS1) describes a **Phase 1** one-shot token-prefix trie: insert at most the first 128 prompt tokens, then DFS visit children in descending subtree request count. This subset locates that operation precisely:

- `python/peek/offline/reorder.py:71` — `reorder_for_prefix_sharing(token_id_sequences, ...)` accepts token-ID lists and returns `permutation[new_position] = original_index`. It checks exact full-sequence duplicate ratio first (`> 0.5` skips); then builds `PrefixTrie()` and skips if coverage of a shared prefix at least 32 tokens is `< 0.1`, or count-weighted average shared depth is `< 64`. Equality at those thresholds does not skip. On acceptance it calls `trie.dfs_order(count_aware=True)` (line 118).
- `python/peek/offline/trie.py:29,35` — `PrefixTrie(max_depth=128)` and `insert` use only the first `min(prompt_length, max_depth)` token IDs. `TrieNode.count` is the pass-through subtree request count.
- `python/peek/offline/trie.py:133,146` — `dfs_order(count_aware=True)` emits indices at each node before child subtrees. Child lists are **stably sorted ascending by `count` and pushed to a LIFO stack**, so the largest subtree is visited first. Equal-count child edges therefore visit in the **reverse of first-insertion order**, with no token-ID lexical tiebreak. Multiple requests terminating at the same node retain their original insertion order in `prompt_indices`.

The retained `prompt.py` defines the author's request wrapper but the one-shot function takes token-ID lists directly. The retained `offline/__init__.py` shows import-time `_install_all()` patching; do **not** import `peek.offline` just to access this function. This source preparation covers only the guarded, count-aware DFS permutation, not the paper's later shadow LRU refinement, eviction hooks, or a full PEEK reproduction. It provides no measured LongQA result and turns no scheduled-token reuse estimate into a service gain.
